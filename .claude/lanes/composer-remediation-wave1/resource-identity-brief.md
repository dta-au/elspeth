## Intended behavior and choice

Every currently admitted spelling of one incoming blob UUID selects the same session-owned resource, gets the same retention protection, and yields canonical response/observation identity. Raw supplied arguments remain auditable and continue to bind their own invocation and proposal receipts. Existing stored marker, sentinel and durable identity grammar is unchanged.

Use one small immutable nominal `CanonicalBlobSelector` (name is an implementation recommendation) containing a `UUID`, with canonical text derived by `str(uuid)`. Put the owned value and its external admission function in a dependency-light shared web module, suggested `src/elspeth/web/blob_identity.py`, imported by Composer tools, planner and proposal reference extraction. It must not import tool registries, service or persistence. An owned constructor rejects impostors; external parsing accepts a string and exactly the same UUID language as the current `UUID(raw)` boundary, with no stripping, extra prefix repair, version restriction or generic coercion. A repairable typed parse failure is mapped to each caller's existing error contract. The existing helper's description saying “canonical” is inaccurate: fix that declaration when replacing it.

Rejected approaches: normalizing Pydantic wire models or the original argument dictionary would alter audit/redaction/proposal hash authority; normalizing only inside SQL lookup would leave current-state retention and planner keys split; making `names_same_blob` parse arbitrary strings would broaden stored authority grammar. One explicit admitted selector is the narrow approach that covers the complete path.

Keep the raw argument models as string models. Parse at each independent external boundary, then carry the owned selector through that operation; do not repeatedly validate and discard UUID values. Pass `.uuid` to existing UUID custody APIs and `.canonical` to canonical text APIs. Do not change all blob persistence types or retrofit every internal helper solely for typing. No schema migration or historical JSON rewrite.

## Authority boundaries and raw hashes

There are two different kinds of UUID-bearing proposal positions:

1. Raw incoming selectors: top-level `blob_id` in the closed reference-tool allowlist, plural `blob_ids`, and legacy `set_pipeline.source.blob_id`. These retain their accepted UUID spellings in stored invocation/proposal JSON. Extract canonical semantic ids for resource comparisons. A raw invocation persisted as Tier 1 does not retroactively become canonical-only input; its original external selector grammar remains the contract.
2. Authored composition authority: nested `blob_ref`, blob_rows `blob_id`, and `path`/`file` `blob:<uuid>` sentinels. Preserve each existing grammar. Widened markers admit hyphenated UUID hex in either case; sentinels require exact canonical lower-case text in `_canonical_sentinel_blob_id`; blob_rows validates hyphenated shape and normalizes case at its existing producer. Do not run the permissive external UUID parser over arbitrary stored option values. Derive canonical comparison values only after the relevant existing owned grammar has admitted that position. Malformed owned authority raises its existing parser/integrity failure; it must not be silently fixed, dropped from retention or translated into ordinary resource absence. Do not expand the closed tool allowlist or scan unrelated arbitrary JSON.

`proposal_blob_arguments_hash` first compares the extracted reference tuple with the canonical receipt blob id, then returns `stable_hash(arguments)`. Make semantic extraction canonical while leaving that final hash over the original private arguments exactly unchanged. Similarly preserve `audit.py` raw `arguments_canonical` / `arguments_hash`, existing set_pipeline authority projection, redaction and hash domains. Equivalent resource selectors can share lookup/observation identity but must not share invocation authority merely because they select one resource. Verify the exact accepting-proposal exclusion still identifies one same-session, pending, matching-tool row, and another pending proposal still prevents the operation.

Do not use normalization of a returned row id to conceal malformed persisted identity. Stored-record admission remains responsible for its own integrity. `names_same_blob` keeps its existing canonical-second-argument precondition and narrow case comparison; the caller must now meet it.

## Regression matrix to implement before the behavior change

Use real stored blobs and public dispatch/loop/accept routes, not only UUID helper unit tests. Spellings: canonical, upper, mixed hex case, braced, hyphenless and lower-case `urn:uuid:` prefix (plus accepted combinations if the original Python UUID parser accepts them). Pin actual pre-change acceptance for the full set; do not narrow to a new regular expression. No tests were executed for this brief.

| Scenario | Positive control | Required refusal / negative control |
| --- | --- | --- |
| Metadata/content/attachment/inspection | Each spelling reads the same same-session row; canonical response id, same content/hash and existing allowlist. | Missing, foreign-session, malformed string, leading/trailing whitespace and non-string selectors preserve existing typed error classification; no bytes, path, metadata or cross-session existence disclosure. |
| Singular and bulk-source binding | Each spelling creates the same canonical binding through direct tool and `set_pipeline.source.blob_id`; uploaded and existing LLM-authored review behavior retained. | Foreign/missing/not-ready resources refuse before publication; manual malformed markers are still rejected by their authority grammar. |
| Plural binding | Different UUIDs with different content bind in supplied order. | Every pair of equivalent spellings triggers existing duplicate-identity refusal before publication; distinct UUIDs with same content still trigger duplicate-document refusal. |
| Current composition retention | Unbound real blob updates/deletes for every spelling. | Every spelling of a bound blob refuses both operations in immediate execution, D1 preview and actual proposal accept. Cover source/node/output, nested lists and mappings, widened inline marker, blob_rows `blob_id`, recognized `*_blob_id`, `blob:` path/file sentinel and direct storage path. Spy/fail the actual effect path to prove it is never reached; assert bytes/hash/metadata and receipt/ledger state remain unchanged. |
| Pending proposal retention | Exact accepting proposal may apply once and replay its own receipt with original arguments. | Another pending proposal referencing any accepted raw spelling retains the same blob. Cross-session proposal does not grant access; wrong-tool/wrong-id/nonpending exemption faults; malformed stored marker/sentinel/JSON faults rather than losing an edge. |
| Publication race | Valid same-session ready blob stages, one pending proposal and one invocation. | Resource disappearance/readiness change between admission and publication retains D1 typed refusal, one invocation and no proposal/effect. Normalization must not revive a raced resource. |
| Raw audit and receipt binding | Canonical and alternate-selector invocations have identical semantic resource identity but their respective original argument JSON/hash; receipt hash equals `stable_hash(original_arguments)`. | Replace stored proposal arguments with an equivalent spelling after receipt creation: hash mismatch still raises integrity failure. Wrong blob, tool, session and receipt binding remain rejected. No historical rewrite. |
| Planner observations | Real scripted loop repeating equivalent selectors records one resource identity for each tool/unchanged nonresource selectors. | Different UUIDs remain separate; invalid/failed lookup does not become successful coverage; content offsets/expected hashes remain distinct. Keep legal rereads and provider budgets. |
| Stored grammar controls | Canonical sentinel and admitted mixed-case hyphenated widened marker still work. | Braced/hyphenless/URN values in stored marker/sentinel positions remain malformed/nonadmitted under existing grammar, even though those strings remain valid *incoming selectors*. |

Use actual composition persistence and snapshots, including refusal before any receipt/ledger creation; checking result prose alone is insufficient. When measuring staged refusal, assert zero blob effect calls and exactly one audited attempted call, not zero audit rows.
