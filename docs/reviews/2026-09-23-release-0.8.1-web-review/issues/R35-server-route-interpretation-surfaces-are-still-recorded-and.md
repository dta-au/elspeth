## Finding

- **Location:**
  - `src/elspeth/web/coordination/repository.py:1256`, next to `:1266-1267` `surface_origin`, and the opt-out marker at `:1228`.
  - `src/elspeth/web/sessions/pending_interpretation.py:2071-2094`, where the review-disabled hash domain uses `actor="composer-llm"`.
  - The docstring at `sessions/service.py:8599-8601`.
  - The contract docstrings at `contracts/composer_interpretation.py:257-260,280-285` and `types/interpretation.ts:147-155`.
- **Wrong:** 889913b1a added `surface_origin` and null LLM provenance for `state_revert`, `yaml_import` and `e2e_seed`. The actor literal does not depend on the origin. **Scenario:** a session opted out of reviews imports YAML with a prompt-review site. The row is born resolved and immutable, with `surface_origin='yaml_import'`, NULL model fields, `actor='composer-llm'`, and an `arguments_hash` that seals that actor. `test_routes.py:8717` exercises this path and never asserts the actor.
- **Fix:** Derive the actor from `surface_origin` (for example `system:yaml_import`) in both the insert and the hash domain, and update the three docstrings. Changing the hash domain changes what these rows certify.
- **Sources:** be-27#1, be-16#1, be-21#1, seam-07-interpretation#2 (all pre-existing), and be-20#2 (diff-anchored: the nullable-provenance widening at `pending_interpretation.py:94-98` is what makes these rows writable at all).
- **Verifier notes:** The same row records the true `surface_origin`, so the contradiction is visible. `'composer-llm'` was already a catch-all sentinel meaning "no user did this". Pending rows get their actor overwritten when they are resolved.
