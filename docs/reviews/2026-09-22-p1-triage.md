## 7. How to execute this

Three constraints shape the mechanics:

- **Filigree has no merge verb.** Consolidation is: comment the evidence onto the
  canonical, then close each duplicate with a reason naming it.
- **Bulk tracker writes get denied by the auto-mode classifier** (recorded twice on this
  tracker). So all writes go through a dry-run-default driver that John fires.
- **Terminal statuses are per type.** Read from `filigree get-template <type> --json`:

  | type | done states |
  |---|---|
  | `phase`, `step` | `completed`, `skipped` |
  | `milestone` | `completed`, `cancelled` |
  | `epic`, `task` | `closed` |
  | `bug` | `closed`, `wont_fix`, `not_a_bug` |
  | `feature` | `done`, ~~`deferred`~~ |

  `deferred` is banned by standing operator order, so a `feature` has exactly one usable
  done state. That bites once: `elspeth-cc1f5e49d1` (guided reframe D) is an *abandoned*
  feature with no abandonment status available, so it closes as `done` with a reason that
  says plainly it was superseded, not delivered. Flagging it because the status will read
  wrong in any later export.

### 7.1 CLI facts the driver was corrected against

Checked with `filigree <verb> --help` on 2026-09-22 — three of these contradict the
obvious guess and would have failed at execute time:

- `add-comment ISSUE_ID TEXT` — **TEXT is positional. There is no `--text`.**
- `close ISSUE_IDS... --reason --status [--force]` — **there is no `--advance` on
  `close`** (it belongs to `start-work`). `--force` uses the template's escape transition
  when the normal one is unreachable, which is what a `bug` sitting at `triage` needs.
- `release ISSUE_ID --if-held --expected-assignee H --reason R`, then
  `update ISSUE_ID --assignee "" --expected-assignee H` — `close` keeps a stale assignee,
  so the clear is a separate step.

### 7.3 The driver

```
.claude/lanes/p1-triage-2026-09-22/apply.py     # the driver  (gitignored lane state)
.claude/lanes/p1-triage-2026-09-22/plan.json    # 67 actions, each with its own evidence
.claude/lanes/p1-triage-2026-09-22/state.jsonl  # written only under --execute
```

It reads each ticket's live state before acting, skips anything already closed, picks the
close status from the ticket's **actual type**, refuses any status outside that type's
done vocabulary, comments the evidence before closing, and records every completed action
