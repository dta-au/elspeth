# Composer provider cancellation path audit

**Date:** 2026-09-27. **Branch:** `fix/composer-provider-boundary-20260927`. **Status:** Closing source and test audit of the repair worktree. This report does not reconcile historical staging rows or claim that staging has been deployed.

## Contract and observed architecture

A dispatched Composer provider attempt moves through quota admission, physical LiteLLM dispatch, one terminal call record, atomic call-audit/token-ledger settlement, and propagation of the request's outcome. `provider_quota.admit_provider_attempt` settles the prior call before another admission; `quota_provider_calls` settles the current span in `finally` ([provider_quota.py](../../src/elspeth/web/composer/provider_quota.py):87-118,136-179). `SessionServiceImpl.finish_provider_attempt` sends the terminal audit envelope through `add_messages_atomic`, which settles the ledger in the same transaction ([service.py](../../src/elspeth/web/sessions/service.py); [audit_checkpoint.py](../../src/elspeth/web/sessions/audit_checkpoint.py)). A missing terminal record for a dispatched call deliberately raises `AuditIntegrityError` and leaves an unknown pending row. Existing negative control: `test_missing_terminal_evidence_retains_pending_attempt` ([test_provider_quota.py](../../tests/unit/web/composer/test_provider_quota.py)). A process death after admission likewise leaves a pending row and blocks a fresh quota admission ([test_provider_quota_end_to_end.py](../../tests/unit/web/composer/test_provider_quota_end_to_end.py)). A positively proven admission cancelled before SDK entry now has a distinct event and zero-use disposition.

The physical Composer dispatch helper admits immediately before calling LiteLLM ([service.py](../../src/elspeth/web/composer/service.py):930-947). Ordinary, advisor, text, planner, and four guided call surfaces use `quota_provider_calls`; auto-title uses `begin_provider_attempt`/`settle_provider_attempt` directly ([provider_quota.py](../../src/elspeth/web/composer/provider_quota.py); [_auto_title.py](../../src/elspeth/web/sessions/_auto_title.py)). Thus cancellation safety depends on both admission and settlement, not only exception classification.

**Timeout boundary:** `asyncio.wait_for` produces builtin `TimeoutError` and the call wrappers mark that `TIMEOUT`; an SDK-raised `openai.APITimeoutError`/LiteLLM `Timeout` is a distinct exception family and must have its own typed branch before the generic SDK fallback. The provider repair's timeout tests should assert one `TIMEOUT` call, unknown post-dispatch usage, no automatic retry, and the existing timeout user response. A pre-dispatch timeout cannot be treated as a sent call merely because its class name contains “Timeout.”

## Confirmed shared quota defects and worktree repairs

### 1. Settlement failure masks request cancellation

Before the repair, `_settle` created and shielded `finish_provider_attempt`, but remembered cancellation only while the settlement task was pending. If that task raised an ordinary exception, `await shield` or `settlement.result()` raised the settlement exception directly; the saved `CancelledError` disappeared. A deterministic in-memory reproduction with a blocked fake `finish_provider_attempt` produced:

```text
settlement cancel=False fail=False observed=success
settlement cancel=True  fail=False observed=CancelledError cause=None
settlement cancel=False fail=True  observed=RuntimeError cause=None
settlement cancel=True  fail=True  observed=RuntimeError cause=None
```

The worktree now joins the owned settlement task, preserves the first `CancelledError` with an ordinary settlement failure as its cause, and promotes registered Tier-1 integrity failure with cancellation as its cause ([provider_quota.py](../../src/elspeth/web/composer/provider_quota.py):54-118). A self-cancelled child is an integrity failure; failed settlement remains pending. Tests `test_cancelled_provider_waits_for_settlement_without_losing_error_priority`, `test_cancellation_during_settlement_observes_child_failure`, and `test_settlement_child_self_cancellation_keeps_attempt_pending` cover these boundaries ([test_provider_quota.py](../../tests/unit/web/composer/test_provider_quota.py)). The latest integrated provider-quota and end-to-end selection passed 23 tests, exit 0. The original fail-closed missing-terminal-evidence control remains.

### 2. Cancellation during database admission can orphan a pending attempt before dispatch

Before repair, `SessionServiceImpl.begin_provider_attempt` committed its admission in a synchronous worker and awaited the result ([service.py](../../src/elspeth/web/sessions/service.py)). The worker contract explicitly allows an already-running worker to finish after its awaiting coroutine is cancelled; its result is discarded ([async_workers.py](../../src/elspeth/web/async_workers.py):194-217,245-290). `admit_provider_attempt` assigned `span.attempt` only *after* that await returned. Therefore a cancellation after worker start could leave a committed pending row while `span.attempt is None`; the wrapper saw nothing to settle, and physical LiteLLM dispatch never happened. A controlled fake-worker reproduction yielded `pending=True settled=False` and no provider dispatch after cancelling the awaiting task and allowing the worker to commit.

This state differs from expected process-death uncertainty: it is graceful request cancellation before dispatch, with a live process able to join admission. The worktree now shields and joins admission, including repeated cancellation, then closes a positively undispatched attempt through `cancel_undispatched_provider_attempt` before SDK entry and lease release ([provider_quota.py](../../src/elspeth/web/composer/provider_quota.py):136-179; [_auto_title.py](../../src/elspeth/web/sessions/_auto_title.py)). The exact-fence persistence API atomically writes one distinct `provider_attempt.cancelled_before_dispatch` audit event, one zero-use operational ledger entry, and a settled attempt; it does not invent a physical `ComposerLLMCall` ([quota_authority.py](../../src/elspeth/web/coordination/quota_authority.py):250-374; [service.py](../../src/elspeth/web/sessions/service.py):10688-10739). The write is idempotent for matching evidence and rejects changed custody, model, or an existing provider call. Zero usage is justified solely by positive proof that the SDK was never entered. After SDK entry, timeout, lost response, or process death, usage stays unknown until real terminal evidence exists.

SQLite tests cover atomicity, replay, exact fence and conflicting evidence; 67 persistence/authority tests passed, exit 0. A real-service auto-title test pauses admission result delivery after commit, cancels before SDK entry, then measures zero SDK calls, one event, one zero-use ledger entry, and a settled intent. The parent lane also ran `test_undispatched_cancellation_is_atomic_and_idempotent_on_postgres` with Docker access: 1 passed, exit 0. The no-provider-call/no-pending controls are tests of this specific predispatch proof; they must not be generalized to a dispatched attempt.
