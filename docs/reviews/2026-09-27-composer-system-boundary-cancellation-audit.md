# Composer cancellation boundaries: closing audit

**Date:** 2026-09-27. **Target:** the `release/0.8.1` repair worktree. **Status:** closing source and controlled-interleaving audit; the reviewed repair and frozen default/PostgreSQL gates passed on candidate `d982e40fe358d9fc6428ee35df3af3cde34bf100`. This report does not claim remote publication, deployment, or reconciliation of historical staging attempts.

## Scope and method

I traced request cancellation through provider admission, guided operations, proposal decisions, freeform tool and response persistence, session leases, pipeline execution, progress publication, and the execution UI. The unit of review is a submitted side effect: its owner must retain the child until it knows whether the effect committed, keep the operation fence alive until dependent writes finish, and expose a receipt that agrees with durable audit and progress. A worker whose Python awaiter is cancelled may still commit; a fenced transaction prevents an unauthorized late write, but it does not by itself tell the caller whether an already submitted write committed.

The discovery search was controlled: `rg -q 'except asyncio.CancelledError'` matched the known positive `src/elspeth/web/composer/provider_quota.py` (exit 0) and missed the known negative `src/elspeth/web/composer/provider_errors.py` (exit 1). An AST walk of `Await` expressions then reported calls through the local `service` binding in the Composer route modules. I checked the instrument against the known direct CONVERT writer (`guided.py`, original line 2201), the known joined reentry writer (line 1289), and a read-only `get_current_state` call. The walk is a locator, not a claim that every service call is a mutation or that it finds writes through other aliases; the table below was completed by reading the helpers, service transactions and tests.

The system has three relevant accumulating states: admitted provider attempts without terminal usage, guided operations without a terminal cohort, and committed results whose request lost the receipt. Cancellation and timeout can grow any of them if the request task abandons a child while a database worker keeps running. A second route or guard then attempts to restore progress, which can create a competing outcome. The high-leverage control is ownership and an authoritative receipt across each submit/commit/notify boundary. Counting exception catches or trust-tier signature changes is not a substitute for that contract.
