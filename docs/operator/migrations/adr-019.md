# ADR-019: Landscape compatibility and preserved stores

This is the current guidance for the ADR-019 pointer in
`SchemaCompatibilityError`. It applies to the 0.8.9 candidate. The
[schema compatibility runbook](../../runbooks/staging-session-db-recreation.md)
defines the current preservation policy.

ADR-019 replaced the single-axis `outcome` / `is_terminal` representation with
`(TerminalOutcome, TerminalPath, completed)`. A store missing
`token_outcomes.completed` or `token_outcomes.path`, or carrying incompatible
token-outcome constraints, is refused. See the
[two-axis terminal model](../../architecture/adr/019-two-axis-terminal-model.md)
for the contract.

## When startup refuses an existing store

1. Stop the candidate from opening the incompatible target. Preserve the
   existing Landscape database unchanged, including SQLite sidecars, and keep
   associated sessions, authentication, blobs and payloads intact. Do not
   delete, reset, recreate, restamp or migrate the preserved store.
2. Keep its compatible prior application available for existing users and any
   read or export operation that application supports. This candidate does not
   make predecessor records readable or reconstruct historical runs.
3. To run the candidate, choose an explicitly new Landscape database target in
   `landscape.url`. For SQLite, use a distinct unused database file path and a
   separate output location for new runs. For PostgreSQL, provision a separate,
   empty supported target namespace. Do not redirect the old application's
   writes to the candidate's store or let both deployments share either store.
4. Follow the deployment runbook for separately authorized initialization.
   Creation requires an object-free, unstamped target; existing compatible
   stores may reopen only after exact schema admission. An epoch number alone
   does not establish compatibility. On refusal, preserve the target and stop.

There is no in-place migration, schema repair, reset or downgrade procedure
here. A fresh target does not transfer old audit history or resume old runs.
Do not run a prior application against the candidate's new store.

The [historical ADR-019 cutover guide](https://github.com/dta-au/elspeth/blob/58b25d524d9c5a2550b0f895ea8f70e1dea9ea51/docs/operator/migrations/adr-019.md)
is retained for context only. Its database replacement and rollback commands
are superseded by the current preservation policy and must not be executed
for this candidate.
