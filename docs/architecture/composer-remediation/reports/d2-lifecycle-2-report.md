## State transitions and bounds

Before spawn, the parent holds the loopback listener. Startup allows at most
eight accepted peers, bounded per-peer frame buffers, and a fixed two-second
bootstrap window. All reads/writes are nonblocking; selectors contain sockets
only. Frames remain limited to 1024 payload bytes and eight received frames;
the parent outgoing buffer is capped at 1028 bytes. Each iteration observes
actual child exit/deadline, with at most a 20 ms selector poll interval.

Authenticated HELLO transitions to watching. BEGIN_RECOVERY, authenticated
channel/protocol failure, or parent stop arms the first immutable 30-second
recovery deadline once. Replays cannot change the armed receipt or extend the
deadline. Parent stop arms first, then sends one SHUTDOWN_REQUEST. Child
graceful intent does not substitute for independent kill authority.

At expiry the owner first polls its retained child, kills only if still alive,
then waits at most one second for reap. Observed exit is terminal: no subsequent
signal. Kill/reap failure raises a visible failure, never successful completion.
No frame-supplied PID, process group, discovered process or waiter thread can
become the target.

COMPLETE is accepted only through the nominal child endpoint witness path.
The child reader receives DISARM_ACK and closes its socket. Parent custody
continues until the actual process exits; completion supplies a maximum
two-second process-exit allowance, taking the minimum with an existing armed
deadline. An atexit hang is killed/reaped and remains a failed outcome.
Bootstrap completion is available only before root binding; slice 3 must bind
the root before construction/worker effects and issue its no-effects witness
only in the corresponding untouched factory phase. A witness is the lifecycle's
assertion after its own joins, not resource introspection performed by this
endpoint. The blocked real-worker probe deliberately withholds COMPLETE.

## Integration obligations and honest limits

Local IPv4 loopback binding is a new runtime requirement; denial must fail
startup closed. Nonce authentication is not OS-isolated descriptor custody:
same-user code able to inspect/manipulate child environment/processes is outside
this claim. Catchable parent shutdown and healthy-child channel loss are
covered. Simultaneous abrupt supervisor destruction and an already-hung child
cannot be guaranteed recoverable by portable user-space code.

The runner inherits original stdin/stdout/stderr, cwd and the environment apart
from consumed bootstrap entries. The parent does not parse/relay MCP bytes or
write stdout. Slice 3 still owns the public thin launcher/private server runner,
closing redundant launcher stdio copies when safe, authenticating before any
runtime imports/construction/worker admission, required executor registration,
full actual teardown/joins and truthful witness issuance. Existing executor
ownership requirements were not weakened to make these probes pass.

Linux establishes real POSIX process custody, deadlines, stdio, helper and
recovery behavior here. Windows process-group/retained-operation adapters are
implemented and pinned by pure controls, **not native execution evidence**.
Native Windows/macOS/BSD public command, console/handle and resource qualification
remain outstanding; no platform support was removed or newly claimed tested.
Parent retains broad gates, signed/static corpus adjudication, Astra review,
D2 integration and public missing-owner acceptance.
