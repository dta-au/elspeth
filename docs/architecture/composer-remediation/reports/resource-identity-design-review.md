## Implementation clarifications

1. **Planner model validation needs actual wiring.** At `pipeline_planner.py:440–457`, metadata and inspection currently interpolate raw values without a model, unlike content and attachment. “Reuse current argument validation” therefore means adding the existing handler models to these branches: `BlobIdArgumentsModel` from `tools/blobs.py` and `InspectSourceArgumentsModel` from `tools/sources.py`. Validate thawed arguments, return no key on model rejection, then call the string-only shared UUID parser. Do not pass `None`, integers, or arbitrary objects directly into that parser and expect its `ValueError` arm to cover them. Include missing/non-string/extra-field cases alongside malformed UUID and whitespace controls. Keep inspection's encoding-key redesign deferred as the plan states.

2. **Projection must not become marker admission.** `contracts/blobs.py:945` intentionally compares only canonical/hyphenated case variants, and the existing tests reject braced/hyphenless graph `blob_ref` values. Keep that comparator and binder grammar unchanged. `proposal_blob_refs.py` currently accepts nonempty marker strings for conservative custody extraction; canonicalizing a parseable string there can conservatively retain a resource without making that graph marker valid. State this distinction in code/test names. Demonstrate that alias selectors work while braced/hyphenless embedded markers still cannot become executable bindings. Keep `_canonical_sentinel_blob_id` validation before any generic projection: uppercase or otherwise noncanonical `blob:` sentinels still raise under its stricter proposal contract, even though the current-state guard conservatively recognizes uppercase sentinel UUIDs. These two existing contracts need not be unified in this slice.

3. **Include the receipt reader as a reviewed dependency.** In addition to `proposal_blob_effects.py`, inspect `sessions/mutation_capabilities.py::_validated_blob_effect_receipt` (`:269` onward). It recomputes `proposal_blob_arguments_hash` from the stored original arguments and compares the result with the durable receipt, then verifies canonical snapshot identity and live state. The proposed projection flows through this reader without a schema or hash change. It should ordinarily need no edit, but the alias retry oracle must exercise it, including both update and delete. The relevant test file is `tests/unit/web/sessions/test_blob_proposal_accept.py`; its existing retry test begins at line 445.

4. **Do not normalize owned evidence as a convenience.** Normalize selectors and extracted references, never a loaded row's identity, receipt identity/snapshot, proposal arguments dictionary, or saved graph. `pending_proposal_reference_id` receives canonical identity from mutation services; preserve that precondition and its exact acceptance check. A receipt or persisted identity corruption must continue to fail rather than being repaired by the shared external-selector helper. Parsed UUID objects required by existing service APIs can be constructed from the admitted canonical string; the “parse once” objective must not force public service signature changes.
