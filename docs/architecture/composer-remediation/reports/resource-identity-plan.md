# Composer resource identity implementation brief

> Planning only. No implementation, test run, scan, commit, or finding closure is represented by this brief. An implementer should execute the bounded tasks below with `superpowers:executing-plans` or the already-selected execution workflow; this document does not request a new approval or execution-method choice.

**Goal:** Equivalent UUID spellings already accepted by Composer identify one session-scoped blob or park throughout lookup, retention, result identity, planner information keys, and proposal custody.

**Architecture:** Normalize accepted external selectors into canonical lowercase hyphenated strings at each independently callable owned boundary using one small shared parser. Keep raw provider arguments and persisted proposal documents intact; compare canonical reference projections while retaining exact hashes over the original documents. Preserve the stricter grammar for blob markers embedded in graph options.

**Tech stack:** Python UUID, Pydantic argument models, SQLAlchemy session store, existing fenced blob services, scripted-provider Composer tests.

**Spec/evidence:** `/workspace/elspeth/docs/architecture/composer-tool-assessment/remediation-plan.md` R2 (lines 224–228, 249–275), R7; tool sheets `get_blob_metadata.md` §7.1 P1/P3, `delete_blob.md` §7.1 P1, `restore_parked_graph.md` §5 N3 and §6.1 item 3. Accepted static-design clarifications are incorporated from `.claude/lanes/composer-remediation-wave1/resource-identity-design-review.md`: actual planner-model wiring, conservative reference projection distinct from marker admission, receipt-reader dependency, and preservation of owned corruption. ## Global constraints and compatibility decisions

- Preserve all existing blob IDs, park IDs, bytes, hashes, records, session predicates, fenced operation authority, and preserve/refuse behavior. No migration, store reset, recovery redesign, or provider bypass.
- Blob-selector acceptance remains Python `UUID(value)` acceptance: canonical, uppercase, mixed case, braces, hyphenless, and lowercase `urn:uuid:` forms normalize. Leading/trailing whitespace remains invalid for blob tools. Do not add a UUID-version restriction.
- Park selectors already admit bounded nonblank text. For parseable text use `str(UUID(value.strip()))`; non-UUID text stays unchanged and still reaches `target_unavailable`. This follows the assessment's bounded recommendation and preserves `park-one` behavior.
- Embedded graph markers retain their current narrower grammar. `names_same_blob` and existing negative tests for braced/hyphenless bound `blob_ref` values remain valid. The repair supplies that helper a canonical target ID; it does not make previously invalid graph markers bindable. `blob:` prefix and filesystem paths remain case-exact.
- Conservative proposal reference projection is a custody operation, not marker admission. It may canonicalize a parseable nonempty marker string to retain its resource while the graph binder still rejects that marker. `_canonical_sentinel_blob_id` must validate before generic reference projection: uppercase or otherwise noncanonical `blob:` sentinels retain their existing proposal rejection, even though the live-state guard conservatively recognizes uppercase sentinel UUIDs. These contracts remain distinct.
- Preserve raw arguments in provider/audit evidence and stored proposal documents. Canonical resource-reference projection is distinct from `stable_hash(arguments)`. Old canonical pending/applied proposal records and their receipts must remain readable and verifiable without rewriting them.
- Normalize external selectors and extracted reference projections only. Do not normalize loaded row identities, receipt IDs/snapshots, stored proposal argument dictionaries, or saved graphs to repair inconvenient evidence. Owned corruption must still fail. `pending_proposal_reference_id` continues to receive a canonical mutation-service identity and preserve exact acceptance checks. Existing service APIs may still construct UUID objects from admitted canonical strings; avoiding duplicate normalization does not justify changing those APIs.
- Public successful `blob_id` echoes become canonical for formerly noncanonical requests; metadata already returns canonical `id`. Key/envelope names and content paging/hash semantics stay unchanged. This is an intentional response-value correction; no frontend union/envelope redesign is needed.
- Keep malformed argument and unavailable-resource dispositions as they are unless needed solely to avoid falsely resolving an invalid planner information key. Do not fold the broader error-code catalogue or async recovery-repair redesign into this task.
- Exclude BOS-01 pagination, parked-window paging, inspect-source snapshot/failure ownership, encoding-aware inspection-key redesign, model/secret discovery, and general observation completeness. This slice can address BOS-03 and XC-08 plus their identity consequences; it cannot close R2 or XC-13 generally.

## Review focus

1. A parseable alias of a bound blob must never permit update/delete, including approval preview and later acceptance.
2. Canonicalization must never turn a foreign resource into an owned one, disclose a foreign/missing identity, or weaken a fence check.
3. Equivalent aliases must collapse to one planner fact, while a different blob, content offset, or expected hash remains a different fact; invalid IDs must supply no fact.
4. Projection of old and new proposals must preserve exact private-argument hashes and receipt recovery, including a crash after effect but before settlement.
5. Park normalization must preserve unknown/foreign indistinguishability, target eligibility, pending-proposal disposition on refusal, and the same provider-authored recovery path.
