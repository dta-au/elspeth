# Composer check justification: evidence, codecs, credentials

Read-only systems review, 6 November 2026, `release/0.8.10-assembly` working tree. Source and meaningful test bodies inspected; no tests, imports, database queries, profiling or product edits performed. This is advice about checks and intervention level, not validation of the concurrent timing repair. Line anchors describe the inspected working tree, which includes concurrent changes.

Decision: which checks actually prevent hostile user/provider input or accidental developer mistakes, and which repeat an invariant because a function discards its own admission result? Boundary: provider input through control-content admission, retained recorder/evidence codecs and local graph handoff. Horizon: one synchronous admission and one operation's later reconstruction; mutable storage and current SQL authority remain distinct boundaries. Trusted operators and plugin developers are not adversaries. No claimed latency benefit.

Observed causal chain: raw text becomes typed data, but APIs often return only an ordinary snapshot or `None`; a downstream owner therefore repeats decoding/scanning or reconstructs a source. Mutable graph exposure creates a second, different reason for rechecking. The hypothesis is that preserving admission results and controlling graph ownership removes unnecessary work. The alternative is that a later check sees changed policy, mutable state or storage, in which case the repeat is justified. The discriminating question is whether those inputs can change through a supported path between the two checks.

## Findings

### 1. SIMPLIFY recorder admission at the decoder return contract; do not remove the raw decoder boundary

**Concrete chain.** `src/elspeth/web/composer/continuation_application_graph.py:197-208` calls `_require_source_chunk` (`334-340`, size/hash/canonical verification), then `decode_recorder_snapshot`. The latter (`src/elspeth/web/composer/continuation_audit_buffer.py:463-486`) verifies the same source again, decodes and projects its complete schema, and invokes `encode_private_chunk` to validate the restored projection. The source constructor then scans the original canonical text again at `208`/`343-349`.

**Justification.** First admission must reject corrupt or accidentally mismatched retained bytes, wrong codec/schema, omitted fields, invalid drain links and credentials retained from users/providers. A correct SHA binding alone does not establish schema or credential safety. Conversely, the second verification of the same immutable `PrivateChunk` inside this synchronous call has no new storage observation or authority to establish. Re-encoding serves a real field-preservation purpose, but need not independently redo all raw-byte admission work.

**Minimal sufficient intervention.** First remove the same-call duplicate verification by arranging one raw-chunk admission owner and an internal already-verified decoder path. Then let that owner return `(original chunk, detached validated snapshot, applicable policy)` rather than discard the admission facts and rebuild them. Keep the public raw decoder fully validating; its other callers do not inherit this constructor's precondition. Do not delete `_admit_recorder_data` merely because this particular call already checked the chunk: that callback also admits memo hits reached elsewhere.

**Policy distinction.** The decoder's scan uses default environment names, whereas the constructor supplies names. On this particular raw-string scan, `src/elspeth/contracts/credential_material.py:240-266,327-352` only uses environment references under a structured credential-field parent, which a root string never has. That is not a general license to collapse structured state scans or scans under different field roles. Prefer an explicit shared admission policy contract over relying on that incidental equivalence.

**Opponent/evidence.** `tests/unit/web/composer/test_application_recorder_source_work.py:59-73` adds a credential-bearing withheld reply and requires refusal on both source routes; `112` onward admits an original chunk and rejects changed raw bytes. `tests/unit/web/composer/test_continuation_audit_buffer.py:277-317` checks field-dispatch completeness with a deliberately removed field. `321-346` actually mutates the original nested provider data after encoding and confirms detached immutable nested decoded values. These support retaining constructors and field checks, not only the outer frozen dataclass. Decisive follow-up: perform the same malformed/hash/schema/credential-tail/field-omission controls against both public raw admission and the new internal handoff, including warm memo hits. Risk: medium if scoped to one call; high if generalized to unverified source reuse.

#### Further intervention-level conclusion: admit recorder fields once, preserve them through owned serialization

The stronger intervention is a **closed recorder/request-context admission flow**, not another cache of large canonical envelope strings. `src/elspeth/web/composer/provider_context.py:326-351` already detaches and semantically checks prepared messages/tools before serialization; V4 result admission checks complete provider fields at `src/elspeth/web/composer/provider_result_admission.py:658-673`, with tool-argument policy remaining separate. Recorder encoding embeds that history and passes the entire document through generic root-string scanning (`src/elspeth/web/composer/continuation_audit_buffer.py:427-447`; `src/elspeth/web/composer/continuation_codec.py:163-183`). Evidence later does the same after constituent state, recorder, application, metadata and transcript admission (`src/elspeth/web/composer/continuation_evidence.py:677-712,740-786`). These are source-flow observations, not measured execution counts.

The root-string scan cannot re-establish structured credential meaning: `src/elspeth/contracts/credential_material.py:240-318` enables credential-field handling only when visiting mapping values; a root string receives text classification as one traversal node. Thus the scan repeats token/URL/assignment detection without proving plugin slots, environment-reference eligibility or decoded structural budgets. When exact immutable fields retain their already-admitted roles, wrapping them in another canonical document introduces no new outsider input. Raw retained-data decoding remains a separate boundary requiring actual byte/hash, grammar, schema and semantic admission; mutable captures require renewed admission of changed values.

**Current nominal records do not establish this stronger contract.** `PrivateProviderContext` checks disposition/type/size rather than credential content (`src/elspeth/contracts/composer_provider_context.py:23-35`); `PrivatePlannerCandidate` holds ordinary raw/canonical strings (`src/elspeth/web/composer/audit.py:221-232`). `ComposerLLMCall` validates and freezes fields without admitting every later error/private field under credential policy (`src/elspeth/contracts/composer_llm_audit.py:265-339`). Ordinary withheld-reply construction likewise checks only nonblank text (`src/elspeth/web/composer/withheld_replies.py:51-53`). Consequently the outer scan currently supplies a real backstop for accidental unscanned record construction. **Do not remove it globally or trust a frozen nominal record as a credential certificate.**

The minimum sufficient next design is one recorder constructor that admits every fresh semantic field and preserves detached immutable request/result atoms in their specific slots. New entries and changed fields receive their applicable rules; unchanged history retains its original admission. Its matching serializer owns exact quoting, field preservation, byte accounting and hash binding, without reclassifying all admitted payload text. Raw decoder entry points reconstruct those admissions from the actual stored source. Use the actual source-producing constructor or lexical handoff, never an `already_checked` boolean, arbitrary “safe string”, generic permit or codec-name exemption. Existing content-addressed request-block proofs establish bytes, not credential semantics (`src/elspeth/web/composer/continuation_audit_buffer.py:321-367`), so they cannot simply be relabelled admitted. This can preserve the existing stored format and records.

Concrete opponents constrain the change:

- **Role assignment:** individually innocuous strings `password` and `ordinary` become a credential-field use when assembled as `{"password":"ordinary"}`. A field-mapper label moved into a plugin secret slot likewise needs admission under its new role.
- **Concatenation:** separately innocuous fragments can form a token, assignment or credential URL. Scan the completed newly produced text; an admitted atom cannot be split or joined and retain its old admission.
- **Decoded wire:** JSON escapes can hide a credential until tool arguments are decoded; preserve the actual refusal tested at `tests/unit/web/test_credential_guard.py:430-434`.
- **Policy change:** an environment reference's eligibility changes when its allowed-name set changes; preserve the ordinary mutation control at `tests/unit/web/test_credential_guard.py:622-647`.
- **Direct construction:** a normal withheld record containing a credential URL must still fail at the strengthened recorder constructor, as the existing source-route control requires (`tests/unit/web/composer/test_application_recorder_source_work.py:59-73`). Cover direct request-context construction, every recorder channel and newly added schema fields as well.

The canonical writer quotes each value and emits punctuation rather than concatenating leaf strings (`src/elspeth/contracts/_canonical_json_writer.py:18-57`). No source-backed case was identified here where merely quoting unchanged, fully role-admitted immutable fields creates a genuine new credential. This is **not** a proof that the heuristic detector gives identical answers on all raw versus serialized spellings: escaping, URL interpretation, native replay fields and schema exceptions need differential controls. Confidence is high in the boundary mismatch and current constructor limitations, moderate in full consolidation feasibility. Risk is high for blanket deletion and medium for a closed recorder/request-context slice. No measured savings or deadline improvement is claimed; implementation remains unauthorized by this review.

### 2. MOVE graph integrity work into a stricter ownership interface before removing projections

**Concrete check.** `AdmittedTurnEvidence._require_original_graph` (`src/elspeth/web/composer/continuation_evidence.py:497-514`) reprojects the admitted snapshot, reconstructs a recorder source and reprojects the graph before `take_graph` or `copy_graph`. The property at `475-480` exposes the mutable graph itself.

**Actor/failure.** A trusted caller can accidentally mutate nested decoded arguments or split a required alias without bypassing Python immutability. `tests/unit/web/composer/test_admitted_turn_evidence.py:155-197` does exactly that with ordinary dictionary assignment and verifies refusal. Thus the current graph check is justified; nominal `AdmittedTurnEvidence` does not prove its exposed graph remains original. First source admission proves original bytes; after `.graph` escapes, the graph is again mutable local state. Rechecking is a mutation refresh, not a second external authorization.

**Minimal sufficient intervention.** Change the return/borrow contract: keep source-admitted immutable evidence separate from mutable execution graphs; allow immutable inspection or a single lexical transfer, and make independent mutable copies explicit. Preserve SQL/current-authority validation outside this data owner. Only then remove graph re-projection on a path whose graph has never escaped. Carry the admitted recorder source lexically rather than reconstruct it in `_require_original_graph`. This is a small ownership redesign with call-site migration, not a local `if` deletion or a global cache.

**Counterevidence/limits.** Existing production readers use `.graph` in `src/elspeth/web/composer/continuation_evidence_application_data.py:392,501,670` and session consumers, so the ownership change is not already established. The test at `314-338` additionally checks that independent decoded graphs do not share mutable owners. Decisive follow-up: migrate all readers for the selected handoff, mutate a copied graph through ordinary dictionaries and prove source proof remains sound, preserve aliases, and reject double transfer. Risk: high for deletion today; medium for bounded API migration. No recommendation to weaken the field-preservation roundtrip or stored records.

### 3. MOVE provider tool-wire admission to an explicit retained parse result; retain pre-effect whole-batch refusal

**Concrete checks.** `src/elspeth/web/composer/provider_gateway.py:1072-1091` scans admitted provider completion/tool wire. `src/elspeth/web/composer/tool_batch.py:1153-1181` repeats metadata and tool-wire scanning before effects; `1453-1455` then parses arguments again. `src/elspeth/web/credential_guard.py:651-686` discards the decoded value and returns `None`.

**Why some repetitions exist.** External provider bytes can encode a credential with JSON escapes; scanning only raw text is insufficient. Malformed text may still be retained in audit, so the fallback text scan is also necessary. Tool-batch comments correctly identify internal adapters bypassing the gateway: they are trusted implementations, but can accidentally return unscanned external content. The common pre-effect admission remains necessary under that currently weaker return contract. Batch state also determines field-mapper interpretation; earlier credential admission is not reusable if that state changes.

**Minimal sufficient intervention.** Make common completion admission return a closed result containing the exact raw wire, parse outcome and detached decoded value, bound to the semantic tool name and relevant credential-state interpretation. Have gateway and alternate adapters converge on that admission before retention/audit; let dispatch consume the parse outcome. Preserve malformed/resource failure classification and raw audit redaction. This changes admission information flow; it is not permission to delete the batch check while alternate paths remain.

**Opponent/evidence.** `tests/unit/web/test_credential_guard.py:430-441` supplies escaped credentials and malformed credential text. `src/elspeth/web/composer/tool_batch.py:1470-1490` distinguishes malformed JSON retained in audit from bounded-resource failures redacted for replay. `credential_state_for_tool_batch` (`src/elspeth/web/credential_guard.py:526-537`) withholds stale state when a batch can replace nodes. A shared result must preserve those differences. Decisive follow-up: same batch through gateway and internal-adapter paths; escaped credential in a later call; field-mapper patch following a node-changing call; malformed and over-bound wire; confirm no earlier audit/effect occurs. Risk: high if gateway check alone is removed; medium for converged admission.

The underlying raw JSON preflight and post-decode checks are **KEEP**: `src/elspeth/web/composer/bounded_json.py:56-85` protects the decoder from raw byte/depth excess, while `88-124,148-160` enforces decoded structure/items/finite numbers. Their predicates differ. A raw-byte cap does not prove finite `1e999` or decoded item budget. The hostile nesting test at `tests/unit/web/composer/test_coerce_stringified_json_object_args.py:87-89` and structure-budget tests at `tests/unit/web/composer/test_review_json_typing.py:137-152` are meaningful controls; repeated invocations on the same already-admitted wire are the target, not these predicates.

### 4. KEEP plugin-specific credential meaning; SIMPLIFY repeated traversal only with a combined field-policy contract

**Concrete checks.** `src/elspeth/web/credential_guard.py:689-737` scans the whole state and each component's options with `allowed_secret_ref_fields`. `src/elspeth/contracts/credential_material.py:240-318` separately classifies text shapes and credential-field contents.

**Actor/failure.** A user/provider can put a low-entropy literal under a plugin credential field whose name is otherwise ordinary. The whole-state generic pass does not prove it safe: `tests/unit/web/test_credential_guard.py:298-311` uses database output `url: low-entropy-secret`. Conversely component-only scans miss metadata and other control fields. Neither existing pass subsumes the other. Field-mapper labels require semantic projection rather than treating a column named `password` as a secret assignment (`src/elspeth/web/credential_guard.py:452-491`).

**Minimal sufficient intervention.** Retain these meanings. If reducing repeat traversal, supply per-component field roles to one state admission traversal and return a policy-bound immutable-state result. Preserve total/per-component budgets and first-refusal semantics intentionally; naively flattening into one budget may change acceptance. Pure text classification can be shared independently, as it already is, without conflating field roles. Mutable environment-name collections in the generic API genuinely require re-observation: `tests/unit/web/test_credential_guard.py:622-647` adds/removes an allowed name and observes changed admission.

**Decisive follow-up.** Compare current versus combined traversal for database URL literals, exact managed/environment references, field-mapper labels, metadata credentials, nested controls and aggregate/per-component budget edges. This is an optional architecture simplification, not evidence of a current security defect. Risk: medium; confidence high that deleting the component pass outright is unsound.

### 5. SIMPLIFY the digest producer contract; do not frame Python monkeypatch resistance as an attacker boundary

**Concrete checks.** `src/elspeth/web/composer/continuation_codec.py:144,221-242` chooses different proof paths when `sha256` differs from `_TRUSTED_PRIVATE_CHUNK_SHA256`. `src/elspeth/web/continuation_retention_memo.py:567-618` accepts a digest callable but only reuses cached digest results for the exact original SHA function. `tests/unit/web/composer/test_continuation_codec.py:858-891` replaces it with a stateful callable returning a different digest on a later call.

**Actor/failure.** That test proves the injected callable's behavior is re-observed. It does not represent a hostile user/provider capability, and the branch does not protect a process already running malicious Python. It may support test instrumentation or an intentional injectable-producer contract. No supported runtime crypto replacement path was identified in this bounded source review; that is a coverage limit, not a whole-repository absence claim.

**Minimal sufficient intervention.** Prefer a fixed SHA implementation owned by the canonical-proof service, with tests observing real digest work rather than changing its semantic contract. Then remove the unnecessary callable trust distinction. If supported runtime injection is intended, explicitly specify its purity/configuration lifetime instead. Keep canonical validation, bounded memo accounting and comparison of each presented reference's digest/length to actual bytes. Those catch external/corrupt source substitution and must remain.

**Counterevidence and follow-up.** Existing producer-change tests deliberately require this behavior, so simply deleting the branch changes that test-facing contract. First confirm runtime callers only need fixed SHA, and preserve changed-canonical/wrong-reference tests (`tests/unit/web/composer/test_continuation_codec.py:850-853`). Risk low to medium for the fixed-service change, confidence moderate; lower priority than ownership and admission consolidation. No measured speed benefit claimed.

## Cross-review

Authority reviewer challenged finding 1: public decoder callers and memo callbacks do not inherit source-constructor checks; a frozen outer snapshot alone does not prove nested immutability. Accepted: recommendation narrowed first to the same-call duplicate verifier, with broader reuse conditional on detachment and nested-field controls. Existing nested detachment evidence is identified above rather than assumed. Reviewer supplied the digest-producer candidate, independently verified in source and the stateful replacement test.

I challenged reconstruction review's proposed final-read graph elimination: `src/elspeth/web/composer/continuation_runtime.py:399-418` indeed consumes only final producer information, but validation *inside* the read can use the graph. `src/elspeth/web/sessions/continuation_runtime.py:168-173,203-205` retains P4/attachment verification and `src/elspeth/web/composer/continuation_evidence_restore.py:165-185` retains source/SQL identity checks. The intervention must supply immutable source-bound semantics to those validators, not reuse an escaped mutable graph or skip them. Same snapshot/hash references, fresh successful complete closure loading and unchanged environment can prove unchanged source semantics under existing SHA assumptions; tuple equality is not independently required. Suggested falsifiers: ordinary nested graph mutation, changed environment, a corrupted late dependency, and changed Stop/P4 SQL state.

## Confidence Assessment

Overall confidence: **Moderate**. Findings 1-4 are grounded in concrete callers and test bodies; proposal safety remains conditional on the specified interface changes. Finding 5 is **Moderate** because supported runtime digest injection was not exhaustively inventoried. No measurement or test outcome is claimed.

## Risk Assessment

Implementation risk: **Medium** for scoped consolidation, **High** for deleting checks without replacing their ownership/admission contract. Reversibility: **Moderate**; pre-1.0 APIs can change, but stored source bytes and audit records must remain preserved. Principal risks are lost credential interpretation, acceptance changes at resource/refusal boundaries, accidental alias mutation, and confusing immutable data admission with current SQL authority. Retain raw boundaries, meaningful adversarial inputs and fresh authority reads.

## Caveats and Required Follow-ups

Read-only advice, not implementation approval or qualification. These findings do not independently authorize implementation. Before relying on removals, select one admission/ownership slice and verify its complete callers, preserve refusal taxonomy and source records, then run focused real outsider/accidental-mutation controls. Keep provider-authored Composer behavior and ordinary tutorial behavior intact. Operator signing, migration, storage cleanup and broad process changes are outside this review.
