# Composer reconstruction checks: independent systems review

2026-11-06; target `release/0.8.10-assembly`. Source-only review of the current working tree. No product imports, tests, profiles, database reads, or Git mutations were run. This review applies the systems-thinking and SME-agent protocols. Mainline changes and results are not qualified by this review. Publication is a durable audit finding, not implementation approval.

## Decision and system boundary

Keep checks that stop hostile user/provider material crossing into trusted message provenance, or detect accidental state/accounting inconsistency. Change the ownership/API when it forces an already admitted fixed document to be reconstructed merely to repeat its admission. Developers/operators/plugin authors are trusted in intent; a forged Python class, malicious internal implementation, or `object.__setattr__` attack is not a justification here. Ordinary nested-dictionary mutation and accidental mixing of valid owners remain relevant.

The boundary is one current Composer restoration, including its separate SQL transactions, policy/schema callbacks, message assembly, and eventual publication of live owners. The time horizon is this operation and a later independently invoked restoration. Fixed source DATA, mutable live graph, and current SQL authority have different lifetimes. The causal hypothesis is that APIs returning both source admission and a mutable graph cause callers needing only the first to pay for both. This is supported by source flow, not by an isolated runtime cost measurement. No change remains a valid option if measurement shows the residual operation is immaterial; no latency or deadline improvement is claimed.

## Findings

### R1 — SIMPLIFY: pair original tool-family admission with its one shelf construction

**Minimum intervention: private owner/API data flow, not another local bypass flag. Confidence: High for redundant acquisition, Moderate for the proposed receiving change.**

[src/elspeth/web/composer/continuation_prompt_producers.py:255-284](../../../src/elspeth/web/composer/continuation_prompt_producers.py#L255-L284) returns only `.inputs` from `_inputs_with_tool_sources_on_connection`, although that function has already admitted actual tool-result and feedback sources at [src/elspeth/web/composer/continuation_prompt_producers.py:332-339](../../../src/elspeth/web/composer/continuation_prompt_producers.py#L332-L339). The ordinary runtime then calls `_rebuild_admitted_shelf` ([src/elspeth/web/composer/continuation_prompt_producers.py:1693-1699](../../../src/elspeth/web/composer/continuation_prompt_producers.py#L1693-L1699)), which calls `_assemble_admitted_cohort` ([src/elspeth/web/composer/continuation_message_families.py:1332-1365](../../../src/elspeth/web/composer/continuation_message_families.py#L1332-L1365)); `_sources_from_admitted_evidence_on_connection` admits those recipes again at [src/elspeth/web/composer/continuation_message_families.py:359-361](../../../src/elspeth/web/composer/continuation_message_families.py#L359-L361). This is discarded useful data followed by reacquisition, rather than a new external trust transition inherently requiring a second recipe reconstruction.

The initial transition proves selected evidence, current inventory, original bootstrap/transcript and recipe source relationships. Reconstructing actual wire still matters: a hostile provider can supply unselected arguments/native material; an accidental source join can attribute one paid response to another tool call. Preserve full paid-response, recorder, historical completion, control-result and wire checks. A lexical acquisition result should carry the actual admitted tool tuples into the existing paired-family helper ([src/elspeth/web/composer/continuation_message_families.py:1299-1330](../../../src/elspeth/web/composer/continuation_message_families.py#L1299-L1330)) in the original transaction, then build the shelf after the transaction ends. Do not retain the cohort on a reusable runtime/producer, cache authority, or independently copy feedback objects that must retain their aliases.

Keep the later independent current read. Its purpose is different: Stop, head/inventory, custody and data may change while assembly and policy callbacks run. Owed-finish and FailureSchema branches already have distinct semantics; the paired helper explicitly refuses them. If Stop changes the ordinary branch into eligible owed-finish, discard the ordinary cohort. R196's bounded shape is supported, but its phrase “final-source acquisition remains necessary” must not be interpreted as requiring every pure graph reconstruction inside that acquisition (R2).

Real opponent bodies: [tests/unit/web/sessions/test_continuation_message_families.py:330-362](../../../tests/unit/web/sessions/test_continuation_message_families.py#L330-L362) changes paid response/audit/recorder facts after a positive; [tests/unit/web/sessions/test_continuation_message_families.py:366-384](../../../tests/unit/web/sessions/test_continuation_message_families.py#L366-L384) injects unselected argument wire. [tests/unit/web/sessions/test_continuation_current_evidence.py:268-288](../../../tests/unit/web/sessions/test_continuation_current_evidence.py#L268-L288) makes Stop durable after graph reconstruction and expects cancellation. These tests were read, not executed. Qualify actual runtime pairing with multi-history results/feedback, transaction identity, FailureSchema, Advisor/owed routes, and final refusal before any publication.

### R2 — MOVE/SIMPLIFY: separate final fresh source admission from unused mutable graph reconstruction

**Minimum intervention: source-admission versus graph-materialization API separation. Confidence: High for the coupling; Moderate for feasibility; not approval for local deletion.**

[src/elspeth/web/composer/continuation_runtime.py:399-418](../../../src/elspeth/web/composer/continuation_runtime.py#L399-L418) performs a final independent runtime read after local state construction and policy callbacks. It passes `_prior_evidence`, then uses `final_source` for bootstrap, producer-input and transcript equality before binding provider cost and disclosure. The prior option only reuses the immutable decoded snapshot ([src/elspeth/web/composer/continuation_evidence.py:416-425](../../../src/elspeth/web/composer/continuation_evidence.py#L416-L425)); dependencies, field semantics and graph construction are repeated at [src/elspeth/web/composer/continuation_evidence.py:430-450](../../../src/elspeth/web/composer/continuation_evidence.py#L430-L450). [src/elspeth/web/composer/continuation_evidence_restore.py:165-170](../../../src/elspeth/web/composer/continuation_evidence_restore.py#L165-L170) constructs a new admission on that final path. The final graph itself is not returned as the live graph.

**Keep the fresh read.** It catches real late changes: [tests/unit/web/sessions/test_continuation_runtime.py:326-424](../../../tests/unit/web/sessions/test_continuation_runtime.py#L326-L424) corrupts the selected evidence bytes from the current-policy callback after first acquisition, requires the final read to refuse, and checks provider cost/disclosure remain unbound. A hostile user can Stop or change admissible current state through supported concurrent actions; accidental persistence mistakes can corrupt referenced bytes. Initial admission cannot prove later currentness.

**Challenge its payload.** Rebuilding another mutable graph is not identical to fresh validation. Fixed source semantics are deterministic for the exact selected root/source references and environment. A successful fresh complete content-addressed closure read, equal selected snapshot/source and equal environment can reestablish those fixed inputs without inventing a second full graph. A separate full-tuple equality is not additionally required when that loader has already deterministically verified the same closure under the existing SHA assumptions.

However, simply substituting the old `AdmittedTurnEvidence` is unsafe and incomplete. Construction-time consumers use graph data: [src/elspeth/web/composer/continuation_evidence_restore.py:239-247](../../../src/elspeth/web/composer/continuation_evidence_restore.py#L239-L247) invokes active-batch and attachment checks; [src/elspeth/web/composer/continuation_selected_batch_graph.py:26-74](../../../src/elspeth/web/composer/continuation_selected_batch_graph.py#L26-L74) compares selected batch codec, wire, cursor and calls against graph facts. Producer/family validators and P4/attachment readers also use that representation. Preserve every current SQL-versus-original-source relationship, using immutable source-bound semantic projections or a deliberately separated source owner. Do not let mutable `.graph` become a certificate of immutable source meaning.

The existing [tests/unit/web/sessions/test_continuation_runtime_evidence_reuse.py:18-54](../../../tests/unit/web/sessions/test_continuation_runtime_evidence_reuse.py#L18-L54) explicitly expects a fresh admitted object and graph lock. That is an implementation-shape assertion, not evidence that a second graph is the threat-model requirement. Retain the test's fresh-source/read and actual owner checks, and replace the fresh-lock assertion only when a concrete new API proves the same behavior. Oppose it with changed environment, late nested dependency corruption under the same reference, P4 receipt change, Stop, and ordinary mutation of the earlier graph. The immutable source proof must neither trust that mutation nor unnecessarily reinterpret it as changed stored bytes.

### R3 — KEEP at exposed ownership boundary; SIMPLIFY only after removing exposure: graph value/alias proof

**Minimum intervention: keep local copy/transfer guards now; any wider removal requires changing the owner API. Confidence: High.**

`AdmittedTurnEvidence.graph` ([src/elspeth/web/composer/continuation_evidence.py:475-480](../../../src/elspeth/web/composer/continuation_evidence.py#L475-L480)) exposes nested mutable graph DATA. `copy_graph` and `take_graph` verify source values and alias partition before giving a consumer mutable ownership ([src/elspeth/web/composer/continuation_evidence.py:482-514](../../../src/elspeth/web/composer/continuation_evidence.py#L482-L514)). This is not protection from malicious internal Python: ordinary code can mutate a returned nested dictionary or replace one shared dictionary with an equal independent dictionary. [tests/unit/web/composer/test_admitted_turn_evidence.py:155-197](../../../tests/unit/web/composer/test_admitted_turn_evidence.py#L155-L197) does exactly these operations through normal references and verifies value/alias refusal, with a positive preserving required aliases. Independent runtime consumers need independent mutable graphs; within one graph, equality does not replace identity where shared mutation matters.

Do not remove these guards globally because the constructor admitted source once. The earlier invariant proves original source semantics, not the current contents of an escaped graph. `_finish_copied_current_evidence` ([src/elspeth/web/composer/continuation_evidence_graph.py:547-568](../../../src/elspeth/web/composer/continuation_evidence_graph.py#L547-L568)) deliberately produces a separate graph while retaining source ownership. A lower-cost local handoff is valid only where lexical exclusivity is established: the R205 original-evidence chain can carry the actual unexposed admitted owner to its one consumer, after the fresh source read, instead of discarding and rebuilding it. A nominal type or frozen outer record alone does not prove exclusivity. The minimum sensible intervention is a one-consumer data handoff; no sealed capability hierarchy is justified.

### R4 — KEEP provenance reconstruction and exact wire checks; do not classify plain-shelf support as obsolete compatibility

**Minimum intervention: retain the existing parsing/provenance boundary. Confidence: High.**

A retained dictionary is not sufficient evidence that its contents were generated by a trusted message producer. `MessageShelfSnapshot.require_owned_links` ([src/elspeth/web/composer/continuation_message_shelf.py:60-84](../../../src/elspeth/web/composer/continuation_message_shelf.py#L60-L84)) rejects guard-provenance keys from plain shelf messages. Shelf assembly rejects native keys when no producer recipe is present ([src/elspeth/web/composer/continuation_prompt_producers.py:1752-1756](../../../src/elspeth/web/composer/continuation_prompt_producers.py#L1752-L1756)), reconstructs each named producer, and compares exact ordered wire at [src/elspeth/web/composer/continuation_prompt_producers.py:1784-1785](../../../src/elspeth/web/composer/continuation_prompt_producers.py#L1784-L1785). Feedback reconstruction additionally binds the actual message and source within the same cohort ([src/elspeth/web/composer/continuation_prompt_producers.py:1786-1806](../../../src/elspeth/web/composer/continuation_prompt_producers.py#L1786-L1806)). Native families check the original committed paid provider response ([src/elspeth/web/composer/continuation_message_families.py:458-483](../../../src/elspeth/web/composer/continuation_message_families.py#L458-L483)). These are trust transitions for hostile provider/user content and accidental source substitution, not repeated checks of an immutable typed value alone.

Keep current policy/schema reconstruction where it can change legitimately: FailureSchema has current policy semantics ([tests/unit/web/sessions/test_continuation_message_families.py:390-417](../../../tests/unit/web/sessions/test_continuation_message_families.py#L390-L417)). Keep exact wire checks even if SQL source admission is paired. An empty recipe tuple/plain-wire branch is not, by itself, a backwards-compatibility defect: it handles messages with no trusted producer provenance, while refusing elevation of plain fields into trusted native material. Do not delete it merely because the project is pre-1.0. No-change protects this boundary; source-pairing may reduce acquisition work without changing it.

## Cross-review and dispositions

The evidence reviewer falsified the overly narrow argument “final_source has few uses, therefore its graph construction is unnecessary”: construction-time P4, active-batch and attachment validators consume graph facts. Accepted. R2 is explicitly an owner/API change preserving those joins, not a local deletion. The reviewer agreed that verified equal deterministic source closure/environment can preserve immutable semantic proof without a second tuple-equality gate. They required normal nested-graph mutation, late dependency corruption, changed environment and P4/Stop opposition; all are retained above. After reading the complete draft, the evidence reviewer confirmed the R2 objection was resolved and found no additional blocker in R2/R3; their positive cross-review does not cover the complete R1/R4 producer chain.

I challenged the authority review's initial proposed deletion of a repeated principal query. `ComposerOperationRunning.__post_init__` ([src/elspeth/web/sessions/composer_operations.py:277-284](../../../src/elspeth/web/sessions/composer_operations.py#L277-L284)) binds session/kind but does not bind claim logical operation to context history; two same-session valid owners can be accidentally mixed without forging Python objects. `require_continuation_mutation` derives its job through context history, while `validate_historical_effect_references` queries by claim. The authority reviewer accepted this counterexample and rejected unconditional deletion. Their narrower proposal returns admitted transaction-local rows to `_require_current_continuation_running` ([src/elspeth/web/sessions/continuation.py:2837-2893](../../../src/elspeth/web/sessions/continuation.py#L2837-L2893)) and preserves its complete claim/history comparison. I support that minimum owner/API intervention: the first helper already checks segment generation, so a second query is not needed merely to add that same predicate; claim binding still is.

## Risk Assessment

Implementation risk: **Medium**, rising to **High** if R2 is treated as a cache or local bypass. Reversibility: **Easy** for source changes before adoption; no stored-record mutation is proposed.

| Risk | Severity | Likelihood | Mitigation |
| --- | --- | --- | --- |
| Reused mutable graph silently substitutes changed values/aliases | High | Plausible with ordinary code | Keep exposed copy/transfer proof; use immutable semantic source facts |
| Stale currentness after Stop, policy callback or concurrent commit | High | Real tested scenario | Preserve independent final admission and defer live cost/disclosure binding |
| Paired transaction includes policy callbacks or widens owed-finish | High | Design-dependent | Assemble policy portions after exit; retain explicit branch semantics |
| Larger API refactor costs more than residual latency warrants | Medium | Unknown | Measure named work and original-clock workflow before expanding scope |

## Information Gaps

No isolated timing establishes the cost of R1 or R2, and no new runtime or PostgreSQL tests were run. Actual R205 receiving code remains mainline-owned and can change during this review. Complete coverage of all graph-consuming P4/attachment validators would be required for R2 implementation. Root's reported earlier exact-recorder-byte controls and remaining first-END deadline miss are context, not results independently reproduced here.

## Caveats & Required Follow-ups

Before implementing R1, preserve current source/failure ordering, SQL topology, one-consumer aliases, and per-transition provider behavior. Before implementing R2, inventory actual graph consumers by source inspection and design immutable semantic inputs for their current joins; do not substitute a flag saying “admitted.” Exercise relevant focused controls and PostgreSQL transaction behavior, and then measure the unchanged original-clock route. A successful micro-optimization does not establish the deadline is fixed. Preserve existing records and explicitly reject unsupported formats; this review authorizes no migration, reset, signing, provider bypass or tutorial-specific path.
