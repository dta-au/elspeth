## 2. U-13: public attachment-root grammar

Extend the existing replacement contract; do not introduce another authoring tool.

| Root form | Supported binding choices |
|---|---|
| Default `source` | Existing `blob_id`; new ordered `blob_ids`; existing `inline_blob`; ordinary plugin options |
| Named `sources[name]` | New `blob_id`; new ordered `blob_ids`; ordinary plugin options |

`inline_blob` remains default-only. Named `inline_blob`, including an explicit null key, remains an undeclared argument. This avoids adding multiple inline creations and their settlement obligations to U-13.

### 2.1 Selector semantics

Exclusivity is determined by **non-null values**, not key presence.

| Input | Required interpretation |
|---|---|
| Selector omitted or explicitly null | No binding selected by that field |
| One non-null selector | Use its existing or newly defined resolver |
| Two or more correctly typed, non-null selectors | Admit the argument shape, then return recoverable `source_binding_ambiguous` |
| `blob_ids: []`, wrong selector types, undeclared keys | Argument-shape failure |
| Empty or malformed non-null identifier | Existing identifier-validation failure; do not reinterpret it as omission |
| No non-null selector | Existing ordinary-options path |

The new `blob_ids` field is nullable, with a non-null value constrained to an ordered list of 1–1,000 strings. It requires provider-authored `plugin="blob_rows"`. One element retains document-row semantics; it does not become singular text-source semantics.

Do not encode selector exclusivity in a model validator or schema `oneOf`. Correctly typed ambiguity must continue through the recoverable semantic channel.

| Change | Guarantees it must preserve |
|---|---|
| Extend default/named source models and declarations. | Existing nullable scalar/inline behavior and semantic-versus-argument failure channels. (`src/elspeth/web/composer/redaction.py:1843–1857`; `src/elspeth/web/composer/tools/sessions.py:690–699,1071–1080`) |
| Add plural resolution to replacement. | Ordered authoritative entries; whole-list validation; no content reads during metadata resolution. (`src/elspeth/web/composer/tools/sources.py:1349–1357,1401–1456`) |
| Keep default-only inline creation. | Existing prepared-custody identity, safe-argument hashing, provenance and settlement. Canonical selector handling must not weaken the custody checks. (`src/elspeth/web/composer/pipeline_custody.py:218–259`) |

| Reuse plural resolution per root. | Duplicate IDs and duplicate content refuse within a list. The same attachment may feed separate roots; duplicate tracking must remain local to each resolver invocation. (`src/elspeth/web/composer/tools/sources.py:1384–1446`) |
| Accept identifiers, not asserted custody metadata. | Caller-authored `options.blobs`, `blob_ref` and source-authoring authority remain prohibited. Top-level `source`/`sources` selection retains its existing field-and-value exclusivity rule. The new nested-selector null semantics do not relax that separate rule. ### 2.2 Candidate assembly and publication

Resolve each root into local candidate data. Publish one replacement only after all roots, nodes, outputs and existing invariants have passed. A successful earlier root must never escape when a later root fails.

Parameterize the plural resolver’s rejection construction using an owned operation discriminator, as the singular resolver already does. Full replacement must produce candidate-specific errors; incremental binding must retain saved-state feedback.

| Change | Guarantees it must preserve |

| Collect root refusals without publishing partial state. | Candidate errors name `source` or `source:<name>` correctly and do not present unrelated saved-state errors as repair targets. (`src/elspeth/web/composer/tools/sessions.py:713–743`) |
| Preserve component-level rejection collection. | Stop further checks for an already-rejected component; continue independent components; report bounded overflow rather than silently dropping it. (`src/elspeth/web/composer/tools/sessions.py:777–808`) |

## 3. U-13: public projection and private authority

### 3.1 Public producer/consumer closure

Repair projection and replacement together:

1. Project singular resolver-owned custody as `blob_id`.
2. Project plural resolver-owned custody as ordered `blob_ids`.
3. Remove the corresponding resolver-owned storage and entry metadata from public options.
4. Preserve ordinary plugin options and reconstructible public review shells.
5. Refuse malformed, contradictory or unsupported custody with `round_trip_unavailable`.

Do not strip arbitrary plugin options merely because their names resemble storage fields. Removal must follow the recognized custody representation.

Extend `AuthoringSource` with an immutable plural-ID representation, such as `tuple[str, ...] | None`. Update raw parsing, owned readmission and encoding together. Remove the named scalar prohibition in both raw and owned branches. Do not add the public selectors to persisted `SourceSpec` merely to transport them.

| Change | Guarantees it must preserve |
|---|---|
| Extend authoring serialization. | The advertised authoring document is supported public replacement grammar; unsupported state produces explicit unavailability. (`src/elspeth/web/composer/tools/_common.py:4053–4147`) |
| Extend raw and owned response admission together. | Closed response shapes, immutable owned collections, nominal owned types and final `SetPipelineArgumentsModel` readmission. (`src/elspeth/web/composer/tools/state_responses.py:71–87,375–437`) |
| Encode plural IDs without metadata. | Source names, identifier order and ordinary options survive serialization. Diagnostic state remains a separate surface. (`src/elspeth/web/composer/tools/state_responses.py:476–488`) |
| Preserve existing persisted representations. | Optional persisted spec fields remain omitted when absent so unrelated content hashes do not change. No migration or store reset is authorized. (`CONTRIBUTING.md:878–886`) |
| Preserve bounded mutation echoes. | Oversized echoes are dropped whole; full replacement does not acquire a whole-document mutation echo. (`src/elspeth/web/composer/tools/_common.py:4150–4187`) |

“Exact authoring projection” means supported source configuration can be reconstructed while the relevant authoritative custody records remain unchanged. It does not promise future availability, transfer reviewed authority, certify stored bytes or authorize execution.

Reapplication through public dispatch resolves **current** records. For an otherwise admissible changed record, the reconstructed entry must use refreshed metadata. Missing, foreign-session, non-ready or prohibited-modality records must produce the appropriate refusal without changing the graph/version.

### 3.2 Reviewed plural reuse

Extend `resolve_reviewed_source_authority` to discover and validate every persisted plural entry before granting private reuse. Use the existing owned entry parser for shape validation.

For every entry, verify:

| Recorded property or boundary | Required check |
|---|---|
| `blob_id` | Valid identity; lookup resolves that entry in the current session |
| Session owner | Current user owns the session |
| Lifecycle | Current record is READY |
| Creation modality | Permitted for plural user-verbatim binding |
| `payload_ref` | Equals the authoritative full content hash |
| `filename` | Equals authoritative filename |
| `mime_type` | Equals authoritative MIME type |
| `size_bytes` | Equals authoritative byte size |
| List structure | Preserve recorded order, supported cardinality and duplicate rules |

A mismatch refuses stale reviewed content. Do not silently refresh a reviewed proposal into a different candidate.

| Change | Guarantees it must preserve |
|---|---|
| Extend scalar authority discovery to plural entries. | Session ownership and current lifecycle checks precede authority issuance. Existing scalar content anchors remain enforced. (`src/elspeth/web/composer/reviewed_source_authority.py:121–207`) |
| Compare the complete persisted entry. | Runtime admission already checks full hash, filename, MIME type and byte size, and independently rejects plural LLM-authored records. Preserve that execution backstop. (`src/elspeth/web/execution/service.py:3813–3853`) |
| Preserve private binding identity. | Authority remains an owned, non-public, session-bound object; candidate reuse requires the exact reviewed source binding. Public IDs and copied metadata cannot activate it. (`src/elspeth/web/composer/tools/_common.py:3647–3679`; `src/elspeth/web/composer/tools/sessions.py:811–865`) |
| Keep reviewed options authoritative only after fresh validation. | The private path currently copies reviewed options and exempts their plural custody from the public prohibition. The new validation must run before that exemption is usable. (`src/elspeth/web/composer/tools/sessions.py:1314–1335,1446–1450`) |
| Preserve commit identity checks. | Owned-state candidate hashes still must equal the proposed content hash. Failed validation must not publish a replacement. (`src/elspeth/web/composer/pipeline_commit.py:402–417,469–479`) |

**Hash limitation:** comparing reconstructed state hashes detects metadata changes only when reconstruction incorporates freshly resolved values. The reviewed path can otherwise compare two identical stale copies. Explicit authoritative entry comparison is therefore required.

Metadata equality also does not establish physical-byte integrity. Plural resolution performs no content read. File verification and execution admission remain separate checks; this change makes no universal precommit full-file hashing claim. (`src/elspeth/web/composer/tools/sources.py:1349–1357`; `src/elspeth/web/composer/pipeline_commit.py:477–479`)

## 5. U-14: source inspection through shared custody

### 5.1 Shared synchronous reader and async compatibility

Extract the existing streaming implementation into one synchronous service operation. Its proposed owned result is:

```python
@dataclass(frozen=True, slots=True)
class VerifiedBlobPrefix:
    record: BlobRecord
    prefix: bytes
    verified_content_hash: str
    total_size_bytes: int
```

The names above are proposed. The required properties are a nominal owned result, immutable prefix bytes, and metadata from the same fenced read as those bytes.

The synchronous operation must:

1. Validate the actual operation context and permitted operation kind.
2. Require `prefix_bytes >= 1`.
3. Acquire existing session BLOB_CUSTODY.
4. Run existing deletion and storage-version reconciliation.
5. Obtain the exact fenced metadata record.
6. Enforce READY lifecycle and non-null stored hash.
7. Stream and hash the complete file in bounded chunks, retaining only the requested prefix.
8. Verify the full hash.
9. Complete the existing post-read fenced-record comparison.
10. Return the owned result only after the context manager exits successfully.

The existing async method remains:

```python
async def read_blob_content_prefix_verified(
    ...,
) -> tuple[bytes, str, int]:
    ...
```

It delegates through the existing worker mechanism to the synchronous implementation and projects its result back to exactly:

```text
(prefix, verified_content_hash, total_size_bytes)
```

Do not expose the new result object through that existing async contract. Execution currently unpacks precisely that triple. (`src/elspeth/contracts/blobs.py:573–595`; `src/elspeth/web/execution/service.py:1504–1519`)

### 5.2 Inspection adapter

`inspect_source` uses the synchronous operation with the real storage root, operation context and authority supplied by dispatch. Preserve nominal context validation and requested-session matching. Do not acquire a replacement authority or construct another recovery mechanism.

Build facts from the returned locked record, verified prefix/hash and actual streamed byte count. Do not fetch metadata again afterward. Preserve the public facts shape and existing encoding behavior.

| Change | Guarantees it must preserve |
|---|---|
| Move streaming into the shared service seam. | BLOB_CUSTODY precedes session metadata transactions; SESSIONS is not retained during filesystem inspection. (`src/elspeth/web/blobs/service.py:3270–3301`) |
| Reuse recovery unchanged. | Committed hash chooses recoverable storage; recovery requires custody and its existing write guard. Unmatched candidates remain untouched for integrity handling. (`src/elspeth/web/blobs/service.py:1101–1189`) |
| Preserve stream verification. | READY-only reads, missing-content classification, null-hash fault, complete-file digest and bounded prefix retention. (`src/elspeth/web/blobs/service.py:3380–3437`) |
| Validate dispatcher-owned context. | Actual storage root, exact owned context, authority and matching session remain required. (`src/elspeth/web/composer/tools/blobs.py:1950–1971`) |
| Keep structural inspection structural. | No raw rows; bounded facts, explicit-encoding warning, credential inspection and unchanged graph/version. (`src/elspeth/web/composer/tools/sources.py:1887–1896,1941–1979`) |
| Preserve continuation evidence. | Register the actual admitted result and selected serialized content. Structural inspection cannot fabricate full-original attachment-inspection clearance. (`src/elspeth/web/composer/tool_batch.py:3691–3704`; `src/elspeth/web/composer/tools/blobs.py:1984–1994`) |

Do not reuse `_locked_read_ready_blob` unchanged: it obtains custody but materializes the file with `Path.read_bytes()`. (`src/elspeth/web/composer/tools/blobs.py:1973–1983`)

### 5.3 Exception-to-result contract

The service retains its typed exceptions. Only the inspection adapter applies the mappings below.

| Condition | Required inspection outcome |
|---|---|
| Missing session engine/session ID | Existing repairable tool failure |
| Malformed arguments | Existing argument-error channel |
| Malformed non-null blob identifier | Existing identifier refusal |
| Missing metadata or foreign-session blob, represented by `BlobNotFoundError` | Repairable “not found” failure; no foreign metadata disclosure |
| Non-ready record, represented by `BlobStateError` | Repairable unreadable-status failure; retain the service-owned lifecycle explanation without a second metadata lookup |
| Already-missing backing file, represented by `BlobContentMissingError` | Existing repairable missing-storage failure; do not expose its storage path |
| ENOENT/ESTALE during open/read | Service classifies these as `BlobContentMissingError`; adapter applies the same missing-storage outcome |
| Hash mismatch, `BlobIntegrityError` | Propagate; no successful facts or generic repairable failure |
| READY record with null hash, changed fenced metadata, malformed owned metadata, `AuditIntegrityError` | Propagate |
| Stale/released authority, `SessionOperationFenceLost` | Propagate; no facts publication |
| Missing/mismatched dispatcher-owned context or storage root | Owned-context fault; do not recast as an LLM argument mistake |
| Unsupported server-supplied operation kind | Preserve the service admission fault |
| Other `OSError`, including EACCES/EIO | Propagate |
| Unsupported/non-text explicit codec or encoding on an unsupported source kind | Existing repairable encoding failure |
| Structural parse uncertainty or truncation | Existing bounded facts/warnings; no invented completeness |

The existing inspection distinguishes missing metadata, non-ready records and already-missing storage as repairable failures. (`src/elspeth/web/composer/tools/sources.py:1898–1928`) The shared service distinguishes raced deletion from genuine I/O faults and integrity anomalies. (`src/elspeth/web/blobs/service.py:161–178,3387–3433`)

This deliberately preserves inspection’s repairable missing-file behavior while retaining stricter service exceptions for other consumers. It is not permission to catch `BlobError`, `OSError` or `Exception` broadly.

## 7. Failing-first and mutation specification

### 7.1 Evidence rules

During implementation:

- Run new-behavior tests against the frozen baseline before applying production fixes.
- Record the completed runner exit and the precise failed assertion or boundary.
- A missing future helper, invalid fixture, wrong plugin policy, absent context or collection error is not acceptable red evidence.
- Use existing interfaces for setup. Create valid plural state through existing binding APIs; create real owned contexts and policy/catalogue pairs.
- Assert setup success and a valid positive control before perturbing the subject.
- Give each mutation an explicit predicate it must break. Collection/setup failure does not kill a mutation.
- Restore the production implementation between mutations.
- Record already-passing safeguards as retention controls, not new-red tests.

The tables below describe required baseline failures from source inspection. None has been executed in this revision.

### 7.3 Public freshness after projection

Add **`test_public_plural_projection_resolves_current_records`** to `test_authoring_reconciliation.py`.

This test depends on producer/consumer closure. Its baseline closure failure is already covered above; do not claim the unchanged baseline independently demonstrates a freshness failure.

Sequence:

1. Bind valid plural state and obtain its public projection.
2. Assert projected IDs/order and absence of resolver-owned metadata.
3. **After projection**, perturb the authoritative record.
4. Reapply the captured public document through actual public dispatch.

Required cases:

| Perturbation | Required oracle |
|---|---|
| Admissible filename/MIME/size/hash change | Accepted replacement entries equal refreshed authoritative values, rather than the saved values |

**Mutation:** bypass current resolution and copy historical entries. The changed-value case must expose stale values, and the unavailable/modality cases must expose missing refusals. Asserting only success or an arbitrary failure is insufficient.

## 10. Completion and compatibility boundary

Implementation is complete only when:

1. Public default/named singular and plural cases pass declared/model/wire admission and actual replacement.
2. Projection closes through public dispatch under unchanged custody; post-projection changes demonstrate fresh resolution.
3. Reviewed plural reuse compares the complete persisted entry and refuses stale content before publication.
4. Exact explanation results carry the expected catalogue code through delivery.
5. Actual inspection dispatch uses shared custody/recovery and passes PostgreSQL contention and post-stream fence-loss tests.
6. Every retained guarantee has its stated control, and each specified mutation fails the relevant predicate.
7. Selected intended contracts and capability teaching match the implementation.
8. Applicable gates and integration checks have completed with recorded exits and unchanged measured inputs.

Compatibility decisions are explicit:

- Existing ordinary options, default singular binding and default inline behavior remain supported.
- New selectors are additive; nullable companion selectors retain their semantic meaning.
- Named inline creation and plural LLM-authored binding remain unsupported.
- Public reconstruction refreshes current admissible metadata; reviewed reuse refuses changed metadata.
- Existing async verified-prefix consumers continue receiving a triple.
- Existing inspection repairable misses remain repairable; integrity, authority and genuine I/O faults remain distinct.
- Existing limits remain in force with their effective restrictions disclosed.
- No migration, store reset, signing operation, deployment or live-provider acceptance is authorized by this specification.

Until execution, mark claims **SOURCE_REVIEWED_ONLY** or **UNVERIFIED**, and retain historical **KNOWN_NONCONFORMANCE** evidence. Red/green and mutation evidence belongs with ordinary test logs/results and the relevant contract revision; no separate sealed plan package or invented assurance infrastructure is required.
