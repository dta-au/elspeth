## 3. U-13: attachment-root authoring contract

### Selected public representation

**I — Extend the existing source grammar rather than adding another authoring tool.** Retain top-level `source`/`sources` exclusivity and explicit failure-route choices. Add these selectors to the replacement source models and registered schema:

| Source form | Binding |
|---|---|
| Default `source` | Existing `blob_id`; new ordered `blob_ids`; existing `inline_blob`; or ordinary plugin options |
| Named `sources[name]` | New `blob_id`; new ordered `blob_ids`; or ordinary plugin options |

**I — Keep `inline_blob` limited to the existing default-source path in this unit.** Named/plural attachment authoring can use existing session blobs without introducing multiple inline creations and their settlement obligations. (`L:src/elspeth/web/composer/redaction.py:1790–1857,2157–2169`; `L:src/elspeth/web/composer/tools/sessions.py:1071–1125`; `L:src/elspeth/web/composer/pipeline_custody.py:218–259`)

**I — Admission rules:**

- At most one binding selector may be present. Conflicting selectors produce recoverable `source_binding_ambiguous`; wrong types and undeclared keys remain argument errors.
- `blob_id` follows the existing singular resolver’s plugin, modality, review and session rules.
- `blob_ids` is an ordered, nonempty list for `plugin="blob_rows"`. One element still means one document row; it does not become singular text-source semantics.
- Preserve list-local duplicate-ID and duplicate-content rejection. Do not introduce cross-root deduplication: the same attachment may intentionally feed two named roots.
- Preserve refusal of caller-authored custody metadata and LLM-authored plural blobs.

These rules extend existing mechanisms rather than granting authority through identifiers. (`L:src/elspeth/web/composer/tools/sources.py:757–776,797–845,1384–1456`; `L:src/elspeth/web/composer/tools/sessions.py:690–699,1074–1080`)

### Candidate construction and publication

**I — Resolve every selected root before publishing one candidate.** Refactor the singular/default and named-source paths around shared per-root resolution. Preserve root names, provider-authored routes and explicit validation-failure choices. A later invalid root must leave the saved graph/version unchanged; it must not publish an earlier valid root. (`L:src/elspeth/web/composer/tools/sessions.py:985–997,1287–1318,1492–1497,1973–2022`)

**I — Preserve the candidate-specific failure envelope.** Full-replacement refusals must describe the rejected candidate, including the correct source component, rather than presenting saved-state errors as candidate repair targets. Parameterize the plural resolver’s rejection construction so replacement and incremental calls retain their respective semantics. (`L:src/elspeth/web/composer/tools/sessions.py:713–743`; `L:src/elspeth/web/composer/tools/sources.py:1359–1382`)

**I — Keep feedback compatibility explicit.** Preserve optional legacy `data.source_blob` for its existing default singular case. New named/plural cases may omit it and use normal validation/version/affected-component feedback. Do not let a per-root loop accidentally report only its last resolved attachment as complete feedback. (`L:src/elspeth/web/composer/tools/sessions.py:985–997,1118,2051–2053`)

### Public projection and authority

**I — Repair the producer and consumer together.** Project singular custody as `blob_id` and plural custody as ordered `blob_ids`; remove resolver-owned storage fields and plural entry metadata from public options. Retain ordinary options and reconstructible review shells. Malformed or unsupported custody must return `round_trip_unavailable`, never an apparently exact document containing rejected custody fields. (`L:src/elspeth/web/composer/tools/_common.py:4053–4147`; `L:src/elspeth/web/composer/tools/sessions.py:2496–2505`)

**I — Extend both raw and owned response paths.** `AuthoringSource` needs an immutable plural-ID representation, matching parser, encoder and readmission checks. Remove both existing named-ID exclusions; changing only the serializer would still fail response admission. (`L:src/elspeth/web/composer/tools/state_responses.py:71–87,375–388,418–437,476–488`)

**I — Define “exact” narrowly and usefully:** the projection is accepted authoring grammar that reconstructs the supported source configuration while the relevant custody records remain unchanged. It does not transfer reviewed-source authority, guarantee future availability, or grant execution approval. Fresh public authoring resolves current READY records. Reviewed/proposed source reuse must independently preserve its recorded identity checks. (`A:docs/reference/composer-advisor-tools/get_pipeline_state.md:18–23,388,443–447`; `L:src/elspeth/web/composer/tools/_common.py:3647–3659`)

**I — Extend reviewed plural revalidation explicitly.** The current reviewed-source resolver discovers scalar references; it must also validate every persisted plural entry against current session ownership, readiness, modality and recorded full hash before granting reuse. (`L:src/elspeth/web/composer/reviewed_source_authority.py:121–161,165–207`; `L:src/elspeth/web/composer/tools/sessions.py:1314–1335`)

**M — Integrity distinction:** plural resolution reads metadata, not attachment contents. Reconstructed-state hashes can detect changed custody metadata; they cannot prove physical bytes match unchanged metadata. Existing proposal candidate-hash comparison is also conditional on owned-state authority. **I:** retain separate tests for stale authoritative records and physical corruption; do not claim universal precommit file hashing. ## 5. U-14: source-inspection custody

**I — Factor the existing verified-prefix reader into a synchronous service operation usable by synchronous tool dispatch.** Keep the existing async method as a wrapper over that shared implementation. Return one owned result containing the locked metadata record, bounded prefix, verified full hash and actual byte count. Fetching metadata again afterward would recreate the split observation. (`L:src/elspeth/web/blobs/service.py:3270–3301,3360–3437`)

**I — Required read sequence:**

1. Admit actual session operation context, authority and storage root.
2. Acquire the existing session custody lock.
3. Reconcile supported interrupted deletion/replacement state.
4. Read exact fenced metadata.
5. Stream the complete file while retaining only the inspection prefix.
6. Verify integrity and complete the post-read fenced metadata check.
7. Build structural facts from that verified record and prefix.

This reuses the existing authority; it introduces no independent lock or recovery implementation. (`L:src/elspeth/web/blobs/service.py:3270–3301,3380–3437`; `L:src/elspeth/web/composer/tools/blobs.py:1950–1973`)

**I — Preserve dispositions:** missing/not-ready attachments retain repairable tool refusals; genuine corruption, invalid owned metadata and lost authority remain faults/refusals according to their existing typed boundaries. Preserve encoding behavior, facts credential inspection and unchanged graph/version. (`L:src/elspeth/web/composer/tools/sources.py:1898–1979`)

**I — Preserve structural scope through continuation.** Register the actual admitted inspection result, as the current dispatcher does. Structural inspection must not manufacture full-original credential-inspection clearance or assert that the model read the complete attachment. (`L:src/elspeth/web/composer/tool_batch.py:3691–3704`; `L:src/elspeth/web/composer/tools/blobs.py:1984–1994`)

**M — Avoid an attractive regression:** `_locked_read_ready_blob` obtains custody correctly but calls `read_bytes()`. Reusing it unchanged would lose bounded-memory inspection. (`L:src/elspeth/web/composer/tools/blobs.py:1973–1983`)
