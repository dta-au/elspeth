## Objective and binding guarantees

Exceptions must reach their responsible owner with their semantic type, original identity, causal chain and useful safe evidence intact. Public descriptors remain separate from private exceptions. Refusal, cancellation and incomplete observation must not become approval, successful completion or an unsupported diagnosis. Diagnostic ownership remains singular. [`S:11,19–29,40–44`]

The following constraints apply to every change and its tests:

| Change boundary | Guarantee that must be preserved | Source |
|---|---|---|
| Composer authoring and recovery | Pipeline structure continues to come from the provider. Failure handling may refuse or withhold; it must not author a substitute proposal. | `AGENTS.md:355–362,370–380` |
| All Composer entry paths | Tutorial sessions use the ordinary backend, including error handling, prompts and recovery. | `AGENTS.md:364–368` |
| Owned exception/carrier handling | Discriminate using concrete owned classes and direct fields. No message matching, structural Protocol dispatch or speculative attribute probes. | `docs/architecture/adr/032-validate-by-trust-domain.md:127–140`; `CONTRIBUTING.md:173–190` |

## Test evidence rules

Tests below have one of two classifications:

- **R — regression:** must fail on the applicable pre-fix behavior and pass after the repair.
- **P — preservation control:** may already pass on the baseline; must fail under its named mutation.

For each R test, implementation must record the actual assertion failure, process exit and tested source identity before fixing that behavior. Import errors, unavailable new symbols, invalid fixtures, unrelated failures and test timeouts do not establish the required red.

A declaration-only prerequisite, such as introducing the owned observation-fault class, may be added before exercising unchanged pre-fix control flow. Dependent repairs must establish their red after prerequisite repairs, with the target defect still present. For example, a publication-retention test must reach the new service-failure carrier before it can establish that publication loses that carrier.

Each test must:

1. Prove that its injected seam was reached.
2. Assert the responsible owner’s observable outcome.
3. Include the deliberately recoverable or independently correct neighbor.
4. Fail under the named behavioral mutation.
5. Settle its asynchronous work and inspect the actual test-process exit.

No implementation or qualification claim follows from the test requirements in this document.

## U-19 / F2–F3: explicit ownership of observation faults

### Observed defects

The progress callback executes inside the stream catch-all, so application exceptions become stream fallback. Bound snapshot-kind mismatch executes inside polling recovery, so it becomes backoff. Acknowledgement and cancellation relationship checks have analogous catch boundaries. [`fe/api/composerOperationObserver.ts:104–145,156–186,195–225`]

Propagation alone is insufficient. `runDurableComposerTurn` can render a general exception’s message and mark the optimistic user row failed. Inactive-session reconciliation independently discards observation rejection. [`fe/stores/sessionStore.ts:471–495,517–519,1320–1329`]

### Owned fault contract

Introduce `ComposerObservationFault`, an owned concrete error with:

- A closed discriminator: `progress_callback_failed`, `ack_identity_mismatch`, `snapshot_kind_mismatch` or `cancel_kind_mismatch`.
- `cause: unknown`, retaining the exact callback-thrown value or the exact local relationship error constructed at detection.
- Fixed value-free outer text.
- No serialized cause, request body, provider payload or inferred server outcome.

Use nominal discrimination for this owned error. Callback classification follows the failing operation, regardless of whether the callback throws `Error`, `TypeError`, `ComposerOperationDecodeError` or another value. Network decoding remains a separate boundary. [`ADR-032:127–140`; `fe/api/composerOperationObserver.ts:212–222`]

### Required change and preservation obligations

| Change | Guarantee to preserve |
|---|---|
| Restrict stream fallback catches to stream acquisition, reads and decoding; dispatch progress outside them. | Transport/decode failures still fall back to authenticated GET. Reader cancellation, lock release, timers and listeners are cleaned up. `fe/api/composerOperationObserver.ts:138–145,195–225` |
| Give acknowledgement, snapshot-kind and cancellation-kind relationship failures explicit typed disposition outside generic recovery. | Real transport and malformed-response recovery continues under the same operation and generation. `fe/api/composerOperationObserver.ts:104–136,145–186` |
| Detach observation on an owned fault while retaining custody. | No settlement, automatic replay, extra submission or implicit cancellation follows from the fault. Existing authorized ambiguous-admission replay remains governed by its original conditions. `fe/api/composerOperationObserver.ts:78–81,104,150–177` |
| Handle the fault before generic terminal publication in `runDurableComposerTurn`. | Retain pending user/custody state, clear progress, and publish no durable failure notice or failed-user-row interpretation. `fe/stores/sessionStore.ts:427–431,459–495,517–540` |
| Add deliberate inactive-session fault handling. | One store-owned, value-free diagnostic disposition replaces silent discard; stale principal/auth/session generations publish nothing. `fe/stores/sessionStore.ts:1310–1329`; `fe/api/composerOperationObserver.ts:67–81` |
| Preserve explicit Stop behavior. | Stop continues to target held immutable identities; only authoritative terminal evidence settles them. `fe/api/composerOperationObserver.ts:37–52,127–136,171–177` |

Foreground recovery uses the existing fixed notice:

> Composer updates stopped before the outcome could be confirmed. Reload this session to check the same action, or use Stop to request cancellation. Your request is still pending.

Preserve any existing custody-recovery notice alongside it. The store owns presentation and a small diagnostic sink receiving only the closed fault discriminator. The observer retains the private cause. Neither owner logs the raw fault.

Inactive-session reconciliation invokes the same diagnostic disposition for a current typed fault without changing another session’s messages, progress or failure history. Explicit reconciliation may later restart read-only observation; the fault itself does not start a replacement observer.

This is a local client contract. It adds no server operation status or durable failure category.

## U-20 / F4–F5: retain service and lifecycle failures through publication

F4–F7 are local design labels: F4 hint admission, F5 session-service/lifecycle failures, F6 primary rejection evidence, and F7 preservation. The master plan does not historically assign those individual numbers. [assembly `docs/release/0.8.10-master-plan.md:145–149`]

### F4: proven admission-to-timeout path

With a non-null secret service and an owned graph/session context, hint preparation calls `_current_env_ref_names`, which calls `get_session`; that service read uses bounded worker admission. The owned admission timeout is rethrown by the generic Advisor timeout arm and becomes `COMPOSE_TIMEOUT` or recoverable `ADVISOR_ERROR` in dispatch. [`web/composer/advisor_checkpoint.py:269–274,367–410`; `web/sessions/service.py:991–993,2749–2756`; `web/composer/tool_batch.py:2798–2858`]

Handle nominal admission failure before generic `TimeoutError`, returning a retained first-party outcome. At dispatch, known service failures use the shared service-failure path below. Plain Advisor timeout keeps its existing recoverable/deadline-limited behavior and original absolute deadline.

This repair does not change `AsyncWorkerAdmissionTimeoutError` inheritance globally.

### F5: proven service and lifecycle paths

The registered `request_interpretation_review` handler receives real interpretation read/write methods. Its write reaches `authority.mutate`, which proves session and durable operation authority before calling the mutation. [`web/composer/session_tool.py:244–275,415–445`; `web/composer/tools/sessions.py:3413–3421,3459–3485`; `web/sessions/service.py:5421–5427`; `web/coordination/repository.py:5709–5725`]

The checks can raise ordinary exception families that currently reach generic plugin-crash conversion. [`web/coordination/repository.py:5417–5459`; `web/coordination/composer_operation_authority.py:1821–1836`; `web/composer/tool_batch.py:3116–3149`]

Add a closed nominal service-failure family before generic plugin-crash capture:

| Original family | Required disposition |
|---|---|
| `OperationalError` | Preserve the exact original for the operation owner’s existing database-unavailable handling. |
| Other `SQLAlchemyError` | Preserve the exact original; do not diagnose database unavailability merely from this broader family. |
| `AsyncWorkerAdmissionTimeoutError`, `RequiredGenerationUnavailable` | Preserve the original for F1’s executor classification. |
| `SessionOperationFenceLost`, `ComposerOperationFenceLost` | Stop dispatch and further mutations. Preserve the original for existing fence/recovery ownership; do not invent authority or an unconditional public status. |
| `ComposerOperationCancelledDuringTurn` | Stop dispatch; preserve committed Stop semantics and the exact original. |
| `ComposerTurnDeadlineExpired` | Stop dispatch; retain the admitted deadline and original deadline evidence. |
| `asyncio.CancelledError` | Retain the existing started-tool cancellation, joining and propagation mechanism; do not convert it into an ordinary service refusal. |

- U-29 mutation-authority revocation as its distinct existing outcome. [`web/composer/protocol.py:542–572`]

### Carrier and batch closure

Add a private, process-local `service_failure` field to `ContinuationBatchState` and `_DispatchOutcome`, typed to the selected exception family or its owned internal alias. Store the original object directly.

Carry it through initialization, preparation, execution, `finally` copyback and final dispatch construction. Relevant existing seams include:

```text
web/composer/tool_batch.py:
  997–1000       batch declaration
  1170–1192      initialization
  1253–1256      preparation restore
  1732–1735      preparation copyback
  1802–1805      execution restore
  3766–3769      execution copyback
  3783          stopped-batch fact
  3804–3831      final projection

web/composer/_compose_loop_carriers.py:315–365
```

For an ordinary nominal service failure:

1. Close the started dispatch exactly once with a controlled result containing `success:false`, `status:"SERVICE_FAILURE"` and a closed, value-free reason.
2. Keep the exception outside tool JSON, prompts, public bodies and continuation data.
3. Stop the issued batch; do not dispatch later tools.
4. Retain the executed prefix, prior mutations, audit invocations and state/effect evidence.
5. Attempt required P4 publication using only existing authority.
6. Propagate the original after successful required publication.

Reason data may distinguish availability, Stop, deadline or authority loss, but does not replace the operation owner’s temporal decision or add public history categories beyond F1.

Use the existing controlled-result convention: audit `SUCCESS` records successful dispatch disposition and permits semantic `success=False`. It must not imply successful review or operation completion. Actual task cancellation keeps its existing `CANCELLED` path. [`contracts/composer_audit.py:51–75`; `web/composer/audit.py:868–881,1005–1031`]

No persisted tool-status enum is added.

### EARLY Advisor and P4 decisions

Copying a field is insufficient. Explicitly update:

| Decision | Required change and preserved guarantee |
|---|---|
| EARLY checkpoint eligibility | Require `service_failure is None` alongside the current cancellation, Advisor failure/timeout and revocation checks. No new Advisor call starts after service refusal. `web/composer/service.py:2905–2931` |
| P4 `crash_pending` | Include retained service failure in the live primary-failure disposition. Preserve the existing success-versus-failure SQL publication distinction. `web/composer/service.py:2948–2971`; `web/sessions/service.py:2480–2532` |
| Post-P4 propagation | Raise the original after publication; retain existing plugin, Advisor, cancellation and effect-verification evidence. `web/composer/service.py:3052–3174` |
| P4 continuation consistency | Keep the reconstructed disposition aligned with the live decision and the explicit serialization refusal below. `web/composer/continuation_p4_batch.py:53–63` |

A service failure grants no permission to publish through a revoked fence. Required publication is attempted or reconciled through existing owners; stale authority must still prevent writes. Do not turn an authority refusal into a new corruption diagnosis merely because it occurred during cleanup.

### Continuation serialization: explicit refusal

**Decision:** this change preserves live service exceptions in process and refuses serialization of any cut containing one.

The codec currently rejects existing live plugin/Advisor owners, but its field map and accepted-field list are manual. Encode/decode equality cannot detect a field omitted from both projections. [`web/composer/continuation_batch_data.py:174–175,372–406,670–704,1206–1228`]

Required behavior:

- Extend the live-exception refusal to non-null `service_failure` before encoding.
- Apply refusal to coupled, prepared/application and P4-pending capture routes using the relevant shared validation.
- Keep supported exception-free wire formats unchanged. Do not add a defaulted serialized field that suggests an exception was restored.
- Keep `RetainedBatchFailure`’s existing vocabulary unchanged. Do not encode a service failure as `plugin_crash`, `advisor_failure` or `advisor_timeout`.
- Keep P4 consistency checks explicit: a live service failure influences live disposition but makes capture unsupported; historical descriptors continue to mean historical data only.
- Do not reconstruct an exception from a class name or descriptor.

Existing retained failure vocabulary is closed, and the P4 codec expressly reconstructs no exception or writer grant. [`web/composer/continuation_tool_batch.py:242–245`; `web/composer/continuation_p4_batch.py:1–5,53–63,131–163`]

The cost is deliberate: a cut containing a live service exception cannot be saved/restored through these data codecs. This does not authorize dropping the failure, bypassing P4, resetting state or fabricating identity.

### Publication failure retention

Cover both publication exits:

1. **Returned unavailability:** P4 returns `unwind_audit_failed`. Raise an integrity-controlling outcome while retaining the service original and available failed-turn/publication evidence.
2. **Thrown publication failure:** catch at the P4 await boundary and retain the exact publication exception and service exception together. A thrown `AuditIntegrityError` remains integrity-controlling, including its original SQL cause.

The current P4 await can throw before post-P4 handling. Non-Operational SQLAlchemy publication errors explicitly become `AuditIntegrityError`, even during failure unwind. [`web/composer/service.py:2948–2971`; `web/composer/turn_audit.py:588–600`; `web/sessions/service.py:2502–2532`]

Use an existing suitable owned retention mechanism or an explicit exception group containing the original objects. Do not overwrite `service_failure.__cause__` to retain a second failure. Preserve its prior cause unchanged. Likewise, preserve the publication exception’s existing cause. A sole service failure must still propagate as that exact object.

Retain simultaneous effect-verification, settlement and cancellation evidence without cycles or duplicate audit drains. Do not claim a write had no effect merely because its await raised. Committed metadata and authoritative readback determine effects. [`web/composer/_compose_loop_carriers.py:323–332`; `web/composer/service.py:3081–3096,3145–3174`; `web/sessions/composer_turn.py:19–41`]
