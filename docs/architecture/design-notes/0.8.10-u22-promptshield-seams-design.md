Restore complete Advisor review for supported graph values above the display threshold, and classify unsupported context consistently across preparation, tool dispatch, synchronous responses, and asynchronous settlement.

## 2. Required result

- **F1:** Supported complete graph values reach EARLY, END, and graph-bearing manual Advisor requests in full. A nonempty manifest cannot itself suppress dispatch.
- **Publication:** A successful END requires genuine model review and the current publication binding. Materialization supplies neither CLEAN nor ADMIT.
- **F4:** A graph outside the supported envelope produces a classified, nonretryable input refusal. Preserve preceding effects, audit evidence, actual calls, and settlement.
- **Authoring:** Resolution changes provider context only. It never expands model-authored handles into mutations, generates pipeline structure, or introduces tutorial-specific behavior.
- **Inspection:** Every new physical invocation receives fresh inspection of its complete prepared envelope under the selected role and mount. Identity, prior detection, and retained results are not inspection permission.

**Binding guarantees:** `AGENTS.md:355–380`; `src/elspeth/web/composer/composition_completion.py:2481–2498`; `src/elspeth/web/composer/content_views.py:171–175`; `src/elspeth/web/composer/prompt_guard.py:460–526`.

## 3. Complete graph preparation

Introduce an owned, frozen `PreparedAdvisorGraph` containing the bounded view, current scope, original manifest, ordered materialized values, and final complete-review parts.

For **each actual attempt**, including transport and format retries:

1. Validate the live COMPOSE authority and current state.
2. Refresh the actor’s permitted environment-reference names; never resolve secret values.
3. Build the credential-screened, privacy-preserving projection and bounded view.
4. Select every manifest entry required for graph review.
5. Materialize the complete selected values.
6. Validate exact coverage and render a distinct complete-review representation.
7. Apply the applicable allowance and prepared-request limits before capture or dispatch.

Replace `_require_complete_graph_summary` with this preparation contract. Retain the graph display for diagnostic consumers; do not instantiate `BoundedCompositionView` with restored values, because its constructor requires markers at manifest-owned positions.

## 5. Historical content and mandatory retention

### Complete effective arguments remain retained

Use separate nominal resolution domains:

| Domain | Authoritative source |
|---|---|
| Current graph | Current fenced, credential-screened projection and its manifest. |
| Historical content | Selected retained message wire after admission and custody rewriting, joined to its original response and producer recipe. |

**Do not replace `MessageShelfSnapshot.messages_json` with bounded displays.** It remains the retained source of complete effective arguments. Generate historical diagnostic displays separately; never mutate registered provider messages to install those displays.

The historical locator is the selected shelf chunk reference plus message index, joined through `producer_recipes[index]` to the original response reference and admitted argument indexes. Capture complete effective wire before deriving a display.

Reconstruction order:

1. Acquire the selected continuation under current authority.
2. Verify the shelf and response chunk bindings.
3. Select the complete `messages_json[index]`.
4. Rebuild through the registered family and recipe.
5. Validate original call identity, unchanged non-admitted fields, and permitted effective argument positions.
6. Reconstruct untrusted partitions; then frame, prepare, and inspect the new request.

The original response is evidence of **received** arguments; it cannot replace custody-finalized **effective** arguments. Neither source is today’s graph.

**Guarantees:** `tool_batch.py:540–595`; `advisor_transcript.py:691–729,849–918`; `continuation_tool_argument_messages.py:86–123,126–186`; `continuation_message_families.py:322–336`; `continuation_prompt_producers.py:461–474`.

Preserve reply-only siblings, outer framing, chronology, and argument provenance. Quoting happens after historical resolution and receives fresh inspection.

**Guarantees:** `service.py:322–367`; `prompt_guard.py:275–308`.

### Mandatory retention has its own support boundary

Retain the **1 MiB encoded limit per private chunk**. In particular, the entire canonical shelf—including complete messages, observed events, history, recipes, duplication, and JSON escaping—must fit. A graph below 1 MiB and a prepared request below 2 MiB do not establish retainability.

Add an owner-side bounded size preflight for every mandatory chunk before encoding or checkpoint submission. Use the actual codec’s encoding rules. A known shelf-size excess becomes `retained_history_bytes`; another mandatory chunk-size excess becomes `retained_chunk_bytes`. Preserve the last valid checkpoint and settle preceding work without dispatching the refused attempt.

Keep the codec’s `AuditIntegrityError` checks intact. Never catch arbitrary `AuditIntegrityError` and relabel it as resource refusal.

**Guarantees:** `continuation_message_shelf.py:50–101`; `continuation_codec.py:72–120`; required runtime chunks: `continuation_runtime.py:616–625`; selected message/shelf join: `continuation_primary.py:145–159`.

Optional provider-context capture may still return `unavailable`. That is separate from mandatory retention failure. Abandonment’s stricter requirement for retained context remains.

**Guarantees:** `provider_context.py:229–260`; `advisor_checkpoint.py:553–555`.

Completed-result recovery makes no new SDK call. A new attempt after resume reacquires authority, prepares again, and receives fresh inspection.

**Guarantee:** `continuation_primary.py:303–336`.

## 6. Classified refusal and accounting

Add a nominal `ComposerContextUnsupported` carrier with:

- A closed reason: graph resource/key limit, required graph coverage unavailable, prepared-request bytes, manual Advisor allowance, retained-history bytes, or retained-chunk bytes.
- Owned role/phase and operation identity.
- Partial state relative to the persisted baseline, undrained tool invocations, actual LLM calls, and failed-turn metadata.
- A fixed, value-free public payload: HTTP 422, `error_type="composer_context_unsupported"`, bounded reason code, and safe detail.

Evidence is process-local and excluded from exception text and public serialization. Persist the semantic refusal through existing required tool/operation audit and settlement ownership. Do not fabricate a PromptShield request hash, detector result, model verdict, or physical call.
