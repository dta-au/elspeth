## 3. Preparation architecture

### 3.1 Advisor graph resolution — seams 1 and 3

**[I]** Add an owned, frozen `PreparedAdvisorGraph` in `advisor_context.py`. It contains:

- the original `CompleteValueManifest`;
- the ordered `MaterializedCompleteValue` tuple;
- the final rendered `AdvisorSummaryParts`;
- the current `ComposerContentScope`.

Its constructor must establish exact reference coverage: every manifest entry appears once, in manifest order, with matching scope, path, hash, and byte length. No Boolean such as `complete=True` may stand in for that evidence. This extends the existing nominal contracts rather than treating handle-shaped JSON as authority.
**Sources:** `src/elspeth/contracts/composer_content.py:161–182`, `:225–244`, `:305–326`; `src/elspeth/web/composer/advisor_context.py:363–412`; `docs/architecture/adr/032-validate-by-trust-domain.md:124–140`.

**[I]** Implement `prepare_advisor_graph(...)` with this sequence:

1. Validate the actual COMPOSE operation and obtain its current content scope.
2. Obtain the actor’s current secret-reference **names**, without resolving secret values.
3. Fit the bounded graph summary.
4. Select **all** entries in its manifest for graph review.
5. Call `materialize_advisor_complete_values(...)`.
6. Render the complete graph evidence and construct `PreparedAdvisorGraph`.
7. Pass that preparation into the audited Advisor request.

Perform these steps within every actual attempt, including transport retries. The current format-retry branch already rebuilds fitting; generalize preparation across the whole attempt loop rather than leaving it conditional on a format retry.
**Sources:** `src/elspeth/web/composer/content_scope.py:13–37`; `src/elspeth/web/composer/advisor_context.py:555–584`; `src/elspeth/web/composer/advisor_checkpoint.py:1405–1510`; `tests/unit/web/composer/test_content_projection_callers.py:185–215`.

**[I]** Retain the bounded view as an owned member during fitting so the complete renderer can replace only manifest-owned positions in a detached display tree. The replacement values come from the materializer. Authored objects containing `complete_value_ref` remain ordinary authored objects. Do not infer resolution authority by scanning strings or dictionaries for marker names.
**Sources:** `src/elspeth/web/composer/content_views.py:96–112`, `:143–161`, `:177–184`; `src/elspeth/contracts/composer_content.py:225–244`.

**[I]** Render the completed evidence using a distinct complete-review representation; do not instantiate `BoundedCompositionView` with restored values, because that type requires markers at its manifest positions. Preserve authored order and scalar types. Recompute configured-source and hash spans at their **new positions** instead of copying old offsets. Every authored value remains an untrusted `PromptGuardContentPart`.
**Sources:** `src/elspeth/web/composer/content_views.py:106–112`; `src/elspeth/contracts/composer_content.py:106–124`; `src/elspeth/web/composer/advisor_context.py:378–412`, `:439–460`, `:505–552`.

### 3.3 History, quoting, and resume — seams 4 and 5

**[M]** Current-state bounding does not bound every replay producer. Planner history retains raw argument strings; ordinary tool dispatch appends assistant history and subsequently attaches admitted argument partitions. Reply-only mode adds another JSON envelope.
**Sources:** `src/elspeth/web/composer/pipeline_planner.py:1981–2013`; `src/elspeth/web/composer/tool_batch.py:515–537`, `:1149–1161`; `src/elspeth/web/composer/service.py:322–367`.

**[I]** Separate two resolution domains:

| Domain | Authoritative content |
|---|---|
| Current graph | Current fenced state, current graph hash, and current credential-screened projection. |
| Historical message or arguments | The selected retained message source and its effective argument bytes after existing admission/custody handling. Never the current graph at a similar path. |

Use nominal resolution-plan types for the two domains. Reuse retained private chunks and message recipes; do not create a general handle-dereferencing service or new persistence table.
**Sources:** `src/elspeth/web/composer/tools/_common.py:3810–3863`; `src/elspeth/web/composer/tool_batch.py:540–562`; `src/elspeth/web/composer/advisor_transcript.py:717–727`, `:849–884`; `src/elspeth/web/composer/continuation_codec.py:72–111`.

**[I]** Bound ordinary historical displays at their producers while retaining exact effective replay content through the existing source/recipe ownership. Before dispatch, resolve selected history and rebuild complete argument/content partitions. Unknown or unavailable historical source content must refuse the attempt; it must not become an ellipsis or a lookup into today’s state.
**Sources:** `src/elspeth/web/composer/pipeline_planner.py:1981–2013`; `src/elspeth/web/composer/tool_batch.py:515–562`; `src/elspeth/web/composer/continuation_message_family_builders.py:76–84`, `:119–140`.

**[I]** Reply-only quoting happens after resolution. Its outer framing, sibling fields, ordering, and decoded authored content must all belong to the new inspection. Previous inspection of the enclosed value grants no permission for this new envelope. Retain Advisor transcript chronology and received/effective-argument distinctions.
**Sources:** `src/elspeth/web/composer/service.py:334–367`; `src/elspeth/web/composer/advisor_transcript.py:691–727`; `src/elspeth/web/composer/prompt_guard.py:275–308`.

**[I]** Every actual retry or hatch performs fresh preparation and inspection using its selected role and mount. Retained completed-result recovery performs no new SDK call; a genuinely new attempt requires current authority and fresh inspection. Preserve SDK retries disabled.
**Sources:** `src/elspeth/web/composer/pipeline_planner.py:1629–1634`, `:3767–3797`; `src/elspeth/web/composer/advisor_request.py:38–40`; `src/elspeth/web/composer/continuation_primary.py:303–336`.

## 10. Genuine maintainer trade-offs

1. **[I] Retain the 1 MiB graph envelope for this release.** This closes F4 by honest refusal and leaves some larger, otherwise inspectable graphs unsupported. Enlarging it requires coordinated traversal, retention, replay, and latency evidence; changing one constant is insufficient.
   **Sources:** `bounded_json.py:11–15`; `provider_context.py:252–258`; `continuation_codec.py:78–84`.

2. **[I] Adopt the independent prepared-request cap.** The recommended 2 MiB default gives a finite aggregate expansion bound across lifecycles, at the cost of new refusals for some previously admitted large requests. Without this or another explicit aggregate bound, per-document inspection limits do not establish bounded final request size.
   **Sources:** `provider_cost.py:179–186`, `:220–240`; `prompt_guard_clients.py:38–66`.

3. **[I] Pay for complete review.** Resolving long graph values increases Advisor input and potentially inspection batches. Retain that cost, existing deadlines, and explicit refusals; reducing it through hidden truncation, cached detector permission, or omitted Advisor calls would recreate the defect.
   **Sources:** `advisor_context.py:497–500`; `prompt_guard_clients.py:148–172`; `AGENTS.md:355–380`.
