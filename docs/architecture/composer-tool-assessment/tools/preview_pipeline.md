# `preview_pipeline` assessment

Baseline: `3b28d537be98234da8135c418bf185a998c18b68` — 0.8.9. Reconnaissance and design only.

## 1. Purpose and exposure

Perform authoring validation, caller-wired runtime preflight and bounded semantic inspection of blob-backed sources. This is a diagnostic tool; it does not execute pipeline rows. It is state-sensitive, noncacheable discovery. It judges the **current, already-applied composition state**. It cannot preview a candidate, a pending approval proposal or a planner draft. Each caller decides whether a runtime (Stage 2) verdict exists. The freeform loop precomputes one per call, the Composer MCP server wires one at construction or explicitly declines, and the proposal planner never supplies one in practice (§3.1, `preview_pipeline-N2`).

## 2. Contracts and authority

The tool takes no semantic arguments. Under `openai_strict`, the wire schema replaces `{}` with the required marker `{"_elspeth_no_arguments": true}` and adds a sentence telling the model to send it; decode removes the marker before semantic admission ([src/elspeth/web/composer/tools/wire_projection.py:120](../../../../src/elspeth/web/composer/tools/wire_projection.py#L120), [src/elspeth/web/composer/tools/wire_projection.py:534](../../../../src/elspeth/web/composer/tools/wire_projection.py#L534); measured, appendix). The handler re-checks its arguments against `EmptyToolArgumentsModel` as its first statement ([src/elspeth/web/composer/tools/generation.py:4480](../../../../src/elspeth/web/composer/tools/generation.py#L4480)).

The envelope carries authoring `validation` and, only when a runtime check ran, a top-level `runtime_preflight`. A run that has none omits the key; it is not `null` (demonstrated, in-memory). `data` is admitted by `PreviewResponse` ([src/elspeth/web/composer/tools/_generation_responses.py:292](../../../../src/elspeth/web/composer/tools/_generation_responses.py#L292)). It holds `preview_is_valid`, `preview_errors`, `edge_contracts`, `proof_diagnostics`, the overview (`sources`, `node_count`, `output_count`, `nodes`, `outputs`) and an optional `structural_preview`. `preview_errors` admits exactly one code, `runtime_preflight_not_run` ([_generation_responses.py:176](../../../../src/elspeth/web/composer/tools/_generation_responses.py#L176)). Each `proof_diagnostics` entry is `{code, severity ∈ {blocking, info}, message, suggested_repair, evidence_locator}`. `evidence_locator` is a closed `ProofEvidence` record that requires `source ∈ {blob, pipeline}`, and for blob evidence also `blob_id` and `source_name` ([_generation_responses.py:192](../../../../src/elspeth/web/composer/tools/_generation_responses.py#L192), [_generation_responses.py:227](../../../../src/elspeth/web/composer/tools/_generation_responses.py#L227), [_generation_responses.py:243](../../../../src/elspeth/web/composer/tools/_generation_responses.py#L243)).

Strict and tolerant structural preview are deliberately distinct. Tolerant findings never establish readiness and never join the conjunct ([generation.py:4540](../../../../src/elspeth/web/composer/tools/generation.py#L4540)). Blob proof requires exact session/store/operation authority. A missing runtime preflight makes `preview_is_valid` false, so a successful tool call can report an invalid preview ([src/elspeth/web/composer/tools/generation.py:4557](../../../../src/elspeth/web/composer/tools/generation.py#L4557)). A malformed source blob claim is the one branch where the call itself fails: `success: false`, `data` absent, a saved-graph rejection with `error_code="source_blob_identity_invalid"` ([generation.py:4525](../../../../src/elspeth/web/composer/tools/generation.py#L4525); demonstrated, in-memory).

## 3. Source trace to the user

`_execute_preview_pipeline` runs in this order:

1. It checks the session-operation fence ([src/elspeth/web/composer/tools/generation.py:4504](../../../../src/elspeth/web/composer/tools/generation.py#L4504)).
2. It builds a `ComposerProofContext` only when engine, session, data root, operation and authority are all present ([generation.py:4510](../../../../src/elspeth/web/composer/tools/generation.py#L4510)).
3. It admits source-proof claims ([generation.py:4525](../../../../src/elspeth/web/composer/tools/generation.py#L4525)).
4. It validates against the policy catalog ([generation.py:4534](../../../../src/elspeth/web/composer/tools/generation.py#L4534)).
5. It invokes the supplied strict and tolerant preflight callbacks ([generation.py:4539](../../../../src/elspeth/web/composer/tools/generation.py#L4539), [generation.py:4545](../../../../src/elspeth/web/composer/tools/generation.py#L4545)).
6. It calls `compute_proof_diagnostics` ([src/elspeth/web/composer/tools/generation.py:4549](../../../../src/elspeth/web/composer/tools/generation.py#L4549)).

Proof loops over blob-backed sources and enforces the 256-source cap ([generation.py:2689](../../../../src/elspeth/web/composer/tools/generation.py#L2689)). It resolves row and bytes under session custody and memoizes repeated blob IDs. It checks CSV/JSON/text and downstream field/type constraints, and returns explicit not-applicable/evaluated/unavailable variants ([src/elspeth/web/composer/tools/generation.py:4233](../../../../src/elspeth/web/composer/tools/generation.py#L4233)). **Correction:** those variants are internal only. The handler collapses `ProofNotApplicable` to `()` and returns the bare diagnostic tuple otherwise ([generation.py:4550](../../../../src/elspeth/web/composer/tools/generation.py#L4550)). The tool result therefore carries no proof status (`preview_pipeline-N4`). The handler then forms the conjunction and the selected preview payload ([src/elspeth/web/composer/tools/generation.py:4553](../../../../src/elspeth/web/composer/tools/generation.py#L4553)).

The freeform exposure is `get_tool_definitions` → wire projection → `composer_loop_tool_definitions`. The planner selects an ordered discovery subset, so exposure can narrow by phase ([src/elspeth/web/composer/tools/_dispatch.py:311](../../../../src/elspeth/web/composer/tools/_dispatch.py#L311), [src/elspeth/web/composer/provider_gateway.py:391](../../../../src/elspeth/web/composer/provider_gateway.py#L391), [src/elspeth/web/composer/pipeline_planner.py:1647](../../../../src/elspeth/web/composer/pipeline_planner.py#L1647)). Public freeform calls pass response-metadata/batch admission and wire decoding ([src/elspeth/web/composer/tool_batch.py:1010](../../../../src/elspeth/web/composer/tool_batch.py#L1010), [src/elspeth/web/composer/tool_batch.py:1399](../../../../src/elspeth/web/composer/tool_batch.py#L1399)).

**Correction:** closed semantic-schema admission happens *inside* `execute_tool`, not before it: `validate_arguments=True` at [tool_batch.py:3034](../../../../src/elspeth/web/composer/tool_batch.py#L3034) reaches [_dispatch.py:925](../../../../src/elspeth/web/composer/tools/_dispatch.py#L925). It is repeated by the handler. For this tool the loop precomputes the strict runtime preflight and, when the result is handoff-shaped, the tolerant preflight *before* that admission ([tool_batch.py:2829](../../../../src/elspeth/web/composer/tool_batch.py#L2829)–[2927](../../../../src/elspeth/web/composer/tool_batch.py#L2927)). On the `none` dialect `decode_wire_arguments` passes `{"x": 1}` through with `wire_conformant=False` (demonstrated, in-memory), so a non-conformant call reaches the preflight precompute before it is rejected (`preview_pipeline-N6`). Internal direct calls must explicitly opt into public argument validation ([src/elspeth/web/composer/tool_batch.py:3008](../../../../src/elspeth/web/composer/tool_batch.py#L3008)).

After the handler, `finalize_tool_result` normalizes validation. On the freeform and planner routes (not MCP; §3.1), discovery result admission selects the declared response contract before serialization ([src/elspeth/web/composer/tools/_dispatch.py:752](../../../../src/elspeth/web/composer/tools/_dispatch.py#L752), [src/elspeth/web/composer/tool_batch.py:3052](../../../../src/elspeth/web/composer/tool_batch.py#L3052)). Admission is fail-closed: a producer payload that violates `PreviewResponse` raises `FrameworkBugError`. Two JSON-source proof branches demonstrably produce such payloads through real custody, and a third does so by source reading (`preview_pipeline-N1`). The loop records the invocation, sends a tool result back to the model, and persists its redacted tool-turn cohort. Subsequent operation settlement owns user-facing success/failure ([src/elspeth/web/composer/tool_batch.py:3344](../../../../src/elspeth/web/composer/tool_batch.py#L3344), [src/elspeth/web/composer/service.py:1515](../../../../src/elspeth/web/composer/service.py#L1515), [src/elspeth/web/sessions/composer_turn.py:1051](../../../../src/elspeth/web/sessions/composer_turn.py#L1051)). ToolCallCard renders the recorded outcome and an explanatory tooltip; this tool has no direct action button ([src/elspeth/web/frontend/src/components/chat/ToolCallCard.tsx:90](../../../../src/elspeth/web/frontend/src/components/chat/ToolCallCard.tsx#L90)). The tooltip text itself overclaims (§5.1). A completed lookup does not imply pipeline readiness.

A source-proof-unavailable result **or a malformed source claim** terminates the issued tool batch after its executed prefix ([src/elspeth/web/composer/tool_batch.py:3391](../../../../src/elspeth/web/composer/tool_batch.py#L3391); `preview_source_proof_stop` returns `ProofUnavailable` or `MalformedSourceProofClaim`, [src/elspeth/web/composer/discovery_response.py:70](../../../../src/elspeth/web/composer/discovery_response.py#L70); both demonstrated, in-memory). Later tools in that batch must not be assumed to have run. **Added:** the service then reuses that terminal preview observation and ends authoring for the whole request through `_terminate_source_proof` ([src/elspeth/web/composer/service.py:1763](../../../../src/elspeth/web/composer/service.py#L1763)). That call passes `llm_messages=[]` and `allow_repair_continue=False` ([src/elspeth/web/composer/composition_completion.py:1215](../../../../src/elspeth/web/composer/composition_completion.py#L1215), [composition_completion.py:1223](../../../../src/elspeth/web/composer/composition_completion.py#L1223)). The model does not get another provider turn in that request to act on the diagnostic's `suggested_repair`. The comment at [service.py:1762](../../../../src/elspeth/web/composer/service.py#L1762) describes this as intended.

## 4. Branches, failures and recovery

The handler branches are:

- **Malformed source proof identity.** The call is refused (`success: false`, `source_blob_identity_invalid`, no `data`), and the batch and request then stop.
- **No blob source.** Proof is not applicable, but the result shows `[]`, which is indistinguishable from a clean proof.
- **Missing authenticated context.** One `source_blob_unavailable` per source, with "Restore the authenticated session and storage context" ([generation.py:4273](../../../../src/elspeth/web/composer/tools/generation.py#L4273)).
- **Unresolvable claimed blob.** Not found, not ready, or **ready with missing bytes** all yield one identical `source_blob_unavailable` ([generation.py:3780](../../../../src/elspeth/web/composer/tools/generation.py#L3780), [blobs.py:1955](../../../../src/elspeth/web/composer/tools/blobs.py#L1955)–[1960](../../../../src/elspeth/web/composer/tools/blobs.py#L1960); `preview_pipeline-N5`).
- **Integrity failure.** This raises.
- **Source cap exceeded.** A blocking `source_inspection_failed` diagnostic.
- **Shared-blob memoization.**
- **CSV/JSON/text diagnostics.** The JSON branches are N1.
- **Proof-work budget exhausted.**
- **Absent strict runtime stage.** A `runtime_preflight_not_run` entry.
- **Tolerant structural advisory.**
- **Valid/invalid conjunction.**

File hash or stored authority anomalies escalate; ordinary source/configuration failures become diagnostics. Recovery should restore authenticated custody or repair the actual source/configuration, never fabricate an empty source.

Argument rejection occurs before the handler body but, on the freeform route, after the preflight precompute (§3). Expected policy/semantic refusal is a failed result on the current state. Controlled-code exceptions, including response-contract `FrameworkBugError`, remain framework/plugin failures, and the common loop retains the executed prefix and audit evidence. Runtime-preflight infrastructure failure is route-specific (`preview_pipeline-N8`). Cancellation, timeout and final persistence failure belong to the request/operation owner, not a handler-local retry. None of these discovery handlers commits graph changes or needs a proposal approval step. Retrying a lookup can recover an argument or infrastructure problem but cannot repair the graph by itself.

**Cache, idempotency, concurrency and retry:** `ToolKind.DISCOVERY`, `cacheable=False`, so every invocation re-evaluates diagnostics. The caller-owned runtime-preflight cache is a separate mechanism keyed on state version, content hash, settings/snapshot hash and tolerance ([composer_preflight.py:170](../../../../src/elspeth/web/composer/composer_preflight.py#L170)). A repeated preview of the same state within a turn reuses the preflight but re-runs proof and its blob reads. Repetition does not author a graph mutation but performs reads, validation and audit again. The shared blob reader may perform storage-maintenance recovery before reading, so graph-read-only does not promise universally write-free execution. Blob metadata/bytes are observed under the exact operation custody for each resolution; the tool does not claim one timeless snapshot across arbitrary later calls. There is no handler retry loop. Recoverable changed/unavailable evidence requires a fresh admitted call; integrity failures must not be retried as invented graph repair. Provider retry accounting remains outside this synchronous diagnostic handler.

## 5. Defects, restrictions and hypotheses

The original lane demonstrated no preview correctness defect. This review adds one response-contract defect (N1) and several gaps. The 2026-11-09 probe runs (§7) demonstrated N1, N2, N6, N7 and N11 and part of N3; the rest remain source-established:

- **`preview_pipeline-N1` — demonstrated through the real custody path and a service-level freeform run for two branches (§7 probe P1). The third branch is source-established and was not reached.** JSON-source proof branches emit diagnostics that `PreviewResponse` rejects with `FrameworkBugError("Malformed generation discovery response")`:
  - Configured-JSON `source_inspection_failed` has evidence without `source` ([generation.py:3879](../../../../src/elspeth/web/composer/tools/generation.py#L3879)). **Not reached** by seven inputs through `set_source_from_blob`. A bad `encoding` or `format` is refused at bind (`plugin_options_invalid`). A missing `data_key`, a truncated document, non-UTF-8 bytes, a scalar root and `format: jsonl` over an array all become an `info` `source_inspection_warning` that carries `source` and is admitted. Reaching this branch needs options that pass bind-time validation but fail `JSONSourceConfig.from_dict`; whether any such options exist is unestablished.
  - The universal-loss JSON `csv_fixed_schema_omits_observed_columns` has no `source` and undeclared `selected_record_count` / `all_rows_inspected` ([generation.py:4041](../../../../src/elspeth/web/composer/tools/generation.py#L4041)). **Demonstrated**: `[{"a":"x","b":"y"}]` with fixed `a: str` and `discard` gives 3 field errors.
  - The sampled `json_fixed_schema_sample_omits_fields` has severity `warning`, which is outside `{blocking, info}`. It also lacks `source` and carries undeclared `sample_extra_record_count` / `all_rows_inspected` ([generation.py:4049](../../../../src/elspeth/web/composer/tools/generation.py#L4049)). **Demonstrated**: `[{"a":"x","b":"y"},{"a":"z"}]` gives 4 field errors. This code is also not in `_BLOCKING_DIAGNOSTIC_CODES`.

  The equivalent CSV control (`a,b / x,y`, same schema) admitted cleanly through the same real path. Instrument: an `awk` scan of every `evidence_locator` literal in [generation.py:2860–4232](../../../../src/elspeth/web/composer/tools/generation.py#L2860) found exactly these three without `"source"`; 14 other producer literals carry it (the positive control). The producer docstring still advertises a `warning` severity ([generation.py:3737](../../../../src/elspeth/web/composer/tools/generation.py#L3737)). On the freeform route the admission at [tool_batch.py:3053](../../../../src/elspeth/web/composer/tool_batch.py#L3053) runs inside dispatch. **Demonstrated**: a real `compose()` whose only tool call is `preview_pipeline` on the universal-loss JSON state raised `ComposerPluginCrashError: Composer plugin crash: FrameworkBugError`. It recorded `preview_pipeline` as `plugin_crash` and persisted the redacted `plugin_crash` tool row. The CSV control in the same harness recorded `success` and returned. The execution and completion consumers have no contract and silently drop the `warning` entry ([execution/service.py:389](../../../../src/elspeth/web/execution/service.py#L389)). A grep of `tests/` for `json_fixed_schema_sample_omits_fields` and `selected_record_count` returned nothing, while the control code `csv_duplicate_headers` matched [test_tools_preview.py:4442](../../../../tests/unit/web/composer/tools/test_tools_preview.py#L4442). Reachability needs only a ready JSON blob bound by `set_source_from_blob` (plugin `json` inferred from `application/json`) with fixed schema and `on_validation_failure="discard"`.
- **`preview_pipeline-N2` — demonstrated route dead end (scripted planner run plus the production decline helper; §7 probe P3).** The planner is routed only for a structurally empty state. Its discovery tools see that empty baseline ([pipeline_planner.py:2491](../../../../src/elspeth/web/composer/pipeline_planner.py#L2491) comment; [pipeline_planner.py:3434](../../../../src/elspeth/web/composer/pipeline_planner.py#L3434)), and its preflight helper declines on empty state ([planning_application.py:558](../../../../src/elspeth/web/composer/planning_application.py#L558); the call site at [planning_application.py:1084](../../../../src/elspeth/web/composer/planning_application.py#L1084) says so). Every planner `preview_pipeline` call therefore returns `preview_is_valid: false`, `no_source_configured` / `no_sinks_configured`, and a `runtime_preflight_not_run` message instructing "This is a server wiring omission … report that preview_pipeline returned runtime_preflight_not_run". The planner cannot preview the proposal it is drafting, which is checked separately at staging ([pipeline_planner.py:1491](../../../../src/elspeth/web/composer/pipeline_planner.py#L1491)). The tool is advertised to the planner yet can neither inform it nor be satisfied. In the run, the real `PlanningApplication._planner_preview_preflight` returned no callbacks and made 0 preflight calls on the empty state. On a non-empty state it made 1 call and wired the callback. A scripted planner turn `preview_pipeline {}` then received exactly the reply quoted above, with `version: 1` and an empty `proof_diagnostics`. The proposal was still accepted on the next turn. With a passing callback wired, the control reply had no `runtime_preflight_not_run`, though `no_source_configured` / `no_sinks_configured` remained.
- **`preview_pipeline-N3` — source-established message/behaviour mismatch.** `runtime_preflight_not_run` is one code with one fixed message ([generation.py:4379](../../../../src/elspeth/web/composer/tools/generation.py#L4379)), and `PreviewError.error_code` is a single literal. ## 6. Ownership, remediation and dependencies

Ownership splits four ways:

- The execution/preflight owner owns runtime admission.
- The source-proof owner owns sampled evidence and uncertainty.
- The blob custody owner owns verified reads.
- The orchestrator owns whether missing proof ends the batch.

A structural remediation should provide one explicit diagnostic result carrying proof applicability, limits and readiness, while preserving the conjunct and authority fencing (R2 branch-complete result contract). The proof producer should construct the owned `ProofDiagnostic`/`ProofEvidence` records directly instead of free dicts, so N1's class cannot recur on any consumer. Per-route Stage-2 availability belongs in R1 invocation dependencies, where a route that cannot supply a verdict either does not advertise the tool or says why (N2/N3/N8). Any streaming verified-read redesign must preserve row/bytes version consistency and full integrity checks (R3, N5).

**Implementation risk:** High for custody/read/validation consolidation; preserve bounded inspection memory, exact content integrity, stage applicability and fail-closed missing-preflight behavior.
