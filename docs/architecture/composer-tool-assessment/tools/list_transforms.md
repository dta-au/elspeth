# `list_transforms` — independent tool assessment

Baseline: ELSPETH **0.8.9**, `3b28d537be98234da8135c418bf185a998c18b68`. Reconnaissance and remediation design only. Incoming `.10 lite` changes are outside this assessment and require affected-source reinspection.

## 1. Purpose and usage

Discover transform plugins that this request is permitted and locally equipped to configure. This supplies the orchestrator's capability search for row or batch processing; it does not reserve a plugin or prove that a particular configuration can execute.

Select before choosing a transform implementation. Requires a PolicyCatalogView and its identical PluginAvailabilitySnapshot. No blob, secret-service or execution context is required. Structural nodes such as gates and queues are not plugins and are not enumerated by these listings.

On both web routes the request context already carries the policy-visible transform names (`available_plugins.transforms`) and the `authoring_aids.discovery_digest` (name, purpose, required-option names, `not_for`, `capability_tags`, `aggregation_output_modes`, profile aliases) before any tool call ([prompts.py:236](../../../../src/elspeth/web/composer/prompts.py#L236), [planner_authoring_aids.py:1801](../../../../src/elspeth/web/composer/planner_authoring_aids.py#L1801)). What `list_transforms` adds beyond that context is per-option `config_fields` (type/required/description/default), `usage_when_to_use`, `example_use`, every plugin's `composer_hints`, `secret_requirements`, `web_config_authority`, `policy_capabilities` and `audit_characteristics`, plus the digest prose the budget may have omitted (`details_via: "list_transforms"`).

## 2. Contract

Arguments are exactly an empty object; extra keys are rejected. The result is a ToolResult with data.available and data.prohibited, plus the current graph `version` (not the state body) and the whole-graph validation envelope (`success`, `validation`, `affected_nodes`, `version`, `data`; measured in-memory). Available summaries carry `name`, `description`, `plugin_type`, `config_fields` (each `name`, `type`, `required`, `description`, `default`), `usage_when_to_use`, `usage_when_not_to_use`, `example_use` (settings-YAML fragment, not the `set_pipeline` node shape), `capability_tags`, `aggregation_output_modes`, `web_config_authority`, `policy_capabilities`, `audit_characteristics`, `composer_hints` and `secret_requirements` ([schemas.py:51](../../../../src/elspeth/web/catalog/schemas.py#L51), [inventory_response_contracts.py:285](../../../../src/elspeth/web/composer/inventory_response_contracts.py#L285)). Only the categorical WEB_SURFACE_PROHIBITED reason can appear in prohibited, and **at this baseline no snapshot producer emits that reason, so `prohibited` is always empty** (see list_transforms-N1). Other unavailable plugins are omitted by design. There is no write, approval requirement, provider call or retry. Successful responses are cacheable only within the compose call; failures are not cached. The policy/plugin set is a request/process snapshot, so this is discovery at that scope, not a live credential-health probe. Repeated calls are observationally idempotent (in-memory: two calls on one view serialise byte-identically, version unchanged, `updated_state is state`).

This is discovery: the handler retains immutable composition state; on the web freeform and planner routes, successful declared inventory data is admitted under its producer response contract before audit/disclosure (the Composer MCP route serialises `ToolResult.to_dict()` without that admission; §3.1). Across both provider dialects, the provider wire projection is decoded to canonical arguments before dispatch; strict transport representation does not grant different authority. A ToolResult's `success` records operation admission, while `validation.is_valid`, runtime preflight, review and execution admission answer separate questions. Owned-code/audit integrity failures escape as faults rather than being reclassified as ordinary invalid model input.

Result size scales with policy, not with the request: measured in-memory, the admitted wire result is 46,169 bytes for the 6 transforms of a default web policy with one LLM profile, and 172,151 bytes for all 40 installed transforms on the trained-operator (MCP) view, of which 11,207 bytes are `example_use`. There is no filter or name argument.

## 4. Alternative paths

Normal operation projects available entries from plugin-owned declarations through policy and operator-profile views. Empty available is a valid discovery result, not an error. An absent SDK, missing credential, unavailable profile or unapproved plugin can remove an entry without placing it in prohibited. Invalid arguments are rejected before requested access; a fault in an admitted catalog/schema remains an owned-code failure and must not be disguised as an unknown plugin. Cache hits reconstruct the current state envelope and re-admit the cached producer response. MCP uses a trained-operator policy view, so a name visible there need not be selectable in an authenticated web request.

Measured in-memory with the default web settings plus one Bedrock LLM profile and an allowlist adding `source:aws_s3`, `sink:aws_s3`, `transform:aws_textract_document_analysis` and `transform:azure_prompt_shield`: 40 transforms installed, 6 listed (`field_mapper`, `line_explode`, `reference_join`, `report_assemble`, `web_scrape`, `llm`), `snapshot.unavailable` held only three entries (`profile_unavailable` ×2, `credential_unavailable` ×1), the other 32 un-allowlisted transforms appear nowhere, and `prohibited` was `[]` for sources, transforms and sinks.

Extra-key refusal shapes differ by caller: freeform/MCP (`raise_schema_argument_errors=True`) raise `ToolArgumentError` (SCHEMA_VALIDATION) for ARG_ERROR routing; the planner seam raises the same; a direct caller with only `validate_arguments=True` gets `success: false` whose `validation.errors` mixes the argument rejection with the graph's standing errors; a direct caller with no flags gets the handler's `ToolArgumentError` (MODEL_VALIDATION). Only the first three are public routes.

## 5. Usability assessment

**SG-05 — intended disclosure restriction with a planning limitation; high confidence.** The orchestrator sees selectable plugins and categorical bans, but not every temporarily unavailable capability or its repairable prerequisite. It cannot conclude from an absent name whether installation, credentials, a profile or authorisation is missing. The policy view documents this deliberate choice; it is not evidence of a registry defect. Workaround: a named selection attempt, a `get_plugin_schema`/`get_plugin_assistance` call naming the plugin (which refuses with the closed reason before any schema read — [test_tools_discovery.py:299](../../../../tests/unit/web/composer/test_tools_discovery.py#L299)), or operator inspection supplies a denial reason. Lists are sufficient for ordinary flat options, but nested enums/unions still require get_plugin_schema. At this baseline the "categorical bans" half is empty in practice (list_transforms-N1), so every unavailable transform falls into the silent class.

The handler itself behaves as coded; the findings below are in the result projection, the advertised contract and its guidance, not in the handler body.

## 6. Structural remediation

Keep authoritative configuration and capability declarations on transform plugins, policy visibility in the policy layer, and capability selection in the orchestrator. If capability planning needs repairable absences, add a deliberately bounded availability query/report rather than bypassing policy or making each list disclose private bindings. All three inventory tools, schema/assistance lookup and mutation failures must share the same snapshot and closed reason vocabulary. Acceptance: a selectable plugin appears with plugin-owned defaults; a banned plugin appears only under prohibited; a missing local prerequisite is reported through the authorised availability surface without exposing secret values; cache reuse cannot transplant another principal's snapshot. Compatibility: preserve available/prohibited and make additional availability evidence explicitly versioned or additive. Implementation risk medium because disclosure and cache scope are security boundaries.

Decide the `prohibited` contract explicitly (list_transforms-N1): either a live producer of `WEB_SURFACE_PROHIBITED` exists and is tested against a real `build_plugin_snapshot`, or the field, its teaching and its repair text are retired together. Settle one authoring authority for option facts (list_transforms-N12) and make the listing either a faithful, typed option summary or an explicitly selection-tier index that points to `get_plugin_schema`.
