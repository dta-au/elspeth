# `patch_output_options` — shallow sink option edit

Assessment baseline: `3b28d537be98234da8135c418bf185a998c18b68` (0.8.9). Reconnaissance/design only. **Overall confidence: High for source and focused tests.** The 2026-11-09 sheet review added in-memory handler/dispatch probes (`execute_tool`, `_handle_patch_output_options` and the Composer MCP `_dispatch_tool`, run against the existing `test_output_rejection_contracts` fixtures). These are not end-to-end service, provider, browser or PostgreSQL runs. Nothing proposed here has been implemented.

## 1. Purpose and usage

Use this tool for an option-only edit to an existing sink when its name, plugin, write-failure route, and description should remain. Read the sink's effective configuration first. It is preferable to full replacement for a small top-level option change, provided the caller understands shallow merge semantics. Available through web Composer and common Composer MCP. The output must exist and its plugin must be admitted by the request's policy/catalog snapshot. Name, plugin, `on_write_failure` and `description` cannot be changed here: at the argument root they are a `schema_shape` `ToolArgumentError`. Inside `patch` they fail the sink's closed config model with `plugin_options_invalid` (both demonstrated). Use `set_output` for those fields.

## 2. Contract

Required `sink_name: string` and `patch: object`; extra fields are forbidden. Patching is **shallow** ([`_apply_merge_patch`](../../../../src/elspeth/web/composer/tools/_common.py#L1753)): absent keys remain, non-null values replace complete top-level values, null deletes a top-level key (silently a no-op if absent). A nested object is replaced wholesale, not recursively merged (demonstrated: `{"schema": {"mode": "fixed", "fields": [...]}}` patched with `{"schema": {"mode": "observed"}}` yields `{"schema": {"mode": "observed"}}`). Null cannot be used to store a literal null. The operation changes only `OutputSpec.options`; name/plugin/failure route/description are retained.

The handler checks the merged options in this order: (1) state-held plugin against the request policy view ([L277](../../../../src/elspeth/web/composer/tools/outputs.py#L277)); (2) a `catalog.get_schema` read whose result is discarded. It works as an admission/fault probe, not as validation against the catalog schema ([L282](../../../../src/elspeth/web/composer/tools/outputs.py#L282)); (3) AWS S3 endpoint policy; (4) literal-credential refusal; (5) session-local destination rules; (6) the plugin config model, which also enforces secret-ref placement ([`_prevalidate_plugin_options`](../../../../src/elspeth/web/composer/tools/_common.py#L2514)); (7) the explicit file-collision policy, required only when `data_dir` is set. After the handler returns, the dispatcher applies the composition interpretation gate ([`_dispatch.py#L983`](../../../../src/elspeth/web/composer/tools/_dispatch.py#L983)). Success increments composition version and returns `affected_nodes`, `validation`/`validation_delta`, `applied_component` (the stored output including effective options), and plugin `post_call_hints` when supplied. It may still leave graph-level errors. Missing output, policy/path/credential/config/collision problems reject with prior state preserved and specific error codes. Option failures may include inline plugin schemas and static repair guidance. Schema/model type errors use `ToolArgumentError` (`schema_shape` at public dispatch, `MODEL_VALIDATION` at the handler). Unexpected schema/config bugs propagate, and so does a raw `TypeError` for a non-string sink path value when `data_dir` is set (see PO-N2).

This is an uncached graph/validation/YAML `MUTATION`. In explicit-approval mode the batch runs an in-memory preview of the patch and then publishes a pending proposal instead of applying it. A preview refusal does not suppress the proposal (PO-N4). When the preview is valid and required controls change the state, the proposal is promoted to a `set_pipeline` proposal ([tool_batch L2057-L2112](../../../../src/elspeth/web/composer/tool_batch.py#L2057)). An empty, identical, or absent-key-null patch still increments version and counts as progress; it is not version-idempotent (demonstrated, PO-N3). It does not write sink artifacts or resolve real secrets. Concurrency and persistence belong to the enclosing session operation. Outer public entry points enable closed schema checks. Direct internal handlers have their own Pydantic boundary but are not substitutes for web authority.

## 3. Implementation trace

The [executor](../../../../src/elspeth/web/composer/tools/outputs.py#L242), [handler](../../../../src/elspeth/web/composer/tools/outputs.py#L335) and [declaration](../../../../src/elspeth/web/composer/tools/outputs.py#L369) use the redaction-bearing [`PatchOutputOptionsArgumentsModel`](../../../../src/elspeth/web/composer/redaction.py#L2259), [`_apply_merge_patch`](../../../../src/elspeth/web/composer/tools/_common.py#L1753), and [plugin config admission](../../../../src/elspeth/web/composer/tools/_common.py#L2514) via [`_prevalidate_sink`](../../../../src/elspeth/web/composer/tools/_common.py#L3631). Absence after success is an assertion-level invariant failure. Unlike `set_output` ([L218](../../../../src/elspeth/web/composer/tools/outputs.py#L218)), the patch path does not call `_post_mutation_invariant_error`. Every code that guard selects is node-centric ([`_MUTATION_BLOCKING_INVARIANT_CODES`](../../../../src/elspeth/web/composer/tools/_common.py#L3905)), so an options-only edit cannot introduce one. [Tool-batch approval](../../../../src/elspeth/web/composer/tool_batch.py#L1728) and [ordinary dispatch](../../../../src/elspeth/web/composer/tool_batch.py#L3008), [audit](../../../../src/elspeth/web/composer/audit.py#L812), and [frontend cards](../../../../src/elspeth/web/frontend/src/components/chat/ToolCallCard.tsx#L75) own publication and visible outcome. ## 4. Alternative paths

Patching an existing authorized output preserves non-option fields. An absent target produces `output_not_found` (also for `sink_name=""`, rejected component `output:`). An unknown or unavailable state-held plugin refuses before schema augmentation. Deleting a required option (`{"path": null}` gives `path: Field required`) or replacing an incomplete nested config is rejected by the plugin model where decidable. Deferred secret/blob markers receive authored-state admission (placement only). Destination authorization against `secret_wiring_policy` happens later in [execution validation](../../../../src/elspeth/web/execution/_validation_authoring.py#L715), and execution resolves actual values separately (PO-N8). A valid patch can introduce/retain graph-level failures which validation reports; a patch success never certifies successful publication to the external sink. A batch that first fails to create the sink and then patches it gets `batch_dependency_refused` for the patch.

## 5. Usability assessment

Earlier lane text said no defect had been demonstrated. This review corrects that. Findings, with provisional IDs:

- **PO-N1, demonstrated (in-memory dispatch):** every successful patch to a `json` sink returns the post-call hint "on_write_failure is not set, but it is REQUIRED…", even when the output's `on_write_failure` is `"discard"`. The hint is computed from [`config_snapshot=output.options`](../../../../src/elspeth/web/composer/tools/outputs.py#L365), but `on_write_failure` lives on `OutputSpec`, not in options. The [json sink hint](../../../../src/elspeth/plugins/sinks/json_sink.py#L629) tests `"on_write_failure" not in config_snapshot`, which is always true because `JSONSinkConfig` forbids that key. The suggested remedy is impossible through this tool: `patch: {"on_write_failure": "discard"}` gives `plugin_options_invalid … Extra inputs are not permitted`. The skill tells the model that `post_call_hints` are "plugin-authored next steps" ([`pipeline_composer.md#L540`](../../../../src/elspeth/web/composer/skills/pipeline_composer.md#L540)). `patch_output_options` is the only sink-hint caller (grep for `_attach_post_call_hints(` in `web/composer`), so the false hint reaches the model only through this tool.
- **PO-N2, demonstrated (in-memory dispatch):** a non-string value at a sink path key (`{"path": 123}`, `{"path": {"x": 1}}`, `{"path": ["a"]}`) raises a raw `TypeError` from `Path(value)` in [`resolve_sink_data_path`](../../../../src/elspeth/web/paths.py#L117), called by [`_validate_sink_path`](../../../../src/elspeth/web/composer/tools/_common.py#L2344). That check runs before the plugin config model whenever `data_dir` is set, which is every web route. With `data_dir=None` the same patch returns `plugin_options_invalid … path: Input should be a valid string` (control). In the compose loop, the escaped `TypeError` becomes `ComposerPluginCrashError` ([`tool_batch.py#L3199`](../../../../src/elspeth/web/composer/tool_batch.py#L3199); source-established). So a malformed Tier-3 provider value crashes the turn instead of returning a repairable refusal. `set_output` raises the same way (demonstrated); the `set_pipeline` outputs path ([`sessions.py#L1811`](../../../../src/elspeth/web/composer/tools/sessions.py#L1811)) is source-established only.
- **PO-N3, demonstrated (handler, dispatch and MCP):** `{}`, an identical value (`{"mode": "write"}`) and a null for an absent key all succeed with byte-identical content (version excluded), version 17→18, and [`tool_result_mutated_composition_state`](../../../../src/elspeth/web/composer/discovery_cache.py#L38) `True`. This extends SG-03 to this tool. [`patch_source_options`](../../../../src/elspeth/web/composer/tools/sources.py#L2254) already detects no-ops.
- **PO-N4, source-established (not exercised end-to-end):** under `explicit_approve`, the preview of an incremental mutation is run, but a `success=False` preview (for example `output_not_found`, `sink_path_policy_invalid`, `plugin_options_invalid`) is discarded. An `APPROVAL_REQUIRED` proposal is still published ([`tool_batch.py#L2088-L2125`](../../../../src/elspeth/web/composer/tool_batch.py#L2088)). The model is told the change is "pending human approval". Acceptance then re-executes, refuses, auto-rejects and returns 422. Only `ToolArgumentError` has a documented reason to defer ([L2114](../../../../src/elspeth/web/composer/tool_batch.py#L2114)). No test covers a refused preview (grep of `explicit_approve` tests in `test_service.py`). This is shared by every incremental mutation tool.
- **PO-N5, demonstrated route difference; defect status is a hypothesis:** through MCP (`data_dir=None`), `{"path": "/outside-session/elsewhere.json"}` succeeds and is stored. [`_validate_sink_path`](../../../../src/elspeth/web/composer/tools/_common.py#L2357) returns `None` when `data_dir is None`, and `require_data_dir_for_paths` is honored only by source paths ([`sources.py#L1134`](../../../../src/elspeth/web/composer/tools/sources.py#L1134)). The same patch with `data_dir="/data"` is refused as `sink_path_policy_invalid` (control). MCP is an operator-local tool, so this may be intended, but sources fail closed in the same context.
- **PO-N6, demonstrated:** the MCP pre-dispatch collision refusal returns only `{success, error, state}`, with no `error_code`, `validation`, `version` or guidance. Web dispatch of the same patch returns `file_sink_write_policy_invalid` ([`server.py#L393-L399`](../../../../src/elspeth/composer_mcp/server.py#L393)).
- **PO-N7, demonstrated plus hypothesis:** the advertised "interpretation_requirements not settable on outputs" rule is enforced in practice by sink config models. All 10 installed sinks are `extra="forbid"` (measured by introspecting `get_sink_config_model` per catalog sink). The refusal is the generic `plugin_options_invalid … interpretation_requirements: Extra inputs are not permitted`, without the advertised reason or alternative. The dispatcher backstop ([`_common.py#L3088-L3090`](../../../../src/elspeth/web/composer/tools/_common.py#L3088)) would say "canonical interpretation requirements failed invariant validation" with no rejected component. That would mislead for outputs, but it is reachable only by a sink with a permissive config model, and none is installed (hypothesis).
- **PO-N8, intended restriction (deferred refusal):** inline `{"secret_ref": …}` markers written through this tool are checked for placement only. `secret_wiring_policy` destination authorization is deferred to execution validation by design ([`_validation_authoring.py#L724-L728`](../../../../src/elspeth/web/execution/_validation_authoring.py#L724)). The credential-repair payload actively teaches this inline form via `patch_output_options` ([`_common.py#L1980-L1988`](../../../../src/elspeth/web/composer/tools/_common.py#L1980)), so an authoring success can be followed by a preflight refusal.

**Intended restriction:** shallow replacement and null-as-delete are explicitly advertised in the tool description. The model must not assume JSON Merge Patch recursion merely from the word “patch.” Workaround: copy the complete intended nested object or use full output replacement deliberately, then inspect the applied echo and preview result.

**Source-established ownership limitation:** output patch, full set, secret wiring, inline-blob wiring, and whole-pipeline edits converge only through several helper/finalizer layers. Their individual tests are meaningful, but adding a plugin option can require consistent updates across authored/deferred/runtime policy seams. PO-N1 (component-level fact missing from the hint snapshot) and PO-N2 (a policy check that runs before type admission) are concrete instances. The proposed remedy is shared candidate admission, not more independent field-name guards.

## 6. Structural remediation

Create a common output candidate operation that applies the chosen edit semantics, asks plugin-owned config/deferred-value contracts for validation, then applies web policy/review/publication once. Keep shallow patch behaviour explicit and stable; do not silently switch to recursive merge. Model results should distinguish accepted edit from ready-to-execute and report effective configuration without requiring a second full state read. Type admission by the plugin config model must precede path/policy checks that dereference values (PO-N2). Plugin hints must receive the component-level facts they reason about, such as `on_write_failure`, rather than options alone (PO-N1). Explicit-approval interception must not publish a proposal for a mutation whose preview was refused (PO-N4, shared with R4/R5).

Acceptance: absent/unset/null/nested replacement cases are independently asserted; the same effective candidate has the same rejection through patch/set/wire/YAML paths; malformed args and unavailable plugins reject without prior-state damage; secret values never enter authoring output; hint/schema faults remain owned failures; repeated/concurrent requests produce truthful version/effect evidence. Compatibility risk is Medium for mutation-envelope changes and High for changing patch semantics, which this assessment does not recommend.
