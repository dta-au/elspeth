# `get_expression_grammar` assessment

Baseline: `3b28d537be98234da8135c418bf185a998c18b68` — 0.8.9. Reconnaissance and design only.

## 1. Purpose and exposure

Return the static expression-language reference text. It supplies syntax knowledge; it neither parses a user's expression nor executes a sample. It is cacheable discovery exposed to the ordinary loop, the planner discovery palette and Composer MCP. On the planner route the same text is also embedded verbatim in every request's authoring aids, so the planner normally needs no call ([src/elspeth/web/composer/planner_authoring_aids.py:2075](../../../../src/elspeth/web/composer/planner_authoring_aids.py#L2075), [src/elspeth/web/composer/planner_authoring_aids.py:2789](../../../../src/elspeth/web/composer/planner_authoring_aids.py#L2789)).

The reference is written for one parser, `ExpressionParser`, but its scope is stated differently on different surfaces (see §5 `get_expression_grammar-N2`). The reference's own header claims gate conditions, `value_transform` expressions and LLM `result_checks` ([src/elspeth/web/composer/tools/generation.py:219](../../../../src/elspeth/web/composer/tools/generation.py#L219)). The declaration description says only "gate expression syntax reference" ([src/elspeth/web/composer/tools/generation.py:401](../../../../src/elspeth/web/composer/tools/generation.py#L401)).

## 2. Contracts and authority

No semantic arguments are accepted. Under the `openai_strict` dialect the wire projection replaces the empty object with one required wire-only marker, `{"_elspeth_no_arguments": true}`, and appends a sentence telling the model to send exactly that. Decode removes the marker before semantic admission ([src/elspeth/web/composer/tools/wire_projection.py:116](../../../../src/elspeth/web/composer/tools/wire_projection.py#L116), [src/elspeth/web/composer/tools/wire_projection.py:525](../../../../src/elspeth/web/composer/tools/wire_projection.py#L525)). The `none` dialect and MCP advertise `{}` unchanged (measured, appendix). The response is exactly `{"grammar": <string>}` inside the discovery envelope. The selected response contract `_admit_expression_grammar` accepts only an owned `ExpressionGrammarResponse` or a mapping whose key set is exactly `{"grammar"}` with an exact `str` value. Anything else is a `FrameworkBugError` ([src/elspeth/web/composer/tools/generation.py:359](../../../../src/elspeth/web/composer/tools/generation.py#L359), [src/elspeth/web/composer/tools/generation.py:363](../../../../src/elspeth/web/composer/tools/generation.py#L363), [src/elspeth/web/composer/tools/generation.py:382](../../../../src/elspeth/web/composer/tools/generation.py#L382)). The contract does not check that the string is the shipped reference; that guarantee comes from the handler. The handler makes no graph, configuration or data-store mutation. The enclosing loop still persists invocation audit and history. The redaction policy marks the tool `handles_no_sensitive_data` with `redact_unknown_argument_keys=True` ([src/elspeth/web/composer/redaction.py:2681](../../../../src/elspeth/web/composer/redaction.py#L2681), [src/elspeth/web/composer/redaction.py:3789](../../../../src/elspeth/web/composer/redaction.py#L3789)).

The parser owns the accepted language. Its operator tables, builtin table, arities and allowed and forbidden AST node sets are in [src/elspeth/core/expression_parser.py:78](../../../../src/elspeth/core/expression_parser.py#L78), [src/elspeth/core/expression_parser.py:171](../../../../src/elspeth/core/expression_parser.py#L171), [src/elspeth/core/expression_parser.py:200](../../../../src/elspeth/core/expression_parser.py#L200) and [src/elspeth/core/expression_parser.py:224](../../../../src/elspeth/core/expression_parser.py#L224). The reference text is a hand-written second statement of that language ([src/elspeth/web/composer/tools/generation.py:216](../../../../src/elspeth/web/composer/tools/generation.py#L216)).

## 3. Source trace to the user

`_handle_get_expression_grammar` validates its arguments against `EmptyToolArgumentsModel` (`extra="forbid"`), drops `context`, and returns `_discovery_result(state, {"grammar": get_expression_grammar()})` ([src/elspeth/web/composer/tools/generation.py:382](../../../../src/elspeth/web/composer/tools/generation.py#L382), [src/elspeth/web/composer/tools/generation.py:387](../../../../src/elspeth/web/composer/tools/generation.py#L387), [src/elspeth/web/composer/tools/_common.py:134](../../../../src/elspeth/web/composer/tools/_common.py#L134)). `get_expression_grammar()` returns the module constant ([src/elspeth/web/composer/tools/generation.py:278](../../../../src/elspeth/web/composer/tools/generation.py#L278)). `_admit_expression_grammar` then rejects wrong carriers, keys and types ([src/elspeth/web/composer/tools/generation.py:363](../../../../src/elspeth/web/composer/tools/generation.py#L363)).

The freeform exposure is `get_tool_definitions` → wire projection → `composer_loop_tool_definitions`. The planner advertises an ordered discovery subset ([src/elspeth/web/composer/tools/_dispatch.py:311](../../../../src/elspeth/web/composer/tools/_dispatch.py#L311), [src/elspeth/web/composer/provider_gateway.py:391](../../../../src/elspeth/web/composer/provider_gateway.py#L391), [src/elspeth/web/composer/pipeline_planner.py:1647](../../../../src/elspeth/web/composer/pipeline_planner.py#L1647), [src/elspeth/web/composer/capability_skill.py:16](../../../../src/elspeth/web/composer/capability_skill.py#L16)). Public freeform calls pass credential and batch admission, wire decoding and closed semantic-schema admission before `execute_tool` ([src/elspeth/web/composer/tool_batch.py:1010](../../../../src/elspeth/web/composer/tool_batch.py#L1010), [src/elspeth/web/composer/tool_batch.py:1399](../../../../src/elspeth/web/composer/tool_batch.py#L1399), [src/elspeth/web/composer/tool_batch.py:3008](../../../../src/elspeth/web/composer/tool_batch.py#L3008)). `execute_tool` makes public argument validation opt-in for internal callers, but this handler validates its empty model itself. Extra arguments are therefore refused even on an internal call with `validate_arguments=False`.

After the handler, `finalize_tool_result` normalizes validation but applies no response contract ([src/elspeth/web/composer/tools/_dispatch.py:752](../../../../src/elspeth/web/composer/tools/_dispatch.py#L752)). Selected-contract admission happens in the callers: the freeform batch calls `admit_discovery_result` ([src/elspeth/web/composer/tool_batch.py:3052](../../../../src/elspeth/web/composer/tool_batch.py#L3052)) and so does the planner ([src/elspeth/web/composer/pipeline_planner.py:4911](../../../../src/elspeth/web/composer/pipeline_planner.py#L4911)). Composer MCP does not (§3.1). The freeform loop records the invocation, serializes the admitted result back to the model and persists its redacted tool-turn cohort. Operation settlement then owns user-facing success or failure ([src/elspeth/web/composer/tool_batch.py:3344](../../../../src/elspeth/web/composer/tool_batch.py#L3344), [src/elspeth/web/composer/service.py:1515](../../../../src/elspeth/web/composer/service.py#L1515), [src/elspeth/web/sessions/composer_turn.py:1051](../../../../src/elspeth/web/sessions/composer_turn.py#L1051)). ToolCallCard renders the recorded outcome with the read-only tooltip. It gives this tool no action button of its own and decodes no grammar payload ([src/elspeth/web/frontend/src/components/chat/ToolCallCard.tsx:90](../../../../src/elspeth/web/frontend/src/components/chat/ToolCallCard.tsx#L90), [src/elspeth/web/frontend/src/components/chat/toolCallDescriptions.ts:35](../../../../src/elspeth/web/frontend/src/components/chat/toolCallDescriptions.ts#L35)). A completed lookup does not imply pipeline readiness.

## 4. Branches, failures and recovery

The successful branch always returns the shipped reference. Unexpected arguments are refused twice. On public routes the closed root schema refuses them before the handler. On internal calls the handler itself refuses them through `EmptyToolArgumentsModel` ([src/elspeth/web/composer/tools/_dispatch.py:1027](../../../../src/elspeth/web/composer/tools/_dispatch.py#L1027), [src/elspeth/web/composer/tools/generation.py:387](../../../../src/elspeth/web/composer/tools/generation.py#L387)). A corrupt response is a framework fault on the freeform and planner routes. On MCP no selected-contract check runs (§3.1). Expected policy or semantic refusal is not a branch here: the handler has no policy dependency. Controlled-code exceptions remain framework/plugin failures, with the executed prefix and audit evidence retained by the common loop. Cancellation, timeout and final persistence failure belong to the request/operation owner, not to a handler-local retry. The tool commits no graph changes and needs no proposal approval step. Retrying a lookup can recover an argument or infrastructure problem but cannot repair the graph by itself.

**Cache, idempotency, concurrency and retry:** `ToolKind.DISCOVERY`, `cacheable=True`. Repeated successful calls return the same text and change no graph or storage. Each call still has its own audit identity, including cache hits. A cache hit rebuilds the envelope's version and validation from current state. A cache entry that fails to admit or encode is a `PLUGIN_CRASH`, not a success. Failures and argument errors are never cached (tests cited in §7). The cache is a local dict scoped to one freeform `compose()` call ([src/elspeth/web/composer/service.py:2500](../../../../src/elspeth/web/composer/service.py#L2500)). It is not a durable cache. **The planner route does not use it.** `pipeline_planner.py` imports only serialization helpers from `discovery_cache` ([src/elspeth/web/composer/pipeline_planner.py:89](../../../../src/elspeth/web/composer/pipeline_planner.py#L89)), so each planner call re-executes. The text is a module constant, fixed for the life of the process, and needs no session lock. The handler never retries. A retry of the primary provider is separate from replaying this local handler.

## 5. Defects, restrictions and hypotheses

No parser/reference behavioural mismatch was demonstrated. Every `Examples:` line parsed and every `Forbidden:` expression was refused by the live `ExpressionParser` (§7).

- **`get_expression_grammar-N1` — source-established UI overclaim (GS-03 class); previously recorded here as a hypothesis.** The tooltip says the grammar is "used by routing and templating" ([src/elspeth/web/frontend/src/components/chat/toolCallDescriptions.ts:36](../../../../src/elspeth/web/frontend/src/components/chat/toolCallDescriptions.ts#L36)). Row templates (LLM prompts, retrieval `query_template`) are Jinja templates rendered in an `ImmutableSandboxedEnvironment` ([src/elspeth/plugins/infrastructure/templates.py:42](../../../../src/elspeth/plugins/infrastructure/templates.py#L42)), not `ExpressionParser` expressions. The capability skill documents that template language separately ([src/elspeth/web/composer/skills/pipeline_capabilities.md:322](../../../../src/elspeth/web/composer/skills/pipeline_capabilities.md#L322)). The reference's own header does not list templates.
- **`get_expression_grammar-N2` — source-established scope inconsistency across surfaces.** At least six surfaces state the scope, and they give five different answers:

- **`get_expression_grammar-N3` — source-established disclosure gap: consumer-specific namespaces and constraints are not in the reference.** The reference says `row` is "the current row as a dict" ([generation.py:221](../../../../src/elspeth/web/composer/tools/generation.py#L221)). That is false for two consumers. A trigger condition may read only `row['batch_count']` and `row['batch_age_seconds']` ([src/elspeth/core/config.py:546](../../../../src/elspeth/core/config.py#L546)). A `reference_join` `output` expression may address only `ref`; `row[...]` is refused there (measured: `ref["description"]` is refused under the default `row` namespace and admitted with `allowed_names=["ref"]`). Several consumers add further rules. `result_checks` must evaluate to exactly `bool` ([result_checks.py:46](../../../../src/elspeth/plugins/transforms/llm/result_checks.py#L46)). `batch_duplicate_annotator` requires literal row keys ([batch_duplicate_annotator.py:48](../../../../src/elspeth/plugins/transforms/batch_duplicate_annotator.py#L48)). `reference_join` refuses amplification, concatenation and container-allocation risk ([reference_join.py:372](../../../../src/elspeth/plugins/transforms/reference_join.py#L372)). A gate's result type fixes its route labels: boolean conditions require exactly `true`/`false`, numeric results are refused, and string results may use custom labels ([src/elspeth/core/config.py:939](../../../../src/elspeth/core/config.py#L939), [src/elspeth/web/composer/state.py:3676](../../../../src/elspeth/web/composer/state.py#L3676)). These are partly mitigated elsewhere. The `trigger.condition` argument description names the batch keys ([src/elspeth/web/composer/tools/transforms.py:344](../../../../src/elspeth/web/composer/tools/transforms.py#L344)), `reference_join`'s schema and assistance describe `ref`, and route-label rules surface reactively in an `explain_validation_error` fix ([generation.py:1142](../../../../src/elspeth/web/composer/tools/generation.py#L1142)). Whether the gap causes extra model repair turns is a **hypothesis**; no provider run measured it.
- **`get_expression_grammar-N4` — demonstrated test-instrument weakness (doc-parity tripwire fails open for several operators).** `test_expression_grammar_documents_every_operator` checks each token with a substring test (`token in operators_section`) ([tests/unit/web/composer/test_tools_discovery.py:202](../../../../tests/unit/web/composer/test_tools_discovery.py#L202)). I replicated that predicate in read-only Python against mutated reference text. Removing `<` and `>` from the Comparison line left no token missing, because `<=` and `>=` mask them. Removing `/` also left no token missing, because `//` masks it. The positive control fired: removing `==` reported `['==']` missing. So the "parser-operator parity" safeguard cannot detect removal of several operator tokens. The builtins test is stronger: it extracts names by regex and compares sets in both directions ([tests/unit/web/composer/test_tools_discovery.py:209](../../../../tests/unit/web/composer/test_tools_discovery.py#L209)). **Pytest-level mutation confirmation (coordinator, 2026-11-09, maintainer-approved):** the real test was run with `-n 0` against three lane-private copies of `src/`, with `elspeth.__file__` verified to resolve into each copy. Unmodified baseline: exit 0, passed. Comparison line rewritten to `==, !=, <=, >=` (`<` and `>` removed): **exit 0, passed** — the tripwire fails open. Control with `==` removed: exit 1, failed. The worktree source was not modified.
- **`get_expression_grammar-N5` — source-established route difference, benign for this tool.** Composer MCP returns `execute_tool(...).to_dict()` without `admit_discovery_result` ([src/elspeth/composer_mcp/server.py:402](../../../../src/elspeth/composer_mcp/server.py#L402)). The selected response contract therefore protects the freeform and planner routes only. For this handler the payload is a constant one-key mapping, so no malformed response is reachable. The difference matters for any discovery tool whose producer can vary.
- **`get_expression_grammar-N6` — source-established grammar under-disclosure (minor).** `%` is listed only as arithmetic ([generation.py:233](../../../../src/elspeth/web/composer/tools/generation.py#L233)), but the parser also admits `"%s" % row['x']` (measured). Preview refuses string `*`/`%` over string-typed fields as `gate_expression_unbounded_string_amplification` ([src/elspeth/web/composer/tools/generation.py:3053](../../../../src/elspeth/web/composer/tools/generation.py#L3053)), and `reference_join` refuses it at load. Several admitted forms are also undocumented: chained comparisons (`0 < row['x'] < 5`), computed subscript keys (`row[row['k']]`), integer indexing (`row['a'][0]`) and unary `-`/`+`. All were measured to parse. None of this is a behavioural defect; the reference is incomplete as a positive description.
- **Intended restriction:** under-budget, the planner aid makes a planner call redundant, yet the tool stays advertised by design ("all read tools remain available", [src/elspeth/web/composer/pipeline_planner.py:351](../../../../src/elspeth/web/composer/pipeline_planner.py#L351)). A redundant planner call is uncached and spends a discovery turn; nothing refuses it. Whether planners actually make it is unmeasured.
- **Hypothesis, unreachable at baseline:** if `grammar_omitted` ever fires, the planner gets a `sha256` it is told stands in for the text. The tool result carries no hash, so the model cannot match the fetched text to the marker without hashing it itself. The arm is unreachable while the aid measures 3,526 of 8,192 bytes.

### 5.1 Guidance parity

Instrument: `grep -n "grammar\|expression\|result_check\|row\.get\|condition…"` over both skill files. It matched the known mentions at `pipeline_composer.md:23` and `pipeline_capabilities.md:37`. A separate `grep -n "batch_count\|batch_age_seconds"` returned nothing in either skill but matched seven lines in `src/elspeth/core/config.py`, which shows the pattern works.

- **Mentions:** `pipeline_composer.md` names the tool as the authority for grammar-inexpressibility named gaps ([pipeline_composer.md:23](../../../../src/elspeth/web/composer/skills/pipeline_composer.md#L23)) and in the autogenerated inventory ([pipeline_composer.md:340](../../../../src/elspeth/web/composer/skills/pipeline_composer.md#L340)). `pipeline_capabilities.md` says to call it "before authoring conditions, unless the expression grammar is already supplied" ([pipeline_capabilities.md:37](../../../../src/elspeth/web/composer/skills/pipeline_capabilities.md#L37)). Its gate capability says the tool "is the full grammar authority" ([pipeline_capabilities.md:141](../../../../src/elspeth/web/composer/skills/pipeline_capabilities.md#L141)). These agree with the planner aid ("no discovery call" when supplied) and with the handler. No stale tool or argument names were found.
- **Undisclosed scope (both skills):** no skill text says that `value_transform`, `result_checks`, trigger conditions, `batch_duplicate_annotator.when` or `reference_join.output` use the same grammar. Only the reference header says the first two. "Before authoring conditions" ([pipeline_capabilities.md:37](../../../../src/elspeth/web/composer/skills/pipeline_capabilities.md#L37)) covers `trigger.condition`, where the reference's `row` = current row is wrong (N3). - **Route-label rule missing proactively:** neither skill states the gate result-type/route-label contract. The only proactive mention is the fan-out example ([pipeline_composer.md:626](../../../../src/elspeth/web/composer/skills/pipeline_composer.md#L626)); the full rule appears only after failure, in an `explain_validation_error` fix ([generation.py:1142](../../../../src/elspeth/web/composer/tools/generation.py#L1142)).
