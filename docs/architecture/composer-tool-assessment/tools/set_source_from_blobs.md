# `set_source_from_blobs` — independent tool assessment

Baseline: ELSPETH **0.8.9**, `3b28d537be98234da8135c418bf185a998c18b68`. Reconnaissance and remediation design only. Incoming `.10 lite` changes are outside this assessment and require affected-source reinspection.

## 1. Purpose and usage

Bind a sequence of existing session documents as a blob_rows source, one retained document per runtime row in authoring order. This preserves payload custody instead of inserting binary bytes into model context.

Use for uploaded/pasted binary documents feeding supported extraction/rasterisation plugins. Requires session engine/session ID and available blob_rows source. The plural route serves user-verbatim uploads; it refuses model-authored blobs whose review custody it cannot represent.

It is the **only** authoring verb that can create or change a blob_rows document list. Every generic writer (`set_source`, `patch_source_options`, `set_pipeline`, and therefore the planner's `emit_pipeline_proposal`) refuses a supplied `blobs` key, and the singular `set_source_from_blob` cannot produce a blob_rows source (§3.1, set_source_from_blobs-N1, set_source_from_blobs-N9).

## 2. Contract

Required blob_ids: nonempty array of strings, at most 1000, and on_success:string. source_name defaults source; options defaults {}; optional on_validation_failure has preserve-on-omission semantics for an existing source, explicit nonempty choice for a new one. IDs must parse as UUIDs ([`UUID()`](../../../../src/elspeth/web/composer/tools/blobs.py#L518) also admits braced, URN and hyphenless spellings) and be unique after **lower-casing only** ([sources.py:1391](../../../../src/elspeth/web/composer/tools/sources.py#L1391)); other spellings of one identity are not folded and then miss the raw-text lookup (BOS-03). Distinct IDs with equal content hashes also refuse as duplicate documents. Each persisted blobs entry comes from authoritative metadata: blob_id,payload_ref,filename,mime_type,size_bytes. Result returns data.source_blobs in order (fields `blob_id, filename, mime_type, size_bytes, content_hash`; the runtime row fields are instead `blob_id, blob_ref, blob_filename, blob_mime_type, blob_size_bytes`, visible to the model only through the stamped `schema.guaranteed_fields` in the applied-component echo), applied component, validation and new version, plus `server_owned_metadata_note` when an echo was dropped. The call validates the whole list before mutating CompositionState and stops at the **first** offending member. It neither reads binary content nor writes blobs; byte staging and integrity admission happen at execution. No auto retry or idempotency key; an identical re-call succeeds and advances the version although the bound source is byte-identical (set_source_from_blobs-N6).

Options are a full replacement, not a merge: the new SourceSpec is built from the caller's options plus the resolved `blobs` and the stamp ([sources.py:1595](../../../../src/elspeth/web/composer/tools/sources.py#L1595)); prior caller options on the same source survive only if re-supplied (resolved reviews are restored by `reconcile_authoritative_reviews`). Re-supplying the stored options verbatim is refused because they contain the server-owned `blobs` key (set_source_from_blobs-N1); re-supplying the stored `schema` stamp is tolerated as an echo.

The handler returns an immutable candidate; it does not itself durably save the conversation. In web explicit_approve mode, the operation is staged as a proposal and re-admitted on acceptance; unlike `ToolKind.MUTATION` tools it gets **no** pre-proposal handler preview or required-control finalisation, and proposal-time validation covers only existence, ownership and readiness (set_source_from_blobs-N7). Otherwise the enclosing tool batch applies the accepted state, and the session turn persists it under its operation authority. Across both provider dialects, the provider wire projection is decoded to canonical arguments before dispatch; strict transport representation does not grant different authority. A ToolResult's `success` records operation admission, while `validation.is_valid`, runtime preflight, review and execution admission answer separate questions. Owned-code/audit integrity failures escape as faults rather than being reclassified as ordinary invalid model input.

## 4. Alternative paths

Manual blobs/blob_ref/source_authoring options, forged guarantees, invalid IDs, missing or foreign blobs, non-READY members, duplicate hashes and LLM-authored modalities refuse the whole list unchanged. A ready row without a content hash is an audit integrity fault, not user error; so is a stored MIME type outside the storage set (raised by the row read guard). Server fabricates the blob_rows fixed-field guarantee from the plugin row contract and then runs plugin/source prevalidation. The selected source may remain graph-incomplete; missing destination sinks appear in validation after successful admission. The declaration says a mixed document set needs one homogeneous source per format (the plugin hints say "homogeneous sources or branches"); the tool itself admits a mixed set and any `STORAGE_MIME_TYPES` member, including `text/csv`, so homogeneity is left to the consumer (`aws_textract_inline_analysis` requires one `document_format` per node and verifies byte signatures at run time). Metadata binding does not inspect binary encodings or guarantee downstream extractor acceptance.

Refusal codes: `source_binding_context_unavailable`, `source_blob_identity_invalid`, `source_blob_unavailable` (not found **and** not ready), `source_blob_duplicate` (repeated ID **and** repeated content), `source_blob_review_required`, `source_data_contract_required`, `failure_route_required`, `interpretation_requirements_invalid`, `plugin_options_invalid`, plugin-policy codes and `review_reconciliation_failed`. An invalid `source_name` and a schema/model violation raise `ToolArgumentError` (ARG_ERROR) instead.

## 5. Usability assessment

**BOS-03 — demonstrated on this route (in-memory handler run).**
The plural binder normalizes IDs only for duplicate detection at
`sources.py:1391`, then passes the original text to `_sync_get_blob` at line 1405.
The in-memory probe (report "Probes") reproduces it here: the upper-case form of
a ready blob's ID returns `source_blob_unavailable` "not found"; the same
upper-case form beside the canonical ID returns `source_blob_duplicate`; braced
and hyphenless spellings pass `UUID()` and then read as "not found", the
hyphenless one even beside its canonical twin. The existing contract test pins
the case-folded duplicate ([test_source_rejection_contracts.py:516](../../../../tests/unit/web/composer/test_source_rejection_contracts.py#L516))
but not the lookup. Under explicit_approve the same upper-case spelling does not even refuse: it ends the compose turn with a bare `ValueError` raised by the exact-string proposal validator (set_source_from_blobs-N7, §7.1 probe 1). Preserve the exact canonical IDs returned by discovery as a
workaround. One owned BlobId boundary should govern duplicate identity and
lookup consistently, with equivalent-ID, duplicate, malformed and foreign-session
rejection controls for every binding route (the proposal reference validator and
pending-retention scan are also exact-string; the delete guard already uses
`names_same_blob`).

**SG-06 instance — source-established plugin/adapter ownership weakness; high confidence.** The adapter imports private blob_rows._ROW_FIELDS and stamps schema guarantees itself (the source explains this was placed here to avoid source-hash churn). That couples Composer authoring to private plugin representation rather than an authoritative public capability/lowering contract. The coupling comment's line reference is stale (it cites `blob_rows.py:226-232 over _ROW_FIELDS`; the literal row dict is at [:233-240](../../../../src/elspeth/plugins/sources/blob_rows.py#L233) and does not iterate `_ROW_FIELDS`, which the plugin uses only at [:253](../../../../src/elspeth/plugins/sources/blob_rows.py#L253)). **set_source_from_blobs-N1 — demonstrated dead end: a bound blob_rows source has no whole-document representation (in-memory public-dispatch run).** `get_pipeline_state` returns the source with `options.blobs`; feeding that state back to `set_pipeline` is refused `plugin_options_invalid` ("must not be called with 'blobs'"), and omitting `blobs` is refused `blobs: Field required`. The successful bind's own `applied_component` echo, documented as "the exact `set_pipeline` arguments" ([`_applied_component_echo`](../../../../src/elspeth/web/composer/tools/_common.py#L4088)), carries those same `options.blobs` (probe P14). Workaround: author the rest incrementally, or call this tool last.

**set_source_from_blobs-N2 — demonstrated misleading refusal for a supplied guarantee stamp.** Supplying `options.schema.guaranteed_fields` (even the exact five plugin fields) returns `source_data_contract_required` with the generic uploaded-CSV text ([sources.py:744](../../../../src/elspeth/web/composer/tools/sources.py#L744)): "its header is a sample", "request the data-contract review with request_interpretation_review (kind=source_data_contract)", or "declare an explicit runtime contract". For blob_rows the correct repair is to omit the key; the server stamps the complete plugin-contract guarantee at `:1468`. **Probe 3 (§7.1): the advice is wrong for blob_rows in both regimes.**
- **No demand beyond the stamp.** This is the N2 trigger: the caller supplies the five fields. With the bound source alone, or with a consumer requiring only `blob_ref`, there is no pending site, and `request_interpretation_review`'s target boundary (`_assert_affected_component`) refuses with "missing pending source_data_contract review site". Following the refusal's advice yields another refusal.
- **A non-custody field is demanded.** With a consumer requiring a field blob_rows never emits (an `llm` node with `required_input_fields: ["colour"]`), the review becomes reachable. The backend enumerates a pending `source_data_contract` site, and the boundary admits it with the server-computed draft `demanded_fields: ["colour"]`; a csv source with the same node yields the identical draft. `stamp_source_options_with_guarantees` would add `colour` to the five custody fields. A user acknowledgement would therefore record a guarantee the plugin's fixed row literal cannot keep.

The resolve arm and the runtime consequence were not run. Classification: demonstrated (misleading refusal, both regimes measured at the handler boundary).

## 6. Structural remediation

Expose a public immutable plugin-owned document-row contract and a typed custody-binding adapter shared by discovery, authoring, preview and execution. Review/provenance admission remains in the web authority layer; plugins must not invent human approval. Regression: legal ordered documents produce exactly the plugin-declared row fields; duplicate IDs/hashes, foreign and non-ready blobs refuse atomically; every authored modality is rejected until a complete equivalent review path exists; metadata-only binding performs no content reads; runtime revalidates retained hashes. Preserve current duplicate/refuse policy unless separately changed. Compatibility risk medium because persisted blobs entries and schema guarantees are runtime inputs.

For set_source_from_blobs-N1, give the resolver-owned `blobs` list a whole-document representation that keeps custody server-owned: either echo tolerance (a supplied `blobs` that `stable_hash`-matches the stored list for the same source is dropped and the stored list retained, as `_drop_echoed_source_authoring` does) or an ID-only form in `set_pipeline` (`sources.<name>.blob_ids`) resolved through the same `_resolve_source_blobs`. Either keeps the LLM as author and the server as resolver; neither lets a caller assert entry fields. Regression: bind → `get_pipeline_state` → `set_pipeline` echo succeeds and preserves the list; a modified or forged list still refuses; the planner terminal can preserve the source. For set_source_from_blobs-N7, route blob-backed graph mutations through the same pre-proposal preview as `ToolKind.MUTATION` tools, or convert the proposal-time `ValueError` into a structured refusal.
