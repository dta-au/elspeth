# `create_blob` — author an immediate session artifact

Assessment baseline: `3b28d537be98234da8135c418bf185a998c18b68` (0.8.9). Reconnaissance and design, plus lane-private probes run against the baseline (§7.1); no production code changed. **Overall confidence: High for source contracts and the probed failure paths; Moderate for unexercised delivery-failure recovery implications (no forked-process kill or lost-result run).**

## 1. Purpose and usage

Use this tool to persist a small textual seed/reference artifact supplied in the conversation or generated by the model, then bind or inspect it through other tools. It creates storage; it does not select a source, author pipeline structure, or execute a plugin. It requires a session engine, session ID, data root, the exact operation authority/fence, and sufficient provenance context. It is web-only and freeform-only: Composer MCP excludes blob tools, and the default proposal-planner palette does not include it (§3.1).

## 2. Contract

Required arguments are `filename`, `mime_type`, and `content`, all strings; `description` is an optional string. Extra fields are forbidden, and an explicitly supplied `null` for `description` is refused by the owned model ([`_OmittableString`](../../../../src/elspeth/web/composer/redaction.py#L1428)); on the `openai_strict` wire the required-nullable `description` has its `null` stripped before the model sees it (§3.1). Content must encode as UTF-8. Empty content is admitted and creates a zero-byte artifact. The MIME vocabulary is `application/json`, `application/jsonl`, `application/x-jsonlines`, `text/csv`, `text/jsonl`, and `text/plain` (the shared `AllowedMimeType` contract); this is text creation, not arbitrary binary upload. No check relates the filename extension to the MIME type, and no content sniffing runs on this path, unlike the upload route.

[`sanitize_filename`](../../../../src/elspeth/web/blobs/service.py#L321) **reduces the filename to its basename rather than refusing directory components**: `../../etc/passwd` becomes `passwd` and `dir/seed.csv` becomes `seed.csv`. Only an empty, `.`/`..` or root-only result is refused; names over 200 UTF-8 bytes are truncated keeping the extension. Whitespace-only names (`'   '`) and names containing NUL are returned unchanged (measured, §7). The result payload returns the stored filename, so a renamed artifact is visible to the model.

Storage admission has up to three bounds, all checked inside the fenced reservation transaction: the per-session total ([`reserve_blob`](../../../../src/elspeth/web/coordination/repository.py#L2794), which also counts admitted sink-output reservations), and the owning identity's cap or the shared container ceiling ([`admit_storage_bytes_on_connection`](../../../../src/elspeth/web/coordination/quota_authority.py#L808)) when such policies exist. The session bound comes from `WebSettings.max_blob_storage_per_session_bytes` (default 500 MiB, [`config.py`](../../../../src/elspeth/web/config.py#L549)), which every production route supplies; the [500 MiB literal](../../../../src/elspeth/web/composer/tools/blobs.py#L1140) in the tool module is only a fallback for direct callers passing `None`.

Success returns a new `blob_id`, the stored `filename`, `mime_type`, `size_bytes`, `content_hash`, and `originated_in="this_tool_call"`. The stored `description` (normalized to `None` when blank) is not echoed. The tool is declared `BLOB_MUTATION` with `blob_store_only=True` but returns through [`_discovery_result`](../../../../src/elspeth/web/composer/tools/_common.py#L1279) — the unchanged-state helper, which also carries the unchanged pipeline's validation — because no graph change occurred. It has no response contract and is not routed through `admit_discovery_result`. Creation is intentionally immediate even under `explicit_approve`; destructive blob operations have a different policy. The call is uncached. Every call allocates a fresh UUID ([`uuid4`](../../../../src/elspeth/web/composer/tools/blobs.py#L1468)) and persists with [`idempotent=False`](../../../../src/elspeth/web/composer/tools/blobs.py#L1535); identical argument replay creates another artifact. No client idempotency key or expected-state argument is exposed.

Missing session/data context yields a failed result; invalid shape, MIME, unsanitizable filename, or UTF-8 encoding raises safe `ToolArgumentError`. Any storage-bound refusal (session, identity or container) returns a failure whose message always reads "Session blob quota exceeded" and carries no `error_code` (§5, demonstrated). Unavailable storage accounting (`StorageAccountingUnavailableError`) and a NUL in the filename are not converted: they escape the handler and take the plugin-crash path (§5, both demonstrated through a compose turn). A revoked identity allowance raises the same error at the handler, but a compose turn for a revoked identity is refused at admission before any tool runs (§7.1). Missing LLM provenance or invalid operation authority is an integrity error. A nonempty exact substring of the triggering user message (with a nonblank message ID) is classified verbatim; other text requires complete model/provider/skill/argument provenance. This classification does not claim the file was manually uploaded.

## 3. Implementation trace

The [handler](../../../../src/elspeth/web/composer/tools/blobs.py#L1559) and its [declaration](../../../../src/elspeth/web/composer/tools/blobs.py#L1655) use the redaction-bearing [`CreateBlobArgumentsModel`](../../../../src/elspeth/web/composer/redaction.py#L1671), [`_blob_creation_provenance`](../../../../src/elspeth/web/composer/tools/blobs.py#L1212), and [`_prepare_blob_create`](../../../../src/elspeth/web/composer/tools/blobs.py#L1380). [`_persist_prepared_blob_create`](../../../../src/elspeth/web/composer/tools/blobs.py#L1498) delegates actual fenced durable creation to [`_persist_blob_content`](../../../../src/elspeth/web/blobs/service.py#L1463) and its [fenced reservation/publication/recovery driver](../../../../src/elspeth/web/blobs/service.py#L2693); handlers do not implement an alternate direct file-write protocol. The driver admits only `CREATE`, `COMPOSE` and `PROPOSAL` operation kinds ([`_CREATE_BLOB_OPERATION_KINDS`](../../../../src/elspeth/web/blobs/service.py#L137)) and reconciles abandoned creations under the session custody lock before each new reservation.

Registration flows through the [_registry module tuple](../../../../src/elspeth/web/composer/tools/_registry.py#L95) and its [derived blob-mutation maps](../../../../src/elspeth/web/composer/tools/_registry.py#L150), and [model definitions](../../../../src/elspeth/web/composer/tools/_dispatch.py#L311). [Public dispatch](../../../../src/elspeth/web/composer/tools/_dispatch.py#L795) admits closed schema/credentials and exact catalog identity and calls the handler without translating exceptions. [Approval classification](../../../../src/elspeth/web/composer/tools/discovery.py#L111) exempts creation by tool name, and [tool-batch worker dispatch](../../../../src/elspeth/web/composer/tool_batch.py#L3008) supplies provenance and operation authority. [Audit](../../../../src/elspeth/web/composer/audit.py#L812) records the invocation; [frontend outcomes](../../../../src/elspeth/web/frontend/src/components/chat/ToolCallCard.tsx#L84) can show completed durable work without falsely claiming a graph version advance. The metadata itself retains origin evidence.

## 4. Alternative paths

Verbatim seed content and model-generated content reach the same storage protocol with different provenance. Invalid text/filename/MIME is rejected before durable publication; a filename with directory components is renamed rather than rejected. The quota/authority driver owns staging, database transitions, and recovery; composition state stays unchanged even after successful creation. A later source bind can fail while the created artifact remains a valid session artifact. Under `explicit_approve`, the artifact is committed immediately while the follow-up bind becomes a pending proposal; rejecting that proposal leaves the artifact stored and counted against quota. A retry with identical arguments is a new creation, not recovery of the prior tool result. A caller missing server authority cannot substitute a model-supplied fence or provenance field.

## 5. Usability assessment

**BOS-04 — source-established lifecycle limitation, High confidence:** successful durable creation has no graph-version delta and no caller-visible idempotency selector. The orchestrator must distinguish “artifact created” from “pipeline changed” and must not automatically repeat creation after uncertain result delivery. A duplicate after a replay is a consequence supported by UUID allocation and `idempotent=False`; an actual transport-loss duplicate was not injected. Workaround: retain the returned ID, inspect the session inventory before retry, and bind the existing artifact when identifiable. Inventory's hidden latest-50 window limits that workaround in larger sessions. Repeated successful creations are also invisible to the anti-anchor accounting (§3.1); whether other loop budgets bound them in practice was not measured.

**create_blob-N1 — source-established guidance/palette mismatch (see §5.1):** the proposal planner receives instructions to call `create_blob` (and `set_source_from_blob`) although neither is in its measured palette. Whether the planner actually attempts the call needs a live provider; the probe was not runnable here (§7.1).

**create_blob-N2 — demonstrated fault-category defect (compose turn, accounting-outage trigger; §7.1):** [`StorageAccountingUnavailableError`](../../../../src/elspeth/web/coordination/quota_authority.py#L845), raised for a revoked identity allowance or a storage-accounting `SQLAlchemyError`, is a `BlobError` but not a `BlobQuotaExceededError`. The [quota catch](../../../../src/elspeth/web/composer/tools/blobs.py#L1539) misses it, so it escapes `execute_tool` and the [tool-batch catch-all](../../../../src/elspeth/web/composer/tool_batch.py#L3199) wraps it as `ComposerPluginCrashError` (turn ends, recorded as a plugin bug). The upload route maps the same condition to 503. Run: a quota-policy read failure during the real handler in a scripted compose turn raised `ComposerPluginCrashError` ← `StorageAccountingUnavailableError` ← `OperationalError`, persisted the tool row as `plugin_crash`, and wrote no blob; the unpatched control created a ready blob. The revoked-identity trigger is narrower than first stated: the handler raises it directly, but a compose turn for an already-revoked identity is refused at admission (`ComposerAdmissionRefused`, no handler call), so through Composer it needs a revocation landing mid-turn or an accounting fault.

**create_blob-N3 — demonstrated result inconsistency (handler level; §7.1):** the [quota failure](../../../../src/elspeth/web/composer/tools/blobs.py#L1650) carries no `error_code`, while `set_pipeline`'s identical inline-blob refusal returns the registered `BLOB_QUOTA_EXCEEDED`. The message always says "Session blob quota exceeded" even when [`IdentityStorageQuotaExceededError`](../../../../src/elspeth/contracts/blobs.py#L324) (an identity cap or the shared container ceiling) refused it, and it reports that bound's usage and limit under the session label. Run: an identity cap of 3 bytes (session limit 10,000) returned `success=false`, `error_code=None` and "Session blob quota exceeded: 7 bytes would exceed 3 byte limit." That is byte-identical to the genuine 3-byte session-limit refusal, so the model cannot tell the scopes apart. A cap of 100 succeeded (control). `set_pipeline` `source.inline_blob` under the same identity cap returned `BLOB_QUOTA_EXCEEDED` with the same "Session" text.

**create_blob-N4 — demonstrated end to end (compose turn; §7.1):** a filename containing NUL passes `sanitize_filename` and `_prepare_blob_create`; the first statement of [`_persist_prepared_blob_create`](../../../../src/elspeth/web/composer/tools/blobs.py#L1508) (`resolve()`) raises `ValueError` before any authority check or reservation. `ValueError` is not `ToolArgumentError`, so the call takes the plugin-crash path rather than ARG_ERROR. Run: a scripted provider reply carrying `"a\u0000b.csv"` reached the real handler; the turn raised `ComposerPluginCrashError` ← `ValueError`, the persisted tool row is `plugin_crash` with `error_class` `ValueError`, and no blob row or file exists. The `ab.csv` control created a ready blob. No pre-dispatch guard refuses the control character. Whether a real provider emits `\u0000` in a filename was not tested.

**create_blob-N5 — source-established audit asymmetry, intent unclear:** identity/container refusals call the quota-exceeded recorder before raising ([`record(...)`](../../../../src/elspeth/web/coordination/quota_authority.py#L869)), whereas the per-session refusal in [`reserve_blob`](../../../../src/elspeth/web/coordination/repository.py#L2794) raises without one. It is recorded here as an asymmetry, not a defect.

**create_blob-N6 — source-established, low impact:** the verbatim test is `content in user_message_content`, so degenerate content (a single character or whitespace) present anywhere in the triggering message is recorded as verbatim with no LLM provenance; content copied from an earlier user message is conservatively recorded as LLM-generated. Downstream, verbatim versus LLM-authored changes later schema-guarantee stamping and review staging for blob-bound sources.

**create_blob-N7 — demonstrated with a simulated death (in process; §7.1):** a death after the blob commits but before the compose turn's tool rows are persisted leaves a ready artifact whose `creating_arguments_hash` has no persisted invocation. Run: the turn-persistence call (`persist_compose_turn_async`) was replaced with a `BaseException` raise, so no `except Exception` compensation could run. The ready LLM-generated blob remained, with `created_from_message_id` set. No assistant or tool row existed, and its `creating_arguments_hash` appeared in no table except `blobs`. In the control turn the same hash also appears in `chat_messages`. After the dead turn's lease was expired, a successor turn's `create_blob` (which runs the abandoned-creation reconcile) left the orphan ready and still unlinked. A forked-process kill was not run. The simulation still let `finally` blocks run, which a real death would not, so it can only under-report an orphan.

Immediate creation and text-only MIME admission are **intended restrictions**, not approval bypass defects; the rationale comment at the interception site is accurate. The undisclosed consequence (the orphan artifact after a rejected bind) is a guidance gap (§5.1). No defect in the shared durable creation driver was demonstrated by this lane.

The declaration does disclose the return fields and MIME enum.
- **`pipeline_capabilities.md` has no `create_blob` mention (0 hits).** This is correct for the surface-neutral contract. Its [inline_blob field row](../../../../src/elspeth/web/composer/skills/pipeline_capabilities.md#L249) lists fields without the MIME vocabulary; the wire enum covers that.
- **User-facing tooltip.** "Creates a new file from inline content for the pipeline to use." is mildly overclaiming: creation does not bind the file to the pipeline.
- No stale tool or argument names were found for this tool; `source.blob_id` is a live `set_pipeline` field.

## 6. Structural remediation

Represent authored artifact effects independently from graph effects and attach a stable operation/result receipt the orchestrator can query after cancellation or result loss. Blob custody should own effect idempotency; the tool descriptor should declare creation's retry class, immediate-approval policy (today a hard-coded name test at [`discovery.py`](../../../../src/elspeth/web/composer/tools/discovery.py#L113)), and required context. Existing precedents are the scoped deterministic identity of [inline custody](../../../../src/elspeth/web/blobs/service.py#L415) (session, originating message, filename, MIME, description, content hash and provenance) and the durable blob-effect receipt already required for blob-only proposal acceptance ([`mutation_capabilities.py`](../../../../src/elspeth/web/sessions/mutation_capabilities.py#L449)). Preserve provenance and quota boundaries. Related paths include inline blob creation in whole-pipeline authoring, authenticated blob creation, and generated-source artifact delivery.

Acceptance: valid creation returns an artifact identity and explicit committed effect; malformed input, stale authority, exhausted quota, or missing provenance publishes no usable artifact; replay under one operation key returns the same committed result; a new operation may intentionally create identical bytes again; crash recovery and post-commit result loss never produce an ambiguous graph success claim. Compatibility risk is Medium for adding replay identity and result fields; preserve existing MIME/provenance contracts and do not deduplicate merely by content hash.
