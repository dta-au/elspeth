# `create_blob` — author an immediate session artifact

Assessment baseline: `3b28d537be98234da8135c418bf185a998c18b68` (0.8.9). Reconnaissance and design only. **Overall confidence: High for source contracts; Moderate for unexercised delivery-failure recovery implications.**

## 1. Purpose and usage

Use this tool to persist a small textual seed/reference artifact supplied in the conversation or generated by the model, then bind or inspect it through other tools. It creates storage; it does not select a source, author pipeline structure, or execute a plugin. Requires session engine, session ID, data root, exact operation authority/fence, and sufficient provenance context. It is web-only; Composer MCP excludes blob tools.

## 2. Contract

Required arguments are `filename`, `mime_type`, and `content`, all strings; `description` is an optional string. Extra fields are forbidden. Content must encode as UTF-8. The MIME vocabulary is `application/json`, `application/jsonl`, `application/x-jsonlines`, `text/csv`, `text/jsonl`, and `text/plain`; this is text creation, not arbitrary binary upload. Filenames undergo sanitization/path-traversal checks. The default session storage quota is 500 MiB unless the context supplies another limit; the custody service enforces it atomically.

Success returns a new `blob_id`, sanitized `filename`, `mime_type`, `size_bytes`, `content_hash`, and `originated_in="this_tool_call"`. It is declared `BLOB_MUTATION` with blob-store-only effects, but returns a discovery-shaped result carrying the original composition version: no graph change occurred. Creation is intentionally immediate even under `explicit_approve`; destructive blob operations have a different policy. The call is uncached. Every call allocates a fresh UUID and persists with `idempotent=False`; identical argument replay can create another artifact. No client idempotency key or expected-state argument is exposed.

Missing session/data context yields a failed result; invalid shape, MIME, filename, or UTF-8 encoding raises safe `ToolArgumentError`; quota exhaustion returns failure. Missing LLM provenance or invalid operation authority is an integrity error. A nonempty exact substring of the triggering user message is classified verbatim; other text requires complete model/provider/skill/argument provenance. This classification does not claim the file was manually uploaded.

## 4. Alternative paths

Verbatim seed content and model-generated content reach the same storage protocol with different provenance. Invalid text/filename/MIME is rejected before durable publication. The quota/authority driver owns staging, database transitions, and recovery; composition state stays unchanged even after successful creation. A later source bind can fail while the created artifact remains a valid session artifact. A retry with identical arguments is a new creation, not recovery of the prior tool result. A caller missing server authority cannot substitute a model-supplied fence or provenance field.

## 5. Usability assessment

**BOS-04 — source-established lifecycle limitation, High confidence:** successful durable creation has no graph-version delta and no caller-visible idempotency selector. The orchestrator must distinguish “artifact created” from “pipeline changed” and must not automatically repeat creation after uncertain result delivery. A duplicate after a replay is a consequence supported by UUID allocation and `idempotent=False`; an actual transport-loss duplicate was not injected. Workaround: retain the returned ID, inspect the session inventory before retry, and bind the existing artifact when identifiable. Inventory's hidden latest-50 window limits that workaround in larger sessions.

Immediate creation and text-only MIME admission are **intended restrictions**, not approval bypass defects. No defect in the shared durable creation driver was demonstrated by this lane.

## 6. Structural remediation

Represent authored artifact effects independently from graph effects and attach a stable operation/result receipt the orchestrator can query after cancellation or result loss. Blob custody should own effect idempotency; the tool descriptor should declare creation's retry class, immediate-approval policy, and required context. Preserve provenance and quota boundaries. Related paths include inline blob creation in whole-pipeline authoring, authenticated blob creation, and generated-source artifact delivery.

Acceptance: valid creation returns an artifact identity and explicit committed effect; malformed input, stale authority, exhausted quota, or missing provenance publishes no usable artifact; replay under one operation key returns the same committed result; a new operation may intentionally create identical bytes again; crash recovery and post-commit result loss never produce an ambiguous graph success claim. Compatibility risk is Medium for adding replay identity and result fields; preserve existing MIME/provenance contracts and do not deduplicate merely by content hash.
