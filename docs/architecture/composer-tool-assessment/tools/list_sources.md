# `list_sources` — independent tool assessment

Baseline: ELSPETH **0.8.9**, `3b28d537be98234da8135c418bf185a998c18b68`. Reconnaissance and remediation design only. Incoming `.10 lite` changes are outside this assessment and require affected-source reinspection.

## 1. Purpose and usage

Discover source plugins that this request is permitted and locally equipped to configure. This supplies the orchestrator's capability search for input acquisition; it does not reserve a plugin or prove that a particular configuration can execute.

Select before choosing a source implementation, or to rehydrate digest prose that the authoring-aids digest replaced with a `details_via: "list_sources"` marker ([planner_authoring_aids.py:1891](../../../../src/elspeth/web/composer/planner_authoring_aids.py#L1891)). Both the freeform catalog context and the planner request already carry the policy-visible source names and a selection digest ([prompts.py:235](../../../../src/elspeth/web/composer/prompts.py#L235), [planner_authoring_aids.py:1120](../../../../src/elspeth/web/composer/planner_authoring_aids.py#L1120)), so the guidance tells the model it "rarely" needs this call ([planner_authoring_aids.py:1913](../../../../src/elspeth/web/composer/planner_authoring_aids.py#L1913)). Requires a PolicyCatalogView and its identical PluginAvailabilitySnapshot. No blob, secret-service or execution context is required. Structural nodes such as gates and queues are not plugins and are not enumerated by these listings.

## 2. Contract

Semantic arguments are exactly an empty object; extra keys are rejected. On the wire this differs by dialect: under `openai_strict` (freeform loop and planner) the only admitted call is `{"_elspeth_no_arguments": true}` and a bare `{}` is a `wire_envelope` argument error; under `none` and on Composer MCP the wire is `{}` ([wire_projection.py:526](../../../../src/elspeth/web/composer/tools/wire_projection.py#L526), [wire_projection.py:952](../../../../src/elspeth/web/composer/tools/wire_projection.py#L952); measured, see appendix; demonstrated on a freeform compose turn, §7.1 probe 4). The result is a ToolResult with `data.available` and `data.prohibited`, plus the current state/version and validation envelope; on an empty draft that envelope carries `success: true` with `validation.is_valid: false` (`no_source_configured`, `no_sinks_configured`). Available summaries include top-level `config_fields` (name, JSON type, required, description, default), usage text, `example_use` (YAML), `capability_tags`, `web_config_authority`, `policy_capabilities`, `audit_characteristics`, `composer_hints` and `secret_requirements`. `config_fields` is a lossy top-level projection: enum values and nested shapes are omitted, a discriminated-union plugin reports a field as required only when every variant requires it, and the first variant's metadata wins ([catalog/service.py:464](../../../../src/elspeth/web/catalog/service.py#L464), [catalog/service.py:518](../../../../src/elspeth/web/catalog/service.py#L518)). Operator-profiled plugins are re-projected through the request's profile contract on web routes ([profiles.py:1594](../../../../src/elspeth/web/plugin_policy/profiles.py#L1594)) but not on the trained-operator MCP view.

`prohibited` is filtered to the categorical WEB_SURFACE_PROHIBITED reason only ([policy_view.py:126](../../../../src/elspeth/web/catalog/policy_view.py#L126)). At this baseline no production snapshot producer emits that reason, so the section is always empty on every route (list_sources-N1). Other unavailable plugins are omitted by design. There is no write, approval requirement, provider call or retry. Successful freeform responses are cached for the rest of that compose call ([composer/service.py:2500](../../../../src/elspeth/web/composer/service.py#L2500)); failures are not cached; the planner has no discovery cache and re-executes every call; MCP rebuilds its trained-operator snapshot on every call. The policy/plugin set is a request/process snapshot, so this is discovery at that scope, not a live credential-health probe. Repeated calls are observationally idempotent within one request.

This is discovery: the handler retains immutable composition state. On the freeform and planner routes, successful inventory data is admitted under `PLUGIN_INVENTORY_RESPONSE_CONTRACT` before audit/disclosure ([discovery_response.py:51](../../../../src/elspeth/web/composer/discovery_response.py#L51)); Composer MCP returns `ToolResult.to_dict()` without that admission (list_sources-N7). Across both provider dialects, the provider wire projection is decoded to canonical arguments before dispatch; strict transport representation does not grant different authority. A ToolResult's `success` records operation admission, while `validation.is_valid`, runtime preflight, review and execution admission answer separate questions. Owned-code/audit integrity failures escape as faults rather than being reclassified as ordinary invalid model input; a malformed catalog summary raises `FrameworkBugError` at admission ([inventory_response_contracts.py:267](../../../../src/elspeth/web/composer/inventory_response_contracts.py#L267)).

## 4. Alternative paths

Normal operation projects available entries from plugin-owned declarations through policy and operator-profile views. Empty available is a valid discovery result, not an error. An absent SDK, missing credential, unavailable profile or unapproved plugin can remove an entry without placing it in prohibited. A named, read-only `get_plugin_schema(plugin_type="source", name=X)` returns that closed reason without a write: an in-memory dispatch run under the default test policy returned `plugin_not_enabled` for `aws_s3`, `profile_unavailable` for `llm` and `plugin_not_installed` for an unknown name ([_common.py:2113](../../../../src/elspeth/web/composer/tools/_common.py#L2113), [_common.py:2191](../../../../src/elspeth/web/composer/tools/_common.py#L2191)). Invalid arguments are rejected before requested access: freeform/planner/MCP raise an ARG_ERROR, `execute_tool(validate_arguments=True)` without raising returns a refusal, and a bare direct `execute_tool` call raises `ToolArgumentError` from the handler's model. A fault in an admitted catalog/schema remains an owned-code failure and must not be disguised as an unknown plugin. Cache hits reconstruct the current state envelope and re-admit the cached producer response. MCP uses a trained-operator policy view, so a name visible there need not be selectable in an authenticated web request.

## 5. Usability assessment

**SG-05 — intended disclosure restriction with a planning limitation; high confidence.** The orchestrator sees selectable plugins, but not every temporarily unavailable capability or its repairable prerequisite. It cannot conclude from an absent name whether installation, credentials, a profile or authorisation is missing. The policy view documents this deliberate choice ([policy_view.py:126](../../../../src/elspeth/web/catalog/policy_view.py#L126)); it is not evidence of a registry defect. Workaround: a named `get_plugin_schema` lookup (read-only, demonstrated above), a selection attempt, or operator inspection supplies the closed denial reason. Neither the tool description nor the skills tell the model about the read-only lookup (5.1). Lists are sufficient for ordinary flat options, but nested enums/unions still require get_plugin_schema.

**list_sources-N1 — the `prohibited` section has no producer; demonstrated (real snapshot builder over a policy matrix, with a producer-mutant control; §7.1 probe 1); high confidence.** Every `PluginAvailability(...)` construction in `src/elspeth` is in `build_plugin_snapshot` and names one of four other reasons ([availability.py:102](../../../../src/elspeth/web/plugin_policy/availability.py#L102)–[:147](../../../../src/elspeth/web/plugin_policy/availability.py#L147)); every other `PluginAvailabilitySnapshot.create` caller passes `unavailable=()` or copies an existing tuple. The only WEB_SURFACE_PROHIBITED producer (the categorical `aws_s3` source ban) was removed by `e7f6f1521` when S3 sources became operator-profiled; the remaining S3 gate requires profile availability and is not categorical ([provider_config_policy.py:62](../../../../src/elspeth/web/provider_config_policy.py#L62)). The snapshot docstring still claims the function declines categorical prohibitions ([availability.py:88](../../../../src/elspeth/web/plugin_policy/availability.py#L88)). The real `build_plugin_snapshot` was driven over five policy cells (default; `aws_s3` allowlisted; every one of the 60 installed plugin ids allowlisted; every id plus Power Automate origins, all operator profiles and the held secret; every id with profiles but no secrets under a second principal). It emitted only `profile_unavailable`, `credential_unavailable` and `plugin_unavailable`, and `list_prohibited_*` was empty for all three kinds in every cell. The instrument was controlled two ways: a hand-built snapshot carrying the reason was reported, and a lane-copy mutant that restored a categorical `aws_s3` producer turned every cell that authorises `aws_s3` red (§7.1 probe 1). The matrix is test settings through the test catalog seam, not a deployment configuration, so the universal claim still rests on the producer search above; the run shows that no reachable combination of the existing knobs supplies the reason. The prohibited tests pass only because they hand-build a snapshot carrying the reason ([test_discovery_prohibited_listing.py:82](../../../../tests/unit/web/composer/test_discovery_prohibited_listing.py#L82)). Consequence: the description, skill block, digest `plugins.prohibited`, advisor `prohibited_ids` and `PLANNER_POLICY_DETAIL_CODES` all describe a branch that cannot fire from a fresh request snapshot (re-reads of records persisted before `e7f6f1521` were not examined); "absent from both" is the universal case. No harm to correctness was shown (the skill's fallback reasoning still applies), but the agent is directed to a channel that is always empty.

**list_sources-N2 — `config_fields` advertises fields that `set_source` places elsewhere or refuses; demonstrated (in-memory dispatch, not end-to-end; §7.1 probes 2–3).** `on_validation_failure` is a required config field on 9 of 10 installed sources (all but `null`), yet `set_source` authors it only as a top-level argument. Placing it only in `options` is refused with `failure_route_required`, whose message and `validation_guidance` never say the value belongs at the top level. Supplying it in both places with the same value succeeds and stores a duplicate `options.on_validation_failure`; this duplicate is harmless. `generate_yaml` writes the top-level value over the options copy ([yaml_generator.py:151](../../../../src/elspeth/web/composer/yaml_generator.py#L151)), so the emitted YAML has one value, and `load_settings_from_yaml_string` loads it. Two different values are refused with `plugin_options_invalid` ("options.on_validation_failure conflicts with the source routing field on_validation_failure"), so a divergent copy cannot reach the runtime. The asymmetry has a source-level cause. Source plugin configs declare `on_validation_failure` as a required config field ([config_base.py:496](../../../../src/elspeth/plugins/infrastructure/config_base.py#L496)), so the catalog projection lists it and the source schema accepts an equal duplicate. A comparison seam already exists at [_common.py:3516](../../../../src/elspeth/web/composer/tools/_common.py#L3516), where a placement-naming refusal could live. The profiled S3 `example_use` returned by this listing puts it under `options:` ([profiles.py:1644](../../../../src/elspeth/web/plugin_policy/profiles.py#L1644)), teaching the refused placement. `blob_rows` advertises `blobs` as required although it is server-owned; that refusal (`plugin_options_invalid`) and the plugin's `composer_hints` both name `set_source_from_blobs`, so that case is mitigated. The description's "this listing already answers ordinary configuration questions" ([sources.py:200](../../../../src/elspeth/web/composer/tools/sources.py#L200)) overclaims for these fields. The trap is not mirrored in the sink and transform listings (§7.1 probe 2). No sink `config_fields` entry shares a name with a `set_output` argument, so `on_write_failure` is not advertised as an option. The only transform overlap is `llm`'s optional request `timeout_seconds` option against `upsert_node`'s structural-barrier `timeout_seconds`; a top-level value on a transform is refused with a message that names the placement (`node_timeout_unsupported`: "only coalesce and row_union nodes accept that field"). The options-only refusals for `on_write_failure` and `on_error` have the same unplaced `failure_route_required` message, but no listing teaches that placement.

**list_sources-N3 — `secret_requirements` omits conditionally required credentials; source-established limitation, demonstrated empty.** Schema fallback considers only fields required in the summary ([catalog/service.py:489](../../../../src/elspeth/web/catalog/service.py#L489)); no source declares `discovery_secret_requirements`. `azure_blob` exposes `connection_string`, `sas_token` and `client_secret` as optional fields selected by `auth_mode`, and its summary, schema and declared requirements are all empty. The listing therefore never tells the agent that most `azure_blob` auth modes need a secret reference, and the same empty set makes the snapshot's credential-readiness check ([availability.py:44](../../../../src/elspeth/web/plugin_policy/availability.py#L44)) vacuous for it. Whether that check is meant to cover auth-mode-conditional secrets is a design question (hypothesis), not a demonstrated runtime defect.

**list_sources-N4 — `example_use` is unvalidated YAML on a tool-argument surface; source-established, impact unverified.** The planner digest withholds `example_use` because it is YAML, not validated against the live catalog, and not the `set_pipeline` shape ([planner_authoring_aids.py:1743](../../../../src/elspeth/web/composer/planner_authoring_aids.py#L1743)); this listing returns it unlabelled. N2 shows one case where the example contradicts tool placement.

**list_sources-N5 — stale redaction rationale; source-established.** The MANIFEST reason ([redaction.py:2609](../../../../src/elspeth/web/composer/redaction.py#L2609)) cites a nonexistent `tools.py:604` and describes the response as import-time registry metadata. It is actually per-request and principal-scoped (snapshot filter, profile projection whose `example_use` embeds a usable alias). The aliases are model-visible by design in the catalog context, so no leak is claimed; the rationale an auditor reads is inaccurate.

**list_sources-N6 — redundant whole-state validation per call; source-established, impact unmeasured.** `_discovery_result` calls `state.validate()` ([_common.py:1279](../../../../src/elspeth/web/composer/tools/_common.py#L1279)); on every dispatch route that summary is replaced by `normalize_tool_result_validation` ([_common.py:3800](../../../../src/elspeth/web/composer/tools/_common.py#L3800)), and the cache-hit rebuild does the same ([discovery_cache.py:101](../../../../src/elspeth/web/composer/discovery_cache.py#L101)). It applies to every `_discovery_result` tool.

## 6. Structural remediation

Keep authoritative configuration and capability declarations on source plugins, policy visibility in the policy layer, and capability selection in the orchestrator. If capability planning needs repairable absences, add a deliberately bounded availability query/report rather than bypassing policy or making each list disclose private bindings. All three inventory tools, schema/assistance lookup and mutation failures must share the same snapshot and closed reason vocabulary.

Resolve N1 by an explicit decision. Either (a) categorical web-surface bans are a live concept, in which case the snapshot builder needs a real producer and a test that drives `build_plugin_snapshot` (not a hand-built snapshot) to emit WEB_SURFACE_PROHIBITED; or (b) they are retired, in which case the description, skill block, digest section, advisor field and detail-code set stop promising them. Under (b), keep the `prohibited` key as a versioned or additive compatibility field, always empty, until decoders and recorded replay fixtures move.

Resolve N2 at the catalog projection ([catalog/service.py:389](../../../../src/elspeth/web/catalog/service.py#L389)) and the profile projection, not in the model: summaries should say where each field is authored (top-level tool argument, plugin option, or resolver/server-owned with the owning tool). The `set_source` refusal for a misplaced failure choice should name the correct argument.

Acceptance: a selectable plugin appears with plugin-owned defaults; under decision (a), a banned plugin appears only under prohibited from a real snapshot; under (b), no surface advertises a prohibited channel; a missing local prerequisite is reported through the authorised availability surface without exposing secret values; cache reuse cannot transplant another principal's snapshot (already structurally true: the cache and the policy view are both per compose call); a listed field marked as a top-level argument is refused with a placement-naming message when supplied in `options`. Compatibility: preserve available/prohibited keys and make additional availability or placement evidence explicitly versioned or additive. Implementation risk medium because disclosure and cache scope are security boundaries.
