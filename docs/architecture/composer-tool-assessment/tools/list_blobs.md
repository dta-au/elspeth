# `list_blobs` — session artifact inventory

Assessment baseline: `3b28d537be98234da8135c418bf185a998c18b68` (0.8.9). Reconnaissance and design; no production change. **Overall confidence: High for the traced contracts and reproduced findings.** Sheet review 2026-11-09 re-checked every anchor and added the route inventory (§3.1), guidance parity (§5.1) and simple enhancements (§6.1); nothing has been implemented. Probe runs on 2026-11-09 (§7.1) re-confirmed BOS-01 and demonstrated list_blobs-N1, N4 (SQLite) and N5.

## 1. Purpose and usage

Select this tool to discover files uploaded, created by the assistant, or produced by a pipeline in the current web session. It answers identity, lifecycle, size, and origin questions before metadata lookup, reading, source binding, or destructive operations. It does not inspect content or certify readiness: pending/error entries remain visible. It does not return `content_hash`; use [`list_composer_blobs`](list_composer_blobs.md) (ready rows only) or `get_blob_metadata` when a pinned hash is needed. Requires the server-owned session engine and session ID. It is available on the web Composer surface; Composer MCP intentionally excludes blob tools because it has no web session database.

## 2. Contract

Arguments are exactly `{}`; extra fields are rejected. The successful `data` is a bare list of entries containing `id`, `filename`, `mime_type`, `size_bytes`, `created_by`, `creation_modality`, and `status`, ordered by `created_at` descending ([query](../../../../src/elspeth/web/composer/tools/blobs.py#L538)) with no tie-breaker, so the relative order of rows with equal `created_at` is unspecified. Storage paths, descriptions, content hashes, content bytes, and detailed LLM provenance are excluded. The underlying query returns at most 50 rows of **any** status, so pending pipeline outputs and error rows count against the same window as uploads. There is no cursor, count, truncation flag, or continuation argument. Vocabularies are closed: `status` ∈ `ready`/`pending`/`error`, `created_by` ∈ `user`/`assistant`/`pipeline` ([contracts](../../../../src/elspeth/contracts/blobs.py#L77)). A pending pipeline-output reservation always reports `size_bytes` 0 until finalized ([reservation guard](../../../../src/elspeth/web/coordination/repository.py#L2600)). Session-fork copies are stamped with the copy time and `creation_modality="verbatim"` ([persist](../../../../src/elspeth/web/blobs/service.py#L1580), [fork copy](../../../../src/elspeth/web/blobs/service.py#L4125)), so in a forked session "newest first" means most recently written in this session and an LLM-generated parent blob reads as verbatim (the fork-writer defect documented at [blobs.py#L440](../../../../src/elspeth/web/composer/tools/blobs.py#L440)).

This is `BLOB_DISCOVERY`, with a selected producer response contract and no declared authored effects (measured: `resolve_tool_effects("list_blobs", {})` → `ToolEffects(domains=())`). It leaves composition version unchanged, performs a fresh metadata read on every invocation, is not eligible for the per-compose discovery cache (measured `cacheable=False`; the [declaration invariant](../../../../src/elspeth/web/composer/tools/declarations.py#L222) forbids caching any non-`DISCOVERY` kind), and does not require mutation approval. The read uses a plain `engine.connect()` with no session-operation fence. Missing session context returns a failed `ToolResult` with no `error_code` (the generic [`_failure_result`](../../../../src/elspeth/web/composer/tools/_common.py#L1399) frames it as a `rejected_mutation` validation entry). Malformed arguments raise a safe `ToolArgumentError`: on public routes the declared schema check raises first; for direct callers the handler's own [`EmptyToolArgumentsModel`](../../../../src/elspeth/web/composer/tools/_common.py#L134) admission still raises. Invalid owned row literals raise `AuditIntegrityError` from [`_guard_blob_row_literals`](../../../../src/elspeth/web/blobs/service.py#L2200), and malformed producer output raises `FrameworkBugError` from the [inventory parser](../../../../src/elspeth/web/composer/tools/blobs.py#L295). Neither is coercible external input. Recognized credentials anywhere in the listed metadata cause a fixed refusal of the whole result (`error_code="credential_material_rejected"`) rather than partial disclosure. There is no transaction spanning this observation and a subsequent bind/update; later tools recheck their own preconditions. Repeating the read has no authored effect, although results can change as artifacts arrive.

## 3. Implementation trace

The [handler](../../../../src/elspeth/web/composer/tools/blobs.py#L587) and [declaration](../../../../src/elspeth/web/composer/tools/blobs.py#L604) are exported through [`TOOLS_IN_MODULE`](../../../../src/elspeth/web/composer/tools/blobs.py#L2287), aggregated into [`_REGISTERED_TOOLS`](../../../../src/elspeth/web/composer/tools/_registry.py#L94), mapped into the [`BLOB_DISCOVERY` handler table](../../../../src/elspeth/web/composer/tools/_registry.py#L149), and emitted by [`get_tool_definitions`](../../../../src/elspeth/web/composer/tools/_dispatch.py#L311). [Public dispatch](../../../../src/elspeth/web/composer/tools/_dispatch.py#L795) checks argument credential material, matching plugin snapshot, schema and context, then invokes the handler. [`_sync_list_blobs`](../../../../src/elspeth/web/composer/tools/blobs.py#L534) performs the scoped SQL query; the [row loader](../../../../src/elspeth/web/composer/tools/blobs.py#L472) validates owned metadata. The tool does not use the blob service: [`BlobServiceImpl.list_blobs`](../../../../src/elspeth/web/blobs/service.py#L2855) already takes `limit`/`offset` with the same ordering, and the [REST route](../../../../src/elspeth/web/blobs/routes.py#L361) exposes `limit` 1–500 and `offset`. The tool re-implements a fixed-50 query instead.

The web worker executes the synchronous operation off the event loop. [Audit finalization](../../../../src/elspeth/web/composer/audit.py#L812) records dispatch status and the semantic result separately: audit `SUCCESS` alone does not mean `ToolResult.success=true`. The [tool ribbon](../../../../src/elspeth/web/frontend/src/components/chat/ToolCallCard.tsx#L84) consumes server-derived outcomes. The [MCP allowlist](../../../../src/elspeth/composer_mcp/server.py#L117) omits this tool.

## 4. Alternative paths

An empty authorized session succeeds with `[]`. A session with pending pipeline outputs includes them (with `size_bytes` 0), so the orchestrator must inspect `status` before selecting a read/bind action. The SQL `WHERE session_id = …` excludes other sessions' rows and missing context fails, but no tool-level test pins either property for this tool (§7). Credential-bearing legacy filenames refuse the entire result; the tool does not redact one entry and call the inventory complete. The refusal text, however, is the generic argument advice ("Store the value through the secret service and use a secret reference", [`CREDENTIAL_REFUSAL_DETAIL`](../../../../src/elspeth/contracts/credential_material.py#L24)), which the model cannot act on for a stored filename. No entry is identified and no tool can remove it. The refusal persists while the offending row is among the 50 newest. Database or owned-data faults propagate through the audited crash path. Recovery consists of correcting context or resolving the actual storage/integrity fault; there is no automatic content recovery in this metadata query.

## 5. Usability assessment

**BOS-01 — demonstrated defect, High confidence:** after 51 ready artifacts, both the ordinary and inline inventories succeed with 50 entries and silently omit the oldest artifact. Controlled 1-row and 50-row cases returned every row; a live SQL count of 51 accompanied a 50-entry result, with no completeness field. Re-confirmed on this branch by re-running the evidence probe unchanged (§7.1, P5). An orchestrator cannot distinguish "the requested attachment is absent" from "it is beyond the hidden window." Repeating the same call cannot recover it. If the exact original ID is already known, metadata lookup and binding remain possible. Otherwise the user's own file panel does not help either: it reads the same newest-50 window (list_blobs-N7), so recovery needs the paged REST API or operator database access. This is a discovery contract defect, not an authorization defect or evidence of data loss. Because pending/error rows and pipeline outputs share the window, repeated runs push the oldest rows out first. Those are often the user's original uploads. How often real sessions exceed 50 rows is unmeasured.

**list_blobs-N1 — demonstrated planner amplification of BOS-01 (SQLite, scripted provider), High confidence:** on the planner route a successful call closes manifest key `blob.index.session` through [`with_result`](../../../../src/elspeth/web/composer/pipeline_planner.py#L294) without reading the data. Only `list_models` gets a completeness-aware key ([`_resolved_discovery_information_keys`](../../../../src/elspeth/web/composer/pipeline_planner.py#L515)). Once every pending key is supplied, the loop injects ["All declared information gaps are closed; emit the terminal proposal now."](../../../../src/elspeth/web/composer/pipeline_planner.py#L5133). That can follow a truncated 50-row result. Introspection measured `supplies("blob.index.session") is True` after `with_result(("blob.index.session",), available=True)`. A planner-loop run then showed it end to end (§7.1, P1): with 51 stored rows, the planner's `list_blobs` result had `success=true`, 50 entries, the oldest row absent and no completeness field, and the very next message was the gaps-closed notice. This held under both the information-aware and the full discovery policy. A 1-row inventory fired the same notice. A failed `list_blobs` (no session context) did not, so the notice depends on success and not on completeness. The manifest's `covers()` has no production caller, so a re-call is not refused, only futile. [`test_blob_discovery_information_is_operation_specific_and_order_sensitive`](../../../../tests/unit/web/composer/test_pipeline_planner.py#L1743) pins the data-independent closure.

**list_blobs-N2 — source-established guidance dead end:** the `inline_source_comparison_incomplete` refusal fires only when more than 50 ready, user-created, larger CSV candidates exist ([scan](../../../../src/elspeth/web/composer/tools/sources.py#L1839), [limit](../../../../src/elspeth/web/composer/tools/sources.py#L116)). Both its message and its [repair guidance](../../../../src/elspeth/web/composer/tools/generation.py#L1831) tell the model to "identify the intended input through list_blobs". In that state the session holds at least 51 blobs, so at least one candidate cannot appear in the 50-row result.

**list_blobs-N3 — source-established duplicated authority:** the tool's fixed-window SQL duplicates the service's paged query (§3) instead of calling it. The limit, ordering and filter live in [three places](../../../../src/elspeth/web/composer/tools/blobs.py#L534) (with [L559](../../../../src/elspeth/web/composer/tools/blobs.py#L559) and [service L2855](../../../../src/elspeth/web/blobs/service.py#L2855)), which is the concrete site of the remediation plan's "duplicated fixed-window queries".

**list_blobs-N4 — demonstrated on SQLite (boundary membership), limitation:** ordering by `created_at` alone is not total. On SQLite (§7.1, P2), three rows with one timestamp came back in insertion order, not `id` order: the same ids inserted in reverse came back reversed. With 52 rows whose three oldest share a timestamp, which tied row survived into the 50-row window was decided by insertion order (a different row in each case). Repeated calls on one SQLite database returned the same order, so reordering *between calls* was not observed; PostgreSQL was not run. Any future cursor must key on `(created_at, id)`, and that order differs from today's tie order. How often ties occur is unmeasured.

**list_blobs-N5 — demonstrated refusal mismatch (SQLite):** the stored-metadata credential refusal (§4) reuses `credential_material_rejected` and argument-oriented advice. It does not tell the model that it did not author the offending value, that it cannot repair it, or what to tell the user. A run with one stored `sk-…` filename and one ordinary row (§7.1, P4) returned `success=false` with `data` null, which withholds the ordinary row too. The code was `credential_material_rejected` and the message was exactly `CREDENTIAL_REFUSAL_DETAIL` ("This control content appears to contain a credential. Store the value through the secret service and use a secret reference."). No entry was named. After 50 newer rows were inserted the refusal disappeared and 50 entries returned, so the refusal lasts exactly as long as the row is in the window. Whether any current writer can still store such a filename is **unverified**: upload routes guard filenames ([routes.py#L163](../../../../src/elspeth/web/blobs/routes.py#L163), [#L295](../../../../src/elspeth/web/blobs/routes.py#L295)), while pipeline-output filenames were not traced.

**list_blobs-N6 — source-established, low:** the missing-context failure carries no `error_code`, unlike the secret tools' `secret_context_unavailable` ([dispatch](../../../../src/elspeth/web/composer/tools/_dispatch.py#L1029)). Production wiring always supplies the engine ([app.py#L2306](../../../../src/elspeth/web/app.py#L2306)), so only direct callers reach it.

**list_blobs-N7 — source-established, cross-cutting:** the user's file panel calls REST without `limit`/`offset` ([client](../../../../src/elspeth/web/frontend/src/api/client.ts#L1573), [store](../../../../src/elspeth/web/frontend/src/stores/blobStore.ts#L99)), whose default is 50 ([routes.py#L365](../../../../src/elspeth/web/blobs/routes.py#L365)). `BlobManager.tsx` has no paging (grep for `limit|offset|page|more` matched nothing; the same file matches `blobs` 9 times). The function's own comment says "List all blobs". Not exercised in a browser: the probe (§7.1, P3) needs a browser and a running server, so it was not runnable here.

**list_blobs-N8 — source-established accuracy limit inherited from the fork writer:** after a fork, `creation_modality` reads `verbatim` for parent blobs that were LLM-generated (§2). The inline comment at [L547](../../../../src/elspeth/web/composer/tools/blobs.py#L547) says the pair answers "who authored these bytes", which is not true for forked rows. The owner is `copy_blobs_for_fork`, not this read path.

## 6. Structural remediation

Invariant: capability/resource discovery must state whether it is complete and provide a bounded route to remaining authorized entries. Ownership belongs to the blob inventory service and shared tool response contract, with orchestrator support for continuation. Replace duplicated fixed-window queries (list_blobs-N3) with a session-scoped inventory page abstraction built on the service's existing `limit`/`offset` query, with a total order (`created_at DESC, id DESC`, list_blobs-N4) and an opaque cursor. Preserve the ordinary inventory's lifecycle/origin fields and the inline inventory's narrower visibility rules. The planner manifest must close `blob.index.session` only on a complete observation, as it already does for `list_models` (list_blobs-N1). Do not solve the defect by removing the bound.

Acceptance: 0, 1, 50, 51, and larger inventories enumerate every authorized row exactly once; pending rows obey each projection's filter; cross-session or forged cursors are rejected; insertions around page boundaries have specified snapshot/continuation semantics; equal-timestamp rows page deterministically; serializers cannot drop `has_more` or equivalent evidence; a truncated first page does not close the planner's `blob.index.session` key. Compatibility risk is Medium because the current successful root is a bare list: introduce a versioned envelope or an explicit new paginated tool and migrate model guidance, the planner manifest and the file panel deliberately. A description warning about the latest-50 limit is temporary containment only.

### 6.1 Simple enhancements

Bounded, non-architectural fixes, distinct from the continuation contract above.

1. **Disclose the window and status semantics in the declaration.** Where: [description](../../../../src/elspeth/web/composer/tools/blobs.py#L609). What: say "at most the 50 most recently created entries, newest first, of any status"; that older entries are not listed and a known `blob_id` still works with `get_blob_metadata`; that pending entries are reserved/in-progress with `size_bytes` 0; and that `content_hash` comes from `list_composer_blobs`/`get_blob_metadata`. Why: the model currently has no way to know absence may be false. Acceptance: the description-parity/teaching gates pass and the text names the bound literally.
2. **Do not close the planner gap on an unbounded-unknown inventory.** Where: [`_resolved_discovery_information_keys`](../../../../src/elspeth/web/composer/pipeline_planner.py#L515). What: until the response carries completeness, do not let `blob.index.session` (and `blob.index.composer`) satisfy the gaps-closed notice when the result length equals the window. Acceptance: a planner unit test with a 50-row stub result does not inject `_ALL_INFORMATION_GAPS_CLOSED_NOTICE`; a 49-row stub still does.
3. **Remove the dead-end repair route.** Where: [`sources.py#L1844`](../../../../src/elspeth/web/composer/tools/sources.py#L1844), [`generation.py#L1831`](../../../../src/elspeth/web/composer/tools/generation.py#L1831). What: for `inline_source_comparison_incomplete`, tell the model to ask the user to name or select the intended upload (or use a `blob_id` already in the transcript) rather than "identify through list_blobs". Acceptance: the guidance test for that code asserts no `list_blobs` instruction while the window exists.
4. **Total order.** Where: [L538](../../../../src/elspeth/web/composer/tools/blobs.py#L538), [L566](../../../../src/elspeth/web/composer/tools/blobs.py#L566). What: add `blobs_table.c.id.desc()` as a tie-breaker. Acceptance: a test inserting rows with identical `created_at` gets the same order on repeated calls.
5. **Actionable stored-metadata credential refusal.** Where: [`_credential_safe_blob_discovery_result`](../../../../src/elspeth/web/composer/tools/blobs.py#L121). What: a distinct `error_code` (e.g. `stored_blob_metadata_credential_refused`) and text stating that a stored file record, not the model's input, matched, and that the user/operator must rename or remove it.
