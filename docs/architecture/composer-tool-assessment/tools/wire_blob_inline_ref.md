# `wire_blob_inline_ref` — pin artifact content into plugin options

Assessment baseline: `3b28d537be98234da8135c418bf185a998c18b68` (0.8.9). Reconnaissance only. **Overall confidence: High for source and focused tests; Moderate for broad plugin compatibility beyond exercised cases.** The review pass added in-memory handler/dispatch probes (SQLite `:memory:` session database and the test module's minimal catalog; listed in §7). The probe pass (§7.1) then re-ran them under the real plugin catalog and drove real `ComposerServiceImpl.compose` turns (scripted provider, real catalog) in explicit-approve and auto-commit mode, plus the proposal accept route. Nothing here has been implemented.

## 1. Purpose and usage

Use this tool when an existing authorized artifact should supply text to a plugin configuration option at runtime without copying bytes into the tool arguments. The documented cases are a `reference_join` table and a user-uploaded LLM prompt ([skill](../../../../src/elspeth/web/composer/skills/pipeline_composer.md#L663)). It authors an `inline_content` marker pinned to authoritative blob metadata. Use source-binding tools instead when the artifact is the pipeline's source input. The destination component must already exist. Session engine/ID and a current ready blob are required; execution later needs the ordinary blob/content authority. This tool is absent from Composer MCP and from the planner palette (§3.1).

## 2. Contract

Required `field_path: string` and `blob_id: UUID string`; optional `encoding` defaults to `utf-8`, with allowed `utf-8`, `utf-8-sig`, `latin-1`, and `utf-16` ([argument model](../../../../src/elspeth/web/composer/tools/blobs.py#L139)). An unknown encoding or an extra argument raises `ToolArgumentError` (an argument error, not a failed result). Canonical paths are `source.options.<field>`, `source:<name>.options.<field>`, `node:<id>.options.<field>`, or `output:<name>.options.<field>`. Every segment after `.options` must match `[A-Za-z_][A-Za-z0-9_-]*`, and component names may not contain `.`, `[` or `]` ([grammar](../../../../src/elspeth/contracts/blobs_inline.py#L37)). List elements and option keys outside that grammar cannot be addressed. Nested object paths are supported. An existing *scalar* at an intermediate segment is refused rather than coerced into an object ([`_set_nested_option`](../../../../src/elspeth/web/composer/tools/blobs.py#L717)). Two cases are not refused (both demonstrated, §5). An existing non-scalar *leaf* (for example a `schema` object) is replaced wholesale. An existing marker at an intermediate segment is descended into as an ordinary object. Nodes whose type is not `transform`, `aggregation`, or `collector`, or which have no plugin, cannot be targets ([L782](../../../../src/elspeth/web/composer/tools/blobs.py#L782)).

Success increments composition version once per call ([source](../../../../src/elspeth/web/composer/state.py#L8221), [node](../../../../src/elspeth/web/composer/tools/blobs.py#L807), [output](../../../../src/elspeth/web/composer/tools/blobs.py#L828)). It returns `data.field_path`, affected component IDs, validation, `validation_delta`, and the applied-component projection. The marker contains canonical `blob_ref`, `mode="inline_content"`, server-pinned `sha256`, and a nondefault encoding if needed ([L1053](../../../../src/elspeth/web/composer/tools/blobs.py#L1053)). Non-canonical UUID spellings are accepted and stored canonically ([L1020](../../../../src/elspeth/web/composer/tools/blobs.py#L1020)), so the direct handler does not inherit BOS-03. A caller-provided hash is not admitted. This is a graph-affecting `BLOB_MUTATION`, not blob-store-only ([effects](../../../../src/elspeth/web/composer/tools/declarations.py#L188)). Explicit approval applies in that session mode (with the gaps in §3.1 and §5), and no cache is used. Repeating the same wiring increments version again (demonstrated 2→3); there is no semantic no-op/idempotency contract.

Runtime-owned fields, source binding metadata, and interpretation-review metadata cannot be overwritten through paths. These checks apply only to the first segment after `.options` (`keys[0]`). LLM-generated artifacts cannot bypass prompt/model reviews by occupying an LLM prompt surface. The guarded roots are `prompt_template`, `system_prompt`, `model` and `queries` templates on `llm` *nodes* ([domain](../../../../src/elspeth/web/execution/_validation_materialization.py#L178)). Missing/not-ready blobs, missing components, illegal paths, policy errors, and reconciliation errors refuse the edit while preserving prior state. Only the interpretation and review-reconciliation refusals carry an `error_code`. Missing blob, not-ready blob, missing component, missing session context, path and endpoint-policy refusals have `error_code=None` (demonstrated for missing node and missing blob). A ready blob with null hash raises `AuditIntegrityError` ([L1032](../../../../src/elspeth/web/composer/tools/blobs.py#L1032)). Wiring metadata does not certify that bytes decode, fit the 256 KiB per-ref cap, that the blob's MIME type is text, or that the resulting plugin configuration is runnable. The handler never checks `mime_type`: a PNG or PDF blob wires successfully, and validation then crashes on it in some cases (N9). Validation/preflight remains authoritative.

## 3. Implementation trace

The [handler](../../../../src/elspeth/web/composer/tools/blobs.py#L1004) (declaration at [L1104](../../../../src/elspeth/web/composer/tools/blobs.py#L1104)) admits `WireBlobInlineRefArgumentsModel`, canonicalizes the UUID, and queries same-session metadata ([`_sync_get_blob`](../../../../src/elspeth/web/composer/tools/blobs.py#L499)). It builds the owned `BlobInlineRef` (which applies the path grammar) and runs the [prompt-surface admission](../../../../src/elspeth/web/composer/tools/blobs.py#L890) against the *prior* state. It then applies [`_apply_inline_blob_marker`](../../../../src/elspeth/web/composer/tools/blobs.py#L735) and, before returning the candidate, runs a canonical interpretation check ([L1065](../../../../src/elspeth/web/composer/tools/blobs.py#L1065)), source/output endpoint policy ([L1075](../../../../src/elspeth/web/composer/tools/blobs.py#L1075)), authoritative review reconciliation ([L1084](../../../../src/elspeth/web/composer/tools/blobs.py#L1084)) and a second canonical check ([L1091](../../../../src/elspeth/web/composer/tools/blobs.py#L1091)). The dispatcher repeats the canonical check a third time ([gate](../../../../src/elspeth/web/composer/tools/_dispatch.py#L772)). The handler does not call plugin-option prevalidation, and the declaration does not set `augments_on_failure`, so failures carry no `plugin_schemas`.

The declaration is listed in the module's [`TOOLS_IN_MODULE`](../../../../src/elspeth/web/composer/tools/blobs.py#L2287) and aggregated by the [registry](../../../../src/elspeth/web/composer/tools/_registry.py#L94). The registry resolves graph effects from the declaration kind ([`resolve_tool_effects`](../../../../src/elspeth/web/composer/tools/_registry.py#L127)). [Model definitions](../../../../src/elspeth/web/composer/tools/_dispatch.py#L311) and provider wire projection expose the argument contract. [Dispatch finalization](../../../../src/elspeth/web/composer/tools/_dispatch.py#L752) revalidates against the request's policy snapshot and adds delta/guidance. The [tool-batch approval decision](../../../../src/elspeth/web/composer/tool_batch.py#L1728) controls proposal versus apply. [Audit](../../../../src/elspeth/web/composer/audit.py#L812) records the outcome, and the frontend presents it ([tooltip](../../../../src/elspeth/web/frontend/src/components/chat/toolCallDescriptions.ts#L92), [card outcome](../../../../src/elspeth/web/frontend/src/components/chat/ToolCallCard.tsx#L84)). Runtime resolution belongs to the marker walker in [`core/blobs_inline.py`](../../../../src/elspeth/core/blobs_inline.py#L578) and to [validation materialization](../../../../src/elspeth/web/execution/_validation_materialization.py#L267) (size caps [L63](../../../../src/elspeth/core/blobs_inline.py#L63); oversized [L497](../../../../src/elspeth/web/execution/_validation_materialization.py#L497)), not to this writer.

## 4. Alternative paths

An uploaded or otherwise eligible artifact can wire a normal option. A missing node, scalar intermediate path, unsupported encoding, non-ready artifact, or forbidden owned field is rejected. A valid metadata marker can still fail later because bytes changed, decoding fails, the blob exceeds the inline caps, or the plugin rejects the resolved value. A binary-MIME blob whose bytes happen to decode does not fail cleanly: validation raises an untyped `ValueError` (N9). A malformed marker that this tool itself produced (N1) also fails later. Edits to reviewed options reopen or refuse incompatible review evidence; they do not silently retain stale approvals. Source aliases and plural source names resolve by their explicit identities rather than choosing an arbitrary source. A blob from another session is reported as "not found", the same as a nonexistent ID ([session filter](../../../../src/elspeth/web/composer/tools/blobs.py#L503); source-established, no test).

## 5. Usability assessment

**Source-established limitation:** this tool's generic path interface accepts prospective references while plugin-specific value validation is deferred. A successful wire is an accepted authoring operation, not proof of runtime readiness. The direct handler is careful about ownership/review rules, but those rules are distributed across path parsing, modality checks, canonical interpretation checks, dispatch validation, and runtime dereference. As a result the orchestrator depends on several later diagnostics to understand one apparent edit. Workaround: inspect the returned applied component and validation, then request preview; do not claim completion from the wire result alone.

The prompt-surface and resolver-owned-field refusals are **intended restrictions**, backed by tests. No prompt-review bypass or stale-review defect was demonstrated in this lane. The findings below are of a different class.

**wire_blob_inline_ref-N1 — demonstrated defect (in-memory dispatch under both the minimal and the real plugin catalog, and an auto-commit compose turn; §7.1), High confidence: the tool can write a reserved blob-identity key and break later blob-tool calls in the session.** The leaf key is never checked against the blob-reference vocabulary. Wiring `node:classify.options.extra.blob_ref`, `node:classify.options.blob_id` or `output:classified.options.reference_blob_id` each succeeded with `validation.is_valid=True`, under the real catalog as well (probe 2). The `llm` plugin schema itself rejects `extra` and `blob_id` as `plugin_options_invalid` ("Extra inputs are not permitted") when the same keys are written through `patch_node_options`. So the wire also bypasses plugin-option prevalidation: it writes keys that no `llm` configuration may hold, and reports the state valid. Each stored a marker *object* under a key that every walker reads as an identity string. Afterwards, `delete_blob` of an **unrelated** blob raised `AuditIntegrityError("… has a non-str blob_ref … CompositionState integrity anomaly")` from the composer retention walker ([L1300](../../../../src/elspeth/web/composer/tools/blobs.py#L1300)). That walker's docstring says this shape "cannot arise from any valid authoring path". The control (an ordinary `prompt_template` wire, then delete of an unrelated blob) succeeded. `update_blob` uses the same guard ([L1741](../../../../src/elspeth/web/composer/tools/blobs.py#L1741)), and the probe's update attempt stopped earlier at provenance admission, so this is source-established for update. Inside a compose turn, `AuditIntegrityError` is re-raised as a fatal tool failure ([service](../../../../src/elspeth/web/composer/service.py#L2763)). Probe 3 demonstrated this in an auto-commit turn with the real catalog. Turn 1 wired `extra.blob_ref` (`success=True`, `is_valid=True`). Turn 2, a `delete_blob` of an unrelated ready blob, made `compose()` raise `ComposerToolFailure` caused by `AuditIntegrityError("Node 'classify' has a non-str blob_ref …")`. The unrelated blob stayed `ready`, and the model never got a tool result for the delete. Before the crash, the wired state had already been written as the session's durable head (`composition_states` row with `extra` and the marker). A second, fresh `compose()` started from that head and asked to delete a third blob. It raised the same `ComposerToolFailure`/`AuditIntegrityError`, and the third blob stayed `ready`. In the control (`prompt_template` wire, then the same delete; then the fresh second turn), both deletes succeeded and both turns returned normally. Every later composer `update_blob`/`delete_blob` in that session therefore fails the turn until the key is removed: demonstrated for `delete_blob` across two `compose()` calls, source-established for `update_blob`. The REST/service walkers treat a non-str id as a non-match and descend into the object ([service](../../../../src/elspeth/web/blobs/service.py#L2066), [repository](../../../../src/elspeth/web/coordination/repository.py#L416)), so user-initiated deletes are not crashed. The walkers diverge. Runtime materialization later reports the key as `malformed: missing mode` (demonstrated with `_discover_blob_content_refs`). No shipped plugin option was found named `blob_ref`/`blob_id` or ending in `_blob_id`. The instruments were `grep -rn "_blob_id\b" src/elspeth/plugins`, whose only hit is a validator name in `blob_rows.py:66`, and `grep -rn blob_ref src/elspeth/plugins`, whose only option is `blob_csv_expand.blob_ref_field`, a column name that is not a reserved key. The control `grep -rln inline_content src/elspeth/plugins` matches `reference_join.py`. The trigger is therefore a mis-targeted LLM path, not a schema-following one. A `reference_join` table literally named `blob_ref` or `blob_id` would also trigger it.

**wire_blob_inline_ref-N8 — demonstrated defect (in-memory dispatch), Medium; same root cause as N1: an existing marker is traversed as an ordinary object.** After a valid wire at `prompt_template`, wiring `node:classify.options.prompt_template.sha256` succeeded (`is_valid=True`) and nested a whole marker inside the old marker's `sha256`. The runtime walker then reported `invalid blob_ref marker` for that field. This is the same late-detection chain as N1, and [`_set_nested_option`](../../../../src/elspeth/web/composer/tools/blobs.py#L724) is the cause: it checks only `Mapping`-ness.

**wire_blob_inline_ref-N9 — demonstrated defect (by the `list_composer_blobs` probe pass, not re-run here), High: a binary-MIME blob wires successfully, and validation then crashes on it with an untyped `ValueError`.** This is the same defect as [`list_composer_blobs`](list_composer_blobs.md)-N8. The handler checks the blob's `status`, `content_hash` and `creation_modality` but never its `mime_type`. In that lane's probes P2/P3, ready `image/png` and `application/pdf` blobs wired with `success=True`, both with the default encoding and with `encoding: "latin-1"`. Its probe P2b then fed such markers to `validate_pipeline_for_trained_operator`, with injected blob metadata/content and downstream build steps patched. PNG, and PDF containing high bytes, under `utf-8` gave a structured `malformed_inline_blob_content`. An ASCII-only PDF under `utf-8`, and any PNG/PDF under `latin-1`, decoded successfully and then raised `ValueError("ResolvedBlobContent: mime_type must be one of [...]")`. The raise comes from [`ResolvedBlobContent.__post_init__`](../../../../src/elspeth/contracts/blobs_inline.py#L123), which is constructed [after the decode](../../../../src/elspeth/core/blobs_inline.py#L372). The validation phase catches only `BlobContentResolutionError` ([catch](../../../../src/elspeth/web/execution/_validation_materialization.py#L536)). `latin-1` decodes every byte sequence, so this tool's own `encoding` enum is enough to reach the crash with any binary upload. Not measured: how the composer's preflight caller or the REST validate route surfaces the exception, and whether the run-admission resolver (which builds the same object) also crashes.

**wire_blob_inline_ref-N2 — demonstrated route defect (compose turn + accept route, §7.1 probe 1), Medium: in explicit-approve mode the agent never sees this tool's semantic refusals.** In probe 1, a wire to `node:nope.options.x` created one pending proposal. The model received `success=true`, `status=APPROVAL_REQUIRED`, with the same status, message and (empty) errors as the valid control wire; only the `proposal_id` differed. At accept, the same proposal returned **422** `proposal_validation_failed` ("Node 'nope' not found in composition state") and was auto-rejected. The structurally valid control proposal returned 200 `committed`. The same seeded `llm` node drew a restricted-policy finding in the missing-node arm's 422 body, so the control was structurally valid but not policy-clean. The pre-proposal preview runs only for `MUTATION`-kind tools ([L2057](../../../../src/elspeth/web/composer/tool_batch.py#L2057); `_MUTATION_TOOLS` is the MUTATION-kind map, [import](../../../../src/elspeth/web/composer/tool_batch.py#L161)). Even for those tools a failed preview still creates the proposal ([L2127](../../../../src/elspeth/web/composer/tool_batch.py#L2127)). The following therefore each return `APPROVAL_REQUIRED` with `success=True` to the agent: a wire to a missing node, an LLM-authored blob on an LLM prompt surface, a structural node, or a forbidden owned root. The refusal reaches only the user, as a 422 auto-reject at accept ([L563](../../../../src/elspeth/web/sessions/routes/composer/proposals.py#L563)). The no-preview half also affects `set_source_from_blob(s)` and `wire_secret_ref`; the preview-failure-still-proposes half affects every incremental mutation tool.

**wire_blob_inline_ref-N3 — demonstrated defect (compose turn, §7.1 probe 1), Medium–High: in explicit-approve mode, `blob_id` admission differs between the handler and proposal creation (a BOS-03 extension), and any blob id that proposal creation rejects aborts the whole turn.** The handler accepted an uppercase ID and stored it canonically (in-memory dispatch). `validate_proposal_blob_references` compares the raw text and raised `ValueError("… does not exist")` for both uppercase and hyphenless spellings of a ready blob. The canonical spelling passed (in-memory, against the real session schema). The same validator raises for missing, other-session and not-ready blobs, which in auto-commit mode would be ordinary failed results. In the tool batch, `create_composition_proposal` is wrapped only for cancellation ([L931](../../../../src/elspeth/web/composer/tool_batch.py#L931)). The surrounding compose-loop handler does not list `ValueError` ([service](../../../../src/elspeth/web/composer/service.py#L2755)), so the error is not converted into a tool result. Probe 1 confirmed this in a real explicit-approve compose turn. For an uppercase id, a hyphenless id and a nonexistent canonical id, `compose()` raised a bare `ValueError("Proposal references blob '…', but that blob does not exist")`. That left 0 proposal rows and 0 tool-message rows, and the provider was called once, so the model never saw a result. The canonical-id control created one pending proposal. The missing-blob arm shows that the crash is not limited to non-canonical spellings: a mistyped or hallucinated id, which auto-commit reports as an ordinary `Blob '…' not found.`, kills the explicit-approve turn. Other-session and not-ready ids take the same validator branch (source). HTTP shape (source-traced, not run): the freeform turn runner's `except` list after `compose()` ([composer_turn](../../../../src/elspeth/web/sessions/composer_turn.py#L1550), L1550–L1844) names no `ValueError` or bare `Exception`, so the error leaves the turn runner untyped.

**wire_blob_inline_ref-N4 — demonstrated defect, Low–Medium: batch-dependency refusal never recognizes this tool.** [`referenced_resources`](../../../../src/elspeth/web/composer/batch_dependencies.py#L115) reads `target`/`target_id`, but this tool's arguments are `field_path`/`blob_id`/`encoding`. A wire into `node:join.options.reference_content` returned `frozenset()`, and `has_unavailable_prerequisite` returned `False` with `("node","join")` refused. The `wire_secret_ref` control returned `{("node","join")}`/`True`. If a same-batch `upsert_node join` was refused, the dependent wire gets the generic `Node 'join' not found in composition state` (no `error_code`) instead of `batch_dependency_refused` with its repair instruction. No state is corrupted. The [projection test](../../../../tests/unit/web/composer/test_dependent_batch_refusal.py#L292) parametrizes `wire_secret_ref` but not this tool. A stale eval fixture uses the same nonexistent `target` argument ([fixture](../../../../tests/unit/evals/composer_battery/test_battery_score.py#L197)).

**wire_blob_inline_ref-N5 — demonstrated result-shape gap, Low: most refusals carry no `error_code`.** Missing node → `Node 'nope' not found in composition state`, `error_code=None`. Missing blob → `Blob '<id>' not found.`, `error_code=None`. Not-ready, missing source/output, illegal path and endpoint-policy refusals are built the same way ([L1027](../../../../src/elspeth/web/composer/tools/blobs.py#L1027), [L1029](../../../../src/elspeth/web/composer/tools/blobs.py#L1029), [L1042](../../../../src/elspeth/web/composer/tools/blobs.py#L1042), [L1064](../../../../src/elspeth/web/composer/tools/blobs.py#L1064), [L1077](../../../../src/elspeth/web/composer/tools/blobs.py#L1077)). The agent and the planner's closed-code mapping cannot tell "choose a different blob" from "create the node first" without parsing prose.

**wire_blob_inline_ref-N6 — demonstrated, Low: a non-scalar leaf is replaced without notice.** Wiring `node:classify.options.schema` replaced the schema object. The result `data` was only `{"field_path": …}`, and validation then reported `Invalid schema mode 'inline_content'`. Validation catches this case. The result does not say that an existing value, or a whole object, was replaced.

**wire_blob_inline_ref-N7 — hypothesis/unverified: the prompt-surface guard is node-only.** [`llm_prompt_surface_field`](../../../../src/elspeth/web/execution/_validation_materialization.py#L181) returns `None` for `source` paths. The `llm` *source* plugin has string `prompt_template`/`system_prompt`/`model` options ([config](../../../../src/elspeth/plugins/sources/llm/config.py#L60)). Prompt-template review sites are enumerated for `llm` nodes only ([interpretation_state](../../../../src/elspeth/web/interpretation_state.py#L1651)), so writing the text directly on an `llm` source appears equally unreviewed. That would make this coverage parity, not a bypass. Whether any source-side review should cover these fields was not established.

## 6. Structural remediation

Unify plugin option authorability and deferred-value capabilities in a plugin-owned contract consumed by schema discovery, path-based wiring, option patching, preview, and runtime. The web layer should own session authorization and review transitions; the plugin should own whether a given option accepts deferred content and how the resolved value is validated. A shared mutation finalizer should reconcile review evidence and emit explicit authoring-versus-readiness outcomes across all edit routes. The same finalizer should give explicit-approve proposals the same dry-run refusal the auto-commit path returns, so the agent sees refusals before a proposal is written (N2). Blob identity should be admitted once into a canonical value used by both the handler and the proposal validator (R2, BOS-03; N3).

Acceptance: each declared deferred field wires successfully and resolves consistently through preview/runtime. Unsupported fields, scalar collisions, reserved identity leaf keys and paths through existing markers reject. Forbidden review/runtime roots remain unwriteable, and generated prompt blobs cannot evade review. Hash mismatch, wrong-session blob, changed bytes, bad encoding, or a non-text MIME type fails with a typed refusal and without execution. In explicit-approve mode, a wire that would be refused in auto-commit mode returns that refusal to the agent and creates no proposal. Compatibility risk is Medium because persisted field paths and marker shapes are public authored data. Preserve current pinning and review/refuse boundaries; no data migration is authorised by this assessment.
