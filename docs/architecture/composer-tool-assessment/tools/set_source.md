# `set_source` — independent tool assessment

Baseline: ELSPETH **0.8.9**, `3b28d537be98234da8135c418bf185a998c18b68`. Reconnaissance and remediation design only. Incoming `.10 lite` changes are outside this assessment and require affected-source reinspection.

## 1. Purpose and usage

Add or replace one named source specification. The model chooses the plugin, options and runtime connection; the tool admits that explicit choice and maintains source review authority.

Use for a configured external source (for example a bucket/key or service source) or an authorised path-based source. On the web routes an authorised local path is one under this session's blob subtree `data_dir/blobs/<session_id>/` ([paths.py:70-79](../../../../src/elspeth/web/paths.py#L70)); on Composer MCP every `path`/`file` option is refused (set_source-N6). For session blob custody use the dedicated singular/plural binding tools. New sources require an explicit failure destination; replacing the same named source can preserve its existing choice. Use `patch_source_options` for an option-only edit. `set_source` cannot replace a source bound to LLM-authored (generated) blob content (set_source-N4).

## 2. Contract

Required plugin:string, on_success:string and options:object. source_name defaults to `source`. The exact name rule ([state.py:272-283](../../../../src/elspeth/web/composer/state.py#L272)): non-empty, lowercase, at most 38 characters ([config.py:78](../../../../src/elspeth/core/config.py#L78)), matching `^[a-zA-Z][a-zA-Z0-9_-]*$` ([config.py:191](../../../../src/elspeth/core/config.py#L191)), so it starts with a letter, not one of `continue`, `fork`, `on_success` ([config.py:71](../../../../src/elspeth/core/config.py#L71)), and not starting with `__`. A violation raises `ToolArgumentError` with no reason (set_source-N2). on_success is not checked at admission: an empty or malformed connection name is admitted and reported as a standing `connection_label_invalid` validation error (set_source-N5).

Optional on_validation_failure distinguishes omitted from null/empty: omission preserves an existing choice, while new/null/empty without a valid explicit choice refuses `failure_route_required` ([_common.py:1910-1923](../../../../src/elspeth/web/composer/tools/_common.py#L1910)). A supplied value is stripped (`" discard "` is stored as `discard`, measured). A named route that matches no configured output is admitted with a standing `quarantine_unknown_output` error, not refused (N5). description is optional informational prose, and **omission clears it** on replacement, unlike on_validation_failure (set_source-N3). Options replace the previous options, rather than merge. An `options.on_validation_failure` key that differs from the routing field is refused `plugin_options_invalid` ([_common.py:3516-3521](../../../../src/elspeth/web/composer/tools/_common.py#L3516)).

Success returns `success`, `validation`, `validation_delta`, `affected_nodes` (the source component id), `version` (+1), `applied_component`, optional `post_call_hints` and optional `data.server_owned_metadata_note` (envelope keys measured in memory: `affected_nodes, applied_component, post_call_hints, success, validation, validation_delta, version`). In practice that note can come only from an echoed requirement row: the `source_authoring` echo branch never reaches success for this tool (N4). Structured rejection returns `success: false` with the exact saved state/version and the saved graph's standing findings after the rejection entry ([_common.py:1340](../../../../src/elspeth/web/composer/tools/_common.py#L1340)); it can attach `plugin_schemas` (`augments_on_failure=True`) and `validation_guidance`. Three classes of input do not produce a ToolResult: argument-model and source-name failures raise `ToolArgumentError`; literal credential material in arguments raises `CredentialMaterialRefused` at the dispatcher guard ([_dispatch.py:908](../../../../src/elspeth/web/composer/tools/_dispatch.py#L908); [test_tools_mutations.py:899](../../../../tests/unit/web/composer/test_tools_mutations.py#L899)); and a non-string or NUL-bearing `path`/`file` raises a raw `TypeError`/`ValueError` (set_source-N1, a defect). No plugin execution, remote source fetch or blob write occurs. No automatic retry or exactly-once key exists; an identical replacement still advances version and counts as progress (demonstrated, set_source-N9).

The handler returns an immutable candidate; it does not itself durably save the conversation. In web explicit_approve mode, the call is first dispatched as a *preview*; the proposal is staged whether or not that preview succeeds, and a `ToolArgumentError` from preview is swallowed ([tool_batch.py:2114-2118](../../../../src/elspeth/web/composer/tool_batch.py#L2114)). If the preview is valid and required-control wiring changes the state, the proposal is relabelled a whole-pipeline `set_pipeline` proposal. It is re-executed on acceptance. Otherwise the enclosing tool batch applies the accepted state, and the session turn persists it under its operation authority. Across both provider dialects, the provider wire projection is decoded to canonical arguments before dispatch; strict transport representation does not grant different authority. `options` is an open object, so `openai_strict` emits this tool with `strict: false` and parameters byte-equal to the canonical schema (measured). The omitted-versus-null distinction for on_validation_failure therefore reaches the handler unchanged on both dialects. A ToolResult's `success` records operation admission, while `validation.is_valid`, runtime preflight, review and execution admission answer separate questions. Owned-code/audit integrity failures escape as faults rather than being reclassified as ordinary invalid model input; review-reconciliation `KeyError`/`TypeError`/`ValueError` are the exception and become the ordinary refusal `review_reconciliation_failed` ([sources.py:1180-1188](../../../../src/elspeth/web/composer/tools/sources.py#L1180)).

## 5. Usability assessment

**SG-03 — demonstrated lifecycle inconsistency (in-memory dispatch, upgraded from source-established); high confidence.** Repeating an identical replacement advances version and is counted as progress by the shared [progress predicate](../../../../src/elspeth/web/composer/discovery_cache.py#L38), while an empty `patch_source_options` call retains the same version. This matters because Composer uses version advance as a progress signal. It is not data loss or a broken promised exactly-once contract. **SG-06 — structural ownership pressure; high confidence.** This mutation repeats policy, profile, credential, path, review and config admission also present in bulk authoring and patch/bind routes. Existing refusal tests defend several seams, but adding a policy requires coordinated edits. N1 shows the cost: one unguarded helper fails the same way on four tools. Workaround: inspect the returned applied component and validation; use the patch tool for an option-only edit and binding tools for blobs.

New findings from the 2026-11-09 sheet review. "In-memory" means a handler or `execute_tool` dispatch run against test-fixture states and catalogs with the public flag set (`validate_arguments`, `require_data_dir_for_paths`, `raise_schema_argument_errors`, a lane-local `data_dir` and a UUID session id). It is not an end-to-end service, provider or browser run. No pytest was run by this review.

- **set_source-N1 — demonstrated (in-memory dispatch); Tier-3 value escapes as a raw exception.** With the public flags, `options.path` of `123`, `["a.csv"]` or `null` raises `TypeError` ("argument should be a str or an os.PathLike object…"), and `"a\x00b.csv"` raises `ValueError` ("embedded null character"). The cause is [`_validate_source_path`](../../../../src/elspeth/web/composer/tools/_common.py#L2311) passing the raw value to [`resolve_data_path`](../../../../src/elspeth/web/paths.py#L22), which calls `Path(value).resolve()`. Control: an in-session string path succeeds, and `/etc/passwd` refuses `source_path_policy_invalid`. The handler's own docstring ([sources.py:1005-1011](../../../../src/elspeth/web/composer/tools/sources.py#L1005)) calls a non-`ToolArgumentError` escape the "wrong disposition for Tier-3 input". In the freeform loop it is wrapped as PLUGIN_CRASH and the turn ends with an HTTP 500 ([tool_batch.py:3199-3248](../../../../src/elspeth/web/composer/tool_batch.py#L3199), source-traced). The path gate (step 9) runs before plugin prevalidation (step 11). On a direct-handler context without the path gate, prevalidation refuses `path: 123` cleanly as `plugin_options_invalid` "path: Input should be a valid string" (measured). ## 6. Structural remediation

Introduce one source candidate-admission operation used by replacement, patch, blob binding and bulk authoring, with explicit author-owned options, binding evidence, policy snapshot and review reconciliation inputs. Plugins retain config/schema ownership; the web adapter owns path/credential/profile policy; the orchestrator owns selection and retry. Shape-check every Tier-3 option value a web-owned gate consumes before that gate dereferences it, so a shared gate cannot crash four tools at once (N1). Define successful_no_change separately from applied and from execution readiness, then use actual accepted content change for progress. Regression: source replacement, equivalent patch and bulk authoring must accept the same legal config and reject forged review evidence, escaping paths, non-string paths, literal credentials and malformed options without version change; an exact replay must follow the declared no-change policy, which updates [test_source_rejection_contracts.py:662-686](../../../../tests/unit/web/composer/test_source_rejection_contracts.py#L662) deliberately (N9). Compatibility risk medium: source naming, failure-route preservation and stored authority metadata must remain readable.
