# `list_models` assessment

Baseline: `3b28d537be98234da8135c418bf185a998c18b68` — 0.8.9. Reconnaissance and design only.

## 1. Purpose and exposure

Discover model identifiers and provider counts. With no provider it returns a provider summary; with a prefix it returns a capped list. The declaration is cacheable discovery. It is a catalog lookup, not a credential-based model access probe.

It is also the tool that every model-binding repair hint names: the value-source preflight, the web validation runtime, composer prevalidation and the `llm` plugin's own composer hints all tell the agent to call `list_models` before writing `options.model` (see §3.1). The planner and both skills make a fresh `list_models` result the **only** permitted source of a literal `options.model` when no operator profile is usable (§5.1). The tool therefore carries more authority in the authoring path than its implementation supports: only one of its branches (exact `openrouter`) is aligned with a configuration validator (§5, `list_models-N1`–`N3`).

## 2. Contracts and authority

Optional provider string: omission means summary, empty string means unprefixed identifiers, ordinary strings are case-sensitive bare `startswith` prefix filters ([L2592](../../../../src/elspeth/web/composer/tools/generation.py#L2592)). Optional positive integer limit defaults to 50 and has no maximum; boolean and string values are rejected by the argument model, and integral floats such as `2.0` are admitted deliberately because JSON Schema integers include them ([`_JsonInteger`](../../../../src/elspeth/web/composer/redaction.py#L1434)). An authored `null` is rejected ([`_reject_supplied_null`](../../../../src/elspeth/web/composer/redaction.py#L1421)); the `openai_strict` wire text says "Pass null" because that route's decoder strips promoted nulls before dispatch ([wire projection](../../../../src/elspeth/web/composer/tools/wire_projection.py#L242), [decode](../../../../src/elspeth/web/composer/tool_batch.py#L1399)).

The OpenRouter branch is taken when `provider.rstrip("/") == "openrouter"`, so `openrouter`, `openrouter/` and `openrouter//` all read the catalog accessor's unprefixed HTTP model slugs ([L2578](../../../../src/elspeth/web/composer/tools/generation.py#L2578)). Any longer OpenRouter prefix, such as `openrouter/anthropic/`, falls through to the bundled LiteLLM list and returns `openrouter/`-prefixed routing identifiers (`list_models-N1`). Other providers use the bundled LiteLLM list ([`read_litellm_model_list`](../../../../src/elspeth/plugins/llm/model_catalog.py#L101)). Output shape distinguishes provider summary from list/count/truncated ([handler](../../../../src/elspeth/web/composer/tools/generation.py#L2539), [declaration](../../../../src/elspeth/web/composer/tools/generation.py#L2636), [response records](../../../../src/elspeth/web/composer/tools/_generation_responses.py#L164), [selector](../../../../src/elspeth/web/composer/tools/_generation_responses.py#L334)).

The OpenRouter accessor returns the live snapshot when the web lifespan primed it, else the bundled slice with the routing prefix stripped ([`_read_openrouter_catalog`](../../../../src/elspeth/plugins/llm/model_catalog.py#L258), [`_bundled_openrouter_slice`](../../../../src/elspeth/plugins/llm/model_catalog.py#L210)). The web server primes it only when a configured LLM profile binds OpenRouter ([`_boot_prime_openrouter_catalog`](../../../../src/elspeth/web/app.py#L562), skip at [L584](../../../../src/elspeth/web/app.py#L584)). Which source is active is available as [`read_openrouter_catalog_snapshot_id`](../../../../src/elspeth/plugins/llm/model_catalog.py#L236) and is recorded on runs, but it is not part of the tool result (`list_models-N4`).

## 3. Source trace to the user

Handler reads the bundled list, validates inputs, selects summary/filter branch, substitutes the OpenRouter catalog count/list where appropriate, and returns `LIST_MODELS_RESPONSE_CONTRACT` data through `_discovery_result` ([L2563](../../../../src/elspeth/web/composer/tools/generation.py#L2563), [`_discovery_result`](../../../../src/elspeth/web/composer/tools/_common.py#L1279)). It explicitly discards ToolContext and does not test current user's provider credentials, the deployment's configured LLM profiles, or plugin policy. The summary always inserts an `openrouter` key, even when the bundled list has none and the deployment does not configure OpenRouter ([L2618](../../../../src/elspeth/web/composer/tools/generation.py#L2618)).

The freeform exposure is `get_tool_definitions` → wire projection → `composer_loop_tool_definitions`; the planner selects an ordered discovery subset, so exposure can narrow by phase ([src/elspeth/web/composer/tools/_dispatch.py:311](../../../../src/elspeth/web/composer/tools/_dispatch.py#L311), [src/elspeth/web/composer/provider_gateway.py:391](../../../../src/elspeth/web/composer/provider_gateway.py#L391), [src/elspeth/web/composer/pipeline_planner.py:1647](../../../../src/elspeth/web/composer/pipeline_planner.py#L1647)). Public freeform calls pass credential/batch admission, wire decoding and closed semantic-schema admission before `execute_tool` with `validate_arguments=True` ([src/elspeth/web/composer/tool_batch.py:1010](../../../../src/elspeth/web/composer/tool_batch.py#L1010), [src/elspeth/web/composer/tool_batch.py:1399](../../../../src/elspeth/web/composer/tool_batch.py#L1399), [src/elspeth/web/composer/tool_batch.py:3008](../../../../src/elspeth/web/composer/tool_batch.py#L3008)). Internal direct calls must explicitly opt into public argument validation; without it the handler's own `_validate_mutation_arguments` still rejects malformed arguments ([L2573](../../../../src/elspeth/web/composer/tools/generation.py#L2573)).

After the handler, `finalize_tool_result` normalizes validation; discovery result admission selects the declared response contract before serialization ([src/elspeth/web/composer/tools/_dispatch.py:752](../../../../src/elspeth/web/composer/tools/_dispatch.py#L752), [src/elspeth/web/composer/tool_batch.py:3052](../../../../src/elspeth/web/composer/tool_batch.py#L3052)). The loop records the invocation, sends a tool result back to the model, and persists its redacted tool-turn cohort; subsequent operation settlement owns user-facing success/failure ([src/elspeth/web/composer/tool_batch.py:3344](../../../../src/elspeth/web/composer/tool_batch.py#L3344), [src/elspeth/web/composer/service.py:1515](../../../../src/elspeth/web/composer/service.py#L1515), [src/elspeth/web/sessions/composer_turn.py:1051](../../../../src/elspeth/web/sessions/composer_turn.py#L1051)). A completed lookup does not imply pipeline readiness.

## 4. Branches, failures and recovery

Omitted, empty, ordinary-prefix, OpenRouter-prefix and no-match calls differ intentionally. Limit truncation is explicit; there is no pagination cursor or offset. Repeating the same limit cannot retrieve the remainder, though a larger limit is accepted. Truncation keeps the alphabetically first `limit` identifiers. With the default of 50, `azure/` (232 entries in the measured LiteLLM) shows only the alphabetically earliest names, which are not chosen for relevance or recency. Catalog exceptions are not evidence that no models exist; conversely an **empty** catalog (LiteLLM absent) returns a successful zero result indistinguishable from a no-match (`list_models-N5`). Argument rejection occurs at the dispatcher on public routes (freeform, planner, MCP pass `validate_arguments=True`); on a direct non-validating call the handler's own argument model rejects the same inputs. The dispatcher's `ToolArgumentError` reads "'tool arguments' must be an object conforming to the declared argument schema" (measured in-memory for `limit: 0`, `limit: true`, `provider: null`, an extra key); the handler path names `list_models arguments` and `ListModelsArgumentsModel` instead. Neither names the offending field (`limit`/`provider`) or the violated bound. Expected policy/semantic refusal is a failed result on the current state; controlled-code exceptions remain framework/plugin failures, with the executed prefix and audit evidence retained by the common loop. Cancellation, timeout and final persistence failure belong to the request/operation owner, not a handler-local retry. None of these discovery handlers commits graph changes or needs a proposal approval step. Retrying a lookup can recover an argument or infrastructure problem but cannot repair the graph by itself.

**Cache, idempotency, concurrency and retry:** `ToolKind.DISCOVERY`, `cacheable=True`. On the **freeform** route, identical argument objects reuse successful results for that compose request. Different limits or provider spellings are distinct keys even when the result is identical. The planner route has no discovery cache; it tracks information keys instead (§3.1). MCP has neither. Repeated lookup has no graph/store effect but is separately audited. The handler does not lock a credential/account snapshot, make entitlement probes or retry providers. Its catalog freshness follows the imported list/catalog service: bundled LiteLLM data is fixed at install time. The OpenRouter snapshot is taken once per web process at boot and is never refreshed in-process. Request cache reuse can intentionally lag a catalog refresh. Primary-model transport retries and any upstream catalog refresh are not equivalent to model-access verification. `_discovery_result` also runs `state.validate()` on every call ([`_common.py:1281`](../../../../src/elspeth/web/composer/tools/_common.py#L1281)), so a lookup that never reads state still pays for full composition validation (shared with every discovery tool; cost unmeasured).

## 5. Defects, restrictions and hypotheses

**GS-03 — confirmed user-facing description defect (model member):** the tooltip claims models available on this deployment's credentials ([src/elspeth/web/frontend/src/components/chat/toolCallDescriptions.ts:25](../../../../src/elspeth/web/frontend/src/components/chat/toolCallDescriptions.ts#L25)), while the producer ignores context and reads public/bundled catalogs ([src/elspeth/web/composer/tools/generation.py:2563](../../../../src/elspeth/web/composer/tools/generation.py#L2563)). Listing an identifier does not establish authorization, account access or provider availability. **Restriction:** no explicit paging; non-OpenRouter freshness is bundled-catalog freshness. No claim is made that a listed current model actually fails.

The findings below were shown by **in-memory handler/dispatch runs** (`execute_tool` from the test helpers, bundled LiteLLM 1.102.0 from the shared venv), not an end-to-end service run. Where a live OpenRouter snapshot matters, it was installed through the production prime/parser (`prime_openrouter_catalog_from_live`) with an injected HTTP response, so no network was used. Counts depend on the installed LiteLLM version. The probe runs are recorded in §7.

- **`list_models-N1` — demonstrated undisclosed dead end.** `provider="openrouter/anthropic/"` takes the bundled branch and returns 17 identifiers of the form `openrouter/anthropic/claude-3-haiku`. In the in-memory run, 0 of the 17 are members of the OpenRouter catalog as returned; all 17 are members after stripping `openrouter/`. The `CatalogValueSource` on OpenRouter `model` would reject every one. The declaration promises HTTP-form slugs only "for provider='openrouter/'" and is silent on narrower OpenRouter prefixes, which is the natural way for an agent to narrow a truncated list. The split is known to the authors (the planner test id [`live-versus-bundled-prefix`](../../../../tests/unit/web/composer/test_model_discovery_scope.py#L55) pins the bundled count) but no test asserts the returned form, and nothing tells the model. This reopens, one prefix deeper, the "composer recommended a model the validator then rejects" loop the handler docstring says is closed ([L2557](../../../../src/elspeth/web/composer/tools/generation.py#L2557)). Case is also significant: `OpenRouter/` returns 0 with no hint. **Probe C/C2 (§7) showed that a live snapshot does not repair this.** With an injected live catalog primed, `openrouter/` returns the live set, but `openrouter/anthropic/`, `openrouter/anthropic` and `openrouter/openai/` return the same bundled `openrouter/`-prefixed ids as before the prime (17/17/58). None is in the validator catalog as returned. After stripping the prefix, 1 of 17 survives, and only because the fixture shares that id. The summary meanwhile advertises `openrouter: 3`, the live size. Running the real `check_config_value_sources` on an `OpenRouterConfig` rejects the first sub-prefix id in both phases ("configured value is not in catalog 'openrouter'; pick a valid value via the list_models composer tool"), and accepts the first exact-branch id. The repair hint therefore sends the agent back to the tool that produced the rejected value.
- **`list_models-N2` — demonstrated catalog-form/config-form mismatch (Bedrock).** `provider="bedrock/"` returns 3 identifiers. At least 89 Bedrock-style identifiers (`ai21.`, `amazon.`, `anthropic.`, `meta.`, `us.` …) sit in the unprefixed `""` bucket, and `validate_bedrock_model` rejects that form ("Bedrock model must be a non-empty LiteLLM 'bedrock/<model-id>' value"). A model following the skill rule "author `options.model` ONLY from `list_models`" therefore has no way to obtain a valid Bedrock literal beyond 3 entries. Prepending `bedrock/` to an unprefixed id is likely what an operator would do, but whether LiteLLM accepts each such id is a *hypothesis*. Bedrock on AWS ECS normally binds through an operator profile, which avoids this path; the impact is confined to profile-less Bedrock authoring.
- **`list_models-N3` — demonstrated summary/filter round-trip inconsistency.** Summary keys carry no trailing slash (`"azure": 232`), and the hint says only "Use provider parameter". Passing the key verbatim, `provider="azure"`, returns 361 identifiers (232 `azure/` + 129 `azure_ai/`); `provider="bedrock"` returns 34 (3 `bedrock/` + 31 `bedrock_mantle/`). The count the summary advertises is therefore not guaranteed to match the follow-up. Probe A (§7) checked every key: 8 of the 93 non-empty keys differ. They are `azure` (232 vs 361), `bedrock` (3 vs 34), `cohere` (2 vs 10), `deepseek` (10 vs 28), `gemini` (80 vs 124), `meta` (1 vs 31), `moonshot` (24 vs 26) and `zai` (16 vs 17). Two causes produce the mismatch. Sibling keys can share the string prefix (`azure_ai`, `bedrock_mantle`, `deepseek-ai`, `meta-llama`/`meta_llama`, `moonshotai`, `zai-org`). The bare prefix can also sweep unprefixed ids in the `""` bucket (`cohere` and `gemini` have no sibling key). Control: `key + "/"` round-trips for all 93 keys. The summary also presents non-provider path segments as providers: image-generation size and quality buckets such as `1024-x-1024`, `256-x-256`, `hd`, `high`, `low`, `medium`, `standard`, `max-x-max` (e.g. `high/1024-x-1024/gpt-image-1`). 94 keys were returned in the measured run. The planner's `model_catalog` docstring already records the `azure`/`azure_ai` sweep ([L1983](../../../../src/elspeth/web/composer/planner_authoring_aids.py#L1983)); the model-facing declaration does not. The planner coverage predicate mirrors the same semantics, so it is consistent, just surprising.
- **`list_models-N4` — demonstrated in memory: route/config divergence with no provenance marker.** What `openrouter` returns depends on route and deployment configuration. The web lifespan serves the live snapshot only if OpenRouter is a configured profile provider and the boot probe succeeded. Otherwise, and always under Composer MCP, it serves the bundled slice. The result carries no `source: live|bundled`, snapshot sha or timestamp, although `read_openrouter_catalog_snapshot_id()` already computes them. An agent cannot tell whether a slug list reflects what OpenRouter currently serves.
  - Probe B (§7), unprimed: `_boot_prime_openrouter_catalog` with no profiles and with a Bedrock-only profile logs `openrouter_catalog_boot_prime_skipped` and never reaches the prime. The snapshot id is then `bundled`. The freeform-shaped and MCP `openrouter/` calls both return exactly the bundled slice (268), with data keys `count/models/truncated` only. Those three keys are all of `ModelListResponse`'s fields, and the serialized result does not mention the source or the sha.
  - Positive control: priming through the production parser flips the snapshot id to `live` and changes the returned set, but the result shape stays identical.
  - Source, not runtime: MCP never primes (0 prime references under `src/elspeth/composer_mcp`, versus 12 in `web/app.py`).
- **`list_models-N5` — demonstrated (with patched accessors) fault softening of an empty catalog.** With `read_litellm_model_list` and `get_catalog_values` patched to return empty collections (the LiteLLM-absent case), the summary returns `success: true`, `{"providers": {"openrouter": 0}, "total_models": 0}` and every filter returns `{"models": [], "count": 0, "truncated": false}`. That is indistinguishable from "no models match this prefix". The value-source walker turns the same condition into an actionable "install the LLM extra" finding via the registered `missing_dep_hint` ([L483](../../../../src/elspeth/plugins/llm/model_catalog.py#L483)); `list_models` does not.
- **`list_models-N6` — source-established dead guidance path.** Both skills tell the model to use "the supplied `model_catalog`" (§5.1), and the planner keeps `model_catalog` supply/coverage branches. But `build_planner_authoring_aids` never attaches that aid, and a test asserts its absence on every surface. The guidance names an input the model never receives, and the planner branches cannot be reached in production.
- **`list_models-N7` — demonstrated at the progress-event producer: a user-facing mislabel (GS-03 class); browser rendering not observed.** For a `list_models` call, the progress stream tells the user "I'm checking available source, transform, and sink tools" with evidence "Reading plugin names and schemas only." That text is accurate for `list_sources`/`list_transforms`/`list_sinks`/`get_plugin_schema`, not for a model catalog lookup.
  - Probe D (§7) called `tool_started_progress_event` and `tool_completed_progress_event`, the builders that `tool_batch.py` and `pipeline_planner.py` emit. The `list_models` events are identical to the `list_sources` events, and none of their text mentions a model. The completion evidence also reads "Checking available source, transform, and sink tools."
  - Controls: `get_pipeline_state` and `list_secret_refs` produce different text.
- **`list_models-N8` — source-established inaccurate audit justification.** `_LIST_MODELS_REASON` says the handler "validates them against the provider registry". The handler accepts any string and does not consult a provider registry; an unknown prefix returns `count: 0`.
- ~~**`list_models-N9`**~~ — **refuted by probe E (§7).** The hypothesis was that a float `limit` never closes its own planner scope. It does: the key is built with `canonical_json`, which emits `["anthropic/",2]` for both `2.0` and `2`, so `json.loads` yields an `int` and the `type(limit) is not int` guard does not fire. Measured: the float key covers itself and a narrower int query, and does not cover a wider one (control). `limit: 2.0` is admitted (`success: true`). Exercised at the predicate level, not through a full planner run.

**Restrictions (intended):** the tool is a catalog lookup, not an entitlement probe; no paid provider calls; OpenRouter alignment relies on the boot snapshot; the bundled fallback is a documented design choice ([module docstring](../../../../src/elspeth/plugins/llm/model_catalog.py#L19)).

### 5.1 Guidance parity

## 6. Ownership, remediation and dependencies

Model-catalog owner owns identifier/freshness semantics; frontend owner should say catalog identifiers rather than credential-qualified availability. If credential-scoped reachability is desired, define that separate capability, its cost, evidence expiry and failure semantics before implementing it. Do not silently make a currently local discovery operation perform paid provider probes. Resolve discovery-contract terminology before orchestrator uses the list as an execution guarantee.

For first-class discovery the tool should answer the question the skills actually ask it — "what can I put in `options.model` for provider P on this deployment?" — rather than "what does LiteLLM know?". Structurally (R2): key the request by `llm` provider literal (`openrouter | bedrock | azure | gateway`) rather than a free-form LiteLLM prefix. Return identifiers in the **config form** that provider's validator accepts (OpenRouter unprefixed from the catalog accessor; Bedrock `bedrock/<id>`, including the unprefixed Bedrock-family entries). For providers with no catalog, return an explicit typed "no catalog — bind via `deployment_name` / operator profile alias" answer rather than zero results. Carry catalog provenance (`source`, snapshot sha) and a distinct "catalog unavailable" outcome. Keep the raw LiteLLM prefix listing only if a consumer needs it, labelled as routing identifiers. This stays inside the composer invariants: the server reports facts and the LLM still chooses the model.

**Implementation risk:** Low for tooltip/progress/description correction; low-to-medium for N1/N3/N5 result changes (strict response records and recorded replays must update in the same slice); medium for paging/freshness contracts and provider-keyed requests. Introducing live credential probes would change cost and authority and needs separate scope.
