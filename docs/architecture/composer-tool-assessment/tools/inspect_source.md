# `inspect_source` — independent tool assessment

Baseline: ELSPETH **0.8.9**, `3b28d537be98234da8135c418bf185a998c18b68`. Reconnaissance and remediation design only. Incoming `.10 lite` changes are outside this assessment and require affected-source reinspection.

## 1. Purpose and usage

Return bounded structural evidence about a session source artifact: raw/runtime header names, naming provenance, sample counts, lexical types, URL candidates, warnings and redacted identity. This supports model decisions; it does not infer a guaranteed runtime schema from a sample.

Select before declaring tabular schemas or choosing text/CSV/JSON handling. Requires session engine/session ID and a READY owned blob with present bytes and correct SHA-256. Optional encoding is meaningful only for CSV/TSV and does not configure the eventual source. Inspection always parses under fixed CSV semantics — delimiter from the filename only (`.tsv` → tab, otherwise comma), no skipped rows, first nonblank row treated as the header — so its facts describe the bytes under those defaults, not under the source options the pipeline will eventually configure (see inspect_source-N5).

## 2. Contract

Required blob_id:string; optional encoding:null|string defaults None, strict nonempty length 1..128 ([`InspectSourceArgumentsModel`, sources.py:159](../../../../src/elspeth/web/composer/tools/sources.py#L159)). The handler retains at most an 8 KiB prefix ([`_INSPECT_SOURCE_MAX_BYTES`, sources.py:111](../../../../src/elspeth/web/composer/tools/sources.py#L111)) and parses at most 100 rows ([`_MAX_ROWS`, source_inspection.py:47](../../../../src/elspeth/web/composer/source_inspection.py#L47)), but streams the entire file in 1 MiB chunks for integrity verification ([sources.py:1785](../../../../src/elspeth/web/composer/tools/sources.py#L1785)). Result data includes source_kind, observed_headers, runtime_headers, field_name_mapping, sample_row_count, inferred_types, url_candidates, warnings, byte_range_inspected, redacted_identity. It excludes row content for headered input; for a headerless or misclassified CSV the first data row is returned as `observed_headers` (inspect_source-N6).

Refusals (ordinary `success=false` results): missing session engine/ID ([sources.py:1898](../../../../src/elspeth/web/composer/tools/sources.py#L1898)); non-UUID blob_id ([sources.py:1912](../../../../src/elspeth/web/composer/tools/sources.py#L1912)); missing or foreign blob — the lookup filters by session ID ([blobs.py:499](../../../../src/elspeth/web/composer/tools/blobs.py#L499)); non-ready status ([sources.py:1920](../../../../src/elspeth/web/composer/tools/sources.py#L1920)); ready row whose storage file is absent ([sources.py:1927](../../../../src/elspeth/web/composer/tools/sources.py#L1927), inspect_source-N1); encoding on a non-CSV blob ([sources.py:1942](../../../../src/elspeth/web/composer/tools/sources.py#L1942)); unknown/non-text codec ([sources.py:1950](../../../../src/elspeth/web/composer/tools/sources.py#L1950)); credential-bearing facts ([sources.py:1971](../../../../src/elspeth/web/composer/tools/sources.py#L1971)). Only the credential refusal carries an `error_code` (inspect_source-N4). Malformed arguments raise `ToolArgumentError` ([sources.py:1901](../../../../src/elspeth/web/composer/tools/sources.py#L1901)). Hash mismatch raises `BlobIntegrityError`; a NULL ready hash raises `AuditIntegrityError` ([blobs.py:1898](../../../../src/elspeth/web/composer/tools/blobs.py#L1898)). An `OSError` raised between the existence check and the open escapes unclassified (inspect_source-N3).

Discovery does not change state or require approval. It is never served from the discovery cache: BLOB_DISCOVERY declarations cannot be cacheable ([declarations.py:222](../../../../src/elspeth/web/composer/tools/declarations.py#L222)), measured `cacheable=False`. Repeated calls therefore re-read the artifact and can observe a changed version. There is no automatic retry. Each successful, contract-admitted call with a producer call ID registers a request-local turn-evidence receipt ([turn_effects.py:396](../../../../src/elspeth/web/composer/turn_effects.py#L396)), but that receipt is not bound to a content version (inspect_source-N8), and no durable receipt binds the eventual source config.

This is discovery: the handler retains immutable composition state; successful declared inventory data is admitted under its producer response contract before audit/disclosure. Across both provider dialects, the provider wire projection is decoded to canonical arguments before dispatch; strict transport representation does not grant different authority. A ToolResult's `success` records operation admission, while `validation.is_valid`, runtime preflight, review and execution admission answer separate questions. Owned-code/audit integrity failures escape as faults rather than being reclassified as ordinary invalid model input.

## 4. Alternative paths

Normal CSV facts distinguish observed lexical data from normalized runtime column names; null runtime_headers means bounded evidence could not resolve a trustworthy header. Explicit CSV encoding re-inspects the same prefix and appends a warning that source config must match separately. Large blobs still incur a full sequential hash read, so bounded result size is not bounded total I/O time. The handler reads metadata and filesystem separately; unlike get_blob_content, set_source_from_blob and the preview proof, it does not use the shared locked/recovery-aware reader. Facts are credential-checked, admitted under SOURCE_INSPECTION_RESPONSE_CONTRACT and registered as turn evidence. MCP excludes this session tool.

JSON/JSONL/text/unknown kinds are inspected as UTF-8 with replacement. An explicit encoding is refused for them, which is an intended, documented restriction ("For CSV/TSV, pass encoding"). The preview proof, not this tool, inspects JSON under the configured source encoding. A headerless CSV draws a "first row looks like data" warning only when every nonblank first-row cell is lexically int/float/bool ([source_inspection.py:701](../../../../src/elspeth/web/composer/source_inspection.py#L701)). A string-valued data row is reported as headers without a warning.

## 5. Usability assessment

**BOS-03 — demonstrated affected caller of inconsistent UUID admission (probe P6, §7).**
The handler validates UUID parseability and then passes raw text to
`_sync_get_blob` at `sources.py:1911–1915`. Probed through public `execute_tool`
dispatch with full operation context: the canonical ID succeeds, while uppercase,
braced (`{…}`) and `urn:uuid:` spellings of the same UUID all pass the UUID check
and are then refused as "Blob '<raw selector>' not found." A malformed ID is
refused earlier, at the UUID check, and a canonical ID from another session is
"not found" (custody holds). SQLite only; PostgreSQL was not run.
`blobs_table.id` is a `String` column on every backend
([models.py:2312](../../../../src/elspeth/web/sessions/models.py#L2312)), so this
is not a SQLite-only artefact. Use the exact discovered canonical ID. Shared BlobId admission should
canonicalize all accepted forms or refuse them uniformly before reads; regression
must include canonical/equivalent/malformed/foreign identities without weakening
session custody or inspection's bounded-memory property.

**SG-04 — demonstrated custody-admission inconsistency; high confidence.** A controlled handler call with session engine/ID but no data_dir, SessionOperationContext or authority succeeds. The get_blob_content control raises AuditIntegrityError. Source at 1915–1931 also reads row and bytes without the shared custody/recovery path; the crash-leftover consequence of that is demonstrated (inspect_source-N2, probe P2). This demonstrates an internal lifecycle-contract gap; it does **not** prove a public authorisation bypass or a reachable concurrent update race. Public route leases may constrain writers, and that reachability remains unresolved. Workaround: use fully wired production session context and re-inspect after artifact changes; operators should not interpret a sampled type as coercion or guaranteed_fields.

**inspect_source-N1 — demonstrated fault softening (BOS-02 class; probe P1, §7).** A ready row whose storage file is absent returns the ordinary failure "Blob storage file missing" ([sources.py:1926–1928](../../../../src/elspeth/web/composer/tools/sources.py#L1926)), with no `error_code`. The canonical blob service raises `BlobContentMissingError` for the same state (measured with `BlobServiceImpl.read_blob_content_sync`). The sibling tool `get_blob_content` returns the identical uncoded failure for the same state, so the softening is shared by the composer tool readers and is not specific to inspection. `SOURCE_INSPECTION_INTEGRITY_ERRORS = (BlobContentMissingError, BlobIntegrityError)` ([source_inspection.py:53](../../../../src/elspeth/web/composer/source_inspection.py#L53)) names that error, but no module references the tuple: `grep -rn SOURCE_INSPECTION_INTEGRITY_ERRORS src tests` returns only its definition.

**inspect_source-N2 — bypass of the documented custody read; crash-leftover consequence demonstrated (probe P2, §7); race reachability unverified (P3 not runnable here).** `_locked_blob_row_for_read` ([blobs/service.py:3259](../../../../src/elspeth/web/blobs/service.py#L3259)) states that a reader fetching row and bytes outside the same-session custody lock "can pair one version's metadata with another version's bytes — escalating a false-positive `BlobIntegrityError` (or `BlobContentMissingError`)", and that "Every content read MUST perform its file I/O and hash verification inside this context". Inside that lock it also heals crash leftovers (`.pre-update` sidecar, delete tombstone, inline-custody stage; [blobs/service.py:1100](../../../../src/elspeth/web/blobs/service.py#L1100)). `set_source_from_blob` ([sources.py:883–893](../../../../src/elspeth/web/composer/tools/sources.py#L883)) and the preview proof ([generation.py:4294–4305](../../../../src/elspeth/web/composer/tools/generation.py#L4294)) were moved onto this reader, citing elspeth-3d1d1fcb6c. `inspect_source` was not moved. Two consequences follow from the code. (a) Where an update interleaves, the result is a false integrity escalation; this was not reproduced. (b) After a crashed update or delete, inspection sees the unhealed state, where a sibling reader would first restore the committed version. Probe P2 demonstrated (b) on fresh blobs per tool: with a `.pre-update` sidecar holding the committed bytes and new bytes in storage, `inspect_source` raised `BlobIntegrityError` and left both files, while `get_blob_content` succeeded and restored the committed version; with storage renamed to a `.{blob_id}.delete-*` tombstone, `inspect_source` refused "Blob storage file missing" while `get_blob_content` restored the file and succeeded. Controls: no leftover, both succeed; a sidecar matching neither hash, both raise `BlobIntegrityError`. This sharpens SG-04; it does not change SG-04's "no public race demonstrated" boundary.

**inspect_source-N3 — source-established unclassified I/O fault, low.** `storage_path.exists()` ([sources.py:1927](../../../../src/elspeth/web/composer/tools/sources.py#L1927)) is followed by `path.open("rb")` ([sources.py:1788](../../../../src/elspeth/web/composer/tools/sources.py#L1788)) with no handler. **inspect_source-N4 — source-established result-shape inconsistency.** All refusals except the credential refusal pass no `error_code`: [sources.py:1899](../../../../src/elspeth/web/composer/tools/sources.py#L1899), 1914, 1917, 1921, 1928, 1943 and 1951. **inspect_source-N5 — demonstrated undisclosed semantic restriction (probe P4, §7).** The handler always uses `delimiter_for_filename(...) or ","`, `skip_rows=0` and no `columns` ([sources.py:1952–1960](../../../../src/elspeth/web/composer/tools/sources.py#L1952); default path [source_inspection.py:150](../../../../src/elspeth/web/composer/source_inspection.py#L150)), and takes the first nonblank row as the header ([source_inspection.py:628](../../../../src/elspeth/web/composer/source_inspection.py#L628)). The CSV source supports `delimiter`, `skip_rows` and `columns`. The preview proof inspects with the configured values ([generation.py:3835–3845](../../../../src/elspeth/web/composer/tools/generation.py#L3835)). So for the same bytes, `inspect_source.runtime_headers` and the source's runtime names can differ: a `;`-delimited `.csv`, a CSV with preamble rows, or headerless data. Meanwhile the description tells the model to "declare runtime_headers exactly". No argument lets inspection apply the intended delimiter or skip count. Measured: `a;b\n1;2\n` as `orders.csv` yields `observed_headers ["a;b"]`, `runtime_headers ["a_b"]` and no warnings at all, whereas the configured-semantics builder with `delimiter=";"` yields `["a","b"]` plus a `csv_non_default_delimiter` warning. A one-line preamble before `name,score` yields the preamble text as the single header (with only a `csv_jagged_rows` warning); with `skip_rows=1` the builder yields `["name","score"]`. This is not a runtime-integrity defect: preview/validation re-check under configured semantics.

## 6. Structural remediation

Give inspection a shared streaming custody read primitive that recovers interrupted replacements and pins metadata/hash/bytes under actual operation authority, without replacing its bounded-memory scan with unbounded read_bytes. The tool owns structural parsing and evidence semantics; blob storage owns version/custody, orchestrator owns schema choice. Regression: missing/expired/foreign authority refuses before filesystem access; genuine corruption raises; a completed allowed replacement returns one coherent version or a recoverable changed-version result; interrupted replacement recovery uses the same path as raw reads; 8KiB/100-row and streaming-memory bounds remain. Compatibility risk medium/high at the internal ToolContext seam; preserve facts payload and source encoding semantics. [test_inventory_inspection_response_contracts.py:84–100](../../../../tests/unit/web/composer/test_inventory_inspection_response_contracts.py#L84) currently pins a custody-less handler invocation, and [test_tools_preview.py:2383](../../../../tests/unit/web/composer/tools/test_tools_preview.py#L2383) asserts only `success is False` for missing context; both need deliberate updating. The same primitive should raise the owned `BlobContentMissingError` for missing ready bytes (N1, BOS-02) and absorb the unclassified `OSError` window (N3). Version-binding the turn-evidence receipt (N8) depends on that primitive returning the full verified hash.
