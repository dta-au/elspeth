# `set_metadata` — independent tool assessment

Baseline: ELSPETH **0.8.9**, `3b28d537be98234da8135c418bf185a998c18b68`. Reconnaissance and remediation design only. Incoming `.10 lite` changes are outside this assessment and require affected-source reinspection.

## 1. Purpose and usage

Apply a partial pipeline name/description update. This affects presentation and advisor evidence, not plugin configuration, executable connections or the generated engine YAML (measured: §7).

Select when the user changes pipeline naming or explanatory metadata. Requires no plugin, blob, secret or runtime dependency beyond the standard composition context. Several refusal messages also send the model here indirectly: an unregistered `pipeline_decision` is to be "recorded in `metadata.description`" (§5.1), which in the freeform loop means this tool or a full `set_pipeline`.

## 2. Contract

Required `patch`: object; only `name: string` and `description: string` are allowed and both are optional within it ([`_SetMetadataPatchModel`](../../../../src/elspeth/web/composer/tools/transforms.py#L147), fields typed [`_OmittableString`](../../../../src/elspeth/web/composer/redaction.py#L1428)). Included strings replace values; omitted fields preserve values ([`with_metadata`](../../../../src/elspeth/web/composer/state.py#L8297)). There is no append, clear-to-default or metadata-specific length bound: `""`, whitespace-only and 100,000-character strings are admitted with no warning, end-to-end on the freeform loop and on Composer MCP (§7, §7.1 P2). The only bounds are generic: the credential guard's 262,144-byte string traversal limit (refused as a *credential*, XC-14) and, on the freeform wire, the 1 MiB raw-argument JSON limit. Empty object is admitted.

Null semantics are **dialect-specific** (measured, §7 and appendix). On the canonical schema, the `none` provider dialect and Composer MCP, `null` is not a declared value and is refused (schema admission at public dispatch; `_reject_supplied_null` in the handler model). On the `openai_strict` wire projection both fields become **required and nullable**, and [`decode_wire_arguments`](../../../../src/elspeth/web/composer/tools/wire_projection.py#L930) strips `null` before dispatch, so on that route `null` is the only way to say "leave this field unchanged" and `{"name": null, "description": null}` decodes to the empty patch. This is not null-deletes merge patch on any route.

The handler reports no affected nodes, carries current graph validation and always constructs a state with version+1. Two route-level steps can change that: the public interpretation gate can refuse the rename outright (§4, METADATA-N2), and the freeform/REST required-control finalizer can add graph components to a version-advancing valid result (§3.1). No plugin call or external write occurs inside the handler; durable save/approval belongs to the enclosing route. No cache or automatic retry; exact repetition is content-idempotent but still advances version. The successful envelope carries `success`, `version`, `affected_nodes` (empty), `validation` and `validation_delta`; it has no `data` and no `applied_component` echo (measured), which is acceptable because the stored strings are byte-identical to the submitted ones.

The handler returns an immutable candidate; it does not itself durably save the conversation. In web explicit_approve mode, the operation is staged as a proposal and re-admitted on acceptance. Otherwise the enclosing tool batch applies the accepted state, and the session turn persists it under its operation authority. Across both provider dialects, the provider wire projection is decoded to canonical arguments before dispatch; strict transport representation does not grant different authority, but it does change how omission is spelled (above). A ToolResult's `success` records operation admission, while `validation.is_valid`, runtime preflight, review and execution admission answer separate questions. Owned-code/audit integrity failures escape as faults rather than being reclassified as ordinary invalid model input.

## 4. Alternative paths

A partial name update preserves description and vice versa. Empty patch preserves all content while advancing version; an unchanged string does the same. Unknown metadata keys (including `tags`) and wrong types, including `null` on canonical routes, reject at schema/model admission with an actionable path message (measured: `arguments.patch.name must be of type string`, `arguments.patch contains unsupported properties`). Ordinary existing graph invalidity remains in the response and does not prevent this informational edit — **except** pre-existing non-canonical interpretation requirements: because the tool declares the GRAPH effect, [`_enforce_composition_interpretation_gate`](../../../../src/elspeth/web/composer/tools/_dispatch.py#L772) re-checks the whole state and refuses the rename with `set_metadata: interpretation_requirements_invalid: …`, naming neither the offending component nor that the cause predates the call (METADATA-N2). Under explicit_approve this mutation is proposed for approval like graph mutations, including when its arguments are invalid (§3.1); under immediate mode it becomes a saved composition edit through normal turn persistence. A later `set_pipeline` that omits `metadata` silently resets both fields to `"Untitled Pipeline"` / `""` (METADATA-N3).

## 5. Usability assessment

**SG-03 — demonstrated progress misclassification; high confidence.** The controlled empty-patch probe preserved every state field except version but moved 4→5, and tool_result_mutated_composition_state returned True. tool_batch uses that result to mark mutation progress and clear anti-anchor state. Empty patch_source_options retained version 4 and returned False under the same probe. This is a cross-cutting progress/effect contract problem, not evidence of wrong metadata values. Workaround: avoid empty/identical metadata calls and do not treat a metadata version advance as proof that pipeline construction progressed.

*Review addendum (understated scope):* the miscount is not confined to empty patches. **Every** successful `set_metadata`, including a genuine rename, counts as graph-construction progress in four production-reachable consumers, none of which a metadata change can satisfy (METADATA-N6; a fifth, (e), is unreachable in production, §7.1 P1).

## 6. Structural remediation

Distinguish attempted, applied, no_change and graph-progress effects in tool results. Compare accepted metadata content before bumping revision; let the orchestrator count meaningful work by explicit goal/effect rather than any version increment. EffectDomain currently defaults all MUTATION tools to graph+validation+YAML, so metadata deserves an explicit projection rather than accidental broad classification.
