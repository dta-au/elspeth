# `list_composer_blobs` — ready inline-content candidates

Assessment baseline: `3b28d537be98234da8135c418bf185a998c18b68` (0.8.9). Reconnaissance only. **Overall confidence: High for source contracts and the reproduced inventory defect.** Nothing on this sheet has been implemented; no live provider, PostgreSQL, browser or deployment evidence exists for it.

## 1. Purpose and usage

Use this narrowly scoped inventory before `wire_blob_inline_ref` (freeform) or before authoring an inline-content marker in a full candidate, when the agent needs a ready artifact's identity and pinned hash without seeing its content. Unlike the general `list_blobs` inventory, this tool exposes only `ready` rows and the five fields needed to name and pin one. "Ready" is not "inline-eligible": the listing does not apply the inline-content size caps, MIME/decoding constraints, or the LLM-authored-prompt refusal that later stages enforce (see §5). Session engine and session ID must be supplied by the web service. It is not exposed by Composer MCP, which has no web blob custody context.

## 2. Contract

The semantic arguments are exactly `{}`. On the `none` dialect the wire schema is the same empty closed object; on the `openai_strict` dialect the wire schema instead requires `{"_elspeth_no_arguments": true}` and the description gains a sentence saying so ([marker](../../../../src/elspeth/web/composer/tools/wire_projection.py#L120), [description suffix](../../../../src/elspeth/web/composer/tools/wire_projection.py#L534)); the wire decoder removes the marker before dispatch.

`data` is `{"blobs": [...]}`; each item contains `blob_id`, `mime_type`, `size_bytes`, `content_hash`, and `filename`. It excludes content, previews, storage paths, source descriptions, creator fields (`created_by`, `creation_modality`, `creating_*`), and non-ready entries. Results are ordered by `created_at` descending with no unique tiebreaker, and bounded to 50 records, without any completeness marker or continuation selector ([query](../../../../src/elspeth/web/composer/tools/blobs.py#L559)). For a pipeline-run output blob, `created_at` is the time its pending row was reserved, not the time it became ready ([reservation insert](../../../../src/elspeth/web/coordination/repository.py#L2606), [finalize keeps `created_at`](../../../../src/elspeth/web/coordination/repository.py#L3924)). A ready row with null hash raises `AuditIntegrityError` rather than fabricating an identity. Missing session context returns a failed tool result with no `error_code` ([handler](../../../../src/elspeth/web/composer/tools/blobs.py#L632)); the production app always wires a session engine ([`app.py`](../../../../src/elspeth/web/app.py#L2039) → [`ComposerServiceImpl`](../../../../src/elspeth/web/app.py#L2302)); the handler also refuses on a null `session_id`, and `session_id` is typed `str | None` through the freeform dispatch ([`ToolBatchContext`](../../../../src/elspeth/web/composer/tool_batch.py#L861), [`_dispatch_tool_batch`](../../../../src/elspeth/web/composer/service.py#L1598)) — whether a production compose can reach dispatch without one was not traced. Schema/model failures are safe argument errors; credential-bearing metadata in any listed row produces one fixed refusal for the whole response (`error_code="credential_material_rejected"`).

The declaration is `BLOB_DISCOVERY`, with a dedicated response contract and no authored effects (measured: `resolve_tool_effects` returns `ToolEffects(domains=())`; control `create_blob` returns `(BLOB_STORE,)`). It does not change composition version, does not enter the per-compose discovery cache (measured `cacheable=False`; control `list_sources` is `True`), requires no mutation approval (excluded from the explicit-approve proposal count because `is_mutation_tool` is false, [count](../../../../src/elspeth/web/composer/tool_batch.py#L1044)), and is safe to repeat as a fresh observation. The returned hash is an observation, not a read lease: wiring resolves authoritative metadata again, and runtime dereference verifies pinned identity. There is no automatic retry or durable idempotency receipt for this read.

## 3. Implementation trace

The [handler](../../../../src/elspeth/web/composer/tools/blobs.py#L617) and [declaration](../../../../src/elspeth/web/composer/tools/blobs.py#L644) are listed in the module's [`TOOLS_IN_MODULE`](../../../../src/elspeth/web/composer/tools/blobs.py#L2287), aggregated into the [registry](../../../../src/elspeth/web/composer/tools/_registry.py#L94), then included in the canonical [model definitions](../../../../src/elspeth/web/composer/tools/_dispatch.py#L311). The dedicated response [parser](../../../../src/elspeth/web/composer/tools/blobs.py#L310), [encoder](../../../../src/elspeth/web/composer/tools/blobs.py#L374) and [contract](../../../../src/elspeth/web/composer/tools/blobs.py#L392) preserve the envelope's closed shape; the [credential guard](../../../../src/elspeth/web/composer/tools/blobs.py#L121) runs inside the handler before outward publication.

[Composer MCP](../../../../src/elspeth/composer_mcp/server.py#L116) excludes blob tools.

## 4. Alternative paths

No ready files yields a successful empty list inside the envelope, even when pending/error rows exist. A malformed owned hash or response causes an integrity/framework failure. A credential-bearing filename in any of the 50 rows refuses the whole response with text written for authored control content ("Store the value through the secret service and use a secret reference", [constant](../../../../src/elspeth/contracts/credential_material.py#L24)), which the agent cannot act on for an argument-free read; uploads already screen filenames ([route](../../../../src/elspeth/web/blobs/routes.py#L163)), so reach is limited to legacy or non-upload writers. After successful inventory, a blob can become retained, replaced, or unavailable before the next action; `wire_blob_inline_ref` must therefore check readiness and pin current metadata itself. The inventory does not perform content integrity reads or storage recovery.

A listed blob can still fail downstream: a ready blob above the 256 KiB per-ref cap ([cap](../../../../src/elspeth/core/blobs_inline.py#L63)) is wired without complaint (no size check in [`wire_blob_inline_ref`](../../../../src/elspeth/web/composer/tools/blobs.py#L1003)) and is refused only at validation ([oversized](../../../../src/elspeth/web/execution/_validation_materialization.py#L497)); an LLM-authored blob wired to an LLM prompt surface is refused by `creation_modality` ([guard](../../../../src/elspeth/web/composer/tools/blobs.py#L1044)), a field this listing omits. A ready binary-MIME blob is also wired without complaint. Validation then either refuses it as malformed or, when its bytes decode, raises an uncaught `ValueError` (N4, N8).

## 5. Usability assessment

**BOS-01 — demonstrated defect, High confidence:** a session containing 51 ready rows produces a successful 50-item `blobs` list without `has_more`, cursor, count, or truncation evidence. The oldest eligible file becomes undiscoverable through this tool. Controls with 1 and 50 ready rows returned all rows; the same SQL-backed probe measured 51 stored versus 50 returned ([evidence](../evidence.md)). This can make a planner conclude that an inline source/reference does not exist when it merely falls outside the newest window. Knowing the original ID allows direct wiring; repeatedly listing does not help. Ready pipeline-run outputs share the same window ([finalize to ready](../../../../src/elspeth/web/coordination/repository.py#L3924)), so repeated runs push earlier uploads out of it (source-established; outputs per run not measured).

**Content-free shape — intended restriction:** exclusion of content bytes, previews, storage paths and source descriptions is documented intent ([handler docstring](../../../../src/elspeth/web/composer/tools/blobs.py#L622), [redaction reason](../../../../src/elspeth/web/composer/redaction.py#L2982), [reference doc](../../../../docs/reference/composer-tools.md#L454)). Omission of **origin** fields (`created_by`, `creation_modality`) is not documented intent: those sources name only the four content-bearing exclusions, and `list_blobs` gives the same model both fields with a stated safety reason ([reason](../../../../src/elspeth/web/composer/redaction.py#L2955)). See N2.

**list_composer_blobs-N1 — source-established, High:** on the planner route a successful call marks `blob.index.composer` as supplied unconditionally (introspected: `planner_discovery_information_keys` returns `('blob.index.composer',)` and one `with_result(..., available=True)` makes `supplies("blob.index.composer")` true) ([key](../../../../src/elspeth/web/composer/pipeline_planner.py#L439), [`with_result`](../../../../src/elspeth/web/composer/pipeline_planner.py#L293)). `list_models` alone gets a completeness-qualified key, added only when its `truncated` flag is false ([`_resolved_discovery_information_keys`](../../../../src/elspeth/web/composer/pipeline_planner.py#L515)). A 50-capped blob list therefore counts as complete evidence, and when it closes the last pending key the planner is told "All declared information gaps are closed; emit the terminal proposal now" ([notice](../../../../src/elspeth/web/composer/pipeline_planner.py#L5133)). Combined with the aid rule "Discover first (list_blobs / list_composer_blobs); if nothing matches, ask one narrow upload/selection question" ([aid](../../../../src/elspeth/web/composer/planner_authoring_aids.py#L363)), the truncated list steers the planner toward asking for a re-upload of a file that exists. This amplifies BOS-01; it is not a separate data defect.

**list_composer_blobs-N2 — demonstrated incidentally (probe P2/P3, §7.1; N2 was not that probe's target, and no probe was assigned to N2), Medium:** the inventory built "for audited inline-content authoring" omits `creation_modality`/`created_by`, yet the consumers enforce exactly that fact: `wire_blob_inline_ref` and `set_pipeline` refuse an LLM-authored blob on an LLM prompt/model surface ([wire guard](../../../../src/elspeth/web/composer/tools/blobs.py#L1044), [set_pipeline guard](../../../../src/elspeth/web/composer/tools/sessions.py#L1604)), and the skill says to "wire the ready user-verbatim blob" ([skill](../../../../src/elspeth/web/composer/skills/pipeline_composer.md#L673)). An agent using only this tool cannot pre-select an eligible prompt blob; it must also call `list_blobs` or accept a refusal turn. Run: an LLM-authored ready blob was listed with the same five keys as a verbatim one, and `wire_blob_inline_ref` then refused it on `prompt_template` ("cannot wire LLM-authored blob …").

**list_composer_blobs-N3 — demonstrated (probes P2/P3 and P2b, §7), Medium:** the listing advertises every ready blob as available for inline content but discloses none of the inline constraints: the 256 KiB per-ref / 1 MiB aggregate caps ([caps](../../../../src/elspeth/core/blobs_inline.py#L63)) are enforced only at validation/preflight ([validation](../../../../src/elspeth/web/execution/_validation_materialization.py#L497), [preflight](../../../../src/elspeth/web/sessions/inline_blob_preflight.py#L167)). Neither skill nor the description mentions them (grep `KiB|256|per-ref|aggregate` in both skills: no cap mention; control: `KiB` matches in `planner_authoring_aids.py` and four other composer modules). The agent learns of an oversize choice one validation round later. Run: a 300 000-byte ready `text/plain` row was listed and wired without complaint; validation of the wired marker then failed `blob_inline_refs` with `oversized_inline_blob_content` ("300000 bytes exceeds per-ref cap 262144").

**list_composer_blobs-N4 — demonstrated (probes P2/P3 and P2b, §7), Medium:** binary document uploads (`image/jpeg`, `image/png`, `application/pdf`) are stored as ready blobs ([storage MIME set](../../../../src/elspeth/contracts/blobs.py#L56), [binary upload](../../../../src/elspeth/web/blobs/routes.py#L197)) and pass the `status == "ready"` filter, so they are listed as inline candidates although inline content is decoded as text ([decode](../../../../src/elspeth/core/blobs_inline.py#L391)). Run: ready `image/png` and `application/pdf` rows were listed and wired (default and `encoding: "latin-1"`). With the default `utf-8` encoding, validation refuses a PNG or a PDF containing high bytes with a structured `malformed_inline_blob_content` ("cannot decode as utf-8"). When the bytes do decode, it does not refuse them cleanly (N8).

**list_composer_blobs-N8 — demonstrated (probe P2b, §7), High:** when a binary-MIME blob's bytes decode (an ASCII-only PDF under `utf-8`, or any PNG/PDF under `encoding: "latin-1"`, which `wire_blob_inline_ref` accepts), validation raises an uncaught `ValueError` ("ResolvedBlobContent: mime_type must be one of [...]") rather than returning a violation. The exception comes from [`ResolvedBlobContent.__post_init__`](../../../../src/elspeth/contracts/blobs_inline.py#L123), which is constructed [after a successful decode](../../../../src/elspeth/core/blobs_inline.py#L372). The validation phase catches only `BlobContentResolutionError` ([catch](../../../../src/elspeth/web/execution/_validation_materialization.py#L536)), and `validation.py` lets untyped exceptions propagate as 500s ([W18 note](../../../../src/elspeth/web/execution/validation.py#L8)). The probe measured the exception escaping `validate_pipeline_for_trained_operator`. It did not trace how the composer preflight caller handles it, and it did not run the run-admission resolver, which builds the same object. The defect belongs mainly to `wire_blob_inline_ref`/`core/blobs_inline.py`; this tool's part is listing such rows as inline candidates. The listing's own `mime_type` field lets an agent avoid the problem only if it knows that inline content must be text (§5.1: nothing says so).

**list_composer_blobs-N5 — source-established, Low:** the missing-context refusal carries no `error_code` and is produced inside the handler ([handler](../../../../src/elspeth/web/composer/tools/blobs.py#L632)), whereas missing secret context is refused at the dispatcher with `error_code="secret_context_unavailable"` ([dispatch](../../../../src/elspeth/web/composer/tools/_dispatch.py#L935)). Production always wires the engine (§2); unless a null `session_id` can reach dispatch (untraced), this is result-shape parity for direct callers rather than a live dead end.

**list_composer_blobs-N6 — source-established, Low:** the whole-response credential refusal (§4) gives an instruction the agent cannot follow and no way to identify or skip the offending row; while that row exists every call refuses. Fail-closed refusal itself is intended; the message and all-or-nothing scope are the gap.

**list_composer_blobs-N7 — demonstrated on SQLite (probe P5, §7), Low:** `ORDER BY created_at DESC` without a unique tiebreaker leaves rows with equal timestamps in an order the query does not specify, so which rows make the 50 boundary is decided by physical storage order. Run: the same 55 ids, all with one `created_at`, were inserted in forward and then in reverse order. The 50-row membership differed: forward insertion excluded r50–r54, reverse excluded r00–r04. With ties, SQLite returned rows in insertion order, so the most recently inserted tied rows fell outside the window. Distinct timestamps (the control) gave identical membership either way. Repeated calls on an unchanged SQLite table were stable. Variation across calls on PostgreSQL was not run (needs Docker), and whether equal timestamps occur in practice (batched writers, coarse clock) was not measured.

### 5.1 Guidance parity

Instrument: `grep -n -i` for the tool name and for `list_blobs|wire_blob_inline_ref|inline_content|blob_ref|content_hash|\b50\b|newest|KiB|256` over both skill files. `pipeline_capabilities.md` (509 lines) has zero mentions of the tool or of any inline-content concept; control: the same file has four `blob` matches (e.g. its L38 discovery step) and `pipeline_composer.md` has two `list_composer_blobs` matches, so the grep works.

- **Declaration description overclaims** ([description](../../../../src/elspeth/web/composer/tools/blobs.py#L650)): "List ready blobs available for audited inline-content authoring" implies the complete eligible set; it is the newest 50 ready rows with no eligibility filter (BOS-01, N3, N4). The frontend tooltip repeats the claim to users: "Lists the ready files available for audited inline authoring" ([tooltip](../../../../src/elspeth/web/frontend/src/components/chat/toolCallDescriptions.ts#L50)) — the GS-03 class.

Neither skill says this tool is ready-only, carries `content_hash`, lacks origin fields, or is capped at 50. The pinned prompt test asserts that exact wording ([test](../../../../tests/unit/web/composer/test_prompts.py#L759)), so a correction must update it.
- **Skill routes inline wiring through a different tool**: the `reference_join` instruction says "use `get_blob_metadata` and wire the existing uploaded blob with `wire_blob_inline_ref`" ([skill L663–666](../../../../src/elspeth/web/composer/skills/pipeline_composer.md#L663)); `get_blob_metadata` needs an ID the agent must first discover, and the listing built for this purpose is not named here.

- Correct references: the [non-UUID repair message](../../../../src/elspeth/web/composer/tools/blobs.py#L526) and the [blob_id custody rule](../../../../src/elspeth/web/composer/planner_authoring_aids.py#L349) name this tool accurately as a blob_id source.

## 6. Structural remediation

Make inventory completeness and bounded continuation part of the blob discovery authority, then derive both ordinary and inline projections from it. Keep this tool's ready-only, content-free contract. The orchestrator should represent “more authorized resources remain” separately from “resource unavailable.” A paginated schema must reject cross-session, expired, malformed, or wrong-projection cursors and must define stability under concurrent insertion/deletion. Ordering needs a unique tiebreaker (`created_at`, `id`) before any cursor is defined. The existing offset-paged `BlobServiceImpl.list_blobs` is a precedent for bounds, not a ready answer: plain offset paging duplicates/skips under concurrent insertion. The planner manifest must take its `blob.index.composer` coverage from the page's completeness signal, as `list_models` already does with `truncated`.

To be first-class for inline authoring, the projection should also state eligibility the consumers enforce, without content: at least `creation_modality` (or a server-derived `llm_prompt_surface_allowed` boolean), and either filter or flag rows outside the inline size caps and text MIME types. Keep `wire_blob_inline_ref` and validation as the authorities; the listing reports, it does not authorize.

Positive checks should enumerate 51+ eligible files across pages, prove content/path/description never appears, and preserve authoritative hashes. Negative checks should reject forged cursors and corrupted ready metadata, and distinguish no ready rows from an incomplete page. Compatibility risk is Medium: `data.blobs` can remain, but new pagination arguments and metadata must reach every provider projection (including the strict no-argument marker, which disappears once the tool has arguments), response admission, the envelope teaching gate, audit redaction, the planner manifest, and planner instruction. Merely adding “latest 50” to prose contains confusion but leaves the capability gap.
