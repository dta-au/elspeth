# `read_attachment` — complete guarded attachment text

Assessment baseline: `3b28d537be98234da8135c418bf185a998c18b68` (0.8.9). Reconnaissance only. **Overall confidence: High for source and controlled positive/rejection probes; Moderate for unmeasured resource impact.** Sheet reviewed and extended 2026-11-09 (corrections are marked *Review correction*; new findings carry provisional `read_attachment-N*` IDs). All added probe evidence is from in-memory handler/dispatch runs against SQLite with genuine operation authority, not an end-to-end service run.

## 1. Purpose and usage

Select this tool for one authorized instruction, requirement, or reference attachment whose complete UTF-8 text the orchestrator needs before reasoning. It exists to avoid confusing a short prefix with a complete document or spending many dependent model turns on small pages. It does not parse tabular source structure. It requires a web session engine/ID, the service data root, and an exact `SessionOperationContext` for the same session plus an operation authority; it is unavailable through Composer MCP.

*Review correction:* the sheet previously said "exact **read-capable** operation authority". The tool's shared reader checks only that the context is an exact `SessionOperationContext` whose fence session matches ([`blobs.py#L1940-L1945`](../../../../src/elspeth/web/composer/tools/blobs.py#L1940)); unlike the canonical [`read_blob_content_sync`](../../../../src/elspeth/web/blobs/service.py#L3327), it never applies [`_require_blob_operation_context(..., _READ_BLOB_OPERATION_KINDS)`](../../../../src/elspeth/web/blobs/service.py#L168). See read_attachment-N1.

## 2. Contract

Required `blob_id: string`; optional `expected_content_hash` is omitted/null or canonical lowercase 64-hex SHA-256. Extra fields and type coercion are rejected: on the public route (`validate_arguments=True, raise_schema_argument_errors=True`) the declared-schema check raises `ToolArgumentError` for compose-loop ARG_ERROR routing; with `validate_arguments` alone it returns `Invalid arguments for tool 'read_attachment': arguments contains unsupported properties.` (probe). `blob_id` must parse as `uuid.UUID`, which also admits uppercase, braced and `urn:uuid:` forms ([`_blob_id_uuid_validation_error`](../../../../src/elspeth/web/composer/tools/blobs.py#L518)). Every supplied hash must match the verified original bytes. Success always returns full exact decoded content and metadata/origin with `start_char=0`, `end_char=total_chars`, `truncated=false`, and `next_offset_chars=null`; this is enforced at admission by [`CompleteAttachmentDataModel`](../../../../src/elspeth/web/composer/_attachment_response.py#L21), which also re-hashes the content and requires `len(content.encode()) == size_bytes`. A complete serialized response must fit **262,144 UTF-8 bytes** at this baseline: [`READ_ATTACHMENT_MAX_UTF8_BYTES`](../../../../src/elspeth/web/composer/redaction.py#L3411) `= min(JSON_MAX_TOTAL_UTF8_BYTES=1,048,576, DEFAULT_CREDENTIAL_TRAVERSAL_POLICY.max_string_bytes=262,144)`. The serialized size is measured on `json.dumps` with its default `ensure_ascii=True` ([`discovery_response.py#L66`](../../../../src/elspeth/web/composer/discovery_response.py#L66)), so each non-ASCII BMP character costs 6 bytes, and the envelope includes the unchanged state's `validation` block. Aggregate provider/guard limits still apply. An oversized file or escaped response explicitly refuses rather than truncates. Paging is an alternative only if the whole original text passes credential admission.

It is uncached `BLOB_DISCOVERY` (measured: `is_cacheable_discovery_tool("read_attachment") is False`, control `list_sources` is `True`), with a selected attachment response contract, unchanged composition version, no mutation approval, and `resolve_tool_effects(...) == ToolEffects(domains=())`. Handler order ([`blobs.py#L2175-L2244`](../../../../src/elspeth/web/composer/tools/blobs.py#L2175)): session engine/ID present → strict argument model → UUID parse → custody-locked read and hash verification → not-found / not-ready / missing-file refusals → **raw byte size > 262,144 refusal** → UTF-8 decode → expected-hash comparison → credential inspection of the whole payload → contract admission → serialized-size refusal. *Review correction:* the earlier summary omitted the raw-size check that precedes decoding.

## 4. Alternative paths

A small valid file yields one complete response. A matching expected hash constrains identity. A mismatch discloses no content, but the mismatch check runs after the size and UTF-8 checks, so an oversized or undecodable file reports that condition instead of the identity mismatch (read_attachment-N7). Invalid UTF-8 has no lossy replacement fallback, and no composer reader decodes another encoding (`inspect_source` takes `encoding` only for tabular structure). If source bytes exceed the whole-input limit, neither this tool nor page reading can bypass it. If only JSON escaping/envelope overhead exceeds the response bound, selected pages remain available. *Now demonstrated:* 60,000 × `α` (120,000 raw bytes) refuses with the serialized-response message, and `get_blob_content` then needs **119** dependent pages. Each page repeats a full read, hash and credential scan (BOS-05). Pending/error blobs and missing files refuse; corruption escalates. A storage recovery obligation is reconciled under custody before reading. Binary document blobs (`application/pdf`, `image/png`, `image/jpeg` are storage MIME types, [`contracts/blobs.py#L46`](../../../../src/elspeth/contracts/blobs.py#L46)) are not refused by type (read_attachment-N5).

## 5. Usability assessment

The full-delivery contract is useful and explicit. **BOS-02 — demonstrated taxonomy divergence:** a ready metadata row with missing storage returns a generic failed tool result here, while the canonical content service raises `BlobContentMissingError`. Same-fence local probes verified that difference, plus a restored-file positive control and expected-hash rejection. Workaround: report an infrastructure/storage problem rather than cycling tool arguments. *Review extension:* the divergence has a third arm. `ESTALE`, the errno a sibling replica's delete produces on a shared NFS mount, is not caught by this reader and escapes as a raw `OSError` (read_attachment-N2).

**BOS-05 — source-established resource limitation:** the handler checks its 262,144-byte limit only after `_locked_read_ready_blob` reads/hashes the entire file. Therefore a successful bounded response or an eventual refusal does not establish bounded read allocation. No operational memory/latency effect was measured. Complete-content admission and refusal are intended safety constraints, not defects to evade by slicing first. The row's `size_bytes` is available inside the lock before `read_bytes()`, so an oversized ready row could be refused before materialisation (§6.1 E10).

In-memory dispatch under an `ARCHIVE` operation context returned `success=true` with the full range. Under the same context, `BlobServiceImpl.read_blob_content_sync` raised `ValueError: session operation context has an invalid operation kind for this blob effect`. No public route was shown to dispatch a composer tool under a non-read kind; exploitability is unverified. Shared by all §3.1 shared-reader consumers. This is the same class as SG-04.

- **read_attachment-N3 — demonstrated undisclosed effective limit.** The bound is on ASCII-escaped JSON, so `size_bytes` from `list_blobs`/`get_blob_metadata` is only a lower bound. ## 6. Structural remediation

The blob service should own one verified-content observation contract with explicit read purpose and operation-kind admission, full-input admission limits, integrity failure classification (including every raced-deletion errno), and canonical identity. Enforce whole-read eligibility before materialising a known oversized artifact where possible; use the existing streamed verification machinery when complete verification is still required. Preserve exact content and untrusted provenance. The orchestrator should distinguish “complete document delivered,” “pages available,” “input forbidden/too large,” “not a text document,” and “owned storage failure.”

Acceptance: a complete small Unicode document returns exact text and terminal ranges; escaped response overflow refuses without any prefix; supplied wrong hash, wrong session, stale authority, non-read operation kind, bad encoding, binary MIME, credentials anywhere, and input limit violations disclose no content; missing owned bytes (`ENOENT` and `ESTALE`) classify consistently with API; resource bounds are measured with oversized valid artifacts. Compatibility risk is Medium for enriched failure outcomes and shared reader changes. The existing complete-success shape can remain unchanged.
