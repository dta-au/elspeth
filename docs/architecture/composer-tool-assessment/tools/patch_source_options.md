# `patch_source_options` — independent tool assessment

Baseline: ELSPETH **0.8.9**, `3b28d537be98234da8135c418bf185a998c18b68`. Reconnaissance and remediation design only. Incoming `.10 lite` changes are outside this assessment and require affected-source reinspection.

## 1. Purpose and usage

Change only author-owned options on one existing named source while retaining its plugin, routing and description. This is the narrow edit operation for source configuration.

Select for option-only edits; use set_source or blob binding to change plugin/binding, and set_source to alter source routing (`on_success`, `on_validation_failure`). Requires a matching saved source and request policy snapshot. On a multi-source graph `source_name` must be supplied: the default `source` is a literal name, not "the only source" (patch_source_options-N9).

## 2. Contract

Required patch:object; source_name defaults `source`. It is a **shallow** top-level merge ([`_apply_merge_patch`](../../../../src/elspeth/web/composer/tools/_common.py#L1753)): absent keys retain values, null deletes (delete of an absent key is a silent no-op), and a nested object replaces that entire value. Routing fields are not arguments, and the patch has no routing-key guard of its own: `on_success`/`plugin` inside the patch refuse only through the plugin config's "Extra inputs are not permitted", while an `on_validation_failure` equal to the routing field is accepted into options (patch_source_options-N4). Existing plugin, failure destination and description are preserved.

Server-owned echoes are tolerated **selectively**: an exact echo of `source_authoring`, of stored `interpretation_requirements` rows, or of the stored `schema.guaranteed_fields` stamp passes ([sources.py:2082-2089](../../../../src/elspeth/web/composer/tools/sources.py#L2082), [sources.py:2107](../../../../src/elspeth/web/composer/tools/sources.py#L2107)); an exact echo of `blob_ref`, of plural `blobs`, or of `path` on a blob-backed source is refused ([sources.py:2099](../../../../src/elspeth/web/composer/tools/sources.py#L2099), [sources.py:2140-2164](../../../../src/elspeth/web/composer/tools/sources.py#L2140)) (patch_source_options-N3). Forged review/provenance is refused. For `interpretation_requirements`, `null` is refused as an invalid shape while `[]` replaces the list and is accepted for a resolved `source_data_contract` row (patch_source_options-N5).

Result on a change: `success`, `validation`, `validation_delta`, `affected_nodes` (the source component id), `version` (+1), `applied_component` (the source and its edges), optional `post_call_hints` and optional `data.server_owned_metadata_note`. After reconciliation the entire authority payload is compared with version neutralised using standard JSON ([sources.py:2247-2259](../../../../src/elspeth/web/composer/tools/sources.py#L2247)): exact no-change returns the original state/version, empty `affected_nodes` and **no** `applied_component`; there is no explicit no-change field (envelope keys measured: `affected_nodes, success, validation, validation_delta, version`) (patch_source_options-N11). The comparison covers the whole graph, so reconciliation of another component makes the result a change attributed only to the source (patch_source_options-N1). No execution, provider call, blob write, auto retry or approval bypass occurs.

The handler returns an immutable candidate; it does not itself durably save the conversation. In web explicit_approve mode the call is first dispatched as a *preview*; the proposal is staged whether or not that preview succeeds and whether or not it changed anything, it is relabelled as a whole-pipeline `set_pipeline` proposal when required-control finalization changes the previewed state, and it is re-executed on acceptance. A no-op source patch therefore reaches acceptance, 409s, and stays `pending` through repeated Accepts (patch_source_options-N2, demonstrated in §7.1). Otherwise the enclosing tool batch applies the accepted state, and the session turn persists it under its operation authority. Across both provider dialects, the provider wire projection is decoded to canonical arguments before dispatch; strict transport representation does not grant different authority (`openai_strict` emits this tool with `strict: false` because `patch` is an open object). A ToolResult's `success` records operation admission, while `validation.is_valid`, runtime preflight, review and execution admission answer separate questions. Owned-code/audit integrity failures escape as faults rather than being reclassified as ordinary invalid model input; literal credential material in the patch raises `CredentialMaterialRefused` at the dispatcher guard ([_dispatch.py:908](../../../../src/elspeth/web/composer/tools/_dispatch.py#L908); [test_tools_mutations.py:2892](../../../../tests/unit/web/composer/test_tools_mutations.py#L2892)). The exception is reconciliation: `KeyError`/`TypeError`/`ValueError` become the ordinary refusal `review_reconciliation_failed` ([sources.py:2233-2241](../../../../src/elspeth/web/composer/tools/sources.py#L2233)).

## 4. Alternative paths

Missing source returns source_not_found, naming only the requested name. Removed/unavailable plugin is a policy refusal before schema augmentation. Patch delta is checked for forged resolver review evidence and planner-authored observed-mode guarantee stamps (`source_data_contract_required` on non-LLM-authored sources); merged options are checked for canonical metadata, endpoint policy, credentials, confined paths and actual plugin config, and an `options.on_validation_failure` that differs from the routing field is refused ([_common.py:3517](../../../../src/elspeth/web/composer/tools/_common.py#L3517)). Review reconciliation can reject atomically. Changed source input/schema can reopen authority reviews ([test_authoring_reconciliation.py:693](../../../../tests/unit/web/composer/test_authoring_reconciliation.py#L693)); unchanged metadata echoes must not downgrade approved evidence. Setting a mandatory option to null ordinarily deletes it and then fails plugin admission; null does not mean plugin-specific nullable value. Because every merged-options gate runs on the whole merged mapping, an empty or unrelated patch is refused when the *stored* options already violate policy (out-of-session path, invalid encoding) ([test_patch_source_options_noop.py:318-338](../../../../tests/unit/web/composer/test_patch_source_options_noop.py#L318)). A valid patch can leave unrelated graph errors. Path policy differs by route: direct callers without flags skip it; web routes confine to the session blob subtree; MCP refuses every local path (N6). The path refusal message is the same generic text for "no data_dir" and "outside allowed directories" ([sources.py:2201-2208](../../../../src/elspeth/web/composer/tools/sources.py#L2201)).

## 5. Usability assessment

**SG-03 — useful existing reference implementation, with two qualifications; high confidence.** This tool explicitly distinguishes no semantic change from a version advance, unlike empty node/metadata patches ([test_patch_source_options_noop.py:155](../../../../tests/unit/web/composer/test_patch_source_options_noop.py#L155) pins empty, same-value, delete-absent and same-nested-value no-ops on both surfaces). It is not a defect here; it demonstrates that the progress contract can be made consistent. The qualifications: the comparison is whole-graph, so an empty source patch that reconciles another component reports a source change (N1); and the explicit-approve path does not consume the no-op, so the user is asked to approve a change that 409s (N2). **SG-06 — shared admission pressure.** The handler repeats source candidate checks and review reconciliation alongside replacement/binding/bulk authoring. Workaround: supply the complete intended nested mapping, and inspect returned applied component rather than assuming recursive JSON Merge Patch semantics.

Reachability of a resolved-but-unstamped node in a saved graph is unverified (the fixture is built from primitives).
- **patch_source_options-N2 — demonstrated (compose turn + accept route, §7.1 P1); explicit-approve dead end.** A no-op patch previews as success with unchanged version; the preview result is used only for required-control relabelling ([tool_batch.py:2057-2125](../../../../src/elspeth/web/composer/tool_batch.py#L2057)), so a proposal is staged and the model is told `APPROVAL_REQUIRED`. On Accept, re-execution again leaves version unchanged and the route raises 409 "Accepted proposal did not change composition state." without the auto-reject that its failure branch performs ([proposals.py:551](../../../../src/elspeth/web/sessions/routes/composer/proposals.py#L551), [L632-L636](../../../../src/elspeth/web/sessions/routes/composer/proposals.py#L632)). `grep -rn "did not change composition state"` over `tests/` and `src/` matches only that source line, so no test pins it. [patch_output_options](patch_output_options.md) and node patches never reach this branch because their no-ops advance version. Measured (§7.1 P1): echo-only and empty patches each staged one pending proposal, and the model saw the same `APPROVAL_REQUIRED` envelope as for a real change. On Accept the route returned 409, the proposal stayed `pending`, and a second Accept returned 409 again. The proposal can only leave that state by user rejection.
- **patch_source_options-N3 — demonstrated (in-memory dispatch, mock catalog); read-modify-write refusal on blob-backed sources.** `get_pipeline_state(component="source")` on the blob-backed fixture returns options `blob_ref: "abc123"`, `path: "<redacted-blob-source-path>"`, `schema`. Patching that mapping plus one real change refuses `source_binding_locked` "Cannot patch 'blob_ref' on a source. Re-bind via set_source_from_blob…"; dropping `blob_ref` refuses again on `path`; the changed key alone succeeds. Echo tolerance covers `source_authoring`, requirement rows and guarantee stamps but not binding keys, and an identical `path` is refused by design ([test_tools_mutations.py:2965](../../../../tests/unit/web/composer/test_tools_mutations.py#L2965)). Refusing the redacted placeholder is correct. The defect is actionability: the message tells an agent that was only echoing to re-bind, and the ownership note never says `path` is locked on blob-backed sources.
- **patch_source_options-N4 — demonstrated (in-memory dispatch); routing/identity keys.** `{"on_success": "elsewhere"}` and `{"plugin": "json"}` refuse `plugin_options_invalid` "…: Extra inputs are not permitted" without naming set_source. `{"on_validation_failure": "discard"}` (equal to the routing field) succeeds, version 7→8, and stores a shadow `on_validation_failure` key in options. Nothing executes incorrectly. The shadow copy is a second authority for the failure destination, and the refusals are not actionable.
- **patch_source_options-N5 — demonstrated (in-memory public dispatch, `validate_arguments=True`); evidence retention asymmetry; policy owner undecided.** On `_resolved_source_contract_state`, `{"interpretation_requirements": []}` succeeds, version 3→4, removes the resolved `source_data_contract` row (with its `event_id`/`accepted_artifact_hash`) and keeps the user-written `schema.guaranteed_fields: ["colour"]`. Validation stays valid. `{"interpretation_requirements": null}` refuses `interpretation_requirements_invalid`, contradicting "null deletes". The same `[]` is refused for a required `invented_source` row ([test_source_interpretation_requirement_guard.py:461](../../../../tests/unit/web/composer/test_source_interpretation_requirement_guard.py#L461)) and for outputs ([test_tools_mutations.py:3369](../../../../tests/unit/web/composer/test_tools_mutations.py#L3369)). Not a review bypass: the stamp still cannot be changed, and dropping it afterwards yields `schema_contract_violation` with no reopened review. Audit-loss residual **refuted** by a real resolve → `[]` → save round trip (§7.1 P5): the `interpretation_events` row is unchanged (`accepted_as_drafted`, `resolved_at` set).
