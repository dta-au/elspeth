# `request_advisor_hint` assessment

Baseline: `3b28d537be98234da8135c418bf185a998c18b68` — 0.8.9. Reconnaissance and design only.

## 1. Purpose and exposure

Ask the independent advisor for bounded guidance, including an evidence-based cannot_complete review. Advice never directly mutates graph structure. The tool is exposed in web freeform Composer and intercepted before synchronous dispatch; the CLI MCP surface deliberately excludes it. It is distinct from mandatory EARLY/END publication checkpoints.

The proposal planner, which serves every structurally empty draft when a session, user message and sessions service are present ([src/elspeth/web/composer/service.py:1233](../../../../src/elspeth/web/composer/service.py#L1233)), does not offer this tool; its own advisor "escape hatch" is a model override inside `plan_pipeline`, not this tool. A first build from an empty draft therefore cannot reach `cannot_complete`.

## 2. Contracts and authority

Public schema requires an allowed trigger and structured request fields with bounded content; `_validate_advisor_arguments` returns an owned request or an argument rejection ([src/elspeth/web/composer/advisor_checkpoint.py:261](../../../../src/elspeth/web/composer/advisor_checkpoint.py#L261)). Budget and deadline admission are server-owned. Cannot-complete review must be alone in its batch and carries current request/graph/evidence; outcomes are CONTINUE, CONTINUE_WITH_LIMITATION or STOP_CONFIRMED. Status and outer dispatch success differ: an audited dispatch closes with `finish_success` while reporting BUDGET_EXHAUSTED, COMPOSE_TIMEOUT, DEADLINE_TOO_CLOSE or ADVISOR_ERROR without useful advice ([src/elspeth/web/composer/tool_batch.py:2262](../../../../src/elspeth/web/composer/tool_batch.py#L2262), [src/elspeth/web/composer/tool_batch.py:2338](../../../../src/elspeth/web/composer/tool_batch.py#L2338)). The public definition is [src/elspeth/web/composer/tools/_dispatch.py:135](../../../../src/elspeth/web/composer/tools/_dispatch.py#L135); the owned argument model is [src/elspeth/web/composer/tools/sessions.py:224](../../../../src/elspeth/web/composer/tools/sessions.py#L224).

Only `cannot_complete` is held to the singleton rule; proactive triggers may share a batch with any other call, including `set_pipeline` ([src/elspeth/web/composer/tool_batch.py:992](../../../../src/elspeth/web/composer/tool_batch.py#L992)). The tool declares no composition effect domains (`ToolEffects()` at [src/elspeth/web/composer/tools/_registry.py:122](../../../../src/elspeth/web/composer/tools/_registry.py#L122)) and is neither a discovery nor a mutation tool for budget and anti-anchor classification (measured: `is_discovery_tool`, `is_mutation_tool`, `is_session_aware_tool`, `is_cacheable_discovery_tool` all `False`; `list_sources` and `set_pipeline` controls `True` respectively).

## 3. Source trace to the user

Batch detects mixed abandonment calls, then advisor interception validates inputs, checks budget and remaining deadline, reserves a call, and invokes AdvisorCheckpointOwner ([src/elspeth/web/composer/tool_batch.py:992](../../../../src/elspeth/web/composer/tool_batch.py#L992), [src/elspeth/web/composer/tool_batch.py:2293](../../../../src/elspeth/web/composer/tool_batch.py#L2293), [src/elspeth/web/composer/tool_batch.py:2442](../../../../src/elspeth/web/composer/tool_batch.py#L2442)). The advisor wrapper replaces the model's `schema_excerpt` with a server-rendered graph summary, adds the visible same-session transcript and makes an independently audited provider call with SDK retries disabled ([src/elspeth/web/composer/advisor_checkpoint.py:312](../../../../src/elspeth/web/composer/advisor_checkpoint.py#L312), [src/elspeth/web/composer/advisor_checkpoint.py:358](../../../../src/elspeth/web/composer/advisor_checkpoint.py#L358), [src/elspeth/web/composer/advisor_request.py:38](../../../../src/elspeth/web/composer/advisor_request.py#L38)). Provider errors and first-party errors have distinct outcomes; successful abandonment advice is bound to request-owned evidence ([src/elspeth/web/composer/tool_batch.py:2542](../../../../src/elspeth/web/composer/tool_batch.py#L2542), [src/elspeth/web/composer/tool_batch.py:2612](../../../../src/elspeth/web/composer/tool_batch.py#L2612), [src/elspeth/web/composer/tool_batch.py:2655](../../../../src/elspeth/web/composer/tool_batch.py#L2655)).

The invocation result retains cost/accounting metadata while model feedback strips budget counters ([src/elspeth/web/composer/advisor_request.py:13](../../../../src/elspeth/web/composer/advisor_request.py#L13)). Invocation and inner LLM-call records flow into turn persistence; the persisted chat row is the manifest-redacted projection ([src/elspeth/web/composer/turn_audit.py:35](../../../../src/elspeth/web/composer/turn_audit.py#L35)). The SPA renders the call as a ToolCallCard ribbon whose label comes from a server-stamped outcome and whose tooltip falls back to "Composer tool call." because the tool has no description entry ([src/elspeth/web/frontend/src/components/chat/toolCallDescriptions.ts:106](../../../../src/elspeth/web/frontend/src/components/chat/toolCallDescriptions.ts#L106)). The planner may incorporate guidance in its subsequent reply. No advice payload grants graph publication authority or replaces END review: a current STOP_CONFIRMED only disables repair continuation, and the END gate still runs ([src/elspeth/web/composer/composition_completion.py:1554](../../../../src/elspeth/web/composer/composition_completion.py#L1554), [src/elspeth/web/composer/composition_completion.py:1743](../../../../src/elspeth/web/composer/composition_completion.py#L1743)). Any later tool batch in the same request discards the stop ([src/elspeth/web/composer/tool_batch.py:1008](../../../../src/elspeth/web/composer/tool_batch.py#L1008), [src/elspeth/web/composer/turn_effects.py:591](../../../../src/elspeth/web/composer/turn_effects.py#L591)); limitations from CONTINUE_WITH_LIMITATION persist for the request ([src/elspeth/web/composer/turn_effects.py:640](../../../../src/elspeth/web/composer/turn_effects.py#L640)).

## 4. Branches, failures and recovery

Argument error: no outbound advisor call or budget use. The advisor's own validator charges a discovery turn and an anti-anchor failure; an earlier generic pre-dispatch rejection (invalid JSON, non-object, wire envelope, canonicalization, missing required path) charges a composition turn and returns a different `{"error": ...}` shape. Exhausted budget, no remaining time, or deadline too close: explicit statuses without egress. Once admitted, failure still consumes budget — including two paths with no egress after reservation: abandonment evidence that exceeds the safe-input boundary ([src/elspeth/web/composer/advisor_checkpoint.py:522](../../../../src/elspeth/web/composer/advisor_checkpoint.py#L522)) and a prompt-guard refusal. Advisor-specific timeout may allow primary continuation; compose-deadline timeout ends the request path. Provider failure gives bounded feedback; malformed advisor response is not a stop confirmation. Controlled-code faults retain the actual exception and audit; prompt-guard refusal is separate. Cancellation propagates with captured inner-call evidence. A successful advisor call clears the **entire** anti-anchor failure window, for every tool ([src/elspeth/web/composer/anti_anchor.py:141](../../../../src/elspeth/web/composer/anti_anchor.py#L141), [src/elspeth/web/composer/tool_batch.py:2713](../../../../src/elspeth/web/composer/tool_batch.py#L2713)); a limitation preserves useful authorized work ([src/elspeth/web/composer/tool_batch.py:2325](../../../../src/elspeth/web/composer/tool_batch.py#L2325), [src/elspeth/web/composer/tool_batch.py:2369](../../../../src/elspeth/web/composer/tool_batch.py#L2369), [src/elspeth/web/composer/tool_batch.py:2470](../../../../src/elspeth/web/composer/tool_batch.py#L2470), [src/elspeth/web/composer/tool_batch.py:2643](../../../../src/elspeth/web/composer/tool_batch.py#L2643)).

**Cache, idempotency, concurrency and retry:** This intercepted async tool is not a cacheable discovery tool. Every admitted call may perform new provider work and consume budget; the tool has no same-arguments idempotency promise. Anthropic prompt-prefix caching, where supported, is a provider optimization and does not mean result replay. A hint invokes one bounded audited provider call with SDK retries disabled; the separate mandatory checkpoint workflow has its own bounded-attempt policy and must not be confused with hint retries (`advisor_request.py:38–40`, `advisor_checkpoint.py:1348`). Budget is reserved before outbound work. Calls run under request/provider custody and current evidence binding; stale advice never authorizes a graph mutation or terminal publication. Cancellation preserves inner-call evidence, and a new hint after uncertain delivery can incur additional cost.

Advice has no independent graph-mutation proposal approval; server-owned egress/budget admission governs the call. A later mutation applying advice follows its own ordinary approval policy. Completed operation replay must reuse the durable operation outcome, while issuing a fresh advisor tool call may spend again; this lane's mocked advisor tests do not establish the entire operation-replay/process-death matrix.

## 5. Defects, restrictions and hypotheses

The earlier review recorded no advisor behavioral defect. The findings below were found afterwards by source tracing and in-memory runs; N2, N6, N7, N8 and N13 were then demonstrated by probe runs through the real freeform `compose()` loop with scripted primary and advisor providers (§7.1). None is a live-provider or deployed-service observation. **Structural observation:** argument validation, budget, timeout, failure mapping, cost audit, evidence binding and feedback shaping live across batch and advisor owners; a registry entry by itself cannot make this a first-class tool. **Restriction:** advisor suggestions require verified subsequent mutation calls and independent final review. No operational claim about live advisor quality, expense or latency is supported by mocked tests.

- **request_advisor_hint-N1 — demonstrated (in-memory handler run).** The model's `schema_excerpt` never reaches the dedicated "Relevant schema excerpt" section. The batch always passes `current_state` ([tool_batch.py:2465](../../../../src/elspeth/web/composer/tool_batch.py#L2465)), and `_call_advisor_for_tool` then overwrites the field with the server graph summary ([advisor_checkpoint.py:358](../../../../src/elspeth/web/composer/advisor_checkpoint.py#L358)). Calling `_call_advisor_for_tool` with a stubbed `_call_advisor_with_audit` and an empty state captured a sent excerpt of `Pipeline: Untitled Pipeline | Source: (none set) | ...`, not the submitted marker. The submitted text survives only inside the transcript's JSON copy of the call's own arguments, which is what [test_advisor_tool.py:606](../../../../tests/unit/web/composer/test_advisor_tool.py#L606) asserts. The argument description promises field-level grounding.
- **request_advisor_hint-N2 — demonstrated (compose probe P2, §7.1); also pinned by a test.** Prompt-budget admission and dispatch measure different messages. Admission measures the public fields with the model excerpt in the excerpt section ([advisor_checkpoint.py:289](../../../../src/elspeth/web/composer/advisor_checkpoint.py#L289)). The sent message adds the request, the visible transcript and the graph summary. `grep -n "limit\|cap\|max_\|truncat\|bound"` over `advisor_transcript.py` found no transcript bound (see P2), and the dispatch-time size check is skipped whenever a transcript is present ([advisor_checkpoint.py:473](../../../../src/elspeth/web/composer/advisor_checkpoint.py#L473)). [test_advisor_tool.py:1762](../../../../tests/unit/web/composer/test_advisor_tool.py#L1762) admits a 308-character cap and asserts the sent content is longer. The settings description ("Public hints count the complete variable message", [config.py:500](../../../../src/elspeth/web/config.py#L500)) and the `_validate_advisor_arguments` docstring ("exact formatted user-message") overclaim. The PROMPT_BUDGET refusal can tell the model to truncate a schema excerpt that would not occupy that section. Probe P2 measured no transcript bound below the provider-context limit. With `composer_advisor_max_prompt_tokens=500`, the cap is 2,000 chars. A small proactive hint was admitted and sent a 4,070-char user message (2.0×). After a 410,088-char in-turn `get_plugin_schema` result, the same hint was admitted and sent 416,468 chars (208×), with the schema text inside.
- **request_advisor_hint-N3 — demonstrated (in-memory redaction run) for the chat-storage projection; not an audit loss for the case checked.** The persisted chat (`role=tool`) row loses outcome-discriminating keys. `known_response_keys` ([redaction.py:4114](../../../../src/elspeth/web/composer/redaction.py#L4114)) omits `outbound_call_made` (DEADLINE_TOO_CLOSE and prompt-guard refusal), `request_rejection` (provider request rejection) and the guard's `error_type`/`detail`/`audit_id`. `redact_tool_call_response`, the function `_serialize_response_via_walker` uses for every `error_class is None` outcome, collapsed each of them to `_unknown_response`. This fails closed and leaks nothing. The exact in-memory invocation record keeps the values; the chat-row and SPA projection does not. The comment's shape list is stale ("Disabled path", "service.py:2114-2358"). The P1 run also observed the collapse through real compose persistence: the DEADLINE_TOO_CLOSE chat row held `_unknown_response` in place of `outbound_call_made`. The same persisted cohort also writes a private `role=audit` "Private credential-filtered tool evidence" row ([audit_storage.py:501](../../../../src/elspeth/web/composer/audit_storage.py#L501), [sessions/service.py:2126](../../../../src/elspeth/web/sessions/service.py#L2126)). A follow-up run of the P1 DEADLINE_TOO_CLOSE case that read private evidence (§7.1, fix-up check for N3) found that row's `result` with disposition `retained` and content `{"budget_remaining":4,"budget_used":0,"outbound_call_made":false,"status":"DEADLINE_TOO_CLOSE"}`, so the audit record keeps that key; the SUCCESS control's audit row likewise retained the guidance the chat row redacts. The `request_rejection` and prompt-guard `error_type`/`detail`/`audit_id` outcomes were not checked in the audit row. N3 is therefore a chat/SPA projection gap, not shown to be an audit gap. The existing test [test_advisor_tool.py:1180](../../../../tests/unit/web/composer/test_advisor_tool.py#L1180) asserts that collapsed durable payload as expected behaviour.
- **request_advisor_hint-N4 — source-established.** Budget class depends on which layer rejects. The generic pre-dispatch rejections at [tool_batch.py:1244](../../../../src/elspeth/web/composer/tool_batch.py#L1244), [:1340](../../../../src/elspeth/web/composer/tool_batch.py#L1340), [:1411](../../../../src/elspeth/web/composer/tool_batch.py#L1411), [:1518](../../../../src/elspeth/web/composer/tool_batch.py#L1518) and [:1685](../../../../src/elspeth/web/composer/tool_batch.py#L1685) set `turn_has_mutation` because `is_discovery_tool` is false. The advisor's own rejection sets `turn_has_discovery` ([:2322](../../../../src/elspeth/web/composer/tool_batch.py#L2322)). A malformed or trigger-less advisor call therefore spends composition budget and receives a different feedback shape (`{"error": ...}` versus `{"status": "ARG_ERROR", ...}`). This contradicts the comment at [:1094](../../../../src/elspeth/web/composer/tool_batch.py#L1094).
- **request_advisor_hint-N5 — demonstrated (in-memory call).** Progress events are misleading. `tool_started_progress_event("request_advisor_hint")` returned "I'm updating the pipeline graph." / "A pipeline-editing tool is running." / "ELSPETH will validate the updated pipeline." - **request_advisor_hint-N6 — demonstrated (compose probe P4, §7.1).** A successful advisor call resets anti-anchor tracking for every tool. `record_success()` clears the whole window ([anti_anchor.py:141](../../../../src/elspeth/web/composer/anti_anchor.py#L141)), The `execute_tool` path resets only on a composition-version advance ([tool_batch.py:3336](../../../../src/elspeth/web/composer/tool_batch.py#L3336)). The explicit-approval proposal branch also resets, on a staged proposal ([tool_batch.py:2243](../../../../src/elspeth/web/composer/tool_batch.py#L2243)). The advisor is the only tool whose non-mutating success clears the window. Repeated identical `set_pipeline` failures interleaved with successful proactive hints never accumulate a §7.7 window. The inline comment ("reset for this tool name") is inaccurate. Probe P4 scripted three identical failing `set_pipeline` calls (each an ARG_ERROR for an unknown plugin). With nothing between them, the §7.7 hint reached the next primary call. With a successful `get_pipeline_state` between the second and third failure, it still did. With a successful proactive `request_advisor_hint` there instead, no hint was sent. The module docstring ("Any tool *success* clears the failure window") states the advisor behaviour. The `execute_tool` comment explains why discovery successes must not clear it. Whether models interleave hints this way in practice is a hypothesis.
- **request_advisor_hint-N7 — demonstrated at the compose layer (probe P3, §7.1); route reachability unverified.** Abandonment evidence that cannot be retained ([advisor_checkpoint.py:522](../../../../src/elspeth/web/composer/advisor_checkpoint.py#L522), raised before `_litellm_acompletion`) maps to the generic ADVISOR_ERROR "Advisor call failed; no guidance returned." ([advisor_checkpoint.py:369](../../../../src/elspeth/web/composer/advisor_checkpoint.py#L369)). Budget was already reserved, and the payload has no `outbound_call_made`. The model cannot tell this deterministic, non-retryable condition from a transient fault. Retrying burns budget, and the comment at [tool_batch.py:2438](../../../../src/elspeth/web/composer/tool_batch.py#L2438) lists only two no-egress cases. Reachability needs a request whose provider context exceeds `JSON_MAX_TOTAL_UTF8_BYTES` (1,048,576). Probe P3 put `get_plugin_schema` → `cannot_complete` in one freeform turn. A 614,788-char schema result gave a retained 770,515-byte advisor context and one SDK call; that is the control. A 921,838-char result gave disposition `unavailable` with reason `bounds`. The result was ADVISOR_ERROR, "Advisor call failed; no guidance returned.", with `error_class: AdvisorAbandonmentContextUnavailable`, zero SDK calls, zero advisor LLM-call audit rows, and `budget_used` 1. The payload has no `outbound_call_made` and no non-retry instruction. The model is fed the error class name, which is its only hint. The probe did not test whether a real route can put this much evidence in one turn; large blob reads are the likely carrier. The POST route caps the user message itself at 65,536 chars ([schemas.py:167](../../../../src/elspeth/web/sessions/schemas.py#L167)).
