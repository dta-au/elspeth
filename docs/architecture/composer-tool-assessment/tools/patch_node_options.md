# `patch_node_options` — independent tool assessment

Baseline: ELSPETH **0.8.9**, `3b28d537be98234da8135c418bf185a998c18b68`. Reconnaissance and remediation design only. Incoming `.10 lite` changes are outside this assessment and require affected-source reinspection.

## 1. Purpose and usage

Edit only an existing node's plugin options with a shallow top-level patch, while keeping node identity/kind/routing. The tool revalidates the exact reconciled candidate before publishing it.

Select for option-only changes. Use upsert_node for input/on_success/on_error/routes/fork changes, and preserve structured prompt interpretation references when editing model prompts.

## 2. Contract

Required node_id:string and patch:object; no other fields. Missing keys remain; null deletes (a null on an absent key is a silent no-op, [`_apply_merge_patch`](../../../../src/elspeth/web/composer/tools/_common.py#L1753)); nested objects and lists replace completely. The five routing keys `input`, `on_success`, `on_error`, `routes`, `fork_to` ([`_NODE_ROUTING_OPTION_PATCH_KEYS`](../../../../src/elspeth/web/composer/tools/transforms.py#L91)) refuse `node_routing_patch_invalid` before any plugin check, even if a permissive plugin would accept them. Other node-level `NodeSpec` fields (`plugin`, `node_type`, `condition`, `trigger`, `description` on a non-queue node, …) are not recognised as such: they are treated as plugin option keys and refused by plugin prevalidation or the structural-node invariants (see patch_node_options-N2). Plugin identity and routes are retained. LLM-owned runtime hashes cannot be written; changing a compiled prompt without its existing prompt_template_parts refuses (`plugin == "llm"` only). Success returns `affected_nodes=(node_id,)` with the applied-component echo, full validation plus `validation_delta` (dispatch injects `prior_validation`), plugin post-call hints, `data.server_owned_metadata_note` when echoed requirement rows were normalised, and a new version. A failed option-shape refusal additionally carries `plugin_schemas` for the node's plugin (`augments_on_failure=True`). **Any successful patch advances the version and reports the node as affected, including an empty patch, a same-value patch and a null on an absent key** (SG-03; patch_node_options-N1). Mutation is not cached (declaration `cacheable=False`) or automatically retried and has no request idempotency key. No plugin execution or provider call is performed.

The handler returns an immutable candidate; it does not itself durably save the conversation. In web explicit_approve mode the call is first dispatched as a *preview*; the proposal is staged whether or not that preview succeeds (a preview refusal is discarded, patch_node_options-N6), it is relabelled as a whole-pipeline `set_pipeline` proposal when required-control finalization changes the previewed state, and it is re-executed on acceptance. Otherwise the enclosing tool batch applies the accepted state, and the session turn persists it under its operation authority. Across both provider dialects, the provider wire projection is decoded to canonical arguments before dispatch; strict transport representation does not grant different authority. A ToolResult's `success` records operation admission, while `validation.is_valid`, runtime preflight, review and execution admission answer separate questions. Owned-code/audit integrity failures generally escape as faults rather than being reclassified as ordinary invalid model input; the exception in this handler is reconciliation, where `KeyError`/`TypeError`/`ValueError` (including a stored approval digest that no longer matches its prompt) become the ordinary refusal `review_reconciliation_failed` ([transforms.py:1885-1902](../../../../src/elspeth/web/composer/tools/transforms.py#L1885)).

## 4. Alternative paths

Missing node is node_not_found. After patch-delta ownership checks, merged options stage default reviews, the canonical requirement shape and the credential-wiring contract are checked. For `transform`/`aggregation`/`collector` nodes with a plugin, the existing plugin is checked against live policy before schema use; batch placement and required fields plus inline prompt restrictions run. Gate, coalesce, row_union and queue nodes skip those plugin checks and are governed by the queue contract and the blocking invariants (stray gate options, any coalesce/row_union options). Queue intrinsic contract and post-mutation invariants reject early; the invariant scan covers the **whole** proposed state, so a standing blocking invariant on another node refuses this patch (N3). Reconciliation verifies existing approved prompt artifact hashes, regenerates structured prompt content and invalidates stale approval; then the final reconciled options undergo plugin prevalidation, retry-budget/profile and path checks. Review contract failure (also whole-state) refuses the whole edit. Thus schema-valid input is insufficient for admission, and accepted mutation is separate from execution readiness.
