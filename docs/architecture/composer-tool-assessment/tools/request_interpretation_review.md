# `request_interpretation_review` assessment

Baseline: `3b28d537be98234da8135c418bf185a998c18b68` — 0.8.9. Reconnaissance and design only.

## 1. Purpose and exposure

Stage a pending interpretation event for the user to accept or amend. This tool creates durable review work without advancing CompositionState in the ordinary case; resolution is a later authenticated user action. In an opted-out session the same call auto-resolves the review and appends a new composition state (see §4 and request_interpretation_review-N1). It is an asynchronous session-aware tool outside synchronous ToolDeclaration dispatch, exposed to the web Composer freeform loop only.

The tool does not create review sites. Every kind except `source_data_contract` needs a pending requirement already staged in `interpretation_requirements` on the source or node (`source_data_contract` sites are computed from current graph demand). The backend's kind-general finalization surfacer writes events for the same sites through the same writer ([src/elspeth/web/composer/interpretation_surfacing.py:817](../../../../src/elspeth/web/composer/interpretation_surfacing.py#L817)), so the tool is one of several producers of the same row, not its only producer.

## 2. Contracts and authority

Required public inputs identify affected component, interpretation kind and user term; llm_draft is optional when an exact staged draft exists ([src/elspeth/web/composer/tools/sessions.py:254](../../../../src/elspeth/web/composer/tools/sessions.py#L254)). The handler requires server-owned session ID, persisted composition state ID, provider tool-call ID, provenance, rate caps and service collaborators. Those are not planner-controlled fields. Content/credential guards and component-kind/draft matching run before any row write; for `invented_source` and `pipeline_decision` the handler's draft match is skipped when `user_term` carries surrounding whitespace, so the writer is the only effective draft check for those two kinds (request_interpretation_review-N3). Success data reports one of three `_kind` values — `interpretation_review_pending`, `interpretation_review_pending_idempotent` or `interpretation_review_suppressed_by_opt_out` — and a fourth, `interpretation_review_blocked`, arrives with `success=false` when runtime preflight blocks card creation ([src/elspeth/web/composer/session_tool.py:262](../../../../src/elspeth/web/composer/session_tool.py#L262)). None of them claims the interpretation is resolved, except that the opt-out row is already resolved by the server ([src/elspeth/web/composer/tools/sessions.py:3213](../../../../src/elspeth/web/composer/tools/sessions.py#L3213)). The closed result-shape authority is the redaction model set ([src/elspeth/web/composer/redaction.py:3259](../../../../src/elspeth/web/composer/redaction.py#L3259)).

The handler validates the site against the in-memory batch `state`, but the writer binds the event to `composition_state_id`, which is the state persisted before the current batch ([src/elspeth/web/composer/tool_batch.py:973](../../../../src/elspeth/web/composer/tool_batch.py#L973)). These are two different authorities whenever an earlier call in the same batch changed state (request_interpretation_review-N2).

## 3. Source trace to the user

`_dispatch` emits the inline async schema ([src/elspeth/web/composer/tools/_dispatch.py:218](../../../../src/elspeth/web/composer/tools/_dispatch.py#L218)). The freeform batch intercepts session-aware names before the generic `execute_tool` path, runs a masked runtime preflight, then awaits `SessionToolOwner` ([src/elspeth/web/composer/tool_batch.py:2741](../../../../src/elspeth/web/composer/tool_batch.py#L2741)). The session owner requires a session id (RuntimeError) and a persisted state id (ARG_ERROR) ([src/elspeth/web/composer/session_tool.py:182](../../../../src/elspeth/web/composer/session_tool.py#L182), [src/elspeth/web/composer/session_tool.py:196](../../../../src/elspeth/web/composer/session_tool.py#L196)), asserts the interpretation effect domain, validates the closed schema, and returns `interpretation_review_blocked` when runtime-preflight findings exist ([src/elspeth/web/composer/session_tool.py:261](../../../../src/elspeth/web/composer/session_tool.py#L261)). `_handle_request_interpretation_review` validates content and exact site, deduplicates, applies vague-term caps and calls the injected session writer ([src/elspeth/web/composer/tools/sessions.py:3242](../../../../src/elspeth/web/composer/tools/sessions.py#L3242)). SessionService prepares a validator and runs the canonical planner inside the session operation authority's locked transaction ([src/elspeth/web/sessions/service.py:4891](../../../../src/elspeth/web/sessions/service.py#L4891), [src/elspeth/web/coordination/repository.py:1038](../../../../src/elspeth/web/coordination/repository.py#L1038)). The planner re-derives kind-specific reviewed-content identity from the anchor and live states. It may reuse a pending event, supersede stale ones, insert a new pending row or, when review is disabled, insert an auto-resolved row plus a new composition state ([src/elspeth/web/sessions/pending_interpretation.py:1736](../../../../src/elspeth/web/sessions/pending_interpretation.py#L1736)).

The tool invocation and interpretation row are separate evidence. The frontend interpretation store loads pending/resolved events; ChatPanel associates review affordances with tool-call identity ([src/elspeth/web/frontend/src/stores/interpretationEventsStore.ts:140](../../../../src/elspeth/web/frontend/src/stores/interpretationEventsStore.ts#L140), [src/elspeth/web/frontend/src/components/chat/ChatPanel.tsx:671](../../../../src/elspeth/web/frontend/src/components/chat/ChatPanel.tsx#L671)). User resolve passes authenticated ownership to the service, which computes accepted content and updates state/event atomically; route-level typed errors preserve 404/409/422/500 distinctions ([src/elspeth/web/sessions/routes/interpretation.py:61](../../../../src/elspeth/web/sessions/routes/interpretation.py#L61)).

## 4. Branches, failures and recovery

Missing session is an internal invariant error; missing persisted state is recoverable sequencing feedback. Invalid kind/site, credential-shaped user term or bad draft rejects before writes. Omitted draft resolves from current staged authority; duplicate current review is reused before rate limiting. Only vague_term takes per-term/day caps; server-shaped mandatory kinds remain uncapped but deduplicated. Opt-out does more than return a suppressed status. The writer auto-resolves the review (`OPTED_OUT` / `AUTO_INTERPRETED_OPT_OUT`), applies the draft to the graph and appends a new composition state derived from the live head ([src/elspeth/web/sessions/pending_interpretation.py:2014](../../../../src/elspeth/web/sessions/pending_interpretation.py#L2014), [src/elspeth/web/sessions/pending_interpretation.py:2147](../../../../src/elspeth/web/sessions/pending_interpretation.py#L2147)). The returned ToolResult still carries the pre-call state, and the turn's own persistence then refuses (request_interpretation_review-N1). Every typed writer refusal (`InterpretationResolveError`) becomes one ToolArgumentError that names the server-owned `composition_state_id` argument and says "reload the latest state and retry" ([src/elspeth/web/composer/tools/sessions.py:3357](../../../../src/elspeth/web/composer/tools/sessions.py#L3357)). That covers genuine races and also padded-term, draft-mismatch, already-resolved-under-padding, missing-requirement and model-without-prompt cases, where retrying cannot succeed (request_interpretation_review-N4). Bare `ValueError` from the writer, for example a missing persisted source, is not converted and reaches the plugin-crash carrier ([src/elspeth/web/composer/tool_batch.py:2786](../../../../src/elspeth/web/composer/tool_batch.py#L2786)). Later accept/amend can fail on stale or resolved events; retry must retain identity and cannot silently create a new approved interpretation.

**Cache, idempotency, concurrency and retry:** This asynchronous session tool is not in the cacheable discovery registry. Idempotency has two layers that do not agree. The handler's dedup key is `(kind, user_term, affected_node_id)` within the current `composition_state_id`, compared with the raw unstripped `user_term`. A pending match reuses its event ID as `interpretation_review_pending_idempotent`, a resolved match rejects with `DUPLICATE_RESOLVED_INTERPRETATION`, and suppression/cap audit rows are not deduplicated (`sessions.py:3035–3125`). The writer reconciles session-wide by node and kind on the stripped term and the kind-specific reviewed-content identity. It can return an existing event for a call the handler did not dedup, and the result then says `interpretation_review_pending` with the reused id (request_interpretation_review-N3). Staged draft identity is checked before that lookup and again by the locked writer. No generic handler retry loop exists. A concurrent stale-site/draft change returns typed corrective feedback; operation authority and the service transaction own insertion consistency. A fresh provider call is not itself a new review identity. Do not generalize the read-then-write dedup into a proven cross-process exactly-once guarantee; PostgreSQL contention was not run.

Review staging does not require a separate graph-mutation proposal approval: the tool is not a mutation tool, so `explicit_approve` trust mode does not intercept it. The resulting interpretation event itself awaits the later user resolve action. Completed operation replay belongs to the operation owner and must reuse its durable outcome rather than issue another tool call. This lane tested current review-row dedup and resolution behavior, not a complete operation-replay/process-death matrix.

## 5. Defects, restrictions and hypotheses

Earlier text said no new interpretation-review defect was demonstrated. That no longer holds; the findings below were found in this review. "In-memory service run" means the real handler plus the real `SessionServiceImpl` on in-memory SQLite through the test harness, with no provider, network or deployed service. The compose-loop runs (one in-memory script, then four pytest turns in §7) used a scripted fake LLM, not a provider.

**request_interpretation_review-N1 — Demonstrated (pytest compose-loop run with the suite's conftest fixtures, §7 probe 1): in an opted-out session, a turn that calls this tool fails at persistence and loses its transcript.** The opt-out writer appends composition state v2 inside the tool call. P4 then calls `persist_compose_turn` with `expected_current_state_id` set to the pre-batch id ([src/elspeth/web/composer/service.py:2837](../../../../src/elspeth/web/composer/service.py#L2837), [src/elspeth/web/composer/turn_audit.py:505](../../../../src/elspeth/web/composer/turn_audit.py#L505)), and the stale-state guard raises `StaleComposeStateError` ([src/elspeth/web/sessions/service.py:2045](../../../../src/elspeth/web/sessions/service.py#L2045)), which the route renders as 409 `stale_compose_state`. The probe ran one scripted `request_interpretation_review` call through the compose loop. With opt-out set it observed `StaleComposeStateError`, zero `chat_messages` rows, a head at version 2, and committed opt-out marker and auto-resolved event rows. The non-opt-out control, run the same way, completed the turn: three chat rows, one pending event, head unchanged. (An earlier non-pytest run of the control failed later on a custody check. That was a harness gap: the conftest fixtures were not loaded.) A handler-level run separately showed `result.updated_state.version == 1` and a pending requirement, while the head was version 2 with the requirement resolved and the draft rendered into the prompt. `affected_nodes` is `()`. No retry with the new head was found: `composer_operation_errors.py:204` maps the error straight to 409. The skill tells the model to keep calling the tool when review is disabled (§5.1), so opted-out sessions reach this path by design. Not run against PostgreSQL or a live provider.

**request_interpretation_review-N2 — Demonstrated (in-memory service run, and a pytest compose-loop run of one `[upsert_node, request_interpretation_review]` batch, §7 probe 2): the handler admits sites that exist only in unpersisted batch state, and the writer can bind a vague-term card to a state that never had the site.** `current_state_id` is fixed once per batch (`tool_batch.py:973`) and state is persisted only at P4. With the persisted S0 holding a plain-prompt LLM node and an in-memory S1 that stages and wires `vague_term`, the call succeeded. The writer's legacy vague-term arm needs only a string `prompt_template` ([src/elspeth/web/sessions/pending_interpretation.py:545](../../../../src/elspeth/web/sessions/pending_interpretation.py#L545)), so it inserted a pending `cool` event bound to S0, whose node options contained only `prompt_template`. After S1 was committed the event stayed pending, and resolving it raised `InterpretationPlaceholderConsumedError` ("reviewed content no longer matches the event's surfacing state"). For other kinds the writer needs the requirement in the anchor, so a same-batch call gets request_interpretation_review-N4's "stale" refusal instead. The compose-loop run settled the containment question; the answer depends on how the site was staged. The persisted S0 held a plain-prompt LLM node, and one assistant message carried `upsert_node` then `request_interpretation_review`. Both calls succeeded in both variants, and the head became v2 with the site.
- **Structured staging** (`interpretation_requirements` plus `prompt_template_parts` wiring): the model's card was bound to S0 and was superseded before the turn ended. The kind-general surfacer then wrote a new pending `vague_term` card bound to v2 (`backend_auto_surface:` provenance). No orphan survived, but the `event_id` returned to the model names the superseded card.
- **Legacy `{{interpretation:cool}}` placeholder** (with `llm_draft`): the card bound to S0 stayed **pending** after the turn, no replacement was surfaced, and resolving it raised `InterpretationPlaceholderConsumedError`. The user is left with a pending card that cannot be resolved.

Whether the repair gate can run before supersession and spend a per-term cap unit was not exercised. Test `test_02c` already passes a structured in-memory state against a persisted legacy state and asserts success ([tests/unit/web/composer/test_request_interpretation_review_tool.py:1581](../../../../tests/unit/web/composer/test_request_interpretation_review_tool.py#L1581)), so the divergence is currently test-pinned as acceptable.

**request_interpretation_review-N3 — Demonstrated (pytest handler runs with the real writer on in-memory SQLite, canonical-term controls, §7 probe 3): `user_term` normalization differs across the handler's arms and gates.** Site matching strips the term ([sessions.py:2583](../../../../src/elspeth/web/composer/tools/sessions.py#L2583)) and so does the vague-term draft lookup ([sessions.py:2839](../../../../src/elspeth/web/composer/tools/sessions.py#L2839)). The invented-source and pipeline-decision draft lookups compare it raw ([sessions.py:2685](../../../../src/elspeth/web/composer/tools/sessions.py#L2685), [sessions.py:2750](../../../../src/elspeth/web/composer/tools/sessions.py#L2750)), as do the dedup gate ([sessions.py:3093](../../../../src/elspeth/web/composer/tools/sessions.py#L3093)) and the per-term cap count ([sessions.py:3021](../../../../src/elspeth/web/composer/tools/sessions.py#L3021)). The writer strips when it matches identity: a padded re-stage reused the canonical event. It still persists the raw term, though. A first padded `vague_term` call stored `user_term=' cool'`, which the raw dedup and cap comparisons then treat as a different term. Measured:
- with a leading space, `_assert_affected_component` returned `None` as the draft for invented_source and pipeline_decision, and accepted an arbitrary non-matching `llm_draft` for both;
- an omitted draft with a padded term was refused as "this site has no staged requirement draft" although one exists;
- a padded call against an existing pending card returned `interpretation_review_pending`, not `_idempotent`, with the same event id;
- after resolution the canonical term got `DUPLICATE_RESOLVED_INTERPRETATION`, but the padded term got the generic "stale" refusal with `code=None`;
- `interpretation_rate_cap_hit(per_term_cap=1)` hit for `"cool"` and returned `None` for `" cool"`.

The writer refused the forged invented-source draft, so no wrong draft was persisted. The defect is wrong refusals, inconsistent result kinds and a whitespace-bypassable per-term cap count. End-to-end cap evasion with changing drafts is source-established, not run.

**request_interpretation_review-N4 — Source-established, partly demonstrated: the writer-refusal mapping loses the cause.** The single conversion at `sessions.py:3365` names `composition_state_id`, a server-owned field absent from the public schema, and always recommends reload-and-retry. This was demonstrated for padded-term cases (request_interpretation_review-N3), measured through `arg_error_payload`. It is source-established for the remaining cases:
- a model-choice site on a node with `options.model` but no auto-staged requirement — the site enumerator emits it ([src/elspeth/web/interpretation_state.py:1695](../../../../src/elspeth/web/interpretation_state.py#L1695)), the handler admits it, and the writer's `_review_requirement_identity` refuses. By the enumerator's own docstring, such nodes exist only in state that predates the mutation-time auto-stager, so this is not the common path;
- a model-only node — the handler deliberately skips the prompt guard ([sessions.py:2791](../../../../src/elspeth/web/composer/tools/sessions.py#L2791)), but the writer's `_find_llm_transform_node` requires a prompt ([pending_interpretation.py:162](../../../../src/elspeth/web/sessions/pending_interpretation.py#L162)).

The backend surfacer documents the same precondition gap ([interpretation_surfacing.py:327](../../../../src/elspeth/web/composer/interpretation_surfacing.py#L327)). The ARG_ERROR payload also drops `ToolArgumentError.code`, so the model never sees `DUPLICATE_RESOLVED_INTERPRETATION` or `RATE_CAP_*` discriminants, only prose.

**request_interpretation_review-N5 — Source-established ownership inconsistency.** The skill matrix says the model surfaces vague_term, invented_source, pipeline_decision, llm_model_choice and source_data_contract. The completion repair gate treats only prompt-template and source-data-contract as finalization-surfaceable ([composition_completion.py:154](../../../../src/elspeth/web/composer/composition_completion.py#L154)). The finalization surfacer it runs before is kind-general ([interpretation_surfacing.py:605](../../../../src/elspeth/web/composer/interpretation_surfacing.py#L605), [composition_completion.py:1969](../../../../src/elspeth/web/composer/composition_completion.py#L1969)). Planner aids say only prompt-template auto-surfaces. Which owner is intended needs a ruling. The difference is observable in `tool_call_id` provenance (`backend_auto_surface:` versus the LLM call) and cap accounting.

**Hypotheses, unverified.** Whether opt-out breaks other writer seams in the same way. The no-tool finalization surfacer ([src/elspeth/web/composer/service.py:1960](../../../../src/elspeth/web/composer/service.py#L1960)) also reaches the opt-out writer, and so appends states after P4. The final-reply write that follows goes through `add_message`, which takes no `expected_current_state_id`, so request_interpretation_review-N1 appears specific to the P4 seam; that is not traced further. (Answered by §7 probe 2: the request_interpretation_review-N2 card is not always superseded. A legacy-placeholder card survives pending and cannot be resolved.) Whether a blocked call (`success=false`, `finish_success` status) that repeats evades the anti-anchor tracker, which records only ARG_ERROR failures. Whether proposals in `explicit_approve` mode leave the in-memory state without the staged site so that this tool always refuses there, leaving settlement surfacing to own those cards.

**Structural observation:** async exposure, effects and handler registration are maintained outside the declaration paradigm; a future async tool must integrate admission, durable effect and audit policy deliberately. **Restriction:** staging is not approval and does not make a graph executable. Avoid treating event insertion with unchanged graph version as a read-only operation; request_interpretation_review-N1 shows the version can change inside the call.

## 6. Ownership, remediation and dependencies

Interpretation service owns exact event/site identity and resolution; SessionToolOwner owns context/audit routing; orchestrator owns request authority and terminal handoff; frontend owns pending/resolved affordances. A first-class async tool interface should model durable interpretation effects explicitly while preserving writer-side revalidation. That includes the opt-out case, where the effect is a resolved event plus a new composition state. The effect receipt must carry the new head, and the compose loop must adopt it, rather than leaving P4 to discover it as staleness (request_interpretation_review-N1; aligns with R4 effect receipts and R6 async lifecycle). The handler should validate against the same state the writer binds, either by refusing sites not present in the persisted anchor or by binding to the batch's state after an intermediate persist (request_interpretation_review-N2). Choosing between those is an orchestration decision. Do not erase rate-limit distinctions or replace exact draft identity with text-only deduplication. Regression depends on authority/operation contracts, not a generic async function wrapper alone.

**Implementation risk:** High for dedup, draft identity, caps or settlement changes. Preserve writer-side checks and pending/resolved UI correlation; no graph version change does not mean no durable effect.
