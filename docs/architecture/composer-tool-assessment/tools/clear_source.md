# `clear_source` — independent tool assessment

Baseline: ELSPETH **0.8.9**, `3b28d537be98234da8135c418bf185a998c18b68`. Reconnaissance and remediation design only. Incoming `.10 lite` changes are outside this assessment and require affected-source reinspection.

## 1. Purpose and usage

Remove exactly one named source root from composition state. The orchestrator selects which root to remove and must decide how the remaining graph will be repaired.

Use for intentional deletion of a source root: dropping an input the user no longer wants, removing an LLM-authored source together with its generated-source provenance when that graph edit is intended (the reviewer names removal as the route at [interpretation_state.py:3340](../../../../src/elspeth/web/interpretation_state.py#L3340)), or removing a persisted root whose name fails validation. Do **not** use it to replace or rebind a source: `set_source`, `set_source_from_blob` and `set_source_from_blobs` replace a named root in place through [`with_named_source`](../../../../src/elspeth/web/composer/state.py#L8221), and the `source_binding_locked` guidance says not to clear the source merely to silence that refusal ([generation.py:1767](../../../../src/elspeth/web/composer/tools/generation.py#L1767)). Clearing first costs an extra version, an intermediate invalid draft and, for reviewed generated sources, the carried review (clear_source-N5). Requires the requested source to exist; omitting `source_name` targets the default root `source` only.

*Correction (review 2026-11-09): this section previously listed "unbinding before blob replacement" as a use. That conflicts with the runtime guidance and with the in-place replacement semantics above.*

## 2. Contract

Arguments: optional source_name:string, default `source`, minimum length 1; no other keys ([`ClearSourceArgumentsModel`, sources.py:166](../../../../src/elspeth/web/composer/tools/sources.py#L166)). The handler removes one key from the source map ([`without_named_source`, state.py:8228](../../../../src/elspeth/web/composer/state.py#L8228)), increments the version once and reports only the removed source component (`source` or `source:<name>`) in `affected_nodes` ([sources.py:2327](../../../../src/elspeth/web/composer/tools/sources.py#L2327)). It does not delete the blob, source file, nodes, edges, outputs or the consumers' `input` connection strings. Unlike [`without_node`](../../../../src/elspeth/web/composer/state.py#L8250), which also drops the edges on the removed node, source removal leaves every edge drawn from the root in place. The success result carries no `data`, and its `applied_component` echo is `None`, because a removal's subject no longer resolves ([_common.py:4110](../../../../src/elspeth/web/composer/tools/_common.py#L4110)). The measured success envelope keys are `affected_nodes, success, validation, validation_delta, version`.

A missing root returns `source_not_found` through `_saved_graph_rejection_result` and preserves the exact state and version. The standing saved-graph findings follow the rejection entry, and `validation_guidance` is attached. Repeated deletion is therefore a failure rather than idempotent success. The handler does not run the source-name validator that `set_source*` use ([sources.py:785](../../../../src/elspeth/web/composer/tools/sources.py#L785), called at 1026/1237/1523), so a syntactically invalid name such as `Bad Name!` also yields `source_not_found`, not an argument error. This keeps a persisted root whose name is flagged `source_name_invalid` ([state.py:8474](../../../../src/elspeth/web/composer/state.py#L8474)) removable and should be preserved (clear_source-N6). Successful deletion usually makes the pipeline invalid (`node_input_not_reachable` on consumers, `edge_unknown_node` on edges from a *named* root), and that invalidity is returned in validation. It is not guaranteed to: see clear_source-N1. No automatic reconnect/retry or external I/O. Public explicit-approve mode stages the deletion for approval, including when the named source does not exist (clear_source-N2).

The handler returns an immutable candidate; it does not itself durably save the conversation. In web explicit_approve mode, the operation is staged as a proposal and re-admitted on acceptance. Otherwise the enclosing tool batch applies the accepted state, and the session turn persists it under its operation authority. Across both provider dialects, the provider wire projection is decoded to canonical arguments before dispatch. Strict mode makes `source_name` required-nullable and says "Pass null to use the default", and the decoder strips the null, while a literal `null` reaching canonical dispatch is refused as a type error. The strict transport representation does not grant different authority. A ToolResult's `success` records operation admission, while `validation.is_valid`, runtime preflight, review and execution admission answer separate questions. Owned-code/audit integrity failures escape as faults rather than being reclassified as ordinary invalid model input.

## 4. Alternative paths

Normal named removal preserves other roots. Deleting a source still used by nodes leaves dangling consumers and visual edges; the tool does not invent substitute dataflow. Public dispatch's post-mutation interpretation gate can refuse retained noncanonical requirements. The handler itself does not perform the review-reconciliation sequence found in the replacement, patch, source-binding and graph mutation tools. That omission cannot drift a node-review anchor at hash level, because every node-review artifact hash is computed from the node and the node tuple only, never from the source map. The removed root's own review rows are discarded together with its options (clear_source-N4). The current source removal method is deliberately smaller than graph repair.

Edge diagnosis after removal is asymmetric. Removing a *named* root flags the edges drawn from it as `edge_unknown_node`. Removing the default root `source` does not, because `"source"` is always a valid edge origin ([state.py:8496](../../../../src/elspeth/web/composer/state.py#L8496)) and always classifies as kind `source` ([state.py:3453](../../../../src/elspeth/web/composer/state.py#L3453)). The sink-mirror check also returns no mismatch when the origin is neither a present root nor a node ([state.py:3556](../../../../src/elspeth/web/composer/state.py#L3556)). If the removed default root routed straight to a sink and another root remains, the post-removal state validates as `is_valid=True` while still carrying the orphan edge (clear_source-N1). A later new default root reattaches that edge, and the mismatch is then caught as `edge_route_mismatch`.

## 5. Usability assessment

**SG-01 — source-established graph edit limitation; high confidence.** A source-map removal leaves diagram and runtime dependencies for later repair. This is permissible draft editing, but success is not graph readiness. **SG-06 — narrowed for this tool; see clear_source-N4.** clear_source omits authoritative review reconciliation while related graph-only mutations invoke it. At hash level this cannot leave a resolved node review drifted, because node artifacts are source-independent. Read-side and preflight consequences of removing a source with a pending review remain unverified. Workaround: inspect validation after deletion, remove or reconnect affected paths explicitly, and obtain renewed review before execution.

## 6. Structural remediation

Define deletion as a typed graph operation returning removed identity, broken connection dependants and invalidated review anchors. Use the same review reconciliation/authority admission as other graph edits, while retaining explicit draft-incomplete semantics and leaving reconnection choices to the model. Regression: remove one of several roots and verify untouched roots; reject absent identities while keeping invalid-name roots removable; keep blob bytes; report all dangling dependants; prove resolved source/downstream reviews are reopened or execution refuses with a repairable reason. Compatibility risk medium: changing from failure-on-second-delete or adding automatic cascade would alter operator behaviour and needs a deliberate decision.

### 6.1 Simple enhancements

1. **Diagnose edges from an absent default root.** *Where:* [state.py:8496](../../../../src/elspeth/web/composer/state.py#L8496) (`valid_from` includes the literal `"source"`). *Why:* N1. *Acceptance:* the N1 fixture fails with `edge_unknown_node` on `e1` after clearing `source`; the named-root mirror is unchanged; existing fixtures with a present `source` root stay green.
