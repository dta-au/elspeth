# `get_plugin_schema` assessment

Baseline: `3b28d537be98234da8135c418bf185a998c18b68` — 0.8.9. Reconnaissance and design only.

## 1. Purpose and exposure

Retrieve the configuration contract for one named source, transform or sink. It supports discovery before authoring and repair after rejection; it does not install or enable a plugin. The declaration is synchronous discovery and cacheable within a freeform compose request. Freeform, planner discovery and the Composer MCP server all invoke the same handler, but they do not return the same shape and do not apply the same policy projection: web routes use the request's profile-projected `PolicyCatalogView`; MCP uses the explicit trained-operator view, whose `get_schema` returns the unprojected full schema ([src/elspeth/web/catalog/policy_view.py:191](../../../../src/elspeth/web/catalog/policy_view.py#L191), [src/elspeth/composer_mcp/server.py:400](../../../../src/elspeth/composer_mcp/server.py#L400)). MCP is name-filtered, not policy-restricted.

## 2. Contracts and authority

Required `plugin_type` is one of source/transform/sink and `name` is a string; unknown root keys are refused. The handler also validates its owned argument model before policy selection ([src/elspeth/web/composer/tools/generation.py:283](../../../../src/elspeth/web/composer/tools/generation.py#L283), [src/elspeth/web/composer/tools/generation.py:316](../../../../src/elspeth/web/composer/tools/generation.py#L316)). Policy admission precedes schema lookup ([src/elspeth/web/composer/tools/generation.py:319](../../../../src/elspeth/web/composer/tools/generation.py#L319)): `_plugin_selection_violation` refuses a non-exact `str`, a structural node name on `plugin_type=transform` (`gate`, `coalesce`, `row_union`, `queue`, with dedicated "not a plugin" guidance), an invalid `PluginId`, and any identity the request snapshot does not hold as available ([src/elspeth/web/composer/tools/_common.py:2191](../../../../src/elspeth/web/composer/tools/_common.py#L2191)).

The canonical response contract carries ten keys: `name`, `plugin_type`, `description`, `json_schema`, `knob_schema`, `composer_hints`, `secret_requirements`, `web_config_authority`, `policy_capabilities`, `aggregation_output_modes` ([src/elspeth/web/composer/tools/_generation_schema_response.py:124](../../../../src/elspeth/web/composer/tools/_generation_schema_response.py#L124)). Admission is nominal and fails closed with `FrameworkBugError` on malformed producer data ([src/elspeth/web/composer/tools/_generation_schema_response.py:91](../../../../src/elspeth/web/composer/tools/_generation_schema_response.py#L91)). `policy_capabilities` is deliberately untaught (ratified fence, [tests/unit/web/composer/tool_result_envelope_fence.json:10](../../../../tests/unit/web/composer/tool_result_envelope_fence.json#L10)). On web routes, `operator_profiled` plugins are projected through `OperatorProfileRegistry.public_schema`, which removes private provider fields and adds a `profile` enum of usable aliases ([src/elspeth/web/plugin_policy/profiles.py:476](../../../../src/elspeth/web/plugin_policy/profiles.py#L476)); the author must select a profile rather than invent raw operator options. The catalog and availability snapshot must be the same request-owned pair ([src/elspeth/web/composer/tools/_dispatch.py:909](../../../../src/elspeth/web/composer/tools/_dispatch.py#L909)).

## 3. Source trace to the user

The concrete path is `_handle_get_plugin_schema` → `_plugin_selection_violation` → `PolicyCatalogView.get_schema` → `_discovery_result` → `PLUGIN_SCHEMA_RESPONSE_CONTRACT` ([src/elspeth/web/composer/tools/generation.py:311](../../../../src/elspeth/web/composer/tools/generation.py#L311), [src/elspeth/web/catalog/policy_view.py:191](../../../../src/elspeth/web/catalog/policy_view.py#L191), [src/elspeth/web/composer/tools/_common.py:1279](../../../../src/elspeth/web/composer/tools/_common.py#L1279)). A successful freeform read immediately marks the `(plugin_type, name)` pair schema-loaded ([src/elspeth/web/composer/tool_batch.py:3310](../../../../src/elspeth/web/composer/tool_batch.py#L3310)); the planner stages the pair and marks it only after the provider round that carried the result has completed successfully ([src/elspeth/web/composer/pipeline_planner.py:5059](../../../../src/elspeth/web/composer/pipeline_planner.py#L5059), [src/elspeth/web/composer/pipeline_planner.py:4161](../../../../src/elspeth/web/composer/pipeline_planner.py#L4161)). The tracker is in-memory per Composer service instance, keyed by session ID, a no-op for `session_id=None`, and has no removal path ([src/elspeth/web/composer/schema_disclosure.py:6](../../../../src/elspeth/web/composer/schema_disclosure.py#L6)).

On later requests the tracker is identity history only. `build_context_string` intersects it with the current snapshot's available identities and `build_schema_contract_evidence` re-fetches each current contract through the request's policy view into `schema_contract_evidence`; identities no longer available are omitted (`unavailable_in_current_policy` when referenced) rather than redisclosed ([src/elspeth/web/composer/prompts.py:471](../../../../src/elspeth/web/composer/prompts.py#L471), [src/elspeth/web/composer/planner_authoring_aids.py:1619](../../../../src/elspeth/web/composer/planner_authoring_aids.py#L1619)). `schemas_gap` (state-referenced minus evidenced) drives `schema_inventory_precondition` ([src/elspeth/web/composer/prompts.py:479](../../../../src/elspeth/web/composer/prompts.py#L479)). A successful `get_plugin_schema` is the only producer of tracker entries; inline `plugin_schemas` on a rejected mutation does not mark the pair loaded.

The freeform exposure is `get_tool_definitions` → wire projection → `composer_loop_tool_definitions` ([src/elspeth/web/composer/tools/_dispatch.py:311](../../../../src/elspeth/web/composer/tools/_dispatch.py#L311), [src/elspeth/web/composer/provider_gateway.py:391](../../../../src/elspeth/web/composer/provider_gateway.py#L391)). The planner advertises a policy-ordered discovery subset ([src/elspeth/web/composer/pipeline_planner.py:1647](../../../../src/elspeth/web/composer/pipeline_planner.py#L1647)); at this baseline the only producer of that policy assigns the full `PLANNER_DISCOVERY_TOOL_NAMES` and `with_manifest` preserves it, so `get_plugin_schema` is never narrowed out ([src/elspeth/web/composer/pipeline_planner.py:379](../../../../src/elspeth/web/composer/pipeline_planner.py#L379), [src/elspeth/web/composer/pipeline_planner.py:398](../../../../src/elspeth/web/composer/pipeline_planner.py#L398)). The escape-hatch turn re-advertises the same set under its own dialect ([src/elspeth/web/composer/pipeline_planner.py:4268](../../../../src/elspeth/web/composer/pipeline_planner.py#L4268)); the manifest's `terminal_only` surface has no caller. Public freeform calls pass credential/batch admission, wire decoding and closed semantic-schema admission before `execute_tool` ([src/elspeth/web/composer/tool_batch.py:1010](../../../../src/elspeth/web/composer/tool_batch.py#L1010), [src/elspeth/web/composer/tool_batch.py:1399](../../../../src/elspeth/web/composer/tool_batch.py#L1399), [src/elspeth/web/composer/tool_batch.py:3008](../../../../src/elspeth/web/composer/tool_batch.py#L3008)); internal direct calls must explicitly opt into public argument validation.

After the handler, `finalize_tool_result` normalizes validation; discovery result admission selects the declared response contract before serialization ([src/elspeth/web/composer/tools/_dispatch.py:752](../../../../src/elspeth/web/composer/tools/_dispatch.py#L752), [src/elspeth/web/composer/tool_batch.py:3052](../../../../src/elspeth/web/composer/tool_batch.py#L3052)). Freeform sends the canonical ten-key admitted result. The planner instead substitutes a bounded `PlannerPluginContract` (`plugin_id`, `schema_hash`, `json_schema`, `knob_schema`, `composer_hints`, `aggregation_output_modes`) whenever projection succeeds and fits the remaining 48 KiB request contract budget, and falls back to the canonical shape otherwise ([src/elspeth/web/composer/pipeline_planner.py:2944](../../../../src/elspeth/web/composer/pipeline_planner.py#L2944), [src/elspeth/web/composer/planner_authoring_aids.py:1215](../../../../src/elspeth/web/composer/planner_authoring_aids.py#L1215), [src/elspeth/web/composer/pipeline_planner.py:1933](../../../../src/elspeth/web/composer/pipeline_planner.py#L1933)). MCP serializes `ToolResult.to_dict()` plus `_ensure_serializable` without `admit_discovery_result` ([src/elspeth/composer_mcp/server.py:402](../../../../src/elspeth/composer_mcp/server.py#L402)). The loop records the invocation, sends a tool result back to the model, and persists its redacted tool-turn cohort; subsequent operation settlement owns user-facing success/failure ([src/elspeth/web/composer/tool_batch.py:3344](../../../../src/elspeth/web/composer/tool_batch.py#L3344), [src/elspeth/web/composer/service.py:1515](../../../../src/elspeth/web/composer/service.py#L1515), [src/elspeth/web/sessions/composer_turn.py:1051](../../../../src/elspeth/web/sessions/composer_turn.py#L1051)). ToolCallCard renders the recorded outcome and explanatory tooltip rather than giving this tool its own direct action button ([src/elspeth/web/frontend/src/components/chat/ToolCallCard.tsx:90](../../../../src/elspeth/web/frontend/src/components/chat/ToolCallCard.tsx#L90)). A completed lookup does not imply pipeline readiness.

## 4. Branches, failures and recovery

Available plugin: return the projected schema. Unknown, disabled or unavailable selection: preserve the graph and return the policy owner's refusal with its closed reason code. The refusal is a `SAVED_GRAPH` rejection, so the refusal entry is followed by the saved graph's standing findings (for an empty state, `no_source_configured` follows `plugin_not_installed`); `_failure_result` documents this as deliberate for discovery tools ([src/elspeth/web/composer/tools/_common.py:1340](../../../../src/elspeth/web/composer/tools/_common.py#L1340), [src/elspeth/web/composer/tools/_common.py:1399](../../../../src/elspeth/web/composer/tools/_common.py#L1399)). Structural node names receive dedicated guidance only for `plugin_type=transform`; `source/gate` receives the generic not-installed text. A catalog or profile-projection fault after successful policy selection (including `ValueError("malformed_profile_schema")`) propagates rather than masquerading as an unavailable plugin. Cache hits reuse admitted data while retaining a fresh call/audit identity. On public routes argument rejection occurs before the handler; the handler itself still re-validates its model before policy selection. Expected policy/semantic refusal is a failed result on the current state; controlled-code exceptions remain framework/plugin failures, with the executed prefix and audit evidence retained by the common loop. Cancellation, timeout and final persistence failure belong to the request/operation owner, not a handler-local retry. None of these discovery handlers commits graph changes or needs a proposal approval step. Retrying a lookup can recover an argument or infrastructure problem but cannot repair the graph by itself.

**Cache, idempotency, concurrency and retry:** `ToolKind.DISCOVERY`, `cacheable=True`; successful same-name/argument lookups are reused within the freeform compose-call discovery cache (key `tool_name` + `json.dumps(arguments, sort_keys=True)`, [src/elspeth/web/composer/discovery_cache.py:121](../../../../src/elspeth/web/composer/discovery_cache.py#L121)), with fresh audit invocation and current-state validation. The planner and MCP routes have no discovery cache; each call re-executes. Failed results are not cached. Repeated calls have no graph/store effect, but are not audit-idempotent: each provider decision is recorded. The catalog/snapshot is fixed for the request; this is not a subscription to concurrent plugin-policy changes. The handler has no retry loop or write lock. Planner discovery calls in one batch run concurrently. A later model call may retry a corrected request; primary-provider transport retries are separately audited by the gateway.

## 5. Defects, restrictions and hypotheses

Demonstrated: on the Composer MCP route, `transform/llm` returns `web_config_authority: operator_profiled` with no `profile` property and with raw credential/endpoint properties, while the shared declaration description instructs "do not author raw options, author `options.profile` instead" (get_plugin_schema-N2). Source-established: the planner route usually omits `web_config_authority`, `secret_requirements`, `description`, `name` and `plugin_type` that the description and skill promise, and its result shape depends on the remaining budget (N1); structural-node refusals carry `plugin_not_installed` whose catalogue fix contradicts the message (N4); the disclosure tracker is unbounded per process (N5); the freeform and planner routes mark disclosure at different points (N6); `list_*` descriptions discourage the very schema reads the context precondition requires (N3, §5.1). Deliberate restrictions: deployment availability policy, operator-profile authoring, secret-reference disclosure, saved-graph findings on refusal, and fencing of `policy_capabilities`. Structural risk: schema emission, policy projection and plugin assistance must continue to describe the same capability; a declaration alone cannot guarantee runtime support.

### 5.1 Guidance parity

The two skills mention this tool by name (`grep -n get_plugin_schema` on `pipeline_capabilities.md` finds lines 31 and 366; on `pipeline_composer.md` lines 340, 431–432, 1421, 1432); the control is the autogen inventory line 340, which is a known mention.

- **Pushes toward under-discovery (N3).** The three `list_*` declarations call `get_plugin_schema` a last resort ([sources.py:199](../../../../src/elspeth/web/composer/tools/sources.py#L199), [transforms.py:187](../../../../src/elspeth/web/composer/tools/transforms.py#L187), [transforms.py:222](../../../../src/elspeth/web/composer/tools/transforms.py#L222)). Against that: `schema_inventory_precondition` "discover planned plugin schemas before first mutation" ([prompts.py:482](../../../../src/elspeth/web/composer/prompts.py#L482)); `pipeline_composer.md:156–159` "resolve that gap before mutation"; `pipeline_capabilities.md:459` "Load the plugin schema before configuring it"; the authoring-aid text "Author options only from schema_contract_evidence for this request or a current get_plugin_schema result" ([planner_authoring_aids.py:1918](../../../../src/elspeth/web/composer/planner_authoring_aids.py#L1918)). A `list_*` entry cannot close `schemas_gap`.
- **Skill teaches fields the planner does not receive (N1).** `pipeline_composer.md:504–519` teaches `web_config_authority`, `secret_requirements`, `name`, `description`, `plugin_type` for `plugin_schemas`, and the declaration lists them as `get_plugin_schema` output. The planner reads the same composer skill ([planning_application.py:1077](../../../../src/elspeth/web/composer/planning_application.py#L1077)) but usually receives the 6-key projection. `pipeline_capabilities.md:31–33` ("The bounded result carries the chosen plugin's public composer hints") is accurate for both shapes but does not name either.
- **Route-blind authority instruction (N2).** The declaration's `operator_profiled` guidance is correct on web routes and wrong on MCP. Neither skill reaches MCP; the `Server("elspeth-composer")` constructor carries no instructions ([server.py:687](../../../../src/elspeth/composer_mcp/server.py#L687)).
- **Declaration incompleteness.** The description lists eight of ten keys; `aggregation_output_modes` is taught only by `pipeline_composer.md:431–437`, and `policy_capabilities` is fenced by ratified decision (not a finding). The argument example `'csv'` is a source/sink name, not a transform name; harmless.
- **No contradiction found** between the two skills on this tool. `pipeline_capabilities.md:34` ("A successful schema read remains current for the whole request") matches the request-fixed snapshot.

## 6. Ownership, remediation and dependencies

Catalog/policy owner owns capability truth; tool owner owns argument and response admission; orchestrator owns disclosure/cache lifetime and per-route projection. Retain this separation. Any registry consolidation should preserve policy refusal before lookup and avoid flattening operator-profile schemas into raw authorable configuration. A route-aware result contract (R2 capability/description parity) should either make the planner projection a declared second response shape or carry the authority/secret facts it drops, and should let the MCP route state trained-operator semantics instead of reusing web-profile prose. Regression dependency: shared catalog/snapshot contract before tool migration.

**Implementation risk:** Medium if consolidating policy/catalog owners or changing the planner projection (budget and hash identities are test-pinned); low for retaining current behavior. Preserve snapshot identity, profile projection and cache scope.
