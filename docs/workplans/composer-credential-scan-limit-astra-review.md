## Why the proposed fix works

The physical boundary currently scans `credential_messages` with the default guard after native-thinking and prepared-Advisor handling (`src/elspeth/web/composer/provider_gateway.py:521`). The detector defaults to 262,144 UTF-8 bytes per string, depth 32, width 512 and 4,096 visited values (`src/elspeth/contracts/credential_material.py:129`). A large ordinary message body therefore fails before its secret-pattern inspection.

`build_messages()` constructs the state context as one string while attaching exact producer-owned JSON content partitions (`src/elspeth/web/composer/prompts.py:606`). The renderer splits large containers into complete scalar/structural units and verifies exact reconstruction (`src/elspeth/web/composer/prompt_guard_rendering.py:73`). Scanning the entire body with a fixed larger ceiling removes the particular physical-boundary obstacle; the existing partitions let the downstream prompt guard inspect smaller units. This supports the proposed mechanism, but only the planned real-builder regression can establish that a chosen synthetic graph passes all subsequent limits.

Replacing an exact string-valued `content` with one scalar marker preserves its position and visit in the residual traversal. The detector has no special credential-parent semantics for the key `content`; inspecting its original scalar separately therefore retains its secret-pattern checks. Every other key and value must remain reachable under the original ordinary limits. Keep the residual guard call directly in `_litellm_acompletion()`: the ownership inventory explicitly requires it at that function (`tests/unit/web/test_credential_boundary_inventory.py:353`).

The proposal correctly retains original detached wire messages for prompt-guard hashing and SDK dispatch. The projection must never replace `kwargs["messages"]`, producer partitions, custody evidence or audit request context. Existing nominal custody and provenance checks remain mandatory (`src/elspeth/contracts/prompt_guard.py:110`; `src/elspeth/web/composer/provider_gateway.py:475`).

## Required changes incorporated in the revised plan

1. **Correct the non-string compatibility row.** Non-string content is not uniformly malformed. The prompt guard permits absent/`None` content and supports list/tuple content composed of text blocks; unsupported image blocks are refused later (`src/elspeth/web/composer/prompt_guard.py:313`; `tests/unit/web/composer/test_prompt_guard_admission.py:316`). Leave non-string values unchanged in the residual tree. Require positive regressions for currently supported text blocks and assistant `None` content with appropriate tool-call context, and negative regressions for unsupported modalities/objects. Nested text-block strings keep the generic 256 KiB ceiling. Do not introduce a blanket string-only admission rule.

2. **State the Advisor exception to the new ceiling explicitly.** `scan_prepared_advisor_content()` currently uses the complete witnessed UTF-8 extent, even beyond 1 MiB, then places a marker in its residual (`src/elspeth/web/composer/advisor_content.py:33`). The ordinary-text 1 MiB cap must apply only after this step. Add a physical-boundary regression with valid prepared content beyond 1 MiB and valid downstream partitions, plus a recognized secret near its tail. Preserve wrong-role, changed-content, overlapping-position and forged-witness refusals. The plan already says to retain this order; make the resulting exception explicit so implementation cannot accidentally rescan the original witnessed body under the new cap.

3. **Specify invalid-Unicode handling and its test.** The generic detector measures using `errors="replace"` (`src/elspeth/contracts/credential_material.py:198`), so raising its byte limit does not enforce the plan's strict UTF-8 requirement. Require strict encoding for each newly selected body before dispatch, with a lone-surrogate regression and zero SDK calls. Choose and document a fixed, value-free error consistent with the existing boundary; do not classify invalid Unicode as a credential merely to reuse the message. Existing prepared-Advisor behavior raises `UnicodeEncodeError` (`tests/unit/web/composer/test_advisor_content.py:121`); changing that behavior is unnecessary for this fix. Avoid propagating candidate-bearing encoder details into public payloads or audit metadata.

4. **Make the positive and negative boundary proofs precise.** Run the approximately 300 KiB graph regression through real `build_messages()`, real evidence detachment, real credential admission and real prompt-guard enforcement, with synthetic custody and a mock guard client returning allow. Do not mock `_litellm_acompletion()` or `enforce_prompt_guard()`. Assert complete detached SDK messages, tools and tail canary; compare the guard's original-wire/provenance evidence, not just its dispatch count. Require one ordinary body exactly 1,048,576 encoded bytes and one byte over, including multibyte cases. Choose bounded producer parts for the positive ceiling test: a single genuine user prompt still meets the generic scan at `prompt_guard.py:217`, and an unpartitioned document can still exceed the prompt service's independent cap. Also test that a single oversized untrusted inspection part remains refused. A positive test that simply disables the subsequent boundary would not prove the defect fixed.

5. **Bound projection work without overstating the existing ingress guarantee.** Check admitted residual collection types and width before the new projection loops/copies, use exact string selection, and retain all entries and keys. The current gateway already deep-copies and detaches evidence before this location, and `detach_prompt_guard_evidence()` already creates dictionaries via `.items()` (`src/elspeth/contracts/prompt_guard.py:125`). Thus the plan should promise no *new* coercion or unbounded projection pass, not claim that this local edit makes all earlier ingress work bounded. Expanding into those earlier contracts requires separate assessment.

## Cycles, aliases and node accounting

An exact Python string has no outgoing container edges. Removing only its leaf reference cannot remove an existing cycle. A shallow copy of a message may redirect the traversal's first edge through an original object, but a genuine cycle remains reachable and eventually rejected by active-object tracking or a resource bound (`src/elspeth/contracts/credential_material.py:205`). Do not recursively rebuild containers or deduplicate repeated messages: those operations could change traversal accounting.

Shared acyclic aliases are not cycles and are currently scanned once per occurrence because active IDs are removed after each traversal. Require synthetic tests for a self-referential metadata value, a cycle through the original message/list, and repeated shared metadata near the node budget. Assert fail-closed behavior for cycles and unchanged repeated-occurrence accounting; do not promise an identical first finding when multiple defects coexist. A long body aliased into ordinary nested metadata must still fail that metadata's 256 KiB bound.

## Error compatibility, finite work and estimates

Selecting a fixed size-or-complexity explanation only for `traversal_limit` is appropriate. Preserve both structured codes, category, surface, detector version and payload shape; keep ordinary credential detail unchanged (`src/elspeth/web/credential_guard.py:49`). The HTTP 422 mapping remains in `src/elspeth/web/sessions/composer_turn.py:1838`. Changing this shared exception's human-readable text affects all its Web/Composer surfaces, not only provider requests; say so explicitly and test both exception text and payload. This is a compatible clarification of prose, not a persisted-record migration. `unsupported_value` wording remains outside the stated change.

The 1 MiB constant is an existing JSON limit (`src/elspeth/web/composer/bounded_json.py:15`), not evidence that every graph or model request of that size is acceptable. Its use as a fixed ordinary-body scan ceiling is defensible. Retaining width and node limits keeps the work finite but does not impose a 1 MiB aggregate request budget. Multiple large bodies remain possible, and encoding/regex inspection allocates and processes their full contents. Observe focused-test runtime as planned; do not add an unrelated aggregate cap or scanner rewrite.

The proposed two-production-file scope is plausible. The line estimates are planning figures, not verified patch measurements; the expanded compatibility matrix may exceed the test estimate. Do not sacrifice these regressions to retain a line target. The listed ownership/attribute gates and existing Advisor, prompt-guard, admission and audit suites are relevant. The canonical full-suite script supports `--workers 1` (`scripts/full-suite-gate.sh:97`). A full default suite before merge is appropriate for this shared transport; no SQL/schema/lock edits are proposed that would independently require PostgreSQL tests.

The revised plan incorporates these clarifications. Proceed to the smallest implementation and its measured regressions. No scanner exemption, global traversal-policy change, graph rewrite, provider bypass, data migration or deployment is needed by this design.
