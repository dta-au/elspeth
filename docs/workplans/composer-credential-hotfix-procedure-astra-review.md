## Original requirements incorporated in the revision

The following records the initial review findings and their required remedies; these are now incorporated, not outstanding changes.

1. **Fix the test artifact destination and specify isolation (§1.3).** The displayed gate command omits `--log-dir`; [the script](../../scripts/full-suite-gate.sh#L115) defaults to `/tmp/elspeth-gates/...` unless an environment override happens to exist. This conflicts with the explicit project restriction. Add an explicit worktree-local log directory, project-local `TMPDIR`, and a unique pytest `--basetemp` through the supported `--pytest-args` option. Require synthetic test configuration without inherited staging database URLs, provider credentials, or state mounts; audit subprocess/default temporary paths before running. The gate exports import roots but does not sanitize the full environment. Its `--workers 1` option is supported. Keep the full default suite and applicable gates; inspect individual stage results because lints are nonfatal by default. No PostgreSQL suite is required solely by this two-module change.

2. **Make cache invalidation conditional on the actual cache mode (§2.5).** Fresh whole-second source mtimes address timestamp/size caches, not unchecked hash-based `.pyc` files or an interpreter configured to skip hash checks. Even for timestamp caches, select a timestamp distinct from the relevant existing cache header, not merely the current source and last publication. Before packaging, identify the actual interpreter, loader, cache location/prefix, optimization mode, and relevant cache headers. Refuse this two-source-file procedure if source timestamps cannot establish invalidation; any narrowly targeted bytecode repair needs an explicit procedure amendment. Exercise candidate and rollback cached imports with same-size synthetic code under the deployed Python configuration, without clearing caches or precompiling away the condition being tested. Python's `SourceLoader.get_code()` distinguishes these modes; the inspected CPython 3.12 implementation at `_bootstrap_external.py:1098–1115` demonstrates the distinction, but does not establish the deployment's cache mode. The repository Dockerfile's `PYTHONDONTWRITEBYTECODE=1` prevents writes, not reads.

3. **Resolve container filesystem and immutable identity prerequisites (§2, §3–6).** Add a recorded gateway ID and use the full recorded IDs in every stop/start/copy command. Current commands operate by names despite the instruction not to patch a reused name. Establish that both targets resolve to ordinary installed source files in the writable layer, not a bind mount, read-only mount/root, symlinked target, or alternate import tree; verify parent paths and the runtime user's read access. Validate the tar's effective members, rejecting duplicates and extension-header path/link overrides as well as the already prohibited entries. Require exact two-file contents and metadata on readback. `docker cp --archive - CONTAINER:/` is an appropriate tar-stream mechanism for a stopped container, subject to these prerequisites and the proposed disposable-container proof. Existing unrelated writable-layer files should remain intact; do not substitute container recreation or image rollback.

4. **Turn quiet/clean-stop language into a concrete acceptance check (§3).** Specify the ingress control and how existing connections and background queued work are handled. Identify the current operation/lease authorities and require no queued/running Composer or execution work, rather than a portal impression of idleness. Define the configured process command, stop signal, graceful timeout budgets, and approved evidence of completed application shutdown. Docker stop success or an apparently acceptable exit status alone does not prove application finalizers succeeded. [Application shutdown](../../src/elspeth/web/app.py#L1200) collects and raises lifecycle failures; [Composer worker shutdown](../../src/elspeth/web/sessions/composer_async_worker.py#L414) cancels owned tasks and separately checks completion. Require stopped state, no forced kill/OOM, and application shutdown-completion evidence, with sanitized observations retained only in the authorized portal/storage location. Establish who prevents supervisor/autoheal/deployment activity from restarting or replacing either container during installation. Do not silently change restart policy or kill active work to satisfy this check.

5. **Require focused behavioral validation on the native runtime (§2.6), and clarify startup acceptance (§5).** Import/compile success in the same image is useful but does not establish the planned credential, residual-tree, Advisor, wire-fidelity, and prompt-guard behavior under the installed dependency set. Run the focused synthetic regressions in that isolated native-Python environment, proving imports use the candidate installed files and accounting for relevant writable-layer dependency changes. No production secrets, state, or network access should be needed. Preserve web-start followed immediately by gateway-start, before waiting for readiness; do not disable boot probes. Explicitly check both start command results and bound recovery if either fails. Starting immediately reduces but cannot eliminate the gateway-readiness race. [Boot probes](../../src/elspeth/web/app.py#L989) share a deadline and can report transient or unqualified outcomes while boot continues. Record outcomes accurately; HTTP readiness cannot imply every model probe succeeded. Define the actual gateway `/readyz` authentication/alias contract and retain the separately authorized normal Composer canary as behavioral acceptance.

6. **Pin backup and evidence prerequisites without assuming deployment facts (§2.3, §2.7).** The immutable manifest/member/hash/readback requirements are correct, as is the warning that online snapshots are not cross-store atomic. Before the interruption, identify the existing cron mechanism, exact authorized account/container and immutable set, creation time/application provenance, active database inventory, and native integrity/encryption verification method. Hash readback alone does not prove a usable SQLite/SQLCipher backup. These are operator inputs to resolve, not facts established by this source review. Make the host/container mapping and access controls of `HOTFIX_PORTAL_DIR` explicit: an arbitrary host directory named after portal data is not automatically an authorized destination. Keep all deployment records and backup verification artifacts there or in designated storage, including intermediate readbacks; code-only archives may remain in the worktree. [Backup and recovery](../runbooks/backup-and-recovery.md#recovery-set) explains the incomplete recovery scope of database-only sets. Do not expand this code hotfix into a database restore or an unrelated backup rebuild.

## What should remain

Retain the exact original module bytes, candidate/rollback metadata verification, and stop-before-copy boundary: the pair is not atomically replaced. Retain rollback of both modules after a partial install, fresh cache-safe rollback publication, and web-then-gateway restart. Keep databases, blobs, payloads, secrets, container objects, and unrelated writable-layer changes in place. Explicitly stating that container recreation discards this hotfix is correct. The approved implementation's two-production-file scope, compatibility commitments, provider requirement, and regression matrix remain unchanged.

No runtime capability, hash parity, backup completeness, drain state, clean shutdown, test pass, or canary success is claimed by this review. Those remain measured execution prerequisites.
