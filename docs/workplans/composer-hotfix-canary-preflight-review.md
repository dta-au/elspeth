## What the exception means

`ComposerPreflight.cached_runtime_preflight()` wraps an exception or timeout retained by the preflight coordinator as `ComposerRuntimePreflightError`; ordinary invalid `ValidationResult` values are returned, not raised ([composer_preflight.py](../../src/elspeth/web/composer/composer_preflight.py#L189)). The wrapper captures partial state only when its version exceeds the turn's initial version ([protocol.py](../../src/elspeth/web/composer/protocol.py#L835)). Consequently an explanation-only turn can call a real provider and later fail preflight with no partial state.

The route returns HTTP 500 with the shared `composer_plugin_error` label; that label does not establish which plugin failed or even establish a plugin as the underlying cause ([composer_turn.py](../../src/elspeth/web/sessions/composer_turn.py#L1707)). The handler persists diagnostic state only when a partial state exists. Without one it records bounded exception-class telemetry, but does not manufacture a new graph version or emit a traceback triage log ([routes/_helpers.py](../../src/elspeth/web/sessions/routes/_helpers.py#L3744)). There is no basis to promise that raw server logs contain the missing cause.

Pending interpretation reviews produce a `PhaseFailure` with `interpretation_review_pending`, a failed interpretation-review check, and execution-blocked readiness ([execution/_validation_authoring.py](../../src/elspeth/web/execution/_validation_authoring.py#L1063)). Known review-capacity and review-integrity exceptions also have explicit validation-result adapters ([validation.py](../../src/elspeth/web/execution/validation.py#L269)). Pending reviews may coexist with another fault, or exercise a buggy review/tolerant-preflight path, but normal pending status alone is not this internal exception. Earlier policy, path, network, resource, secret, semantic and batch phases also run before review handling; authoring-tolerant Composer preflight can proceed further than strict execution validation. Therefore a normal pending-review result from `/validate` would not conclusively rule out a fault in Composer's tolerant path.

## Lowest-risk diagnostic sequence

1. **Read existing evidence first.** Use the user's normal authenticated `GET /api/sessions/{session_id}/state` for the new canary session. Ownership and plugin policy remain enforced. The response includes the persisted `validation_errors` ([state.py](../../src/elspeth/web/sessions/routes/composer/state.py#L638); [_helpers.py](../../src/elspeth/web/sessions/routes/_helpers.py#L998)). YAML import already invokes state preparation with `preflight_exception_policy="persist_invalid"` ([state.py](../../src/elspeth/web/sessions/routes/composer/state.py#L1021)). Thus the import itself may already have captured the bounded exception class, message and frames, even though the later explanation turn had no partial state. This is an opportunity to inspect existing evidence, not a claim those diagnostics exist. Retain any result only in the portal/designated storage.

2. **Validate the exact current snapshot through `POST /api/sessions/{session_id}/validate?state_id=...`.** The route verifies ownership, acquires normal operation authority and runs real validation with the user's secret/plugin scope ([execution/routes.py](../../src/elspeth/web/execution/routes.py#L912); [execution/service.py](../../src/elspeth/web/execution/service.py#L3240)). It does not execute the pipeline or send a Composer authoring request. It can surface missing review-event evidence, so it is not a strictly write-free endpoint, but it does not resolve or approve reviews. Keep the returned check/error/readiness structure in the portal. This can identify an ordinary configuration or review blocker without another model call. It can also fail internally; the route does not promise a sanitized traceback response for arbitrary exceptions.

3. **Respect the remaining observability limit.** If existing state diagnostics and normal validation provide no cause, do not force a graph mutation, revert, re-import, or change trust mode solely to trigger partial-state diagnostic persistence. Do not call the validator in a new privileged service object, pass `user_id=None`, substitute an unrestricted plugin snapshot, or directly invoke private preflight with fabricated lease/blob authority. These would not reproduce the user's normal path. Existing controlled exception-class telemetry may narrow a subsequent operator investigation, but it is not a traceback or unique session attribution. Obtaining missing frames would require a separately scoped diagnostic investigation or observability change, with actual request custody and enclave storage preserved; it is outside the two-file credential hotfix. The source does not establish a public endpoint guaranteed to recover the missing exception after this no-partial-state failure.

Do not use YAML export as a diagnostic shortcut: it has distinct secret-resolution behavior and records a completion event, so it is neither equivalent to Composer preflight nor an inert inspection ([state.py](../../src/elspeth/web/sessions/routes/composer/state.py#L1332)). Do not launch `/execute` to investigate a Composer admission hotfix.

## Preparing the normal canary

Keep the user-owned canary session and independently uploaded files. Confirm file references belong to that session and use its normal policy, credentials and review workflow. List/read the pending reviews through the normal review surface; leave required human decisions to the authorized reviewer. Never copy approval metadata, forge review evidence, use opt-out to make validation green, or replace missing credentials with a privileged account's credentials.

When diagnostics identify ordinary remediable configuration issues, correct them through supported user actions. Complete required reviews only on their substantive merits, under the normal approval authority. Revalidate and account for remaining completion/execution gates. An expected pending-review result is meaningful control evidence, but it does not establish successful full canary acceptance or explain away an internal preflight error.

After the approved patch and its tests are complete, use one bounded normal Composer request against the representative composite graph. The LLM must still perform the requested authoring/explanation work through the configured provider. If a graph change is desired, specify a small useful change in the new session and review it normally; do not add a mutation just to manufacture diagnostic state. Retain provider-call evidence, the relevant message extent, exact snapshot context and final outcome in the portal. A successful primary provider call alone demonstrates that that request passed physical dispatch; it does not prove the message exceeded the old bound, that the overall turn succeeded, or that credential protections passed.

The inspected patch changes only physical message credential admission and traversal-limit wording. It does not modify preflight, interpretation resolution, provider authoring, or persistence. Synthetic full-boundary regressions remain the proof of credential and wire-fidelity behavior. If the new graph still hits the independent preflight exception, report canary acceptance as blocked on that exception rather than broadening this hotfix or claiming the complete user workflow passed.
