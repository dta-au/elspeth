## Verdict

One P2 disposition gap in the reviewed API: capacity refusal while converting
the **first** complete malformed H to retry-ready propagates without settling
that paid H. The successful path otherwise has a coherent source-level chain
from retained first response through settlement and a fresh issued gate to a

## Finding

### P2 — Retry-ready retention can leave the first paid H unsettled on capacity refusal

At [the retry SQL capacity admission](../../src/elspeth/web/sessions/continuation_checkpoint_end_retry.py#L260),
the proposed batch includes a new full recorder snapshot, marker, and root.
This is additional storage after the complete response/H has already been
retained. The H reserves a fixed paid-overflow tail, not an arbitrarily growing
copy of the recorder: see [the H replacement](../../src/elspeth/web/sessions/continuation_checkpoint_end_owed.py#L225)
and [the recorder append](../../src/elspeth/web/sessions/continuation_checkpoint_end_retry.py#L127).
Consequently a retained first response can fit while its retry-ready batch
does not. The aggregate accounting explicitly counts distinct historical keys
([capacity contract](../../src/elspeth/web/sessions/continuation_retained_capacity.py#L623)).

The refusal happens before the child CAS, quota settlement, and audit writes,
so rollback preserves the original complete H correctly. However,
[the warm API awaits this transaction without a capacity disposition](../../src/elspeth/web/composer/continuation_checkpoint_end_format_retry.py#L93).
It returns only a retry source and has no paid terminal alternative. Thus this
path exits with a paid, complete first attempt still unsettled rather than
the approved honest paid-overflow terminal. The existing catch in
[first-return retention](../../src/elspeth/web/composer/continuation_checkpoint_end_first_return.py#L137)
handles failure to retain H, not failure of this later retry-ready batch.

Add an explicit overflow disposition at this boundary using the retained
first-H authority and its reserved tail, or make the caller's mandatory
handling explicit and implement it before connecting this API. Do not retry
the SDK, discard the complete response, increase per-document limits, or
change recorder drain state. Native validation should force an allowance
where H fits and the recorder/marker/root batch does not, and prove both
rollback and the final settled paid terminal. This review did not execute
that test or measure a specific byte threshold.

This concerns the first malformed-H conversion, separately from the known
second-attempt no-SDK/overflow terminal-reader work.

## Source dispositions

- **Malformed complete response eligibility:**
  [retention](../../src/elspeth/web/sessions/continuation_checkpoint_end_retry.py#L180)
  requires ordinal zero, the current original H, the issued returned audit,
  and a parser result whose failure class is `malformed`. Successful and
  missing/incomplete output cannot grant this retry.
- **First accounting before second SDK:** settlement, public/private audit,
  recorder retention, child commit, and H consumption occur in the same SQL
  transaction before the warm owner is created. The cold reader checks the
  exact recorder bytes, ledger fields and original quota fence, public audit,
  and private audit. The recorder's earlier drain semantics are deliberately
  unchanged; finalizer reproof/deduplication remains the applicable contract.
- **Fresh gate with original provenance:**
  [warm preparation](../../src/elspeth/web/composer/continuation_checkpoint_end_format_retry.py#L112)
  selects and re-proves the committed cut, obtains a new orphan observation
  with the same source cohort, and reissues the original caller/pass locals
  against the current runtime. Ordinary, source-proof, and iteration caller
  dialogue distinctions are preserved. The dependency
  [current phase refresh](../../src/elspeth/web/composer/continuation_live_phases.py#L362)
  replaces the source while retaining live runtime owners; it does not rebuild
  their clocks. Per-call timeout is still supplied by the future caller, so
  this is not proof of its eventual deadline calculation.
- **One second physical attempt:**
  [first-return entry](../../src/elspeth/web/composer/continuation_checkpoint_end_first_return.py#L83)
  requires the issued retry source and identical owner/gate when completed
  children exist. The physical producer derives ordinal one from that child
  and rejects more than one completed child. SQL preparation verifies that
  the input ordinal agrees with the phase. The format re-prompt uses the
  retained first schema-validity result.
- **Bounded cold history and second-H provenance:**
  [the retry reader](../../src/elspeth/web/sessions/continuation_checkpoint_end_retry.py#L378)
  calls historical H proof with `expected_retry_ordinal=0`, so the historical
  branch cannot recurse into another retry. The second-H reader
  [re-proves its retry-ready predecessor](../../src/elspeth/web/sessions/continuation_checkpoint_end_owed.py#L573)
  and compares the first/second complete gate inputs, allowing only the
  checkpoint/capture references and retry ordinal to differ. Pass, caller,
  orphan, publication, and retained semantic input remain bound.
- **Transactional storage:** H rebind preflights the complete prospective
  response/event/root batch while replacing, rather than adding, the old
  reservation. Retry-ready retention preflights its entire recorder/event/root
  batch before effects or accounting mutations. This supports rollback by
  source inspection; PostgreSQL/SQLite rollback behavior was not exercised.

## Follow-up: exact P2 repair source review

The root subsequently changed only the warm retry controller and SQL retry
module for this finding and held both files during this follow-up. This
section supersedes the original verdict **at source-review level only**:
the P2 disposition gap is addressed in the reviewed code. Its native
verification remains open. No additional concrete defect was identified in
this exact repair. No tests or native workloads were run by this reviewer;
the root's reported Ruff and two-file mypy results were not independently
re-executed or treated as runtime proof.

The [prospective recorder construction](../../src/elspeth/web/sessions/continuation_checkpoint_end_retry.py#L147)
now runs `validate_recorder_projection` before bounded private-chunk encoding.
The dependency [validator](../../src/elspeth/web/composer/continuation_audit_buffer.py#L252)
serializes the entire prospective recorder, decodes it through the existing
closed document/DTO validation, and compares the re-encoded projection.
Invalid recorder DATA therefore fails validation before the size decision;
it cannot become an oversized-record terminal merely because encoding checks
size first. The subsequent encoder measures the original canonical text and
constructs its exact overflow witness, rather than fabricating a size from a
different reconstruction. Existing call uniqueness and drain semantics remain
unchanged.

The [warm controller](../../src/elspeth/web/composer/continuation_checkpoint_end_format_retry.py#L113)
now returns either its issued retry source or `EndCheckpointPaidOverflowTerminal`.
It forwards the actual aggregate-capacity exception, or the witness from an
exact `ContinuationMandatoryCaptureOverflow` cause whose codec is
`RECORDER_CODEC`, to the existing owed-overflow writer. Other integrity errors
are re-raised. The caught error has already left the locked SQL transaction,
so the first H remains the current rollback cut when fallback starts.

The fallback passes the same `prepared`, `owed`, and issued `returned` values.
The existing [owed-overflow writer](../../src/elspeth/web/sessions/continuation_checkpoint_end_owed_overflow.py#L162)
checks these against the complete current H, original physical attempt and
fence, then uses its reserved terminal tail. The service performs an
independent terminal read before returning. This is the appropriate existing
authority for settling this first paid H; it neither grants a second SDK call
nor treats a missing response as usable. The successful retry path and its
original runtime-clock owners are unchanged.

Native cases still owed include aggregate refusal after H fits; a valid
prospective recorder exceeding the document bound; malformed recorder DATA
that must remain an integrity error; rollback before fallback; and exactly
one terminal accounting outcome without retry. Existing production-caller,
retry-ready crash-resumption, and second-terminal-reader boundaries remain
open. The global V4 guard stays closed; this is no feature acceptance.
