The budget claim must remain precise: canonical text proofs and recorder block-hash proofs share an aggregate 1 MiB retained UTF-8 payload accounting limit. The existing one-entry recorder-request projection has its **own** aggregate limit of up to 1 MiB. It is not charged to the shared counter. Source observations:

- [Memo proof families](../../src/elspeth/web/continuation_retention_memo.py): canonical proof keys contain complete immutable text, byte bound and actual producer function; recorder block keys contain complete text, expected digest and actual producer. Successful computations alone publish under the same lock as closure. Entries are evicted under pressure; oversize valid results are returned uncached. Close clears counters and values and blocks late publication. Nested scopes restore context tokens; SQL wrappers capture only the memo and create a fresh Context for each invocation.
- [Private chunk codec](../../src/elspeth/web/composer/continuation_codec.py#L111): a proof retains immutable encoded bytes and SHA, not the decoded tree or chunk owner. Every verification still compares the actual reference's digest and byte length. Malformed nominal fields and string subclasses bypass the fast path. Admission still calls the bounded UTF-8/canonical strict-JSON producer before credential admission; state chunks parse and construct a fresh state and run the current state guard. Generic credentials use the current call's policy inputs. Historical verification falls back to its existing canonical-before-binding path on admission refusal, rather than changing verification into a new cap-enforcement policy.
- [Recorder transfer](../../src/elspeth/web/composer/continuation_audit_buffer.py#L182): each transfer checks the reference document and complete block-reference set, proves each text/digest pair, parses fresh values and inserts them into a fresh recorder block owner. Hash hits do not skip JSON parsing or store parsed dict/list values. Per-block ordering remains hash, parse, insertion before visiting the next block. Recorder snapshot projection, cursor/link validation, restoration and canonical round-trip checks still execute.
- The repair does not memoize SQL authority, source materialization, a mutable application owner, provider clearance or a deadline. Actual producer replacement invalidates cache entries. Mutation of transitive globals while retaining the same producer function is not an invalidation guarantee, consistent with the existing pure-function memo contract.

Inspected controls include interleaved canonical SHA hits with changed text/reference rejection; changed credential policy on a hit; LRU pressure and oversized-proof nonretention; request aggregate sizing, nested scopes and close-during-computation; fresh recorder trees after mutation; changed block text/digest; first-block parse failure before a later hash; producer replacement, scope separation and original exception identity. The new block tests are meaningful negatives around an actual successful transfer.
