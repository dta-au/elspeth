## Disposition

pass. The implementation is suitable for the requested native qualification

The checks below describe source behavior and its limits.

## Actual SDK observation and exception custody

[The private SDK scope](../../src/elspeth/web/composer/provider_sdk_observation.py#L45)
surrounds only `litellm.acompletion`, after `mark_sdk_entered`; it requires
original V4 custody/attempt and rejects existing returned evidence. It issues
only for OpenAI-family provider errors, timeout, or cancellation. Arbitrary
owned parser, recorder, SQL and projection errors do not independently issue
an SDK witness. Its weak registry binds custody, exact attempt, observation
category and original exception identity; copying the carrier cannot satisfy
that registry.

Both gateway branches record SDK return after leaving the scope. Thus an
outer timeout detected after an actual return has no newly issued no-result
witness and cannot enter this terminal writer merely because it is a timeout.
A cancellation actually delivered inside the SDK await is recorded as
`no_observed_result`; a later outer timeout conversion can close that original
observation without falsely asserting a received provider result. This differs
from a provider-raised timeout classified `provider_timeout`.

[Gateway finalization](../../src/elspeth/web/composer/provider_gateway.py#L1752)
requires both an issued witness and exact original exception identity through
bounded causes/groups. Direct originals and the direct timeout conversion
become the committed control. Companion error groups remain errors, chained
to that control, after truthful SDK settlement. This does not reclassify an
owned audit failure as the provider failure. The bounded ancestry traversal
also fails rather than accepting an arbitrary exception-text match.

[Custody finalization](../../src/elspeth/web/composer/provider_quota.py#L1194)
requires its original PRIMARY admission and callback, reserves required SQL
and projection tickets, joins required completion, and compares the cold
result to the original hold/attempt before consuming live issuance and
clearing custody. Actual external cancellation and cancellations observed
during the required join are carried forward. Timeout-causing cancellation
is not automatically re-raised as an independent external cancellation.
The existing generic settle path leaves entered unresolved V4 custody intact;
it does not substitute an ordinary ledger settlement for this terminal.

## Charge truth, atomic closure and retained bounds

[Receipt preparation](../../src/elspeth/web/sessions/continuation_sdk_quota.py#L30)
accepts only the issued original observation and, when present, the exact
custody call with matching attempt/start and non-success status. Actual known
cost is retained; otherwise cost remains explicitly unknown. Usage is observed
only when valid original bounded measurements exist; missing measurements
remain unavailable/NULL. Reserved budget is never converted into an observed
charge. The ledger uses the original requested-model/fence association;
receipt usage can retain the actually observed model separately.

[The connection writer](../../src/elspeth/web/sessions/continuation_primary_sdk_finalization.py#L50)
rechecks original prepared/admitted custody, physical attempt, original hold,
current dispatched effect/head, parent and live segment history. The service
wraps it in the ordinary mutation locks/fence and one transaction. Within the
reserved batch, it inserts the bounded receipt, CAS-updates the effect,
appends the failed terminal, closes parent/segment/history, settles the
physical ledger, cold-proves the active-H terminal, consumes H, and re-proves
the consumed terminal. A writer exception does not intentionally leave an
intermediate committed settlement.

[The tail builder](../../src/elspeth/web/sessions/continuation_primary_sdk_tail.py#L127)
reserves the hard receipt allowance plus exact terminal-root and two-event
sizes. It reconstructs the plan, uses canonical content-derived receipt keys,
checks actual event/root sizes and total prospective bytes, and uses the
existing aggregate batch admission. The receipt is bounded terminal audit
evidence; no successful full-provider cohort or usable output is fabricated
when ordinary full-audit construction failed.

[The cold reader](../../src/elspeth/web/sessions/continuation_primary_sdk_terminal.py#L105)
reconstructs original admitted input/head, physical actor, identity and
combined recipe; verifies receipt content/key, terminal root/events and public
error; checks original physical-ledger association and usage, closed
parent/segment/history, and consumed H for the verified result. A merely active
H or dispatched effect returns no SDK terminal. The cold receipt is evidence
of the committed result, not authority to replay another physical call.

## Compatibility and actual caller joins

[Reservation compatibility](../../src/elspeth/web/sessions/continuation_primary_terminal_reservation.py#L16)
reconstructs the old combined-tail.v2 hash first and preserves its original
three alternatives when the stored hash matches. Fresh reservations use v3
with the SDK alternative. Existing overflow/incomplete/no-SDK cold readers
pass the stored historical contract hash. The new SDK writer and reader
require v3, so they refuse to claim this new alternative was reserved by a v2
hold. There is no in-place hold upgrade or store reset in the reviewed code.
This is a preserve/refuse boundary, not a promise that old v2 entered SDK
failures can be newly closed by this writer.

[PRIMARY binds the callback before admission](../../src/elspeth/web/composer/continuation_primary.py#L625),
then accepts only the exact committed control held by its own custody. The
result preserves the verified receipt/snapshot and deferred cancellations.
[The driver arm](../../src/elspeth/web/sessions/continuation_driver.py#L1968)
cold-verifies that result again, enters settlement, checks the failed terminal
record's checkpoint/cursor, and uses the ordinary verified release path with
deferred cancellations. It does not feed this result to ordinary PRIMARY
success handling or schedule another SDK attempt.

## Required native evidence and review limits

The following remain qualification work, not passed checks:

- Actual provider raise, SDK timeout and external cancellation through the
  gateway: one physical call, one ledger closure, consumed H, bounded failed
  result and no retry/output.
- A returned SDK object followed by outer timeout or owned parser/retention
  failure: no no-result witness or false SDK-failure terminal.
- Audit construction/retention companion failure: truthful bounded terminal
  where possible, original companion and cancellation identity preserved.
- Failure at each transaction boundary, commit-success/readback-failure,
  cancellation during required SQL, and cold reconciliation after process
  loss. The dedicated driver result arm is inspected; generic exceptional
  re-entry/reconciliation after ambiguous commit is not qualified here.
- Known versus unknown cost, NULL usage, every original actor/ledger/source
  association, altered receipt/root/events, forged issuance, duplicate use,
  exact-capacity and old-v2/new-v3 recipe controls.
- Relevant enclosing and PostgreSQL persistence checks; the PRIMARY source
  findings do not qualify other provider families or the independent END
  clock work. Shared observation code being present does not establish an
  SDK terminal finalizer for those families.

The review is intentionally bounded to the requested new PRIMARY chain. It
does not claim a whole-tree audit, a frozen native result, V4 activation, or
exhaustive proof of cancellation and crash behavior.
