# Independent V4 returned-incomplete architecture review

Verdict: add a distinct `paid_incomplete` terminal, with a new `composer.paid-incomplete.v1` receipt. The existing paid-overflow contract cannot honestly represent missing, unavailable, unsupported or cyclic original fields without a measured byte excess. Preserve the overflow contract and its readers. This is a source review, not executed qualification; no tests, Git operations, network access, or source edits were performed. Live files may change concurrently. The requested U40 raw parser is an integration proposal here, not a source implementation verified by this review.

## Smallest precise extension

1. At the actual successful SDK `await` boundary, before response parsing, create an owned return witness tied to the exact admitted physical attempt and invocation. It must not retain the raw object in repr, serialize it, traverse properties twice, or grant ordinary success authority. A closed parser outcome distinguishes complete capture, measured overflow, and non-byte incomplete capture. Non-byte reasons should be bounded literals such as `missing_required_field`, `field_unavailable`, `unsupported_field`, `cyclic_field`; use a bounded field/category enum, not provider keys, values, exception text or object repr. Catch only the parser's nominal incomplete outcome. An arbitrary first-party exception is not such evidence.
2. New frozen receipt: schema `composer.paid-incomplete.v1`; original identity/fence/source binding; existing producer vocabulary; outcome `terminal_paid_incomplete`; `evidence_status="incomplete"`; `retryable=false`; `provider_returned=true`; closed reason and capture-surface enum; known/unknown bounded cost; explicit observed/unavailable usage. No byte measurements, absent-output hash, successful-response audit, placeholder result, truncated content, or null-filled pretend full response. Reuse existing bounded identity/cost/usage components if names are tolerable; do not broadly rename existing codecs.
3. Add SQL/frontier disposition `paid_incomplete` with the same mandatory receipt/chunk invariant and explicit provider-attempt binding. Keep receipt chunks unmistakably typed as receipts even though the existing SQL column is named `result_chunk_key`. Exclude this disposition from replayable responses, graph mutation, tool execution, advisor guidance, title updates, handoff/resume, and format-retry admission. A shared bounded receipt codec and shared terminal mechanics are appropriate; each existing family retains its own source issuer and exact closure proof. No new result table or general-purpose fallback framework is needed.
4. In one owner transaction: verify original current dispatched admission; append the bounded receipt plus exact family terminal snapshot/events; CAS the paid effect; apply existing enclosing-effect unknown closure where required; fail parent/segment; settle physical attempt and quota exactly once; cold-prove the complete terminal with H active; consume that exact H and cold-prove again. Preserve rollback on every prefix. Cost observations must be extracted independently and safely from the original response, so failure to retain content does not erase an already-known charge. Unknown is null/unknown, never zero or fabricated pricing. The existing quota adapter (`continuation_paid_overflow_quota.py:90-129`) binds the original physical fence and allows unknown token fields; reuse those semantics without treating requested model as an observed returned model.
5. Pre-dispatch reserve H for the maximum exact terminal append among overflow, non-byte incomplete and no-SDK outcomes, including events/snapshots/receipt overhead, and bind the expanded fallback contract hash. Existing maximum-receipt calculations deliberately pin fields/schema (`continuation_primary_paid_overflow_tail.py:98-167`), so update the reservation proof explicitly rather than assuming a smaller receipt implies the complete append fits. Keep both 1 MiB limits unchanged. Do not consume or release H merely because a nominal parser exception arose; consume only after the entire durable closure passes cold verification. SQL failure leaves attempt and H pending for the existing integrity path.
6. Add an independently discriminated cold reader that derives original admission and terminal shape from SQL only, checks receipt identity/digest, codec, exact events/snapshot, physical/quota settlement and H contract/state. Route public reads through it. Suggested public error is `paid_result_incomplete` with existing paid terminal status 507, a static explanation that the returned paid result could not be fully retained and was not used or retried, `evidence_status`, `retryable=false`, bounded cost status/amount, and request ID. Keep provider-specific details private. Status 507 is continuity with the existing paid-retention API; the distinct error code carries the non-byte distinction.

## Compatibility and boundaries

Adding a persisted disposition and new H fallback semantics changes readers and CHECKs. Bump the session epoch from the live 84 to the next coordinated epoch (85 only if still unallocated), including schema identity/hard-cut declarations and relevant tests. Preserve/refuse existing stores; do not auto-migrate, reset, rewrite old receipts, or rebind old active holds to a new reservation. Keep historical overflow v1 codec readability where the supported reader contract requires it. A new scalar enum hidden under unchanged epoch 84 would permit mixed actors to disagree about terminal replay and is not an acceptable shortcut.

Three states remain distinct: pre-dispatch refusal proves no SDK entry and retains its existing no-SDK outcome; SDK entered but no response returned remains policy-pending and must not claim paid returned-incomplete; actual raw return plus nominal mandatory-capture incompleteness admits this new terminal. A return with complete retained evidence but invalid business/tool format also must not be relabeled incomplete merely to avoid the existing malformed/format policy.

Required focused proof before landing: each of the five families with actual gateway return and parser incomplete outcome; known and unknown charge; no next provider retry and no tool/graph/title/guidance use; cold restart reconstruction; wrong-attempt/fence/source rejection; missing/cyclic/unsupported/throwing external field cases; entered/no-return and pre-entry controls; injected transaction-prefix rollback and H accounting; maximum terminal-reserve proof; SQL CHECK and epoch preserve/refuse tests on SQLite and PostgreSQL. Existing overflow exact-limit/+1 and unchanged complete-response tests remain necessary regression controls. This review does not claim those checks ran or that the proposed extension is integrated.
