## 5. How to work

**Durability first.** Work in worktrees under `.claude/worktrees/<name>`, on
branches. Commit at every stop, including WIP. Source code under a gitignored
path is a defect: no snapshot directories, and no copying trees into
`.claude/lanes/`. Lane folders are for short notes and logs only. Today's
failure was four days of uncommitted work hidden in gitignored snapshot dirs.
Do not repeat it.

**Slim structure.** Follow the lane-process review:
- each unit is a commit group on the target branch, with one review per carried
  branch;
- red-team review only for Composer authoring-path units;
- the full testcontainer suite once at final qualification, plus wherever a
  unit touches schema, SQL, session or Landscape persistence, or locks (the
  `AGENTS.md` rule);
- evidence is the canonical scripts' outputs and recorded exit codes, never
  versioned envelopes, rehash records or receipt JSON.

**Workflows, subagents, skills.** You are authorized to use the Workflow tool
and subagents for parallel work where they add value. Size the model and
effort to the task: Haiku or Sonnet for mechanical checks and small carries,
Opus or Fable at high effort for first Compose, Common, the C3/C4 fencing
work, the security group and design reviews. Use the skills each unit calls
for (plan Appendix B), for example `superpowers:test-driven-development`,
`superpowers:systematic-debugging`, `superpowers:verification-before-completion`,
`engine-patterns-reference`, `tier-model-deep-dive`, `config-contracts-guide`,
`logging-telemetry-policy`, the ECS/ACA operating skills, the
`red-team`/`code-review` agents and the `ordis-quality-engineering` reviewers.
Brief every subagent to write its findings to a file and return the path plus
a summary. Never let a subagent leave work uncommitted.

**Gates.**
- `scripts/branch-safety-check.sh` before every commit, rebase or merge.
- Focused tests per unit.
- For the final qualification, `scripts/full-suite-gate.sh --execute --detach
  --stages ruff,mypy,contracts,lints,pytest,testcontainer`; read its
  `summary.txt` and the `frozen=` line. The full suite takes about 32 min
  locally.
- One broad suite at a time on this shared host; testcontainer runs serially.
- Run the keyless trust-tier corpus as a set diff against `main` and fix what
  is fixable. The bare `lints` stage exits 1 by design, so the diff is the
  signal.
- Worktree subprocess tests need `PYTHONPATH` exported, and you must verify
  that `elspeth.__file__` resolves inside the worktree.
- Never run `uv run` in a worktree whose `.venv` is a symlink: it wipes the
  main venv.

**Reporting.**
- Keep one short status file at `.claude/lanes/release-0.8.10/STATUS.md`:
  current target-branch SHA, units done and remaining, current blocker. Update
  it at each milestone.
- Report to the maintainer at milestones in a few lines.
- Ask only about genuine trade-offs the rulings do not settle. Decide the calls
  that follow from repository policy or plain engineering judgement.
- **Hard stops (ask first):** pushing or merging to `main`, deleting branches
  or worktrees that hold unmerged work, any data migration, reset or deletion
  outside a dev store, and anything touching operator keys.

**Definition of done.** Every unit is assembled on the target branch. The final
full-suite gate summary is all green with `frozen=YES`. The testcontainer
selection is green. The keyless diff has been reviewed. CHANGELOG 0.8.10 and
the upgrade notes are written, including the epoch-79 fresh-store procedure
for ECS and ACA. Each #327 item is checked off or explicitly deferred with the
maintainer's approval. The four security findings' status is stated honestly:
S1–S3 have source landed and stay open until operator installation; S4 is
closed by design. Then ask the maintainer for the single merge to `main`.
