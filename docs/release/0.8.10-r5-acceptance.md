# R5 acceptance and local keyless reporting in 0.8.10

Root adopted this reconciliation on 29 October 2026 after independent source
and requirement-provenance review. R5 proves exception kinds within its supported
supplied-source graph. Explicit unconfined writes may prevent that proof in a
larger graph. Unknown read results do not establish favorable class provenance;
canonical setter spelling does not prove target or dictionary-storage confinement.
The taxonomy's conservative writer refusal is retained.

The replacement acceptance keeps the unfiltered actual-source directory
entrypoint and independently checks its complete canonical inventory, successful
reads/parses, exact original source/AST forwarding, one shared taxonomy and
read/visit coverage. It exports all findings and suppression observations, and
must reach the independently specified `isinstance(value, str)` R5 assertion in
`contracts/runtime_val_manifest.py`. Supported builtin/external/owned ancestry,
actual Composer definition graphs, alias/tuple positives, nonexception/mixed
negatives, R4/R6 and explicit writer/capability oppositions remain required.

Normal and reversed complete-input cases each perform one expensive scan under
the unchanged 600-second whole-item thread timeout. Their separate passes are
insufficient: final frozen qualification must join both reports, require equal
complete input graphs/package policy, and compare the entire finding and
suppression multisets. Missing, duplicate or corrupted pair controls must refuse.
Finite file/directory/direct-AST parity compares equal supplied graphs; an isolated
file intentionally has fewer facts than a complete directory.

The local pre-commit trust-tier invocation now uses explicit `--report-only`.
Exit zero means the keyless HEAD/actual-working-tree comparison completed. It
prints complete raw added/removed occurrences and `REVIEW REQUIRED` for additions,
including site-identity changes that cancel in the line-insensitive summary.
Invalid output, unreadable/unparseable scan diagnostics and operational failures
remain nonzero. Default CLI behavior and explicit `--strict` retain the normalized
no-additions ratchet; no environment variable switches acceptance mode.

This local tool measures only `trust_tier.tier_model`. It does not replace
[master-plan A4](0.8.10-master-plan.md)'s named-base/candidate `--rules all` review.
Root must retain both complete raw corpora, inspect additions and removals, and
fix or individually adjudicate every addition against the exact frozen sources.
Unreviewed additions still block release and landing. Successful reporting is
neither machine adjudication nor landing clearance. Signing remains suspended;
agents must never hold an operator key, and this reporter refuses a key-bearing
environment. No baseline advancement, approval manifest, adjudication database or
finding-specific exception is introduced.
