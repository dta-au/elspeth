## P2 — Recovered retry loses H0 publication scope at the second response

The retry gate is correctly reissued against the first H's publication scope:
[retry publication source](../../src/elspeth/web/composer/continuation_checkpoint_end_format_retry.py#L123)
returns `proof.owed.new_hold.session_operation_id`, and
[gate capture/reproof](../../src/elspeth/web/composer/continuation_checkpoint_end_locals.py#L261)
uses it to recompute and compare the entire original publication review.
After recovery that operation ID differs from the replacement runtime's fence.

However, the actual warm second-response computation
[calls `compute_end_gate` without the original-scope argument](../../src/elspeth/web/composer/continuation_checkpoint_end_computation.py#L223).
Its publication-admission predicate therefore recomputes with the replacement
runtime's operation ID. A valid second `ADMIT` response bound to the retained
H0 packet is treated as not admitted, producing repair/block behavior instead
of the corresponding clean consequence.

Cold H1 has the complementary defect:
[both its packet comparison and computation use H1's own paid hold scope](../../src/elspeth/web/composer/continuation_checkpoint_end_cold_consequence.py#L195).
If the second SDK was admitted under the replacement fence, H1's hold names
that new fence, while the retained publication is still H0-bound. This is not
an assumption about a lossy packet: the
[ordinal-one SQL input equality](../../src/elspeth/web/sessions/continuation_checkpoint_end_owed.py#L573)
requires the second input to equal the first except checkpoint/capture
references and retry ordinal; publication is intentionally unchanged. Cold
H1 therefore rejects a legitimate packet before consequence computation.

Use the exact first-publication source derived from the issued retry lineage
for the warm second-response computation, and from `retry_history.owed` for
the cold ordinal-one computation. Ordinal zero continues to use its own H.
Do not fix this by rewriting the current evidence operation ID, weakening the
full-packet equality, accepting an arbitrary old ID at an authority boundary,
or rebinding the original publication to H1's paid fence. Native controls must
cover recovery at H0/retry-ready followed by a clean second response, and
recovery again at H1; both must preserve first publication provenance and
current writer/second-call custody.

## P2 — Retry restore rejects an unrelated global family-1 child

[The restore probe](../../src/elspeth/web/composer/continuation_checkpoint_end_format_retry.py#L199)
rejects any effect named `provider:1:1` as proof that this pass's second
physical call was already admitted. But
[paid admission](../../src/elspeth/web/sessions/continuation_checkpoint_paid.py#L537)
allocates family-1 ordinals across the entire operation, not per END pass.

With an earlier EARLY/END checkpoint, `provider:1:1` may be this END's first
attempt or an unrelated completed call. A valid current retry marker then
fails restoration with “already admitted its one ordinal-one paid child” even
though this pass has no second attempt. The original first effect is already
available as `proof.marker.effect_key`; the global key must not stand in for
the current retry chain. Derive the second-call exclusion from the proved
pass/outer effect and actual marker-to-admission lineage/current head.
Preserve refusal of an actually admitted second attempt. Validate a retry
after earlier family-1 calls, plus a true second-admission negative.

## Positive source dispositions and limits

- `TurnEvidence.review_candidate_for_source_operation` is a pure projection.
  It preserves the live evidence object's current operation ID and current
  fence, checks request identity, and computes all packet fields from actual
  evidence. The original operation ID participates in binding and semantic
  repair key; it does not itself grant SQL or provider authority. Existing
  `identity`, `review_candidate`, persisted-effect acceptance and abandonment
  methods continue to use the live operation scope.
- The new weak publication source requires object-identity registration of
  proof and actual phase owner. Its verifier joins original H/marker/input,
  current selected phase, original outer phase, completed first child, and
  actual runtime. Gate capture and later reproof compare the entire derived
  publication. A bare decoded proof or boolean is not an SDK permit.
- Retry restore checks current running/head under SQL lock, reads the exact
  marker and settled first H through ordinary recovery-event lineage, restores
  the actual runtime, and observes the fresh pending cohort. The SQL retry
  writer separately rechecks current running/H and first malformed result
  under the session lock before settling its paid audit/quota/recorder/evidence
  consequence. The unrelated-global-ordinal defect above limits successful
  restoration, not those checks' necessity.
- Cold H0 packet verification uses the deeply read original hold scope and
  compares the complete packet. The shared computation preserves legacy warm
  short-circuiting: it evaluates publication-source matching only after a usable
  ADMIT verdict and matching binding. The two H1 consumers need the lineage
  correction above.
- Warm/cold first-retry cost projection runs after durable SQL settlement,
  requires the matching original call, one outstanding physical charge and no
  duplicate charge, and uses the call's original accountability flag. These
  are source checks, not executed proof of crash, cancellation, duplicate
  delivery, or replacement-budget behavior. No clocks are recreated by the
  pure publication helper or weak-source issuance.

No broad audit, native results, feature acceptance, or full recovery support
claim follows. Current-fence freshness, rollback, ledger/cost replay, and
publication negatives must be exercised by the root's native checks.

### New P2 — Second paid-incomplete control is verified against first custody

The new [live helper](../../src/elspeth/web/composer/continuation_checkpoint_end_live.py#L57)
invokes its nested `call(owner, gate, retry)` with newly issued retry owners
after first-H settlement. If the second provider returns a paid incomplete
result, [the physical Advisor wrapper](../../src/elspeth/web/composer/advisor_checkpoint.py#L1036)
raises `V4PaidIncompleteCommitted` for that second custody. Neither the live
helper nor first-return wrapper converts it before it escapes.

The [outer shared gate handler](../../src/elspeth/web/composer/composition_completion.py#L2651)
still passes the invocation's first `checkpoint_phase_owner` and first
`checkpoint_end_input` to
[the custody verifier](../../src/elspeth/web/composer/continuation_checkpoint_end_physical.py#L283).
That verifier resolves physical custody from the exact supplied gate and calls
`require_v4_paid_incomplete_committed`. Thus a valid second-call terminal is
checked against first-call custody and fails integrity validation. Its durable
settlement is not undone, but the caller loses the intended terminal control
and its deferred cancellations.

Convert this exception inside the nested live `call`, while its actual
`owner` and `gate` are available: use the existing original-custody observer
and raise the existing nominal paid-incomplete control. Do not accept the
exception's data without its original physical source. Test malformed first
complete response followed by paid-incomplete second response, checking one
charge per actual call, no third SDK, the terminal reader, and cancellation
propagation. This is a returned-incomplete ownership defect, distinct from the
already acknowledged END no-SDK/transport work.

- The first malformed complete result is settled by the bounded retry owner

  A malformed second response proceeds to the existing ordinal-one terminal
  computation. Normal Review/repair completion projects its committed call

  the legacy duplicate retention tail.

- This review qualifies only the ordinary live caller joins inspected here.
