## Decision and future deliverable

Preserve the full mandatory paid result. Refuse before dispatch whenever its complete retained tail has no proved finite producer bound. Preserve the existing 1,048,576-byte private-document/evidence contracts. Aggregate operation allowance, transient memo RAM, and a producer's complete result bound are different quantities. No production default or new lifetime cap is proposed.

The authorized immediate slice is **immutable original parent policy with a supported schema boundary**. The live app still calls `continuation_policy_from_settings` at `web/app.py:2324`; that returns V2 (`composer/continuation_policy_settings.py:58`). The explicit V3 builder at :102 returns None when `composer_continuation_max_retained_payload_bytes` is absent. Wiring it alone would disable fresh default composition and cause configured operations to reach refusals rather than complete paid composition. That activation is deferred and not approved.

## What a usable paid-tail design must add

Use the existing original fenced operation/effect owners, not a parallel policy system. Before its first dispatch mutation, a route must derive a producer-specific bound for every mandatory post-effect byte: original response, audit/cost record, tool result/evidence/recorder outputs, all distinct intermediate roots/events, and settlement/failure/cancellation terminal. Calculate UTF-8 plus canonical JSON escaping, nested JSON strings and duplication from the actual codecs. Include success, malformed/error and cancellation outcomes. Every individual private document must remain within its current cap as well as the aggregate operation allowance.

Only after that proof exists: persist an effect-bound reservation atomically with dispatch admission under the existing session lock/CAS; enforce `actual retained bytes + outstanding holds + proposed bytes <= admitted allowance` in every writer. Bind hold to original policy hash, effect key, source root/cursor and producer-envelope identity. Materialization replaces the hold with actual bytes in the same transaction, and releases only the proved unused remainder. Retries, successors and recovery must recover the same hold; unknown in-flight outcomes retain it. No new generation replenishes it. Prevent unrelated writes consuming the hold. This needs a narrow persisted hold representation and schema/test work; an in-memory counter or the current unpaid prospective reserve cannot prove it.

**Exact unresolved constraint:** no current source contract proves that an entire externally produced response and its mandatory representations fit the unchanged private-document limit. Passing max_tokens, parsing a schema, checking bytes after return, or configuring a larger aggregate allowance does not prove that. A transport hard stop on excess bytes would lose part of a paid result and violates the fixed preserve-full policy. Provider/model-specific enforceable bounds must cover content, tool ids/names/arguments, reasoning and metadata, not merely generated token count. Tool producer bounds must cover their actual owned outputs too. No external specification was researched or asserted in this read-only pass. Until such a producer contract is established, this design deliberately selects pre-dispatch refusal and cannot honestly claim paid usability. An alternate chunked representation would require separate explicit design/authorization and cannot silently override the existing private-document contract.
