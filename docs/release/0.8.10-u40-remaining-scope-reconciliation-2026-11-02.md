### K-7: missing join and the smallest coherent implementation boundary

The retained contract is explicit: [K-7](../architecture/design-notes/0.8.10-continuation-protocol-design.md#L721)
requires a recorded role-owned provider call for every graph-authoring
transition in a two-segment walk, no frontier advance from notes/oscillation,
and no attempted action merely because advice names it. The current
[architecture](../design/composer-continuation-architecture.md#L214) also
requires the backend to request the existing Advisor owner when a no-op/cycle
has no productive retained action; it cannot depend on PRIMARY voluntarily
calling `request_advisor_hint`.

The relevant existing code is:

- [Closed decision parser/format](../../src/elspeth/web/composer/advisor_output.py#L348):
  `parse_continuation_advisor_decision` derives physical decision identity from
  the actual Advisor call; `continuation_advisor_response_format` owns its
  response schema.
- [Semantic decision/action retention](../../src/elspeth/web/composer/continuation_progress.py#L397):
  `retain_advisor_action` checks the selected frontier and the owned action
  source, canonicalizes obligations, rejects an outstanding action, and does
  not accept whole-request Stop with unresolved execution.
- [SQL action binding](../../src/elspeth/web/sessions/continuation.py#L1980):
  `bound_action_json` compares the actual PRIMARY/review/read owner, including
  the exact permitted read tool and canonical arguments. [Execution receipts](../../src/elspeth/web/sessions/continuation.py#L2012)
  join the actual effect and creator, advance monotone receipt history, and
  clear an action only on its terminal committed/refused disposition.
- These are not currently a live decision producer. Exact production-name
  lookup found the parser, response-format and `retain_advisor_action` only
  at their definitions. Independently, the actual [END owner](../../src/elspeth/web/sessions/continuation_end.py#L144)
  calls `_try_terminate_no_tools`, and [post-batch iteration](../../src/elspeth/web/sessions/continuation_next_iteration.py#L137)
  calls `_maybe_run_early_checkpoint` and `_classify_and_budget_turn`.

Two explicit constraints make a simple callback insertion incorrect:

1. [PRIMARY `_primary_frame`](../../src/elspeth/web/sessions/continuation_primary.py#L101)
   rejects `active_action_json` and `active_action_source`. Its preparer
   [writes `action_json=None`](../../src/elspeth/web/sessions/continuation_primary.py#L334).
   The [next-action/in-flight structural checks](../../src/elspeth/web/composer/continuation_next_action.py#L186)
   also exclude active actions on ordinary PRIMARY paths. Removing these
   guards wholesale would widen authority; it would not bind prescribed work.
2. Existing generic [provider preparation](../../src/elspeth/web/sessions/continuation.py#L2349)
   delegates ordinary Compose PRIMARY, then requires the reserved initializer
   for its other path. It does not provide a current semantic Advisor-frame
   preparation API. The existing [Advisor call owner](../../src/elspeth/web/composer/advisor_checkpoint.py#L805)
   supplies real quota/audit/cost custody, but its [structured trigger contract](../../src/elspeth/web/composer/advisor_checkpoint.py#L505)
   and request-options builder currently select the checkpoint/abandonment
   schemas. A semantic-decision request needs an explicit owned variant;
   passing an arbitrary response-format mapping is not an existing API.

A bounded implementation should proceed as one coherent vertical slice:

1. Write live tests through the existing continuation app/worker fixture,
   first demonstrating an ordinary success and actual no-op/cycle that needs
   adjudication. Use the actual role-owned Advisor call with its current
   guard/quota/cost/audit path; only SDK/guard I/O is scripted.
2. Introduce a dedicated semantic Advisor request/result/source owner rather
   than repurposing the reserved Initialize grant. Reuse the existing closed
   response format, prepared input/provenance discipline, provider custody
   and physical audit identity. The SQL side must reprove current
   owner/fence, exact selected CAS, complete original input and actual paid
   response/accounting before constructing/retaining the action source.
   `ContinuationActionSource`'s nominal type alone is not SQL authority.
3. Retain the decision and action before a scheduling boundary, using
   `retain_advisor_action`; retain whole Stop as a model verdict, never as
   `cancel_requested_at`. Keep publication's independent review/commit gate.
4. Extend the actual action allowance, preparation, readback and receipt path
   for the exact prescribed owner. A prescribed PRIMARY still calls PRIMARY
   to author its arguments/graph. Pass the bound action into its real effect;
   let existing execution receipts mark prepared/dispatched/committed/
   refused/unknown. Never derive a graph from frontier text, restart an
   original budget, or mark execution from Advisor advice.
5. Restore the same retained source under the next real fence and execute
   only the selected productive action. Notes, progress events, rollover and
   paid-call occurrence alone cannot manufacture semantic novelty. Unknown
   execution must reconcile before dependent work.

The first implementation can be factored into new, specifically named
semantic-Advisor source/runtime modules, but these would be **new code**, not
APIs this review found already implemented. Full K-7 completion also requires
the supported read/review action branches and model-terminal proposals; a
PRIMARY-only first slice must be labelled partial until those paths and their
refusals are covered.

Tests to reuse/extend are
[actual control/successor](../../tests/unit/web/sessions/test_continuation_control_successor.py#L67),
[actual completion owners](../../tests/unit/web/sessions/test_continuation_completion_owners.py#L259),
and [semantic frontier controls](../../tests/unit/web/composer/test_continuation_progress.py#L60).
The latter already include
`test_same_action_cannot_gain_freshness_from_rollover_or_advice_words`,
`test_action_receipt_custody_is_once_only_and_monotone`,
`test_retained_action_requires_exact_advisor_source_and_selected_frontier`,
and `test_provider_receipts_and_json_key_order_cannot_create_action_novelty`.
They are pure/source controls, not substitutes for the live join.

The live proof must include a real two-segment graph-authoring walk with an
actual separate role-owned call at each transition; an unexecuted prescribed
action retained across disposal; useful negative discovery; repeated advice
and oscillating/no-op graph responses; subset Stop with actionable remainder;
whole Stop with unresolved execution; and a direct human Stop that does not
wait for adjudication. Mutation opponents must skip the successor's provider
call, treat notes as frontier progress, mark attempted on advice, replace the
selected decision/source/fence, and reset the original cost/deadline snapshot.
Each needs a reached positive and a discriminating failure, not a counter
increment added only to make the assertion pass.

The smallest owner is one private live lifecycle per physical segment, held
outside portable frame/snapshot DATA. Start it after the actual running
owner exists; bind the original user-message identity plus current operation,
session-operation id/epoch and exact lease. Give its same callback to first
initialization, cold restoration and every warm context. Thread the existing
callback through actual PRIMARY/model-call events; tool/Advisor/iteration/END
already carry `bindings.progress` when populated. Restore must not replay old
progress events. Retire the old callback at yield/disposal and join heartbeat,
in-flight publication and exact-token cleanup before releasing the physical
owner; the next segment acquires a fresh token. A gap with zero progress
inflight leases does not mean the durable logical operation has completed.

Two existing behaviors need a deliberate repair, rather than blind reuse:

1. [HTTP `composer_request_lifecycle`](../../src/elspeth/web/sessions/routes/_helpers.py#L2681)
   cancels its business owner on renewal lease loss and eventually on
   transient exhaustion. It cannot be wrapped unchanged and described as an
   advisory progress lifecycle. Distinguish nominal progress-only
   `ComposerRequestLeaseLost`, `ComposerProgressIdentityInactive`,
   `ComposerProgressSessionUnavailable`, actual `OperationalError`/pool
   timeout and bounded admission loss from programming/integrity errors.
   Disable only the advisory channel on the former; preserve the original
   exception/cancellation and make defects visible on the latter. COMPOSE
   fence/required-work loss remains business authority loss.
2. [Registry cleanup](../../src/elspeth/web/coordination/composer_progress_authority.py#L542)
   shields/joins deletion but still submits ordinary `run_sync_in_worker`.
   [Shared worker admission](../../src/elspeth/web/async_workers.py#L157)
   refuses ordinary work after [begin_drain](../../src/elspeth/web/sessions/composer_async_worker.py#L201).
   Exact deletion on drain therefore needs an owned, prebound cleanup
   capability. The existing [QueuedClaimRelease](../../src/elspeth/web/async_workers.py#L58)
   is the narrow pattern, not a progress API that already exists. Bind only
   the actual progress authority's `end_request` and the issued exact lease;
   keep fresh admission/publish/renewal refused during drain and preserve
   executor-generation quarantine. Do not add a generic drain callback or
   unrelated executor. If cleanup cannot run, report its actual failure and
   retain expiry/reaper semantics; do not claim successful unregister.

## Risk Assessment

K-7 touches durable action authority, paid source identity, cold restoration
and request-wide progress; it is the higher integration risk. Broadly deleting
active-action refusals, accepting an old nominal source as current clearance,
using advice as execution, or skipping PRIMARY would violate the contract.
Progress is advisory but its cleanup can strand a physical owner during drain;
generic drain admission or swallowed programming failures would create real
authority/lifecycle defects. Failure parity can double-write audit/state if
held HTTP helpers are reused without preserving current terminal ownership.
