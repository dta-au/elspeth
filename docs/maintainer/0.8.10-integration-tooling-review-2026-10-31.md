# Integration tooling review — 31 October 2026

The required guarantees are sound. The current mechanisms do not consistently
deliver them. Keep narrow, coherent commits, independent review, meaningful
opposed tests, source provenance, one owner of integration, finite execution and
real cleanup. Fix the gaps between working files and committed files, between a
valid finding corpus and an analyser failure, and between a direct-child exit
and a reclaimed test slot. Reuse the existing supervisor instead of maintaining
separate lifecycle implementations in inline controllers.

This review prioritizes code quality, then efficiency, then speed. It applies
[ADR-046](../architecture/adr/046-audit-grade-is-a-product-characteristic.md):
protect code, tests, runtime data and release evidence; keep development
coordination ordinary and small. It recommends no scope reduction, gate waiver,
second development line, backup deletion, signing or permission ceremony.

## Prioritized findings

### F1 — P1: custom controllers release ownership before proving cleanup

The exported pytest controller waits for its immediate `Popen` child and removes
the capacity row in `finally` (transcript lines 50–57). On a normal exit it never
checks for surviving descendants. After timeout it sends TERM to the group but
sends KILL only if the immediate child is still alive five seconds later. A
parent can exit promptly while a descendant ignores TERM; the slot is then
removed although work remains. An error while registering the just-started
child also occurs before the guarded wait.

The keyless variant has no separate child process group. Its timeout path calls
`terminate()` and a second ten-second wait, without escalation. If that wait
raises, its `finally` clears capacity, and the outer `finally` restores the
shared source without establishing that the analyser has stopped (transcript
lines 109–123). Python `finally` also cannot promise restoration after controller
SIGKILL or host loss.

These are implementation gaps, not evidence that either retained run leaked a
process. In particular, the recorded attempt2 native exit `-11` is a terminal
direct-child exit. Its source was restored. The affected pytest receipts do not
contain a descendant-cleanup proof equivalent to the canonical supervisor's.

**Minimal fix:** route each custom command through
`scripts/ci_proof_progress.py`, which already owns Linux subreaping, group TERM,
KILL, bounded reap and cancellation. Release its reservation only after the
supervisor has actually exited and reported complete cleanup; retain an
unresolved reservation when cleanup is incomplete. Preserve command, native
exit and JUnit records. Remove the duplicate lifecycle code. This adds no new
controller or approval step.

### F2 — P1: the canonical gate can pass an invalid lint run

`scripts/full-suite-gate.sh:613` makes `lints` nonfatal by default; line 607 only
turns a nonzero stage result into failure when that stage is fatal. Consequently
an invocation selecting `lints` can finish with `RESULT=PASS` and zero outer
statuses after a lint CLI configuration error, crash or other invalid scan. The
documented reason for advisory findings is valid; it does not justify treating
every exit as a completed measurement. The text-regex finding count at line 589
cannot prove corpus completeness.

**Minimal fix:** distinguish a complete findings result from a failed scan.
Parse the full JSON output, reject parse/read diagnostics or invalid/missing
output, and require the exit to agree with the corpus. Keep complete findings
advisory pending the required base/tip review. Make an invalid scan nonzero and
incomplete. `scripts/trust_tier_ratchet.py:310` already demonstrates the
exit/JSON consistency check. Preserve its distinction between measurement and
clearance.

Root did not make this mistake in the reviewed increment: its canonical run
selected only ruff, mypy and contracts; the manual all-rules attempts remain
explicitly incomplete. This finding concerns the next use of the canonical
lint stage, not the validity of that static result.

### F3 — P1: the no-stash hook checks different possible bytes from Git

`scripts/git-hooks/pre-commit-dispatcher.sh:20` obtains staged path names, then
lines 37–40 run `pre-commit ... --files`. Filename-bound hooks inspect the
working files. Git commits the index. A partially staged file can therefore
have failing staged bytes and passing working bytes. The branch preflight
checks staged secret/home content, but has no equality guard for the other
checks. The installed pre-commit implementation confirms that a nonempty
`args.files` disables its staged-file isolation.

**Minimal fix:** keep no-stash dispatch. Refuse selected paths whose staged
bytes/mode differ from the working version, and hold their writers until the
commit finishes. Alternatively check a deliberately isolated index view; do
not restore other owners' files. Add an opposed partial-staging case to the
existing dispatcher tests, whose current regression covers deletion-only
dispatch rather than this case. Whole-tree hooks also consume foreign working
inputs: selected-path equality does not turn those results into checks of the
complete index. Bind final qualification to the intended assembled commit
tree; describe earlier mixed working-tree results with their actual boundary.

This is not a discovered defect in commit `183a94d9e`. Independent immutable
`git show` SHA256 comparisons of all seven feature paths against
`attachment-keyless/candidate-files.json` returned exit 0 and matched exactly.
Root also reports whole-file staging while writers were held. The queue was
the separately intended eighth path. Apply the explicit guard to future
staging rather than invalidating this bounded increment.

### F4 — P2: repair analyser liveness before another large retry

The first all-rules baseline attempt exceeded 300 seconds without JSON.
Attempt2 records `exit=-11`, `timeout=false`, elapsed
`240.46246981620789` seconds, with unchanged sampled inputs. Its stderr contains
60-second stack dumps, ending in `possible_value_origins` at line 644. Neither
JSON file contains a corpus. These facts establish a failed measurement; they
do not establish the ultimate cause of the native crash.

There is a concrete investigation target:
`exception_taxonomy.py:594` recursively transfers origins through AST
expressions and defaults. The visited-name/depth guard at line 661 is on
`possible_mutation_roots`; it is not a bound on total expression-transfer work
or repeated fan-out. The CLI emits the complete JSON only after all selected
rules finish (`core/cli.py:241` and `:372`), so increasing the outer timeout alone
does not identify the expensive rule/input or make the traversal supportable.

**Minimal fix:** isolate the failing rule and source expression, then make
origin traversal share finite scan-local work, with cycle/depth/work behavior
that preserves the existing conservative mutation vetoes. Confirm the native
crash cause independently; do not label it solved from a stack sample. Add
small stderr rule/input progress diagnostics if needed, keeping the final
corpus complete. A bound reached must produce explicit incomplete analysis,
never an omitted finding dressed as a pass. Receive the fix with the existing
exception/mutation oppositions and the exact failing input, then complete A4's
full base/tip comparison.

The seven-path temporary reversal was careful and demonstrably restored the
reviewed bytes. It was a mixed marginal baseline with observer context held
fixed, not the immutable full receiving-base tree. Prefer a source reader that
can consume the exact Git revision/input map without rewriting the active
receiver for future comparisons. The source-only taxonomy already accepts an
AST mapping; this is an engineering direction to assess, not a claim that all
rules currently support such a reader. Do not create an extra active line or
copy a source tree into lanes to solve it.

### F5 — P2: capacity and source binding need one small shared implementation

The custom controller's `flock` protects JSON updates, but its admission check
occurs outside the lock and its child starts before registration. Thus the
lock proves serialized file writes, not atomic admission. Root's single-owner
discipline currently supplies the scheduling guarantee. Keep that explicit.

The inspected `test-capacity/STATE.json` was **2,096,044 bytes** by filesystem
metadata. It combined `active=[]`, a current release-completion owner,
`admissions_enabled=true`, a paused quota record and extensive historical
delivery material. These are snapshots with different meanings; loading or
copying the whole record does not settle present capacity. Run-specific
`capacity.json` files usefully record actual sibling commands/load and modest
allocations, but are observations rather than a host-wide exclusive lease.

Source binding is duplicated too. The custom controller hashes all tracked and
untracked nonignored file bytes at endpoints. The canonical gate hashes Git
status and dirty-file content every five seconds (`full-suite-gate.sh:373`),
with documented gaps for short reverted edits and excluded inputs. Neither
mechanism alone proves that no source changed between observations. The
writer hold is an essential part of the guarantee, not optional paperwork.

**Minimal simplification:** maintain a small active reservation record with
owner, exact process identity, resource allocation and log location; retain
historical results in their existing logs. Check/reserve under one lock, then
bind the launched identity; do not equate a JSON edit with cleanup. Share one
tested input-digest helper and the existing supervisor between focused and
broad runs. Record its coverage honestly, including ignored inputs and
symlink referents. Preserve writer holds for global scans. Do not reset or
delete shared historical state as part of this review.

The attachment increment was bounded by actual settings-to-I/O behavior, not a
test total. The disconnected old-literal mutation failed at requested read
sizes and real policy fingerprints. The SQLite and real serial PostgreSQL
receiving paths were distinct. Supported-interpreter checks were separate;
the Python 3.12 PEP-696 skips were explained. Observer failures and its native
worker crash remained visible rather than being absorbed into the attachment
claim. These are material safeguards worth keeping.

The canonical static result has matching terminal evidence: ruff/mypy/contracts
each exit 0, healthy freeze watchers, `frozen=yes`, driver/launcher/supervisor
exit 0 and `cleanup_complete=true`. The six-minute affected AST check's result
was scoped to its selected guards. Neither result was called a full release
gate. Re-running broad suites for every small adjustment would not improve
that evidence; reuse results while the relevant input boundary remains bound.

Creating a separate frozen-lock Python 3.12 environment preserved the primary
environment. After the first build advertised a missing `mutmut.pytestplugin`,
Root rebuilt under a path outside `.pytest_cache`, retained the old attempt,
and disabled no plugin. The receipts/logs support the failure and successful
replacement environment. The stated filename-sniff explanation was not
independently traced to the dependency's setup source in this review. Keep
clear environment provenance; do not convert preserving a failed tool
environment into a new universal retention rule. Existing backups/spares stay.

Root read the failures, restored owned files, used normal hooks/preflight and
pushed an explicit SHA with a matching remote readback. The WIP commit message
and landing queue keep A4, observer work and release acceptance open. Publishing
that coherent increment was supportable; a broken analyser should block the

force unrelated completed work to remain only on disk.

## Caveats and Required Follow-ups

Before relying on a repaired mechanism, exercise its specific adverse case:
parent-exits/descendant-survives; TERM-resistant analyser; invalid/missing lint
corpus; and staged bytes differing from working bytes. Use the existing focused
tests and actual failing input, then run the affected whole-tree checks. These
are future validation requirements, not results claimed by this review.

Keep A4 incomplete until both exact full corpora exist and additions/removals
are reviewed. Keep release source, bounded receiving, WIP publication, final
qualification and main/merged-SHA CI as separate claims. Root should implement
these repairs in proportion to their risk, under the existing one-line
ownership boundary. The review itself changes no tooling, refs or runtime.
