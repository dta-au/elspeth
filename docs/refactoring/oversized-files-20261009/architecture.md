# Oversized-file decomposition

This is the architecture and ownership map for branch `refactor/oversized-files-20261009`, based on main `9e481bc85a32ee15f808c5e2b16cab7634e57b8e`. It is a refactoring design, not a claim that the mapped changes have landed. The immediate implementation is the processor-test slice below. Streaming PR #281 keeps priority and owns its active surfaces; the other designs become executable after its changes are integrated and remeasured, or after its owner explicitly releases a bounded scope on a measured stable base. No such release was received during this design.

The inventory deliverable in this directory is the size authority. Its fixed-snapshot raw measurements distinguish main, published PR #281 (`9f26833c8f6a7c56abd2c5b35c80484ebe0c82bc`), streaming-local, and repair-integrated (`703cdd1674d01d422baa4d54f210105edccf498c`). Sizes below are main-snapshot physical lines; they must not be mistaken for the final streaming branch. AST inspection supplied symbol boundaries, while source reads and explicit repository reference searches supplied dependencies. This note does not assert behavioral parity from AST inspection.

## Constraints and ownership

Move coherent responsibilities, with a working target of at most 5,000 lines per authored module and no authored module above 10,000 at the end of its scheduled decomposition. The threshold is a maintenance trigger, not a reason to split an individual proof or replace assertions with a generic loop. A remaining oversized file is unfinished work, not success concealed by a thin facade.

## State-model and validation architecture

The current dependency problem is visible in the source: `CompositionState` owns immutable edits and serialization plus a large `_validate_with_probe_cache`; `_check_schema_contracts` is another large function; `_producer_resolver` already imports state while state imports its types under `TYPE_CHECKING`. Move leaf definitions first rather than creating a cycle and hiding it with runtime imports.

1. `state_specs.py` owns `PipelineMetadata`, `SourceSpec`, `NodeSpec`, `EdgeSpec`, `OutputSpec`, node/edge vocabulary, and shape normalization needed by their constructors. It depends on runtime contract/config declarations, not `CompositionState`. Keep the import-time vocabulary mismatch refusal executable under optimized Python. Runtime-derived defaults remain derived, not copied literals.
2. `validation_types.py` owns `ValidationEntry`, `ValidationSummary`, `EdgeContract`, schema/row-union/coalesce detail records and serialization. It depends on spec/value definitions only. Existing public imports from `state` may be explicit named re-exports while `state.py` continues to own substantive `CompositionState` behavior; private callers migrate to the real owner. No generic export machinery.
3. `validation_probes.py` owns `ValidationProbeCache`, its probe result records, plugin-config exception classification, and source/sink/transform probe lifetime. A single cache instance is passed through one validation call and closed on every exit. Preserve constructor side effects and failure classification; do not add global caches.
4. `validation_topology.py` owns connection targets/lineage/reachability, cycle detection, gate/edge route parity, and structural collector/queue validation. Consume explicit specs and graph inputs; return the same ordered `ValidationEntry` values and fact records. It does not author or repair a graph.
5. `validation_templates.py` owns prompt-role and template/query-variable validation, template parsing and required-input checks. Preserve parsing memoization at the same lifetime and diagnostics with the same codes, attribution, severity, text, and remedies.
6. `validation_schema.py` owns `_check_schema_contracts`, value-transform binding and schema/guarantee propagation. It consumes specs, topology facts, and the caller-owned probe cache. First move the function without algorithm changes; only then split internal walks by producer resolution, branch join, and consumer acceptance if measured size still requires it.
7. `state_validation.py` owns the ordered validation orchestration currently in `_validate_with_probe_cache`. `CompositionState.validate` remains a real entry point that establishes the probe lifetime and calls it. The orchestrator receives the state and typed dependencies; it never imports the public `state` facade to recover globals.

`state.py` has observed monkeypatch dependencies: state tests replace `_parse_template_names`, `multi_query_source_row_columns`, and `_runtime_connection_lineage`, and the tool-schema test replaces `OutputMode`. A function moved to another module looks up that module's globals, so an old re-export would silently stop those patches affecting execution. In the extraction commit, update each test to patch the implementation owner's lookup or pass an explicit existing dependency where the boundary warrants it; verify that the patched failure/counter still trips. Do not add `sys.modules` aliases, module mutation bridges, `__getattr__`, or dictionary forwarding to simulate the old globals. Check direct private imports and decorators as well as patch strings.

Keep two authoring invariants measurable: validation can reject/redact the provider's proposal, but no new module constructs pipeline structure in place of the provider; tutorial transitions execute the same path. Any later optimization on rootless/tutorial paths still needs per-transition provider-call scrutiny. This decomposition proposes no planner optimization.

## Authority-gate architecture

Use `tests/helpers/authority/` for reusable analyzer implementations and data with explicit imports; use real `test_*.py` modules for assertions and adversarial programs. Do not put source scans in conftest. Policy records are typed Python data, and remain independent of the live source they constrain.

**Sessions:** `session_policy.py` owns `TablePolicy`, authority registries and reviewed writer/read manifests; `session_writer_scan.py` owns `WriterIdentity`, lexical resolution and `_ProductionWriterCollector`; `session_containment.py` owns probe, wrapper and caller-side proof; `session_inventory.py` owns scan orchestration and exact drift comparison. Keep collector types in a leaf module if policy-to-scan imports would otherwise cycle. Initially move the collector as a whole; its reaching-binding and unknown-path behavior must not be redesigned during extraction. Keep table-policy tests and exact writer-set checks separate from adversarial resolver tests. Long manifest data can be split by named authority domain into typed tuples with one explicit concatenation order, never dynamically discovered modules.

**Clock:** `clock_sources.py` owns lexical/function/connection facts and `_ClockScanner`; `clock_fences.py` owns first-fence, leader deadline, worker registration and heartbeat proofs. Keep database-clock authority tests for live-tree assertions; separate lexical/provenance fixtures and mutation controls into their own test modules. Landscape currently imports `_clock_captured_alias_is_mutated`, `_clock_lexical_scopes`, `_leader_deadline_sources_are_proven`, `_lexical_binding_sites`, `_worker_heartbeat_contract_violations`, and `_worker_registration_contract_violations`. Its imports and the ordinary database-clock test's `_clock_returning_references`/`_scan_sources` imports migrate directly to these owners.

**Landscape:** `landscape_policy.py` owns `MutationApi`, scope registries and exact inventories; `landscape_sources.py` owns `SourceUnit`, `_Resolver`, source reading and symbol resolution; `landscape_dml.py` owns DML/raw-SQL identification and fingerprints; `landscape_authority.py` owns `_AuthorityProof` and caller/API authority checks; `landscape_transactions.py` owns order, subordinate-helper and escape checks; `landscape_deadlines.py` owns deadline issuance/locking/finalization recipes and proofs. If deadlines exceed the target, separate issuance from finalization with explicit typed facts between them. Test suites keep independent inventory-pin and violation assertions, plus adversarial mutation cases by proof family.

Source roots must become explicit analyzer inputs. Existing `_repo_root()` implementations derive the root from the test file depth; moving them and leaving `parents[3]` unchanged would scan the wrong tree. Keep `iter_gate_files`/`iter_gate_sources` as the one enumeration authority, fail on unreadable/unparseable or disappearing source, and pass the intended root through caches. Cache scope must not leak source units from one tree into another.

`scripts/fencing_inventory.py` currently imports the test file through `spec_from_file_location`, with an independent module name per tree, then reads private symbols directly. Move its invocation to the real analyzer API and carry `tree` explicitly. Preserve the ability to compare two distinct trees in one process: ordinary imported-module globals must not collapse the two root contexts. `scripts/probe_receiver_marker_inertness.py` is another explicit consumer. Do not leave a test module as a symbol-only compatibility barrel for scripts.

An extraction is accepted only if live-tree writer identities, occurrence ordinals, DML/caller/internal/subordinate inventories, write shapes, and every violation set agree before and after. Compare full records/fingerprints, not totals. Keep exact pins hard-failing and unresolved evidence refusing. Re-run the existing adversarial aliasing, shadowing, branch merge, raw SQL, connection escape, authority forgery, deadline/lock-order and cancellation/finalization cases. Add a relocation-specific negative control when an extraction changes a scanner's root, imports or dispatch. Then run the full suite: these are test/scan infrastructure changes, not isolated ordinary test moves.

## Sequence, rollback, and remaining blockers

1. Complete the isolated processor-test slice and review its measured collection/execution results. If assertions, parameterization, imports or patch behavior differ, repair the split or revert only that slice's owned changes; do not alter production to satisfy a moved test.
