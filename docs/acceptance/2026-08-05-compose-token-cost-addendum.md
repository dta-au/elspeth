# Addendum: the compose token cost is a caching problem first

Date: 2026-08-05. Supplements and partially corrects
`2026-08-05-compose-token-cost-brief.md`. Evidence: two read-only
`database-bootstrap` inspections of the live round-3 session store (task ids
`4f97e718…`, `a1007371…`), direct unit measurement of the deployed 16-plugin
prompt surfaces, and code/test reading on `release/0.7.2`. Measurement scripts
and full sub-reports are in the session scratchpad; the store queries are
reproducible from `ops-local/acceptance/run_task.py` against
`a-fa1b99c60192978b10f7-database-bootstrap`.

## The finding in one line

Prompt caching covers only ~31k of the 49.3k fixed prefix — the dynamic
context (~21k, 98.4% deployment-constant) and the entire growing message
history are re-billed at **full input price on every one of the 151 Sonnet
calls**, and that uncached repetition, not the size of any prompt component,
is where most of the USD 22.41 went.

## Corrections to the brief

**C1 — "Prompt caching is active and working" is true for only part of the
request.** `apply_anthropic_cache_markers` (`llm_response_parsing.py:810-858`)
places exactly two markers: the first `system` message and the trailing tool.
`test_provider_cache_markers.py:328` positively asserts the dynamic-context
message is *not* marked. Anthropic caches up to and including a marker, and the
wire order is tools → system → messages, so the cached prefix is **tools +
system only (~31k tokens)**. Everything else — the ~21k dynamic context, every
assistant turn, every tool result — is uncached input on every call. The
observed costs fit this model: warm first calls ($0.074–0.082, 14 sessions)
match a 0.1× read of ~31k plus ~18k of fresh input; the three ~$0.17 first
calls are cold cross-session cache writes; call-index-5 means ($0.17) match
0.1×31k + 1×~45k. The brief's cache-hit evidence (call 2 cheaper than call 1)
only proves the 31k prefix was reused.

**C2 — The growth curve is NOT the schema carry-forward.** Proven from the
store: all 17 sessions have exactly one `user` row and strictly monotonic
per-session token sequences — no session ever re-entered `compose()`
(recompose or guided-exit would rebuild the message list and show a token
drop; none exists). `llm_messages` is built once per `compose()`
(`service.py:4919`) and appended to in-loop, and `schema_contract_evidence`
renders from `_schemas_loaded_for_session` — empty on every first compose
(310 canonical bytes). **The carry-forward contributed zero tokens to round
3.** The +39k growth is the appended tool results — a raw `get_plugin_schema`
result is 8.4–19.1 KB (~2.1–4.8k tokens) and stays in the message array for
the rest of the compose — which also explains why the largest step follows the
opening `get_plugin_schema` burst.

**C3 — The 96 KB ceiling is unreachable in the deployed shape.** Under the
profile-bound catalog view (ADR-036 alias projection), the largest single
contract entry is 3,540 canonical bytes; the 8-entry cap binds first at
~21.7 KB canonical ≈ 53 KB rendered ≈ 13.4k tokens — and only on a
second-or-later compose of a session. Separately, the cap counts *canonical*
bytes while `prompts.py` renders with `indent=2` (measured 2.0–2.4×
inflation), so the budget under-counts the wire by ~2×.

**C4 — The residual is ~21k tokens and is the largest prefix component.**
Directly measured: `build_context_string()` under the deployed 16-plugin
policy with an empty state is **84,897 chars**. The accounting closes at an
implied 4.03 chars/token against the 49.3k baseline: context ~21k (43%),
SYSTEM_PROMPT ~18k (36%), tools ~10.2k (21%). The brief's 3.7 chars/token
over-counted system+tools and under-attributed the context by ~2.6k. The
"untrusted current state" is 679 chars — 0.8% of the message; **98.4% of the
context is deployment-constant** (`authoring_aids` 58,515 chars +
`plugin_hints` 22,563 + policy/plugin lists), byte-identical on every call of
every session for a given deployment.

**C5 — Constraint 2 (skill/tool drift gate) is stale.** There is no
`test_skill_drift.py` and no `## CRITICAL: Tool Schema Availability` heading
on this branch (the `get_tool_definitions()` docstring is out of date). The
real coupling is the autogen `## Tool Inventory` block
(`pipeline_composer.md:185-191`), regenerated by
`scripts/cicd/generate_skill_inventory.py --write` and checked in CI — and it
matches tool *names* only. Schema-body slimming touches no skill gate at all.

**C6 — Round 3's audit rows cannot answer cache questions.** The deployed
build persisted a 6-field projection (`model_requested`, `model_returned`,
`status`, `total_tokens`, `reasoning_tokens`, `provider_cost`). Current HEAD's
`_LLM_CALL_PUBLIC_AUDIT_FIELDS` (`audit.py:291-319`) adds
`prompt_tokens` / `completion_tokens` / `cached_prompt_tokens` /
`cache_creation_input_tokens` / `cache_read_input_tokens`, so the **next**
deployed round measures the cache split directly. Verify the fix wave against
those fields, not `total_tokens` alone.

## Re-ranked work

**1. Fix the cache architecture (new; the dominant lever).**
(a) Move the deployment-constant 98.4% of the context (authoring aids, plugin
hints/policy/list — byte-stable per deployment) into the marked cached prefix,
leaving only the ~1.4k-char varying tail (current_state, schema evidence,
progress) outside it; place that varying tail **after** the chat history, not
before it, so history caching survives multi-turn sessions. (b) Add a sliding
message-level `cache_control` breakpoint on the last stable history message
each call (Anthropic allows 4). Estimated effect on the round-3 shape: mean
session $1.32 → roughly $0.40, no content or model-quality change. The
untrusted-content doctrine is unaffected — marking a `user`-role message for
caching does not elevate its role; it only requires byte stability, which the
constant block already has.

**2. Delete intra-context duplication and indentation (~7.4k uncached
tokens/call).** Drop the redundant `plugin_hints` block (discovery digest
already carries the identical hints) and render compact separators. Two
production edits; three test assertions to update (`test_prompts.py:437, 468,
895`). Also halves the wire cost of any future carry-forward evidence. Worth
doing even before item 1; after item 1 it still shrinks cold writes and 0.1×
reads.

**3. Schema carry-forward: deprioritise (was brief item 3).** It cost zero in
round 3 and its byte ceiling is unreachable in the deployed shape. If touched:
a most-recently-referenced window (whole contracts for state-referenced
identities, `digest_only` omission records for the rest, so `schemas_gap`
stays honest — preserving the bb5a81213 guarantee) plus re-expressing the
budget in rendered bytes. Do not adopt digest-only-with-rehydrate: a raw
`get_plugin_schema` round trip is 2.6–5.4× the bytes of the projected entry
and re-enters the discovery churn the digest was built to kill.

**4. Tool payload: cost-deprioritise (was brief item 2).** It is already
cached at ~0.1× after call 1, so trimming it moves ~$0.03/session, not
$0.34 — the brief priced it uncached. If trimming for latency/cold-writes:
trim the un-pinned nested `parameters` prose (measured −1.2–1.5k tokens/call
at conservative caps), keep names/order/top-level descriptions/`required`
untouched, and never phase-gate the tool list mid-session — the render order
means a mid-session tools change invalidates system + history cache, is
net cost-negative, and every existing gate stays green while it regresses
(subsequence filtering is explicitly blessed by
`test_litellm_tools_preserves_definition_order`).

**5. SYSTEM_PROMPT: unchanged rank (last), now with a map.** Cached at 0.1×;
trim for quality/latency, not cost. Overlay-only dedup (~5 KB) is safe-ish
(25 pinned assertions); the big two-section consolidation carries ~57.

## What the old ten-cent figure would actually take

With items 1–2 landed, the irreducible per-call read is the cached prefix
(~40k tokens after dedup) at 0.1× ≈ $0.012/call — a 10-call compose pays
~$0.12 in prefix reads alone before history, writes, and output. Sub-$0.10
therefore additionally requires fewer calls per compose (better first-shot
authoring; the 60 `get_plugin_schema` calls suggest schema pre-provisioning
for the plugins the pipeline actually references) and/or a smaller constant
catalog digest. ~$0.25–0.40 per compose is reachable without any
model-quality trade; below that, the trade space opens.

## Measuring the fix wave

Same store queries as the brief, plus the new fields from C6:
`cache_read_input_tokens` should approximate the prefix+history size on warm
calls, and `(total_tokens − cache_read_input_tokens)` per call should flatten
to the per-turn delta. Wall-clock stays a non-metric.
