## 0. The choice, and why

**Both judges name platform-native.** Architecture lens: platform-native 8.5 /
contract-first 7.5 / mirror-first 5.5. Reality lens: platform-native 8 / contract-first
7.5 / mirror-first 7. There is no disagreement to adjudicate this round (the 20:47

single maintainer (~1,500 lines against a 13,017-line mirror), and had the highest
citation-accuracy rate under adversarial re-measurement — including the one place it
disagreed with both other designs (`acquire` at `repository.py:4077`, not `:4112`) and was
right.

## 1. Goal

Ship an Azure Container Apps deployment of ELSPETH that is **equivalent in evidence** to
the AWS ECS acceptance: a checked-in Bicep bundle composed from Azure Verified Modules; an
acceptance receipt family whose `schema_facts` derive from the same source as ECS's; three
runbooks and an operating skill; ACR publication already in CI; and one live, unmocked
acceptance run at replica count > 1 exercising the four multi-replica probes on the landed
epoch-51 substrate — flipping `docs/reference/deployment-platforms.md:93-98` from
"reserved / unsupported / deferred" to "maintained" **in the same commit as the sanitized
receipt**.

"Equivalent" is read as equivalent evidence, not equivalent code. Where Azure's control
plane already produces the fact (revision state, replica list, console and system logs,
Resource Graph inventory, Flexible Server metrics), the acceptance records a sanitized
projection of that fact; Python survives only where the fact is ELSPETH's own (schema
facts, fence semantics, receipt binding, probe decision tables).

  (`state-engine-live-provider.yml:125-137,372-388`); only the two
  `azure_blob@managed_identity` cases re-run *inside* the environment, because managed

- No zero-overlap rollout guarantee: ACA overlaps revisions during readiness, and the

### 3.2 Identity

- One UAMI for the app and every Job: `AcrPull`, `Key Vault Secrets User`,
  `Storage Blob Data Contributor` on the acceptance blob container only (so the two
  `azure_blob@managed_identity` cases run in-environment via `AzureAuthConfig
  use_managed_identity`, `plugins/infrastructure/azure_auth.py:25-60`).
- **PostgreSQL authentication is a role password in Key Vault**, not an Entra token (§2).
- **Acceptance gives rA and rB distinct runtime roles** (`elspeth_runtime_a` /
  `elspeth_runtime_b`, two Key Vault secrets, two revisions differing only in the URL
  secret reference). This makes probe 3's dead-owner primitive deterministic (§7).
  Production uses one runtime role.
- Acceptance runner identity: the operator's `az login` context plus `Log Analytics Reader`
  on the workspace and `Reader` on the RG. No credential enters a receipt
  (`_FORBIDDEN_RECEIPT_KEYS`, `receipt_contracts.py:656`, reused through the shared module).

### 3.3 Secrets and TLS

Container Apps secret references (`keyVaultUrl` + `identity`) for
`ELSPETH_WEB__SESSION_DB_URL`, `ELSPETH_WEB__LANDSCAPE_URL`, `ELSPETH_WEB__SECRET_KEY`,
`ELSPETH_WEB__SHAREABLE_LINK_SIGNING_KEY`, `ELSPETH_FINGERPRINT_KEY`, the composer
endpoint key(s) and `operator_metrics_bearer_token`. The schema-init Job gets the
schema-owner URLs; the runtime Job and the app get runtime URLs (the two-role split of
`deploy/aws-ecs/terraform/modules/scenario/locals.tf:543-569`). Rotation = new secret
version + new revision; receipts record secret **names and versions**, never values.

`require_aws_authenticated_tls` is target-gated to `aws-ecs`
(`deployment_contract.py:136,150,373,379`) and the baked RDS bundle is AWS-only
(`Dockerfile:168-169`); the ACA runbook sets `sslmode=require` minimum, `verify-full`
against the Microsoft root when the operator bakes it; the doctor's `postgres_tls_check`
(`doctor.py:354`) reports the posture either way.

### 3.4 Telemetry

- **Logs:** environment `appLogsConfiguration` → Log Analytics; console logs carry the
  structlog JSON (`ELSPETH_WEB__LOG_JSON=true`), system logs carry revision/replica
  lifecycle. No sidecar, no agent-config hash to validate.
- **Operator metrics:** `ELSPETH_WEB__OPERATOR_TELEMETRY=prometheus` (default,
  `config.py:198`) with `operator_metrics_bearer_token`; the driver scrapes `/metrics` per
  replica through its label URL. `aws-otlp` is refused off-ECS by the doctor
  (`doctor.py:195`); `apply_operator_pipeline_telemetry` short-circuits for non-ECS targets
  (`operator_telemetry.py:533`). Neither file is touched.
- **Evidence queries** are checked-in `.kql` files whose SHA-256 is bound into the
  receipt; table and column names are verified live by 6b-0 and **never pinned in a unit
  test** (Azure has both `_CL` and resource-specific table shapes). Queries: the doctor
  `--json` report by job execution name; `RunStarted`/`RunFinished` lines by sentinel hash
  summarised by replica; replica lifecycle for the probe-3 window; the 409 body
  (`app.py:1061`, `"Session operation is already active"`) joined to two replica names.

### 3.5 Rollout

- **Production:** `activeRevisionsMode: Single`, revision suffix = candidate short SHA;
  `az containerapp update --image <acr>/elspeth@<digest> --revision-suffix <sha>`. ACA
  waits for readiness (`/api/ready`, `app.py:1872`), shifts traffic, deactivates the old
  revision. The overlap is an equal-key overlap the fences serialise; the epoch sentinel
  (`validate_external_schema_or_raise`, `app.py:1289-1292`) refuses an unequal-epoch
  candidate before it is ready.
- **Probes:** startup probe on `/api/health` (`app.py:1862`) with a failure budget
  covering ECS's 150 s `startPeriod` (`ecs.tf:176-179`), then liveness 30 s / 3 and
  readiness `/api/ready` 10 s / 3.
- **Ingress session affinity ON in production** (`ingress.stickySessions.affinity:
  sticky`): the WebSocket ticket store (`execution/websocket_ticket.py:26`;
  `execution/routes.py:127-128`) and the composer progress registry are process-local, so
  a browser must return to the replica that issued its ticket until 07-26 Tasks 7-8 land.
  The bundle test pins it; acceptance disables it (label URLs make targeting a
  control-plane fact).
- **Ingress idle timeout** feeds the composer transport ceiling, which must be the minimum
  across hops (`config.py:47-68`); the Bicep takes
  `ELSPETH_WEB__COMPOSER_TRANSPORT_IDLE_CEILING_SECONDS` as a **required parameter with no
  default**.
- **Proof of rollout** (replaces the ECS jq gate at
  `aws-ecs-existing-service-redeploy.md:509-548`): exactly one active revision at 100 %
  with the candidate digest; `replica list` → N `Running`; `/api/health` 200,
  `/api/ready` 200; `/api/system/status` (`app.py:1895`) reports target, `frontend_build`
  and (after 6b-3) `instance_id`.
- **Rollback:** `revision activate <previous>` + 100 % + deactivate the candidate, only
  when the compatibility record says `rollback_permitted`; for Scenario A that is `false`
  by the record's own rule (`aws-ecs-deployment.md:1540-1545`), so the runbook says
  "repair forward" exactly as ECS does.
- **Scale-in** sends SIGTERM; with 6b-2 the lifespan marks the instance `draining`
  (readiness fails), stops the heartbeat, releases owned fences, records `stopped`.

ELSPETH beyond the schema-owner/runtime role split every external target already requires.
It is the same shape as the 07-26 spec's `maintenance-cutover-forward-only` proof.

(partition/kill owner, list replicas, address replica); two ports.
