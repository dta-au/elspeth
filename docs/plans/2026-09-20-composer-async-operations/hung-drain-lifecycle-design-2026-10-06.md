## Selected mechanism and supported runtime

Add an owned `ProcessWatchdog` plus a tiny stdlib-only exec helper module. Start it at the beginning of `create_app`, before operator telemetry/bootstrap/readiness/session/execution/composer owned workers are created. It targets `os.getpid()` in the actual application factory process. With reload, that is the serving application child, not the Uvicorn reload supervisor. A direct Uvicorn factory invocation also targets its actual serving PID. Do not spawn after quarantine/hang, fork Python code into a multithreaded child, or launch the helper through a worker pool. Use Popen with an argument list, no shell, no preexec_fn, immediate exec of the private helper entry point; only reviewed control descriptors are passed.

The supported production hard-recovery contract is Linux with functioning process pidfd and pidfd_send_signal. Open a process pidfd with flags0 before launching the helper and pass that exact handle. This is not a PID-number lookup performed later and never uses PIDFD_THREAD. Startup must actually open/prove this capability and obtain the helper handshake; unsupported kernels/security policy/helper launch cannot produce ready=true. No silent fallback to the old SIGTERM-only behavior. Non-Linux production support is not invented here; it requires a separately reviewed native supervisor implementation before claiming the same contract.

A process pidfd refers to the original process despite PID reuse. Poll readability without PIDFD_THREAD proves the last thread in that group exited; the helper need not be the target's parent and must not pretend it can waitpid its parent. [Linux pidfd contract](https://man7.org/linux/man-pages/man2/pidfd_open.2.html), [Python pidfd signalling](https://docs.python.org/3.13/library/signal.html#signal.pidfd_send_signal).

Production supports one serving app/recovery owner per OS process. Multiple test app factories use an explicitly injected owned test double. No detection of pytest, environment magic, exposed HTTP switch or runtime structural impostor is allowed. Real production factory default always performs the real handshake; TestClient fixtures inject a nominal fake watchdog and fake clock/signal sink so pytest is never a kill target. Factory construction failure must retain/close its watchdog through the explicit failed-startup recovery protocol, not leak a helper. Existing external instance/replica identity and auth behavior remain unchanged.

## Private control and acknowledgement

The factory creates an unnamed private AF_UNIX socketpair before exec. Only its reviewed helper endpoint and exact pidfd are inherited; no public socket name, HTTP endpoint, shared filesystem, operator credential or secret-bearing environment variable is added. A random per-launch nonce is exchanged over that already private descriptor, kept only in memory, never in argv/logs. Bounded closed messages validate version, nonce and target identity. The descriptor/nonce capability authenticates the one application owner; public clients cannot trigger it. Do not use pickle or arbitrary command payloads.

Protocol states:

1. STARTING -> WATCHING: helper verifies the inherited exact target handle is live, accepts HELLO, replies `WATCHING_ACK(version,nonce,target_pid,grace_seconds=30)`; app waits at most2 seconds before creating owned workers/serving. Failure means boot refusal and exact helper cleanup.
2. WATCHING -> GRACE_ARMED: app sends `BEGIN_RECOVERY(reason)` from a closed enum: REQUIRED_GENERATION_UNRESOLVED, REQUIRED_WORKER_LOST, NORMAL_SHUTDOWN, FAILED_STARTUP, WATCHDOG_CHANNEL_FAILURE. Helper fixes `deadline=monotonic_now+30.0` once and replies `GRACE_ACK(deadline,nonce,target_pid)`.
3. A duplicate BEGIN returns the original deadline. Repeated Stop/shutdown signals do not extend grace. Once armed, no app message can disarm the target while required SQL is unresolved.
4. GRACE_ARMED -> TARGET_EXIT_OBSERVED if the exact process pidfd becomes readable. Otherwise, at the deadline helper uses pidfd_send_signal(SIGKILL) on exactly that target, then keeps polling the same pidfd until exit is observed. Sending SIGKILL is not exit proof.
5. WATCHING/GRACE_ARMED -> DISARMED is permitted only on an authenticated normal-completion receipt proving all owned work/generations/required projections and lifecycle SQL joined and engines finalized. Helper acknowledges and exits; app closes/reaps the exact helper. A timeout, done asyncio wrapper, merely returned worker.stop, or requested shutdown cannot create that receipt.

The helper uses its own monotonic clock and selector in its separate interpreter, no asyncio/shared executor/DB/provider work, and no app GIL. Message sizes and message count are bounded. Closing/malformed/nonce-invalid control while target lives arms grace and retains a safe fixed integrity diagnostic; EOF is not target-exit proof. No arbitrary extension/reset message exists. The helper ignores ordinary signal termination requests as a request to arm its same grace: a local process-group SIGTERM/SIGINT can therefore reach it even if the target's Python signal handler is blocked. Its signal integration uses a wakeup fd/selector, never a lock in a Python signal handler.

## Grace authority and current ProcessRecovery integration

New application-owned constant `WEB_PROCESS_RECOVERY_GRACE_SECONDS=30.0` is the sole hard-recovery grace authority for this contract. It is not composer transport timeout, DB lease TTL, Uvicorn request grace, or ACA60. The watchdog supplies its fixed deadline in ACK; the application cannot claim it armed merely because it sent a byte. Thirty seconds is a proposed reviewed lifecycle budget, not a measured current setting. ACA's host60 remains an independent outer budget for the shipped configuration. Longer existing composer drain settings do not extend the independent hard-recovery deadline; document this explicit lifecycle change in the master.

Retain ProcessRecovery as the single process-level entry point. Its synchronous request_shutdown first atomically closes new-work admission and sets the local draining Event, then retains one owned async escalation task (no shared SQL admission needed). That task sends BEGIN and awaits the exact ACK with a1-second ACK budget. Only after ACK does it issue its existing self-SIGTERM. The signal drives Uvicorn normal shutdown and joins while the external helper independently owns the deadline. A lost ACK cannot produce a successful supervision claim: while the event loop remains able to run, failure to obtain ACK requests immediate SIGKILL of the current process and leaves no false SQL release/result. If the target freezes after BEGIN, the independent helper still arms/executes from its received message; ACK reception in the target is not necessary for the helper's clock to advance.

Every existing required worker/membership/orphan escalation uses this shared recovery owner. R2 generation custodian supplies a typed unresolved-generation observation and calls it once. No provider, START, SQL bundle or uncommitted business publication is replayed by supervision. The watchdog stays outside task cancellation/drain registries so cancelling composer owners cannot cancel it.

Host-initiated normal teardown also arms the same watchdog at begin_shutdown before any await, marks draining and preserves Uvicorn's ordinary signal/exit semantics; already armed recovery retains the earlier deadline. Do not monkeypatch Uvicorn globally. For local explicit grouped termination the helper sees the host signal directly. For ordinary SIGTERM delivered only to the serving PID, this hook requires the target to execute Python; the limits below apply.

If the helper exits unexpectedly while the target lives, an application-owned watcher immediately marks draining and invokes fail-closed process termination; do not respawn it after owned threads started. A closed/failed control channel follows the same rule. If startup handshake failed before any owned work, kill/reap only the helper and refuse boot. While active SQL is unresolved, never cancel the helper or release logical/physical custody because its channel failed. The same emergency process-exit boundary destroys process-local capacity only on real process exit.

## Readiness, admission, task custody and restart

Admission/worker claim checks read the same latch before starting new work; already submitted actual SQL stays joined. An admission transaction already in flight may finish its existing outcome, but cannot start fresh provider work after draining. No new readiness route or user-visible API is introduced.

Keep R2's exact terminal/renewal/release barrier: drain registered actual Futures and required projection outcomes; valid committed terminal wins; stop and join renewal; prepare_lease_release; last exact lease-release SQL; then logical release. A hung/unknown ticket cannot pass this barrier. The process timer does not synthesize resource release, stopped membership, rollback, durable audit, zero usage or failed-terminal receipt. On hard exit the OS destroys local threads/locks/capacity; persisted running job and lease expire under DB clock. Fresh existing recovery reads actual DB state/strict terminal first and may settle only through existing fenced recovery. SQL on the remote server can still complete after client process death; process exit is never rollback proof.

No helper or recovery coordinator starts a replacement process. Once hard-recovery grace is armed for unresolved generation, the old process forbids same-process executor replacement and never becomes ready again. Normal R2 replacement of a fully drained generation remains allowed only before that process-level escalation latch. Old process PID/nonce cannot be reused as a replacement readiness witness.

A watchdog can report pidfd-readable in native local tests; when target is container PID1, namespace teardown may kill the helper before it reports, so the outside controller/runtime must supply the exit witness. This is not a global ACA replica/revision no-overlap promise. Existing other replicas may remain ready throughout, and ACA may create other instances independently. Distributed exclusion still depends on exact database fences/leases. For a same-container crash restart, acceptance must observe the old container/process exit before asserting a fresh process slot ready; source settings alone do not prove a deployed platform event sequence. ## Supported host-stop contract and explicit limits

- Acknowledged R2 recovery trigger: the independent helper enforces30 seconds even if the target subsequently blocks its GIL or interpreter exit. This is the mandatory amendment guarantee.
- ACA host stop: existing template60 applies when the host starts termination, independently of the application helper. Source/official documentation do not prove self-SIGTERM starts that host timer.
- Supported local hard-bound host stop: deliver SIGTERM/SIGINT to the owned foreground/process group containing app and helper, or use the private controller capability. The helper arms even when target Python is wedged. Preserve ordinary CLI Ctrl-C/signal exit behavior after successful graceful cleanup.
- SIGTERM sent only to a target whose GIL was already frozen before any BEGIN/hook: no arbitrary untriggered GIL-hang detection is promised by this minimal watchdog. Local users need grouped/external supervision; ACA has its independently host-triggered contract. Do not silently add heartbeat-based kill behavior.
- A process stuck in uninterruptible kernel sleep may not exit immediately even after SIGKILL. The watchdog waits for pidfd proof and no replacement for that slot is authorized. OS/supervisor intervention remains required; no Python plan can declare that process dead on a wall-clock deadline.

## Normative bounded v1 IPC codec and constructor ABI

This section is controlling over abbreviated protocol descriptions above. IPC is a private unnamed AF_UNIX SOCK_STREAM socketpair. Each frame is exactly a4-byte unsigned big-endian payload-length prefix followed by that many UTF-8 JSON bytes. Payload length is1–1024 bytes; zero, oversized, negative/interpreted signed lengths, trailing undecoded bytes, invalid UTF-8, duplicate JSON keys, nested values, missing/extra keys, unknown kinds/versions and malformed fields refuse. Sender emits compact JSON; receiver compares parsed exact closed values, not raw JSON key order. The receive buffer is bounded to1028 bytes plus at most one next-frame prefix; incremental reads never allocate a peer-declared oversized buffer. Each endpoint accepts at most8 frames per launch. There is no heartbeat, arbitrary command, text diagnostic or unbounded message queue.

Exact schemas (each lists its COMPLETE key set):

| Direction/kind | Keys | Exact values/types |
| --- | --- | --- |
| app→helper HELLO | v,kind,nonce,target_pid,grace_ns | v exact int1; kind exact HELLO; canonical nonce; reflected positive target int; grace_ns exact int30000000000 |
| helper→app WATCHING_ACK | v,kind,nonce,target_pid,grace_ns | Same closed values, kind WATCHING_ACK |
| app→helper BEGIN_RECOVERY | v,kind,nonce,target_pid,reason | kind BEGIN_RECOVERY; reason exactly one previously listed closed enum member |
| helper→app GRACE_ACK | v,kind,nonce,target_pid,grace_ns,armed_at_ns,deadline_ns | kind GRACE_ACK; grace_ns30000000000; positive exact integer clock readings; deadline_ns−armed_at_ns exactly30000000000 |
| app→helper COMPLETE | v,kind,nonce,target_pid,completion_seq | kind COMPLETE; completion_seq exact int1, sent at most once |
| helper→app DISARM_ACK | v,kind,nonce,target_pid,completion_seq | kind DISARM_ACK; completion_seq exact int1 |

Every frame's common fields have exact schema above; bool is never an integer. Floats are prohibited throughout, including NaN/infinity and exponent forms for integer fields. Top-level value must be one object; all field values are scalar. `nonce` is exactly64 lowercase hexadecimal characters produced by32 random bytes at launch; compare against retained expected nonce using constant-time comparison. No nonce or frame payload is logged or copied into environment, argv, URLs or filesystem. The helper argument list may contain only its two numeric inherited descriptor indices as launch metadata; these numbers do not confer capability without the actual inherited handles. HELLO establishes the nonce only through the inherited private endpoint. Later frames must match it exactly. There is exactly one HELLO/WATCHING_ACK and one COMPLETE/DISARM_ACK; BEGIN/GRACE duplicate pairs are bounded to four and return the original immutable clock readings. Thus at most six protocol frames per direction are valid; the8-frame transport ceiling is a defensive bound, not permission for extra commands. Unsolicited ACK, repeated HELLO, COMPLETE after refused completion proof or state-inappropriate kind refuses.

The application creates `os.pidfd_open(os.getpid(),0)` and retains its exact initial PID solely as reflection metadata. Helper signalling always uses the inherited process pidfd, never os.kill of a public/transmitted PID. Before WATCHING_ACK the helper checks actual pidfd liveness/permission using signal0, then validates the bounded kernel `/proc/self/fdinfo/<inherited-pidfd>` Pid field against the retained startup PID (one unique positive decimal Pid, bounded4096-byte read; parse kernel metadata as a boundary, not a tool-call domain). This is inspection of its already inherited handle, not opening a public PID to obtain kill authority. Exited/invalid/wrong descriptor or reflected PID refuses startup. Numeric PID reuse cannot redirect the retained handle. Parent ACK validation requires its exact PID/nonce/grace and expected state. GRACE_ACK uses the helper's own `monotonic_ns`; its fixed deadline is not derived from a timestamp supplied by the app. Duplicate ACK must preserve the first armed/deadline pair.

COMPLETE is an authority statement by the exact private owner, NOT a helper SQL-verification claim. The application may construct nominal `ProcessCompletionWitness` only after actual generation/Future/projection/producer/renewal/release joins and engine finalization, or after failed startup proves no owned work was ever dispatched and all construction resources are finalized. This owned witness permits its control owner to send COMPLETE(completion_seq1). The helper verifies only private-channel identity, closed schema, state and sequence. It cannot verify SQL and must not pretend a message boolean/hash supplies that evidence. No public endpoint can create a completion witness. Helper retains the target pidfd until DISARM_ACK/exit; completion without an application-owned witness is an integrity defect before any frame is sent.

Concrete proposed ABI (names/types are normative design, not implemented source):

- `ProcessWatchdogControl`: owned nominal ABC with `assert_watching()`, `begin_recovery(reason)->awaitable[GraceAcknowledgement]`, `complete(witness:ProcessCompletionWitness)->awaitable[None]`, read-only `target:ProcessWatchdogTarget`, and an owned helper-outcome observer. No runtime-checkable Protocol dispatch.
- `ProcessWatchdogFactory`: internal callable receiving the exact draining threading.Event and returning ProcessWatchdogControl. The production function creates the pidfd/private channel/helper and obtains the startup ACK. It does not accept a caller-supplied target PID.
- `create_app(settings:WebSettings|None=None, *, process_watchdog_factory:ProcessWatchdogFactory|None=None)`: None ALWAYS means start the real supported Linux watchdog; it is not a disable flag. An explicit trusted in-process factory is a dependency injection point, not wire/config/user input.
- `ProcessRecovery(*, watchdog:ProcessWatchdogControl, instance_draining:threading.Event)`: one shared recovery owner; the current request_shutdown/begin_shutdown entry points retain their external shape, own their pending ACK/termination task and never use a shared worker slot.
- `OwnedTestProcessWatchdog` in test support implements that nominal ABC with fake target/clock/ack and a recording signal sink. It NEVER opens pidfd, starts a helper or signals pytest. Central factory/TestClient fixtures inject it explicitly, or monkeypatch the runtime-resolved production factory symbol to that owned test factory. The function's default must not capture the real factory as a definition-time callable, which would bypass fixture replacement. No pytest discovery/environment magic, production disable setting, structural SimpleNamespace or generic mock masquerade is permitted.

At the FIRST factory side-effect boundary, create the exact draining Event, resolve/start the watchdog and construct ProcessRecovery; do this before telemetry bootstrap, DB initialization, readiness runner creation or other application-owned threads/SQL. Once FastAPI exists, attach those same owned objects; membership lifecycle constructors receive/reuse the same Event rather than creating an independent readiness flag. ## Normative startup, active-channel and shutdown cleanup sequencing

1. Construct socketpair and process pidfd before owned workers. Popen uses close_fds=True and an explicit pass_fds tuple containing ONLY its reviewed endpoint and pidfd, with shellfalse/preexec_fn absent; do not mutate unrelated parent descriptor flags. The parent closes the duplicated child endpoint immediately after successful launch. The helper closes nonowned descriptors and has no DB/provider/stdout payload channel.
2. During the2-second handshake the owner retains every descriptor and exact Popen object. Spawn/HELLO/ACK/schema/pidfd failure closes both remaining channel endpoints and target pidfd, terminates ONLY the exact helper through its retained Popen identity, and reaps it. No target kill is armed before a valid WATCHING handshake. If helper cannot be reaped, boot still refuses; do not leak it and announce readiness. Implement bounded terminate→kill-helper→actual-reap cleanup, with no reuse of a numeric helper PID after the retained child is reaped.
3. After successful registration, app owns parent endpoint/Popen/target receipt; helper owns its endpoint/target pidfd. Close unused parent pidfd after registration if retained control no longer needs it; never close the helper's handle remotely. The helper stays alive until authenticated completion or exact target exit. An unexpected target exit causes helper to close handles and exit; no orphan helper remains awaiting a dead PID. Container PID1 exit may terminate helper before its own final diagnostic; outside process/container exit proof remains controlling.
4. Start one strongly retained application helper-monitor/ACK task before lifespan's first SQL. On active helper death, malformed/broken channel or lost ACK, set the same draining latch, record a nominal lifecycle-integrity outcome and fail closed by terminating the application as described above. Do not respawn helper after owned threads. Test doubles record this requested termination without any real signal. A nonce-invalid frame never becomes a successful ACK; it does not log reflected payload.
5. Recovery/normal shutdown never cancels or drops the helper/monitor while SQL/projection custody is unresolved. Acknowledged grace is immutable. If COMPLETE's owned witness cannot be constructed, keep watching/armed and wait for actual drain or true process exit; no cleanup finally may falsely disarm.

Missing DISARM_ACK does not establish disarm; retain process-level recovery. Only after actual helper exit is its Popen/remaining handles retired. Unexpected helper exit BEFORE completion stays a fault; expected helper exit AFTER exact completion ACK is idempotent cleanup.
7. Constructor failure after WATCHING but before app/lifespan ownership transfers follows the synchronous bootstrap scope below. WATCHING_ONLY permits its narrow completion witness; once construction side effects started, arm failed-startup recovery BEFORE potentially blocking finalizers and retain the independent helper until target exit. ## Synchronous factory-abort boundary (controlling clarification)

`create_app` is synchronous, including when Uvicorn invokes it inside an already-running event loop. Its exception scope never calls asyncio.run, awaits a coroutine, or schedules an unretained cleanup task. Pure settings/profile validation may precede the first side effect. The source currently constructs operator telemetry at app.py1353, performs synchronous external-schema validation at1609, opens/closes Landscape at1624, and initializes session schema at1663; membership registration and heartbeats begin later in lifespan (1893). A failed synchronous DB call returning is its actual-call completion witness, but does not prove telemetry threads or engine resources finalized. The existing wrapper at1282–1304 explicitly invokes engine finalizers on failure; their weakref registration alone is not a completion receipt.

Add exact synchronous bootstrap methods to the nominal control ABI: `abort_bootstrap(reason:FAILED_STARTUP, witness:BootstrapCompletionWitness|None)->None` and `complete_bootstrap(witness:BootstrapCompletionWitness)->None`. They use a private nonblocking socket/selector with owner monotonic deadlines, never the event loop/shared executor. COMPLETE/DISARM_ACK has a1-second exchange budget; BEGIN/GRACE_ACK has the same1-second budget specified above. While reading partial frames, selector iterations always recheck the current handshake/ACK or armed grace deadline; a partial prefix/body cannot block expiry. These methods reuse the same codec/state machine and cannot race an async channel owner: ownership transfers to the lifespan monitor only after factory success.

The factory has one explicit lexical bootstrap scope, holding the watchdog and the exact resources it constructs; this is not a generic global resource registry.
