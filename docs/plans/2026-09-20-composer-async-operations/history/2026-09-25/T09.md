"""Public error envelope for a composer turn that settles without an HTTP request.

A synchronous ``/messages`` or ``/recompose`` turn answered its failures through
two layers. The route's typed ladder raised ``HTTPException`` bodies, and the
app-level exception handlers registered by :func:`elspeth.web.app.create_app`
rendered every other class the turn could raise. An asynchronous turn (spec §5)
settles in a worker that has neither a ``Request`` nor that handler stack, so
this module reproduces the exact ``(status, JSON body)`` each layer would have
sent. The request id persisted at admission is injected exactly where the app
injects the middleware id (D4).

Dispatch is Starlette's own ``_lookup_exception_handler`` algorithm: the first
class in ``type(exc).__mro__`` that has a projection wins. A subclass is
therefore projected exactly as the app would have rendered it
(``GuidedCustodyIntegrityError`` as ``AuditIntegrityError``, a
``PermissionError`` through the ``OSError`` arm). Parity with the real handlers
is proved by ``tests/unit/web/sessions/test_composer_operation_errors.py``,
which renders every row through ``create_app``.

Two classes are classified here rather than mirrored:

* everything the app leaves unhandled (a bare 500 today) becomes the generic
  ``operation_failed`` envelope with a fresh ``diagnostic_id`` that is written
  to the server log with the exception class, never the message;
* ``AsyncWorkerAdmissionTimeoutError`` (a ``TimeoutError``, so an ``OSError``
  whose ``errno`` is ``None``, which the app re-raises as a bare 500) becomes
  the app's own 503 ``database_unavailable`` envelope. A saturated DB-offload
  pool is a retryable infrastructure fault, never the compose wall clock.
"""

def project_composer_operation_error(
    exc: BaseException,
    *,
    request_id: str | None,
    session_engine_dialect: str,
) -> ComposerOperationError:
    """Project a turn's terminal exception into the envelope the synchronous route would have sent.

    ``request_id`` is the id ``RequestIdMiddleware`` stamped on the admitting POST and
    the job row persisted (D4). ``session_engine_dialect`` feeds the server log event
    only; no body depends on it.

    Raises ``TypeError`` for a ``BaseException`` that is not an ``Exception``
    (cancellation, interpreter exit, a ``BaseExceptionGroup`` holding one). The
    worker settles those through its cancellation path, never through an error
    envelope.
    """
    mro = type(exc).__mro__
    if Exception not in mro:
        raise TypeError(
            f"{type(exc).__name__} is not an Exception; the composer worker settles it through its "
            "cancellation path, never through an error envelope"
        )
    error, log_fields = _project(exc, _projected_class(mro), request_id=request_id, session_engine_dialect=session_engine_dialect)
    log = slog.error if error.http_status >= 500 else slog.warning
    log(
        "composer_operation_error_projected",
        request_id=request_id,
        http_status=error.http_status,
        failure_code=error.failure_code,
        error_type=error.error_type,
        diagnostic_id=error.diagnostic_id,
        exc_class=type(exc).__name__,
        **log_fields,
    )
    return error

def _projected_class(mro: tuple[type, ...]) -> type | None:
    """Starlette's ``_lookup_exception_handler``: the first MRO class with a projection."""
    for cls in mro:
        if cls in _PROJECTED_CLASSES:
            return cls
    return None


def _project(
    exc: BaseException,
    projected_class: type | None,
    *,
    request_id: str | None,
    session_engine_dialect: str,
) -> tuple[ComposerOperationError, _LogFields]:
    if projected_class is None:
        return _operation_failed(request_id=request_id), {}
    if projected_class is StarletteHTTPException:
        http_exc = cast(StarletteHTTPException, exc)
        # Starlette annotates ``detail`` as ``str``; FastAPI's subclass carries any JSON value.
        detail: object = http_exc.detail
        if type(detail) is dict:
            # The cast asserts only what ``type(detail) is dict`` just proved; the JSON render below
            # rejects any non-JSON value exactly as Starlette's renderer would.
            envelope = cast(dict[str, JsonValue], detail)
            return _dict_detail_error(http_exc.status_code, envelope, request_id=request_id, failure_code="http_error"), {}
        return _error(http_exc.status_code, {"detail": detail}, error_type=None), {}
    if projected_class is SessionOperationFenceLost:
        # Non-leaking by construction: byte-identical to the ordinary ownership 404, no request_id.
        reason = cast(SessionOperationFenceLost, exc).reason
        return _error(404, {"detail": "Session not found"}, error_type=None), {"fence_loss_reason": reason.value}
    if projected_class is SessionOperationConflictError:
        return _error(409, {"detail": "Session operation is already active"}, error_type=None), {}
    if projected_class is AuditIntegrityError:
        return _audit_integrity_error(cast(AuditIntegrityError, exc), request_id=request_id)
    if projected_class is StaleComposeStateError:
        body = {"error_type": "stale_compose_state", "detail": _STALE_COMPOSE_STATE_DETAIL, "request_id": request_id}
        return _error(409, body, error_type="stale_compose_state"), {}
    if projected_class is FingerprintKeyMissingError:
        body = {"detail": _FINGERPRINT_KEY_MISSING_DETAIL, "error_type": "fingerprint_key_missing", "request_id": request_id}
        return _error(503, body, error_type="fingerprint_key_missing"), {}
    if projected_class is SecretDecryptionError:
        body = {"detail": _SECRET_DECRYPTION_DETAIL, "error_type": "secret_decryption_failed", "request_id": request_id}
        return _error(409, body, error_type="secret_decryption_failed"), {}
    if projected_class is OperationalError:
        operational = cast(OperationalError, exc)
        driver_error_class = type(operational.orig).__name__
        return _database_unavailable(request_id=request_id), {
            "db_dialect": session_engine_dialect,
            "db_sqlstate": database_sqlstate(operational),
            "db_driver_error_class": driver_error_class if _DRIVER_ERROR_CLASS.fullmatch(driver_error_class) else None,
            "db_connection_invalidated": operational.connection_invalidated,
        }
    if projected_class is AsyncWorkerAdmissionTimeoutError:
        return _database_unavailable(request_id=request_id), {"db_dialect": session_engine_dialect}
    if projected_class is OSError:
        os_error = cast(OSError, exc)
        if os_error.errno not in _RETRYABLE_STORAGE_ERRNOS:
            # The app re-raises these (app.py:2174-2175): a bare 500 today.
            return _operation_failed(request_id=request_id), {"errno": os_error.errno}
        body = {"detail": _STORAGE_UNAVAILABLE_DETAIL, "error_type": "storage_unavailable", "request_id": request_id}
        return _error(503, body, error_type="storage_unavailable"), {"errno": os_error.errno}
    raise FrameworkBugError(f"composer operation error projection has no arm for {projected_class.__name__}")


def _audit_integrity_error(exc: AuditIntegrityError, *, request_id: str | None) -> tuple[ComposerOperationError, _LogFields]:
    """Mirror of ``_audit_integrity_error_handler`` (app.py:1363-1410)."""

        },

def _database_unavailable(*, request_id: str | None) -> ComposerOperationError:

def _operation_failed(*, request_id: str | None) -> ComposerOperationError:
    diagnostic_id = str(uuid.uuid4())
    return _dict_detail_error(
        500,
        {
            "error_type": "operation_failed",
            "detail": f"The composer request failed. Reference {diagnostic_id}.",
            "diagnostic_id": diagnostic_id,
        },
        request_id=request_id,
        failure_code="operation_failed",
        diagnostic_id=diagnostic_id,
    )


def _dict_detail_error(
    http_status: int,
    detail: dict[str, JsonValue],
    *,
    request_id: str | None,
    failure_code: ComposerOperationFailureCode,
    diagnostic_id: str | None = None,
) -> ComposerOperationError:
    """``handle_http_exception`` (app.py:2247-2266) for a dict detail: inject the id, overwriting any route value."""
    envelope = {**detail, "request_id": request_id}
    error_type = envelope["error_type"] if "error_type" in envelope else None
    return _error(
        http_status,
        {"detail": envelope},
        error_type=error_type if type(error_type) is str else None,
        failure_code=failure_code,
        diagnostic_id=diagnostic_id,
    )


def _error(
    http_status: int,
    content: object,
    *,
    error_type: str | None,
    failure_code: ComposerOperationFailureCode = "http_error",
    diagnostic_id: str | None = None,
) -> ComposerOperationError:
    return ComposerOperationError(
        http_status=http_status,
        failure_code=failure_code,
        error_type=error_type,
        body=_rendered_json(content),
        diagnostic_id=diagnostic_id,
    )


def _rendered_json(content: object) -> dict[str, JsonValue]:
    """The JSON value a client receives: Starlette ``JSONResponse.render``'s exact ``json.dumps`` arguments."""
    rendered: dict[str, JsonValue] = json.loads(
        json.dumps(content, ensure_ascii=False, allow_nan=False, indent=None, separators=(",", ":"))
    )
    return rendered

**Review notes**
- **Pool diagnostics are lost on the terminal path.** The adapter logs sqlstate, driver class, invalidation
  and dialect for `OperationalError`, but not the three pool gauges `handle_database_unavailable` logs
  (`app.py:2138`). They need the live `Pool`, and the contract signature carries only the dialect string. If
  operators want them, the smallest change is a CONTRACT DEVIATION that adds
  `session_pool: Pool | None = None` and calls `admit_pool_diagnostics` (`schema_probe.py:387`). It is not
  taken here.
- **Literal duplication is deliberate and pinned.** The adapter repeats the handler detail strings and
  `_RETRYABLE_STORAGE_ERRNOS`, because it cannot import `elspeth.web.app` (cycle through the lifespan-started
  worker) and the handlers are closures. The parity test renders every one of them through the real
  handlers, and `test_retryable_storage_errnos_mirror_the_app` pins the errno set. A refactor that moves the
  body builders into a shared module both sides call would remove the duplication. It would edit `app.py`
  handlers and restage signed tier-model keys, so it is left out of scope.
- **Dict-subclass details.** The app discriminates with `isinstance(detail, dict)` inside a declared
  `@trust_boundary` (`app.py:1072-1092`). The adapter uses `type(detail) is dict` to avoid a new R5 finding.
  These differ only for a `dict` subclass detail, and no raise site on either route produces one; every
  ladder builder returns a literal `dict`. If a future raise site uses one, the parity test will not see it
  unless a row is added.
- **Seven registered handlers are named out, not projected.** They are `CorruptPreferencesError`,
  `AuditStory*` (×2), `AuditAccessLogWriteError`, `RunAlreadyActiveError` and the two validation handlers.
  The partition test forces a decision for any new handler, but the "no path from send/recompose" claim for
  the five domain classes rests on raise-inventory-send §3, whose closure over `_compose_loop` was not walked
  (its §6 limits). If Task 10's moved body reaches one of them, add it to `_APP_HANDLER_CLASSES` with a
  parity row.
- **Logging failure is not contained.** `_log_correlation_warning` (`app.py:2018-2043`) contains logging
  failures, but the adapter's single `slog` call does not: a logging-backend exception would escape into the
  worker's settlement. Task 11 must treat an exception from the adapter as a defect to settle
  `operation_failed` with a second adapter call, not as a reason to leave the row nonterminal.
- **`ExceptionGroup` members are not inspected.** A group containing a typed `HTTPException` (for example
  the SOL close failing after a ladder raise, `lifecycle.py:1087`) becomes `operation_failed`, matching
  today's bare 500. If Task 11 wants the member's typed body, that is a behaviour change to rule on, not
  parity.
- **Convergence/plugin-crash/preflight rows are literal bodies.** Their builders write session rows. Because
