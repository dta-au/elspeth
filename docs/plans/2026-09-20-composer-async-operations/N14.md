Not a deviation, recorded so the reader does not look for one:
- **`add_message_with_transcript` loses its key keyword instead of renaming it.** With `running` required, the ingress
  key is `running.claim.operation_id`. A second keyword carrying the same id would be a second source of truth and an
  alias of the old wire name (ruling 6: no alias). `requested_state_id` stays a keyword: the turn passes the request's
  `state_id`, which the request hash binds to the job's `base_state_id` (E8).
- **`ChatMessageRecord.operation_id` and `MessageIngressFresh.operation_id` are `str`.** The record field was
  `client_request_id: UUID | None`; the job's `operation_id` is a canonical 36-character `str` everywhere in the owned
  types (contract §Owned types), and the wire field is `str | None` (contract §Wire DTOs). One type end to end.
- **Admission 409/429 bodies carry `request_id` only through the app handler.** The route raises `HTTPException` with
  the contract's dict `detail`; `handle_http_exception` injects `request_id` into a dict detail (E4). Route-test apps
  mount no app handlers, so tests compare the contract dict exactly.
