# 1.5 — A completed guided session keeps its conversation (final)

Group A-1.5-completed-chat

Tickets: elspeth-986801d218 (IA-6)

Token = confirmation hash (`history[-1].response_hash`); tool-less step-4 advisory solver over the frozen CONFIRM_WIRING record, bound to the live committed structure; teaching lives in the context opener only; no wire change.

## User-visible behaviour

- After **Confirm wiring** the completed surface keeps the conversation column: stepper at Review/Validation/Ready, the Accept cards, the "Pipeline ready / Review required" card, the full guided transcript as a live `role=log` with a new **After confirmation** divider before the first post-commit question, an **Explain this pipeline** button, the "Working on it…" strip with Stop, and the same docked **Describe what you want** composer (text only — no upload affordance) with a completion placeholder: *"Ask about the pipeline you just built — what a step does, how routes connect, or what a check means."*
- Send (or Explain) posts one `/guided/chat`. ELSPETH answers in prose about the **committed** pipeline — components, routes, validation state, what the checks mean — and cannot edit it. The reply appends to the transcript; terminal stays `completed`, `next_turn` stays null, the right pane keeps drawing the committed composition, the SideRail (Run/Export) stays, the heading stays "Pipeline ready" (the verdict is not cleared by a question — see Frontend), and the run gate is untouched.
- If the committed structure has been changed underneath the completed session (a direct `POST /messages` compose), chat refuses with 409 `guided_chat_committed_graph_changed` rather than explaining a graph that no longer exists.
- **Open freeform editor** remains the only structural way out (exit → `exited_to_freeform` → guided chat 409 as today; `/guided/reenter` restores COMPLETED and the channel returns).
- **Tutorial**: transitions 1-13 untouched. The completed dwell (Accept cards pending, then hand-off) shows the same composer every user gets — no `isTutorial` hide (see Rejected findings). After graduation the completed session opens in the ordinary ChatPanel with the channel live, so `TURN_7_LEARNING_BULLETS` "ask in the chat panel" is literally true with zero tutorial-specific code (ADR-031).

## Mechanism

### Backend

**Token (no wire change).** `guided_completed_chat_token(guided)` in `guided_replay.py` beside `guided_turn_token`: exact `GuidedSession`, `terminal.kind is COMPLETED`, non-empty history with every record answered, `history[-1]` is `STEP_4_WIRE`/`CONFIRM_WIRING` with a 64-hex `response_hash`; returns that hash (the CAS id of `{action: confirm_wiring, proposal_id, draft_hash}`, guided.py:4687-4700). `AuditIntegrityError` otherwise. `GuidedChatRequest.turn_token` stays required 64-hex (schemas.py:816); `ComposerChatTurn.turn_token` stays non-null on USER turns; retry custody `acquireGuidedRetry("guided_chat", sid, [turn_token, message])` is unchanged.

**Durable committed turn loader.** `_load_durable_committed_wire_turn(guided, *, payload_store) -> tuple[Turn, PreparedGuidedJsonPayload]` in `routes/composer/guided.py` beside `_load_durable_current_turn` (:265): requires COMPLETED and `history[-1]` = answered STEP_4/CONFIRM_WIRING (via `guided_completed_chat_token`), loads the payload by `record.payload_hash` (`purpose="turn"`, re-hashed by `load_guided_json_payload`), builds `Turn(type, step_index=3, payload=dict(deep_thaw(...)))`, `validate_current_turn`. Does **not** consult `active_proposal` (completion nulls it, guided.py:4707) and does not call `_schema8_prospective_occurrence` (whose `_build_get_guided_turn` raises for STEP_4). `_ChatPreflight` keeps `current_turn: Turn` non-optional.

**Committed-structure binding (new; closes the drift path).** `guided_structure_projection(state) -> tuple` in `composer/guided/planning.py`: the ordinal-label subset the wire payload was built from — `(kind, label, plugin, node_type)` per source/node/output in `proposal_component_label` order, plus `(from_label, to_label)` per connection — sharing the labelling helper `build_guided_proposal_projection` uses (planning.py:3865/3898/3906), so it is derived from the same authority, not a parallel definition. Preflight on COMPLETED requires `guided_structure_projection(state) == _wire_payload_structure(current_payload.payload)` (same subset read from the frozen CONFIRM_WIRING payload: `sources/nodes/outputs[].label|plugin|node_type`, `connections[].from_label|to_label`), else 409 `{"code": "guided_chat_committed_graph_changed", "detail": "The committed pipeline was changed outside guided mode; open the freeform editor to continue."}`. Prompt-template patches from interpretation Accept (service.py:8314-8316) do not touch this subset, so post-Accept chat is admitted; a freeform compose that adds/removes/rewires components is refused. No new marker, no schema bump.

**Admission.** `preflight()` in `guided_chat_atomic.py` gains a COMPLETED arm placed *before* the current `terminal is not None → 409` (guided_chat_atomic.py:1014) and therefore before the step / deferred-intent gates (:1016-1024): `terminal.kind is COMPLETED` → require `body.turn_token == guided_completed_chat_token(guided)` else 409 `"turn_token does not identify the confirmed pipeline."`; load via `_load_durable_committed_wire_turn`; structure check above; freeze `_ChatPreflight(current_turn=<wire turn>, current_payload=<wire payload>, guided=guided)`. `EXITED_TO_FREEFORM` keeps the verbatim 409 `"Guided session is already terminal."`. A uniform transcript-cap check (all steps) returns 409 `{"code": "guided_chat_history_full"}` when appending two turns would exceed `GUIDED_MAX_CHAT_TURNS` / `GUIDED_MAX_CHAT_HISTORY_CHARS` / `GUIDED_MAX_CHAT_CONTENT_CHARS` (state_machine.py:56-60), replacing today's InvariantError 500 at the cap (:976-990). The upload sentinel (:1134-1150) is already gated on STEP_1 + unanswered turn shape, so a completed session never reaches it.

**Authority.** `_guided_committed_graph_authority(guided, current_payload)` beside `_guided_advisory_graph_authority` (:310-362). Built from **owned records only** — the answered `TurnRecord` and the content-verified `PreparedGuidedJsonPayload` — never re-probing the `Turn` mapping, so no new `isinstance(Mapping)` site, no new `@trust_boundary`: exact-type checks (`type(guided.terminal) is TerminalState`, kind identity, `active_proposal is None`, `history[-1].turn_type is CONFIRM_WIRING`, `history[-1].response_hash is not None`, `history[-1].payload_hash == current_payload.payload_id`, `current_payload.purpose == "turn"`), membership reads of `proposal_id`/`draft_hash` from `current_payload.payload`, then `GuidedAdvisoryGraphAuthority(turn_type=CONFIRM_WIRING, payload_id, proposal_id, draft_hash, covered_deferred_intent_ids=(), payload)` whose `__post_init__` re-validates (chat_solver.py:1473-1560). The fingerprinted `_guided_advisory_graph_authority` and its `test_ref` are not edited.

**Context (all post-commit teaching lives here; skills untouched).** `build_step_chat_context_block` (chat_solver.py:2159) gains one keyword-only `committed: GuidedCommittedBuildSummary | None = None` (new frozen dataclass: `is_valid: bool`, `validation_error_count: int`, exact-type `__post_init__`). `None` → every existing caller renders byte-identically (golden pin). Non-None is valid only with `step=STEP_4_WIRE` and a CONFIRM_WIRING authority (InvariantError otherwise) and changes three things:
1. The opener paragraph (:2215-2222) becomes: *"The guided build is FINISHED: the user confirmed and committed this pipeline. **Freeform.** `POST /messages` is untouched (still accepts a completed guided session and layers the transition prompt, messages.py:195-202; `test_progressive_disclosure.py:440` stays green).
