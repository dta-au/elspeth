Tickets: `elspeth-f2a8550b3d` (Slice E / I-4), `elspeth-e4c2ebb697` (I-7). Base: `ebfab6fd2` on `release/0.8.0`. Every critic finding below was checked against that tree; the file:line citations are from it.

### User-visible behaviour

**Stepper ticks (2.5).** A tick is *reviewed* when the server ledger has a settled decision for that stage — not when its index is below the current step. Source is reviewed iff `reviewed_components.sources` is non-empty; Output iff `reviewed_components.outputs` is non-empty; Transforms iff the session is at Wire or completed; Wire iff completed. The current step's tick is `current` (aria-current) even when it also holds a decision (a source being re-edited). A reviewed tick that is *downstream* of the current step (Output while a source is re-edited at step 1) stays reviewed. Every reviewed, non-current tick is a real `<button type="button" aria-expanded aria-controls>` inside the existing `<li>`; current and upcoming ticks stay static. Pressing it opens that stage's **decision sheet** between the stepper and the transcript with no request: heading "<Stage> — decided", one row per component settled there (`name · plugin display name`), and that stage's own chat turns replayed read-only (filtered by `ChatTurn.step`). Source/Output rows come from the server-projected reviewed ledger (E3); Transforms rows are the current wire payload's nodes at step 4 and the committed `compositionState.nodes` on a completed session; the Wire sheet (completed only) shows the step-4 chat turns and the "Guided pipeline wiring confirmed." record.

**"Change this" (2.5).** One button per component row, absent when `terminal !== null`, absent under `isTutorial` (a PERMANENT exclusion, not the provisional hide this design originally proposed — operator ruling 2026-09-04 on `elspeth-f2a8550b3d`; lane 3.2 `elspeth-18cebcf219` no longer removes it), disabled while a respond/chat is pending. Per stage:

- From step 2, the Source sheet's "Change this" sends `control_signal:"back"` and reopens that source's reviewed settings form, prefilled, at step 1. **Chat on the reopened form is advisory-only** (`guided_chat_atomic.py:251-275, 455-457, 567-568` withhold every resolution while `active_edit_target` is set and suffix the reply "No changes were applied through chat…"). The sheet copy says so ("Opens the source's settings form; edit it there and press Continue") and the docked composer's placeholder changes to the edit-state line (below). This is the same rule today's review-card Edit already lives under; making chat author the correction is lane 2.4's sweep, not this one.
- From step 3, the Source/Output sheets' "Change this" sends the **existing bound revise shape** (`{proposal_id, draft_hash, edit_target:{source|output}}`, no feedback — `guided.py:3159-3163` forbids feedback for these kinds at step 3). The proposal is superseded (row kept, `rejected`/`superseded`), the prefilled form opens.
- From step 4, "Change this" on **any** tick's row **focuses the wire card's existing correction form with that component preselected** (`WireStageTurn.tsx:331-334` already does this for nodes; `correctionTargets` lists sources, nodes, connections and outputs, :309-324). The user types the feedback the step-4 shape requires (`guided.py:3205-3212` — `is_correction` needs `correction_feedback` + `edit_target`); no second re-plan path, no client-authored feedback string.
- Nothing downstream is deleted: other reviewed components stay reviewed; a proposal that depended on the changed component is superseded and the planner re-authors it when the learner reaches Finish outputs again.
- On a completed session all four ticks open read-only sheets with no "Change this": commit is one-way, and post-commit questions are 1.5's chat channel.

**Refusal instead of data loss.** From step 2 with an output mid-form — a pending output past `plugin_selection`, or an output Edit in progress (`active_edit_target` output) — the Source sheet shows "Finish the output you're configuring, then you can change the source." in place of the button, and the server 409s the same case (`guided_back_pending_component`). The client keys the note on `guidedNextTurn.type ∈ {schema_form, multi_select_with_custom}` at step 2, which is exactly the set of turns `_build_get_guided_turn` renders for those two server facts (`guided.py:419-431, 445-455`); a stale sheet that still sends the request gets the 409 mapped to the same note (store arm below). A pending output still at `plugin_selection` (single_select showing, nothing typed) is dropped silently — `GuidedSession.__post_init__` forbids any pending output beside an active source edit (`state_machine.py:1049-1053`), so this drop is the invariant, not a convenience.

**Docked composer on the reopened form.** At step 1 with a `schema_form` turn (first form or re-edit — chat is advisory for both, `guided_chat_atomic.py:574-579`) the placeholder reads "Update the form on the card, then press Continue — chat can't edit it." (≤80 chars).

**Wire stage (2.7).** No route reads "not yet checked". A null `schema_contract` whose `to_endpoint.kind === "discard"` reads **"discard route"**; any other null reads **"no static check"**. Roll-up: "9 routes — 1 connected, 3 with no static check, 5 discard routes" (zero counts elided), followed by one cause-free sentence true in every null case: "Routes with no static check are not verified before the run; whatever their destination requires is enforced row by row when the pipeline runs." Confirm stays enabled when `validation.is_valid` (ADR-007 abstention is admissible; `can_confirm == not blockers` pin untouched) but reflects it: caption under the button "Confirming accepts N routes without a static check." when N > 0, and `aria-describedby` on Confirm = blockers panel + routes note + caption. The step-4 placeholder becomes a function of live state: pending acknowledgement cards → "Resolve the N pending acknowledgement cards, then press Confirm wiring."; client validation issues → "Fix the issues named on the card, then press Confirm wiring."; otherwise → "Press Confirm wiring on the card, or Re-plan wiring to change a component." In the tutorial the read-only empty box therefore shows why Send does nothing; no new `isTutorial` branch.

### Mechanism

**Backend (2.5).** BACK is a custody mutation whose successor the existing turn rebuilder derives.

- `stage_transitions.py`: new `PendingComponentInProgress(ValueError)`; new pure `back_refusal(session, target) -> Literal["stage_unsupported","pending_component"] | None` — the single legality authority (`step is not STEP_2_SINK` → `stage_unsupported`; any pending output past `plugin_selection` or `active_edit_target is not None` → `pending_component`); new pure `return_to_component_edit(session, target) -> GuidedSession`: `type(target) is ComponentTarget`, `target.kind == "source"`, `target.stable_id in reviewed_sources` (else `ValueError`), calls `back_refusal` and raises `PendingComponentInProgress` on `pending_component`, drops pending outputs at `plugin_selection` together with their `output_order` ids, returns `replace(session, step=STEP_1_SOURCE, active_edit_target=target, active_proposal=None, pending_output_intents={})`. Legality table stays this narrow: output targets from step 2 are served by `begin_component_edit`; source/output targets from steps 3/4 by `_rewind_reviewed_component_form`.
- `guided.py` preflight: new `_verify_schema8_back_request(observed_guided, body)` called immediately after the terminal guard (`:3099-3106`) and **before** `_verify_schema8_proposal_binding` (`:3107`): if `body.control_signal == "back"`, map `back_refusal` → 409 `{code:"guided_back_stage_unsupported"}` / 409 `{code:"guided_back_pending_component"}`. This is why the promised 409s survive: the projection call at `:3310-3323` sits inside `except (PluginConfigError, TypeError, ValueError)` → 400, and the settlement re-run converts the same classes to `AuditIntegrityError` (`:4843-4845`). The guard derives from the same pure predicate the transition raises on, so preflight and settlement cannot disagree; if state moved between them, the settlement's existing "contract changed after reservation" path is the correct outcome.
- `guided.py` `_schema8_answer_and_project_next`: BACK arm beside EXIT (`:2624-2650`): `_schema8_only_response_fields(body, "control_signal")` (edit_target is not in that field set); the `_schema8_require_runnable_sink_form` precondition becomes `control_signal not in {EXIT, BACK}`; construct `ComponentTarget(kind=body.edit_target.kind, stable_id=body.edit_target.stable_id)` (owned constructor; canonical-UUID check is its `__post_init__`); call `return_to_component_edit`; response payload `{"control_signal":"back","edit_target":{kind,stable_id}}`; answered record summary is the constant "Returned to the source stage to change a reviewed source." (constant like every sibling summary — never a component name); successor derived by `_build_get_guided_turn` (STEP_1 + `active_edit_target` → `build_step_1_schema_form_turn_from_resolved`, `:386-393`). No new emitter.
- Generic settlement site (`:4886-4894`): `reason = "user_returned" if index(resulting.step) < index(prior_step) else "user_advanced"`.
- `_rewind_reviewed_component_form` (`:2944-3040`): add `emit_step_advanced(prev=origin_step, next_=target_step, reason="user_returned")` between the answered and emitted events (today the 3/4→1/2 rewind records no step change).
- `guided_chat_atomic.py:1872-1880`: replace `and not rewound` with reason selection (`"user_returned" if rewound else "user_advanced"`) so the deferred-intent management rewind (3/4→2, `guided_chat_intent_management.py:850-918`) is recorded too. After this, `user_returned` is the only reason under which `prev > next` is legal **and every backward move emits it** (three seams, one spelling).
- Audit vocabulary in **both** closed sets: `guided/audit.py::_VALID_ADVANCE_REASONS` (`:34`) and `sessions/guided_audit.py::_ADVANCE_REASONS` (`:44`, consulted by `_valid_guided_synthetic_payload :90` — a reason outside it demotes the row to the unknown-tool sentinel path at `:173-200`, silently). Make `guided_audit._ADVANCE_REASONS` import from `guided/audit.py` (one authority) and pin equality.
- `protocol.py` `ControlSignal.BACK` docstring: handler, carrier (`edit_target`), legality table, and that step 3/4 edits use the bound revise/correction shapes, not BACK.
- `schemas.py` `_validate_token_action_shape` (`:747-796`): `edit_target` without a proposal binding is legal iff `control_signal == "back"`; `control_signal == "back"` requires `edit_target` with kind `source|output` and forbids `chosen`, `edited_values`, `custom_inputs`, `correction_feedback`, `component_action`, `proposal_id/draft_hash`, `source_blob_id`. Every other rule verbatim; the pin at `test_guided_operation_requests.py:223` (`control_signal:"back"` illegal beside `component_action`) stays true.

### Open decisions for the operator
