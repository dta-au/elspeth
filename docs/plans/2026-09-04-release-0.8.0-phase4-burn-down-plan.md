## 3. Cross-lane contradiction: the preference authority is dead by ruling, not missing

Three lane plans point at one absent class from opposite directions:

- **Lane C (G4 / C7)** and **lane A (G10 hand-off)**: restore `UserPreferenceAuthority` /
  `RepositoryUserPreferenceAuthority` from `4c59c9d02:preferences/service.py:116-330` and
  pin `ELSPETH_USER_PREFERENCES_LOCK_CLASSID` alongside it.
- **Lane D (C1)** and **lane E (G8)**: the class is dead by operator ruling 8925 #3.

The ruling is in `docs/plans/2026-09-04-multi-replica-integration-method.md:318`, quoted
from comment 8925: *"Preferences/user-secret: HEAD + stage-3 refinement is FINAL —
preferences serialized by the per-session write lock, never by the compose lease
(mid-compose trust downgrade must always land); user_store row versions kept. Record as a
deliberate Task-5 inventory exemption."* The doc's own state column adds that the old
`RepositoryUserPreferenceAuthority.apply_patch` reviewed entries are dead (8949). Row M3
(`:281`): *"nothing may reintroduce compose-lease serialization of preferences."*

**Ruling 3 is FINAL; C7 and A-G10 as written are overruled.** Consequences, carried
into one ticket **X1** (lane E executes; lane D's D2 owns the manifest side):

1. Delete `tests/testcontainer/web/test_user_preference_authority_postgres.py` (its
   subject does not exist; its two proofs — advisory-lock wait, post-lock DB clock — are
   the compose-lease serialization the ruling forbids). Clears the collection error.
2. Delete `tests/unit/web/test_app.py:1292`; keep `:1291`. Clears the second
   double-claimed id.
3. `ELSPETH_USER_PREFERENCES_LOCK_CLASSID` (`src/elspeth/contracts/advisory_locks.py:81`,
   comment `:76-80` names the dead consumer). Its only consumer in the tree is the file
   deleted in step 1. It was born in `fec6a4f32` (2026-07-31); **no release tag contains
   that commit** (`git tag --contains fec6a4f32` → only `backup/deferred-platform-wip-broken-2026-09-04`,
   `backup/multi-replica-merge-resolved`), so the "on-the-wire ABI" comment describes a
   wire it never reached. Two honest options — operator decision **Q6** (§7):
   - **delete** the constant and its comment: `test_advisory_locks.py` passes untouched
     (lane C's own stated alternative), nothing pins an unused value; or
   - **keep** it as a reserved classid and add it to both pin sets in
     `test_advisory_locks.py` with a comment naming ruling 8925 and the retired consumer.
   Default in this plan: delete (a declaration pin of an unconsumed value is the
   "declaration pins existence" anti-pattern lane C itself names).
4. Lane D's D2 rewrites tests #1/#6 to the ruled writers (`PreferencesService.update_composer_preferences._sync`,

   `RepositoryUserPreferenceAuthority.apply_patch._sync` manifest rows (`:179, :229, :560, :751, :756, :761, :3917-3938`).
