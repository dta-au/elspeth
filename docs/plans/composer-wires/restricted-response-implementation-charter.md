## Architecture and ownership

1. Each discovery declaration references its **producer-owned response contract**. Contract types/constructors live beside the producer or an existing shared authority. A shared leaf module is appropriate only for genuinely shared families. ToolDeclaration remains a dependency leaf; it must not import producer modules, registry or planner. Registry aggregation derives name-to-contract lookup from declarations.
2. A contract owns successful variants, permitted absent-data outcomes, and any independent failure data for that tool. Generic helper failure is validation-only with no data. Argument-error projection is a shared owned family referenced explicitly, not a wildcard permitting arbitrary failed data. Select by declared tool and actual outcome/producer arm before admission; do not run all discovery schemas as one giant trial union.
3. Reuse actual owned classes/TypedDict definitions. Where a known producer is a mapping, give its construction an exact typed root and provide selected strict admission to an owned form. Owned catalogue models are admitted nominally as their declared concrete classes. Neither arbitrary BaseModel nor arbitrary `to_dict`/Protocol implementations qualify. Admission rejects unexpected root fields and wrong values; it never strips extras, coerces corruption or returns an empty success placeholder.
4. The heterogeneous registry can erase type variables internally, but its entry must close them at the selected contract. Prefer a generic contract/adapter binding admission and serialization for one T, so the planner carries the resulting owned admitted value and its bound serializer. An unchecked input parameter may be object; **accepted payload definitions may not be object/Any/catch-all BaseModel/JsonValue root fallbacks**. A final encoded JSON-value return is serialization output, not permission to admit arbitrary JSON as a response.
5. Preserve data root kind: list_blobs and list_secret_refs return lists. Do not wrap them under invented keys. Preserve optional fields, nulls and current insertion order. Shared PluginInventory response structure is intentionally the same for list_sources/list_transforms/list_sinks; reference one contract. Distinct tools with indistinguishable shapes cannot be distinguished by type alone. Contracts prove structure; dispatch/audit identity supplies tool attribution. Do not promise semantic-origin detection or add wire tags to manufacture it.
6. After canonical producer admission, apply current surface projection. Shape admission does not authorize disclosure. Restricted state uses the supplied policy-owned context, never original state values; successful preview remains refused; schema projection and remaining-budget checks retain their order. The final restricted envelope is an owned immutable value, constructed once with final success/data, without later subscript updates or a closure mutating a shared dict.
7. Redaction MANIFEST remains security policy, not the complete response schema. Do not replace it, derive schemas from its intentionally broader policy, or move its sensitive/public judgments into declarations. Existing TAUGHT/envelope gates remain separate evidence and should consume/reuse new producer authority only where that is their actual seam.

A static compiled adapter may be useful when matching existing owned-model practice. Define it once beside its producer contract; never recreate it per tool call. Do not introduce a new recursive validation framework or general AST binding analyzer. The concrete implementation must demonstrate how the selected type flows through cache/audit/serialization, rather than adding a type alias over the same unchecked object.

## Restricted projection contracts and precedence

`guided/planning.guided_redacted_current_state_context` owns the restricted context contract:

- Root: schema (guided.current-state-context.v1), version, sources, nodes, outputs.
- Source item: name,plugin,option_keys,on_success,on_validation_failure.
- Node item: id,node_type,plugin,option_keys,input,on_success,on_error.
- Output item: name,plugin,option_keys,on_write_failure.

These are internal closed records. External identifiers are string values, not permission for extra keys. Restricted state data is whole context, {sources: context source list}, {node: one context node}, or {output: one context output}. Earlier fixtures with arbitrary label/extra projection fields are not the production authority; rebuild them from the actual context producer.

Retain existing ordered behavior from `_serialize_provider_discovery_result`:

1. Successful get_plugin_schema is nominally checked/projected on **all** surfaces first. Unsupported projection yields its fixed failure. Aggregate contract budget checks canonical UTF-8 bytes with strict greater-than; equal fits and None skips. Restricted schema success uses the closed envelope; unrestricted uses existing ToolResult serialization with the projected contract data.
2. Other unrestricted responses keep their existing full canonical response route, now subject to their selected producer shape contract rather than unchecked fallback.
3. Restricted successful preview substitutes the established surface_projection_unavailable result. Failed preview retains the current failed-call authority; do not replace argument failure with a preview projection failure.
4. Restricted non-state discovery uses its selected admitted producer response. Failure alone is never a reason to bypass admission.
5. Restricted failed get_pipeline_state retains actual failure authority before selectors. For successful state: explicit set_pipeline_arguments denial first; then authoritative exact sources/node/output result shapes; then full inspection shape; otherwise existing surface refusal. Source/node/output contents come exclusively from the supplied context. Preserve alias collision precedence (full/all/pipeline may identify actual nodes/outputs).
6. Missing projected lists historically default to empty; decide compatibility from actual post-MODEL owned context construction, not arbitrary partial test mappings. Malformed trusted candidate id/name access must remain a loud exception, distinct from a valid unmatched candidate's surface refusal. Do not turn corruption into a successful empty list.

Projection failure data currently has fixed error/error_code and optional next_tool because it is an independent restricted response projection explicitly preserved by twin retirement. Register that projection's own contract beside its producer, not as every tool's generic failure payload. If root's post-MODEL snapshot has changed its representation, use that authority rather than reintroducing historical fields.

## Wire, state and operational preservation

Keep restricted envelope insertion order: success,validation,affected_nodes,version,optional data. Validation order: is_valid,errors,warnings,suggestions,semantic_contracts,graph_repair_suggestions; entry order: component,severity,error_code. Preserve json.dumps whitespace/ASCII escaping, ordering within nested lists/maps, omission rules and existing owned-model dumps. Avoid asdict, sort_keys, compact separators, unconditional model defaults or new tags.

Replacing success/data on projection failure does not silently rewrite the underlying validation.is_valid, version or affected nodes. Closed validation strips messages/state-bearing attribution/contracts and retains fixed pipeline attribution, severities and fallback codes. Canonical schema hash/budget encoding remains distinct from wire encoding. Respect current successful-only discovery cache eligibility from error-twin retirement; do not re-cache failures. Cached success data still passes selected contract/current surface projection and current schema budget, and gets current envelope state/version.

No tool handler runs to establish a response schema. Contract registration/compilation has no session engine, provider context, current policy, remaining budget or operational side effects. It can cache compiled schema machinery, not admission or disclosure verdicts.
