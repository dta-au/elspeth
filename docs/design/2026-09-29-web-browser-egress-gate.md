# `web_browser` egress gate: design and release decision

**Date:** 29 September 2026
**Source baseline:** `release/0.8.1` at `4093249d8205e0e573b40dff4df2ff6dccd2a619`
**Decision:** **NO-GO for catalog admission or live execution of `web_browser` on this baseline.** HTTP form search remains the first usable route for government-style search pages. ABN Lookup is one exemplar, not a runtime exception.

This is a design review of Stage 5 in the [modern web fetch plan](../plans/2026-09-29-modern-web-fetch-plugin.md#2-browser-rendering-and-form-filling). It does not certify an implemented sandbox. The release gate is an observed property of each deployment: a browser process must have no route to DNS, HTTP(S), WebSocket, or other network destinations except an enforcing gateway, and all network use must be recorded or denied.

Playwright supports browser/context proxy options, but these are configuration, not proof that a process cannot open a different socket ([BrowserType](https://playwright.dev/python/docs/api/class-browsertype), [Browser](https://playwright.dev/python/docs/api/class-browser)). Its documentation says context routing misses requests handled by service workers; a popup's first request may complete before a page-level event handler runs ([network](https://playwright.dev/python/docs/network), [BrowserContext](https://playwright.dev/python/docs/api/class-browsercontext), [service workers](https://playwright.dev/python/docs/service-workers)). Playwright can route WebSockets created after registration, but that is not an operating-system egress rule ([BrowserContext WebSocket routing](https://playwright.dev/python/docs/api/class-browsercontext)).

These findings measure source configuration, not live packet reachability. The claim that a browser launched in the current web process could bypass an application proxy is an inference from that configuration and the absence of a browser-specific isolation layer; the hostile probes below are the required deployment measurement. The existing AWS `gateway_container` in the web task is the LLM gateway ([`ecs.tf`](../../deploy/aws-ecs/terraform/modules/scenario/ecs.tf#L276)); it is neither a browser egress proxy nor a separate network identity.

## Required boundary

```text
ELSPETH engine -- bounded control/evidence channel --> isolated browser worker
                                                   |
                                                   | only permitted network peer
                                                   v
                                             policy gateway
                                                   |
                                          pinned, audited upstream
                                                   v
                                            approved HTTP(S) origin
```

1. **Separate network identity.** Run the browser and its renderer, worker, download, and helper processes in one dedicated network namespace/container or stronger equivalent. Deny raw outbound TCP/UDP, DNS, IPv4/IPv6, loopback access to host services, and cloud metadata. Permit only the gateway endpoint and the bounded control/evidence channel. Browser and gateway cannot share a pod/task network namespace if the gateway has broad upstream egress: a compromised browser could bypass the proxy. A proxy environment variable, Chromium launch flag, Playwright `route`, or DNS block by itself does not satisfy this rule. Preserve Chromium's own sandbox inside the outer isolation where the target platform supports it.
2. **Gateway owns resolution and connection.** Require a nonempty exact scheme/host/port origin allowlist for browser jobs. Parse each logical URL, reject credentials, ambiguous encodings and non-HTTP(S) schemes, and validate method and destination *before* DNS. Resolve DNS in the gateway, reject a mixed safe/unsafe answer set, pin the selected IP for the connection, preserve the logical Host/SNI, and repeat for every redirect. No browser-side DNS is needed. Gateway authentication binds a short-lived job/row token to its allowed origins and budgets; it must not accept a caller-supplied policy expansion.
3. **No opaque HTTPS tunnel as an audit substitute.** An ordinary HTTP proxy can accept `CONNECT` and validate its host, but an opaque tunnel cannot observe inner URL paths, methods, body hashes, redirects, or response bytes. Stage 5 therefore needs a gateway that can enforce and archive *each* decrypted HTTP request/response, with a controlled worker-trusted interception certificate, **or** a demonstrably complete browser-to-gateway request protocol with the same enforcement and no direct socket path. Certificate failures abort the job; disabling verification to make interception work is forbidden. Client certificate/pinned-certificate sites may be unsupported initially. A blind `CONNECT` is denied.
4. **Block protocols that cannot be audited yet.** Initially reject WebSocket upgrades, WebTransport/QUIC, raw TCP/UDP/WebRTC, and unsupported schemes at both gateway and network boundary. Record the attempted destination and denial. Normal HTTP(S) loads from frames, popups, dedicated/shared workers, XHR/fetch, EventSource, CSS/images/fonts, redirects, form submissions, and downloads must traverse the gateway. Set `service_workers="block"` when creating each context; prove the block with a registration fixture. Block protocol upgrades rather than silently treating them as an ordinary response. No browser API may open an unreviewed local file or browser extension resource; a `data:`/`blob:` document cannot grant extra egress.
5. **Bound each job and each request.** Enforce request count, redirect count, request body bytes, response compressed and decoded bytes, response time, total wall time, download bytes, pages/popups, actions, and per-origin concurrency at the gateway/worker. Defaults must be finite. Reject new requests when any budget is exhausted and terminate the worker on cancellation. A response or download is held until its admitted bytes/evidence are durable; partial or unrecorded content cannot become a successful pipeline result.
6. **Isolate row state.** Create a fresh nonpersistent context for every row/work item, with service workers blocked and no profile reuse. Close context before returning; keep cookies, cache, storage, and upload bytes within the row. The gateway must strip credentials on unapproved cross-origin transitions; deny cross-origin redirects unless each target is explicitly approved. Only payload-store blobs can supply uploads.

The gateway should call the same shared URL/origin validation policy as the Python HTTP client, or a reviewed language-equivalent contract with parity tests. The existing `allowed_origins=()` behavior means no restriction for HTTP calls ([`web.py`](../../src/elspeth/core/security/web.py#L389)); browser admission must require a populated allowlist. The gateway's own egress policy needs explicit access to approved upstream ports; the browser's policy permits only the gateway/control channel. Each target deployment must prove those rules in its actual runtime, not just in local Docker.

### Smallest deployment shape

The minimum useful build is one browser worker image with pinned Chromium/Playwright, one gateway process with an independently enforceable network identity, and a narrow control API from ELSPETH. The engine never launches Chromium inside the web service. The worker receives a row, a short-lived policy token, and bounded actions; the gateway is the only owner of upstream DNS and sockets. The first browser release may support navigation/render/extraction with WebSockets and unsupported protocol features blocked; browser forms and credentials need the later Stage 6 policy and redaction gates. If the required HTTPS per-request inspection cannot be provided, this minimum build remains **NO-GO** rather than downgrading to opaque CONNECT.

| --- | --- | --- |
| Local Linux/systemd | Add a dedicated worker unit with a separate network namespace or equivalent firewall-enforced identity, `NoNewPrivileges`, filesystem sandbox, pinned browser runtime, and only the gateway/control sockets reachable. Run the gateway under a distinct unit/identity with DNS and upstream egress; add lifecycle and health dependencies. AWS states that SGs do not filter Amazon DNS, instance metadata, or ECS task metadata ([VPC SG rules](https://docs.aws.amazon.com/vpc/latest/userguide/vpc-security-groups.html), [Amazon DNS](https://docs.aws.amazon.com/vpc/latest/userguide/AmazonDNS-concepts.html)). The exact systemd, ECS, and Azure network rules must be implemented and tested before enabling the corresponding target. This document deliberately does not claim that one platform's firewall syntax transfers to another.

## Audit, replay, and failure semantics

- Add versioned browser job/action/request contracts, and call types or an equivalent first-class Landscape representation. Record job ID, run/state/operation/row IDs, action index, subrequest index, parent page/frame/request ID, logical URL with sensitive query values fingerprinted, method, exact origin decision, DNS answer set and selected IP, pinned destination, safe header/body fingerprints, redirect edge, response status/headers/body hash/size, timing, denial/cap reason, and artifact references. Store the network graph in deterministic gateway order; correlate Playwright page/frame/action events afterward. Never use the browser event stream as the sole network ledger.
- Record a durable **admitted** event before forwarding. Record dispatched and terminal outcome separately. A crash after an admitted POST but before a terminal result is ambiguous; resume must not silently resubmit it. Denied requests have explicit terminal evidence. Audit failure is fail closed for network forwarding.
- Archive bounded response bytes, DOM snapshot, selected output, and optional screenshot/download into content-addressed payload storage under a stated retention/encryption policy. Redact cookies, authorization, secrets, and sensitive query/form data from operator-visible records. A screenshot is evidence and may contain secrets; it is not the parsed output.
- First replay mode returns archived browser output/artifacts and matches the exact source job/action/request graph without starting a browser or gateway upstream connection. It does **not** claim deterministic JavaScript re-execution. Verify mode admits the exact source action and request shape before live dispatch, then compares observed artifacts using a declared fidelity policy. Missing, reordered, oversized, or hash-mismatched evidence fails closed. A second live fetch is verify, never replay.
- Add a worker/gateway version, Chromium build, viewport, locale, timezone, and relevant browser flags to job evidence. A changed runtime may change DOM, request order, cookies, or rendering; verify must surface that drift rather than rewriting source evidence.

## Hostile local and deployment acceptance gates

| Probe | Required observation |
| --- | --- |
| Raw socket, DNS, loopback, metadata, IPv4 and IPv6 from browser process and renderer/helper child | No direct connection or resolution; only gateway/control peer reachable. Prove with a known-positive gateway request and known-negative disallowed peer from inside the **same** network identity. Repeat against each deployment target. |
| Main page, iframe, popup first navigation, image/CSS/script, XHR/fetch, dedicated/shared worker, EventSource | Each allowed request appears once in gateway ledger with correct origin, pinned IP, size, and parent graph; unapproved origin blocked before forwarding. |
| Service worker registration and cached fetch | Registration blocked; no network response can bypass gateway ledger. Route/HAR instrumentation alone is insufficient per Playwright's documented caveat. |
| WebSocket, WebTransport/QUIC, WebRTC, non-HTTP schemes, direct proxy `CONNECT` | Denied at gateway or network boundary; no bytes reach the target. A Playwright event alone is insufficient. |
| 30x chain to private IP, unapproved origin, mixed DNS answers, DNS rebinding, alternate port | Each hop independently denied before transport when policy fails; no target receives the request. Preserve a positive same-origin redirect control. |
| Form POST, duplicate/Unicode fields, file upload, large/streaming download, decompression bomb | Wire body hash/size and safe evidence match; cap trip yields terminal refusal and no successful output. A dispatched ambiguous POST is not retried on restart. |
| Two sequential rows with cookies/storage; popup and iframe in first row | Second row sees no cookie/storage, cannot inherit a popup or service worker, and gets its own policy token/budget. |
| Gateway crash, audit-write failure, worker cancellation, browser crash | Fail closed; no unaudited successful output; orphan processes/sockets terminate and uncertain requests remain explicit. |
| Offline replay with network namespace still denied; modified/missing source evidence; verify drift | Replay makes zero upstream connections and reproduces archived output; tampering and changed request/action order fail; verify admits before egress and reports drift. |

Build the fixture with local allowed and forbidden servers that count received requests. A rejection assertion must check **both** the gateway denial and the forbidden server's zero count. Include controls proving that the counters and the gateway ledger detect a deliberately allowed request. Run the same hostile probes under the actual worker image/network policy and against AWS/Azure deployment variants before claiming platform support. Do not run a public government-site canary to establish this security boundary.

## HTTP capability that can ship independently

The release can expose the existing row-oriented `web_scrape` and binary `blob_fetch` path, including fixed-node or row-owned addresses, row-mapped GET queries, ordered URL-encoded forms, and bounded multipart POST with payload-store file references, subject to their own focused gates and documented request policy. These calls use the Python SSRF-pinned audited HTTP client and its replay/verify path; they do not require Chromium. Generic government-search pipelines should express each site's URL, search fields, selectors, ambiguity policy, and pacing in configuration. Do not register `web_browser`, advertise browser actions in Composer, or route a JavaScript-dependent page through an unisolated Chromium fallback while the gate is red.

## GO condition

`web_browser` may enter the catalog only when its implementation, deployment manifests, audit/replay contracts, and hostile gates above are in one reviewed change and pass on every enabled target environment. If a target cannot enforce distinct browser/gateway network identities, disable browser admission on that target and report the capability unavailable. Until then, keep using the existing `web_scrape`/`blob_fetch` HTTP path for fixed-node or row-owned URLs and form search.
