"# Bounded Web reserve proof: concrete design, not an implementation verdict\n\n**Status: DESIGN_ONLY.** A finite cut appears possible in principle. No candidate has yet shown that cut is closed, and no public gate is cleared. The earlier stopped proposal showed an *unimplemented* boundary, not that the product must lose a protection. Keep its report and all rejected proposals unchanged. This review used current source and Python AST reads only; it did not import the scanner or product, run pytest, change live source, or execute a global dispatch scan.\n\n## Measured supported boundary\n\n`current-web-rows.json` (SHA-256 `3ce6fd126cb9a16984686500a3f3d0735aa7276969a9d6c3e24c95637c267f9f`) records the current AST call inventory: **32 `.reserve` attribute calls in nine `src/elspeth/web` files**. This is a syntax inventory, not 32 successful certificates. It walks backwards through the *actual* selected constructors, parameters, getters, field stores/loads, bind/adopt edges, imports and callable descriptors, then forwards to ticket/SQL/provider/telemetry consumers. Every call must have one owned callee, one owned receiver, correct scope, and a complete source-visible origin. A type annotation, spelling, file hash, or `isinstance` against a structural Protocol is not an origin. Where a selected caller has multiple valid branches, each executable branch needs its own certificate. Unexpected reassignment, unsupported aliasing, subclass/descriptor override, callable escape or unresolved input is refusal.\n\nThe existing `local`, `lease_fields`, `lease_origin`, and `prove` machinery (:8169–8515) already expresses parts of the local chain. The concrete change would replace **only** the current implication “any `dispatch_failures()` occurrence in any production unit => no Web certificate” (:6329–6345, :8380–8381) with “a failure on the protected origin/effect graph => no certificate”; it must preserve `_reserve_run`'s actual-row enumeration (:8518 onward) and the old `_mutation_callable_escapes` dependency (:8542 onward). It cannot simply filter the 317 messages after computation or return a certificate when an unresolved protected edge remains. The unrelated existing Landscape DML/API/caller/fence tests remain independently required.\n\n## Finite origin and effect closure needed\n\nThe smallest new rule is a **protected reference/effect slice** with these exact inputs: the 32 call AST nodes; the selected constructor/getter/bind/adopt/validator/consumer definitions above; their imports; the old mutation recognizer's protected callable identities; and the complete current SourceUnit mapping. Resolve a reference to a canonical module/class/function/field identity through direct imports, relative imports, aliases and transitive reexports **only until its protected identity is either proved or unknown**. For those identities, inspect all source units for writes, deletes, rebinding, subclass/metaclass overrides, descriptor substitution, first-class passing/capture and dynamic module access that can reach the identity. Reject unknown at a protected dependency. Do not build a general interpreter for other classes or arbitrary production reflection. A positive control is each actual row with its present constructor and ticket consumer unchanged; another is a harmless unrelated local reflection that neither exports nor reaches a protected identity and leaves every row certificate unchanged. Negative controls must mutate the *companion source*, leaving the selected call-site AST intact, to show that the effect scan is causal rather than a call-site hash check.\n\nSource-wide checking remains necessary for effects *into* this finite graph: Python module globals and builtins can be modified from another file. “Outside the model” is valid only when the resolver shows no import/reexport, call-argument/return, field/descriptor, dynamic-loader, or builtin edge from that expression to a protected identity. Unknown target of a dynamic loader or unresolved selector that could address a protected module remains UNKNOWN/refused. This avoids requiring recovery of every unrelated class while preserving the negative properties relevant to reserve and the old mutation test.\n\n## Previously rejected witnesses and required disposition\n\n| Witness from the two Astra NO_GO reviews | Finite refusal mechanism; positive counterpart |\n|---|---|\n| Companion `builtins.sorted = foreign`, `builtins.tuple = foreign`, `builtins.staticmethod = foreign` with unchanged selected site | Treat these **three actually consumed operators** as exact protected bindings at `composer_operation_errors.py`:149 and the compiler-private factory in `coordination/repository.py`:4509. The finite cut must also retain existing foreign receiver, alias/rebinding, descriptor, wrapper, raw-write, DML authority and fence negatives in the architecture tests. A source pin may guard that the reviewed inputs did not move; it never substitutes for the origin/effect reasoning above.\n\n## What remains to implement and decide\n\nThe exact protected reference/effect slice is **not implemented**. The current `dispatch_failures()` scans the whole corpus and emits 317 historical diagnostics; its present `prove` rejects all rows on any such result. The 317-site diagnostic run did not execute row proof. Therefore there is no current evidence that the proposed finite cut admits all 32 rows or still rejects all companion witnesses. The old gate cannot be switched to this design by changing one assertion. Required next work is one narrowly scoped resolver/effect rule for the protected identities, causal companion negatives on both supported interpreters, then independent review and root-run public node plus older mutation node on the actual final source. No old red is reclassified as a pass by this document.\n\nThe precise unresolved design question is **how to prove source-unit closure for protected aliases and effects**, including imported dynamic loaders, relative imports, transitive reexports and scope-specific class/comprehension lookup, without accepting an unknown that could reach the graph. If source inspection reveals a call or mutation that reaches a protected identity but cannot be resolved under this finite rule, the chosen cut must refuse it. That would be an implementation blocker for the current source, not evidence that the required property must be dropped. Conversely, if a proposed cut *declares* one of those reachable edges irrelevant, it loses a required protection: the smallest examples are the companion `builtins.sorted` replacement changing the exception-ordering callee with the selected `sorted(..., key=_integrity_category)` unchanged, and the foreign unbound initializer reaching `self.authority` despite the sealed argument. Those tradeoffs require an explicit new scope decision; they are not authorized by deferring general proof work to #284.\n\nAll product physical-custody, terminal SQL, PostgreSQL, TLS/browser, default-suite, current public gate, parity, trusted operator signature and protected CI obligations remain separate. This is a concrete design for Astra/root review, not a candidate patch, SOURCE_GO or merge clearance.\n"
