"# Concrete telemetry ownership and cleanup design (implementation held)\n\nThis revision selects a design for actual review. The previous telemetry-cleanup-proposal.md is preserved unchanged. No operator_telemetry.py changes are authorized by this document. The selected failed-bootstrap contract remains absolute: after any constructor side effect, arm FAILED_STARTUP before finalizers and keep it armed even after successful cleanup. No bootstrap COMPLETE optimization, async factory cleanup task, new pool or default callback is proposed.\n\n## Selected process ownership\n\nOne actual create_app lexical lifecycle owns one process telemetry runtime. It allocates a nominal OperatorTelemetryCleanupOwner before calling telemetry bootstrap and registers that exact owner in the existing constructor cleanup collector before any telemetry acquisition. The owner has a private construction seal, an immutable identity token, a synchronized acquisition registry, and terminal cleanup state; callers cannot manufacture a structural substitute.\n\nProposed selected API:\n\n- OperatorTelemetryCleanupOwner.create_for_application() -> OperatorTelemetryCleanupOwner, called once by the actual factory owner.\n- bootstrap_operator_telemetry(settings, *, cleanup_owner: OperatorTelemetryCleanupOwner, factories: OperatorTelemetryFactories | None = None) -> OperatorTelemetryRuntime. The owner is required, not defaulted.\n- cleanup_owner.shutdown_sync() -> TelemetryCompletionWitness. This prebound exact method is the registered factory finalizer before bootstrap starts. It works on partial acquisition and returned-runtime acquisition alike.\n- runtime.shutdown_sync() -> TelemetryCompletionWitness delegates to the exact owning cleanup owner.\n- async runtime.shutdown() -> None retains its current public async signature, calls the same synchronous owner, and raises retained cleanup failures or unresolved custody rather than manufacturing successful completion.\n\nThe process-global runtime record contains both runtime and exact owning cleanup-owner identity. Under the existing global runtime lock, a new owner may acquire telemetry only when no process runtime record exists. Repeated bootstrap by the SAME exact owner while its runtime is active returns the same runtime without acquiring resources or adding another finalizer. Bootstrap by a DIFFERENT owner raises nominal AuditIntegrityError before any telemetry acquisition. The foreign owner's empty finalizer does not close the existing runtime. There is no borrowed lifetime lease or transfer to a later app.\n\nOn cleanup the process record is retained as CLOSED, not cleared to permit another production bootstrap. OpenTelemetry's process-global provider is write-once; installing a fresh provider after closing the first would otherwise leave API meters attached to a dead provider. A new app lifecycle in that process is therefore rejected rather than pretending a restart succeeded. Actual deployment creates one app per process. Explicit test reset remains a test-only path and must use replaceable injected setter/factories for repeated lifecycle construction; it must not silently reopen a globally installed closed production provider. The existing same-provider/global-provider reset behavior needs focused compatibility tests and an explicit fixture migration, not a production fallback.\n\nThis deliberately rejects multiple independent app owners in one process. It does not close another owner's runtime on a failed second constructor. Review should assess this exact restriction against actual factory callers before implementation.\n\n## Default Prometheus closure policy\n\nDefault Prometheus mode has the same process owner and closure rule as aws-otlp. Normal shutdown unregisters the actual Prometheus collector and closes the provider; it does not retain the current mode-specific early return. Prometheus has no periodic reader thread, so its physical witness consists of successful exact unregister/provider cleanup, not a fabricated thread witness. A failed unregister is retained and prevents normal watchdog COMPLETE. A CLOSED runtime cannot serve a later independent app lifecycle.\n\nPrometheus registry membership is checked against the exact acquired collector at the SDK boundary; do not infer closure from absence of exporter traffic or lack of threads. Tests use a dedicated CollectorRegistry through injected factories so controls never alter unrelated process-global collectors. Production continues the existing default registry; no metrics endpoint or authentication policy changes are proposed.\n\n## Concrete reader API: subclasses, not a forwarding proxy\n\nInstalled SDK MetricReader.collect and _set_collect_callback are marked final, and MeterProvider registers the actual reader identity in its measurement consumer and global reader set. A wrapper proxy which forwards to an inner reader would risk a callback bound to the wrong identity. This design uses concrete owned subclasses of the existing installed readers:\n\n- _OwnedPrometheusMetricReader(PrometheusMetricReader)\n- _OwnedPeriodicExportingMetricReader(PeriodicExportingMetricReader)\n\nThey inherit collect, _set_collect_callback, _receive_metrics, force_flush, temporality, aggregation, ticker, and registration behavior unchanged. Neither final method is overridden. The only behavioral override is shutdown(timeout_millis=30000, **kwargs) -> None, which invokes the SDK superclass shutdown exactly once, records the original exception in a preallocated owned receipt before re-raising, and records actual completion evidence. The instances passed to MeterProvider are these SAME actual subclass objects; callbacks, collection consumer identity, reader hash identity and Prometheus collector callback remain normal SDK identity.\n\nReader cleanup receipts are initialized before SDK superclass initialization. They contain retained original BaseException objects, shutdown invocation/return state, and actual physical custody. A nominal reader subclass is allocated using __new__, registered with the cleanup owner, and then initialized with its explicit owned initialization function. This registration-before-initialization is an acquisition seam, not a compatibility alias. A superclass constructor that raises can therefore leave the actual partially initialized owned object reachable. Cleanup consults explicit initialization stages and only retained resources known to have been acquired; it does not invoke arbitrary methods on a partially initialized object.\n\nThe periodic reader captures the exact SDK-created threading.Thread at the installed SDK boundary. The exporter wrapper records its original shutdown errors before existing health-only logging can suppress them. Capturing private SDK fields is a Tier-3 parse into an owned resource receipt with exact assertions, not dynamic structural security dispatch. Missing or wrongly typed fields are nominal ownership defects. The selected integration is version-sensitive and must be verified against the installed SDK and locked dependency version.\n\nProduction factories select the owned reader subclasses; test factory types are updated to return the same nominal owned readers or dedicated nominal owned test readers. No isinstance Protocol dispatch. A custom non-nominal reader returned by a factory is rejected before provider ownership transfer, retaining the actual acquisition receipt so failed construction remains supervised.\n\n## Partial acquisitions and transfer\n\nThe cleanup owner is already reachable from the actual app lexical cleanup collector before bootstrap starts. Resource registration is synchronous, locked and cannot await. Ownership stages are explicit:\n\n1. Prometheus subclass object registered before SDK initialization. Its collector, once created, is retained; successful registry registration is recorded separately.\n2. Raw exporter registered immediately after its constructor returns; exporter construction that fails without returning an actual object is not claimed owned or joined.\n3. Owned health exporter wrapper registered before handing it to periodic reader.\n4. Periodic reader subclass object registered before superclass initialization. After successful initialization, it owns the exporter chain. If initialization raises after thread start, the retained partial object captures the actual thread/event/exporter and enters partial cleanup.\n5. Provider actual object is allocated and registered before initialization using an owned MeterProvider subclass with the same SDK constructor contract. Reader cleanup ownership is transferred to provider only after successful registration of those exact reader identities. Failed initialization leaves the readers individually owned, even if the SDK's static registered-reader set was already updated; exact registration receipts must repair only the entries acquired by this owner.\n6. Runtime construction and instrument wiring do not change ownership. The owning runtime identity becomes process-global only when bootstrap successfully installs/returns it. Any later app construction fault uses the already registered owner.\n\nTransfers are exact source-owner/target-owner identity transitions under one lock; no two cleanup branches invoke the same resource. Provider failure after attempting a reader does not cause a second reader shutdown. Provider initialization failure before transfer invokes individual owned reader cleanup once. Raw exporter cleanup happens individually only if periodic-reader ownership was never transferred. The outer collector invokes one owner finalizer, not one independent finalizer per resource which could double-close a transferred child.\n\nA failure during owner registration itself is an owned integrity defect. Registration precedes initialization for owned SDK subclasses; immediate returned raw-exporter registration must use an already preallocated registry slot so failure cannot strand an object between acquisition and publication. If a third-party raw exporter constructor internally acquires inaccessible resources and raises, the owner retains the incomplete acquisition receipt and refuses a completion witness. It cannot infer inaccessible resources were joined. FAILED_STARTUP remains armed, and the actual independent watchdog remains the process boundary.\n\n## Shutdown and physical evidence\n\nOne owner cleanup invocation is serialized as NEW -> RUNNING -> FINISHED_SUCCESS or FINISHED_FAILURE/UNRESOLVED. Repeated calls after completion return the retained witness or re-raise the retained originals. Concurrent cleanup while RUNNING refuses completion; it never sets completed because cleanup merely started. Each actual resource's SDK shutdown is invoked once.\n\nFor returned providers the SDK shutdown drives exact owned-reader subclass shutdown methods. Each reader override retains its original exception before SDK aggregation. MeterProvider's replacement generic exception is not used to reconstruct originals or matched by message. When reader originals exist, the owner reports those originals and records the provider aggregate as an associated SDK diagnostic object; it does not promote duplicate aggregate text into a new semantic root. An independent provider exception without any recorded reader failure remains an original secondary failure. All actual originals stay reachable for review; public error bodies never contain their representations.\n\nPeriodic reader superclass shutdown performs its existing bounded join and exporter cleanup. The owned override then joins the retained actual thread to real completion if the bounded join left it alive, regardless of superclass success or failure. This synchronous physical join may block the event loop; the already armed independent process watchdog supplies the external grace, not an asyncio timeout. No new executor or abandoned to_thread await is used. The owner retains thread custody until not is_alive and exact join returned. If superclass shutdown raised before setting its event, partial cleanup explicitly requests the actual retained shutdown event before joining, without invoking SDK shutdown a second time. Exporter errors are retained separately. Actual joined thread plus a cleanup error is FINISHED_FAILURE, not success.\n\nNormal async app shutdown must ARM NORMAL_SHUTDOWN before invoking this synchronous telemetry cleanup. FAILED_STARTUP cleanup similarly begins only after ARM. A successful witness requires every acquired reader/provider/exporter custody discharged, exact Prometheus collector unregistered, actual periodic threads joined, and no retained semantic cleanup fault. Only normal successful lifecycle may use that witness for watchdog COMPLETE. Failed startup never sends COMPLETE even with a successful witness.\n\nA primary factory error plus secondary cleanup errors produces a BaseExceptionGroup containing the exact originals. A single original is raised unchanged. The registry retains physical completion and semantic errors separately. No exception string determines whether a resource was acquired, whether a thread stopped or what public error policy applies.\n\n## Installed SDK facts and remaining bounded limitation\n\nRaw inspection evidence: /tmp/transport-telemetry-sdk-readers-full.log and .exit, completed exit 0. MetricReader.collect and _set_collect_callback are final. MeterProvider keeps actual readers in its static registration set and passes its measurement-consumer callback to those identities. PrometheusMetricReader registers a collector and stores collector._callback = self.collect; shutdown unregisters it. PeriodicExportingMetricReader starts a daemon thread during construction, then may register an at-fork callback. Shutdown sets an event, performs a timed join, and shuts down exporter without checking thread liveness. MeterProvider.shutdown catches original reader exceptions and constructs a replacement generic exception string.\n\nThis design addresses returned/partially initialized owned SDK reader/provider objects through pre-registration. It cannot produce custody for inaccessible partial resources inside a throwing raw exporter constructor. Such bootstrap outcome remains UNRESOLVED and armed. If dependency-level proof requires joining those inaccessible resources rather than relying on failed-bootstrap process expiry, this proposal is bounded NO-GO for that constructor class; it does not add a fabricated owner or assert no allocation.\n\n## Meaningful acceptance controls\n\n- New owner creates one runtime; same exact owner repeats idempotently; foreign owner and CLOSED record refuse before acquisition and never close the existing runtime.\n- Default Prometheus normal shutdown unregisters only its exact collector and provider once; mutation restoring mode-specific no-op fails this control. Existing unrelated collector remains registered.\n- SDK-backed counters and histograms collected through each owned subclass preserve exact metric data and callback/reader registration identity; force_flush remains equivalent. Mutation using a forwarding proxy or swapping identity must fail.\n- Fail immediately after each acquisition/transfer and during instrument/global-provider setup; actual owner inventory includes every exposed allocation, closes each once, and preserves primary identity and all secondary originals.\n- Failed registration and partial provider registration clean only this owner's reader entries; foreign entries remain.\n- Actual periodic worker held beyond SDK timed join cannot yield successful witness. Release it and prove thread join before success. Mutation omitting actual liveness check fails. Isolated watchdog child proves hung worker cannot cause COMPLETE; no live endpoint/exporter traffic.\n- Reader original shutdown failure survives MeterProvider aggregation without message parsing; two originals plus primary remain exact objects. Independent provider failure is retained.\n- Duplicate, concurrent, foreign cleanup and provider-after-reader failure prove once-only cleanup and no RUNNING completion.\n- Every constructor side-effect failure proves FAILED_STARTUP ARM before cleanup and no COMPLETE afterward, including successful cleanup. Normal lifespan proves actual successful witnesses before COMPLETE.\n- Throwing raw-exporter constructor is an explicit unresolved negative: no claimed resource-free result or successful witness.\n- Focused controls and owned fake watchdogs only; full touched-source review and frozen gates remain required later.\n\nNo production telemetry implementation is contained in this refinement.\n\n## Global installation identity clarification\n\nOperatorTelemetryFactories gains an explicit get_meter_provider: Callable[[], object] alongside its existing setter. Production uses metrics.get_meter_provider; replaceable test factories expose their actual retained installed provider. After setter invocation, bootstrap requires getter result is the exact acquired provider object before publishing ACTIVE process runtime. A foreign already-installed SDK provider is an owned installation refusal: cleanup only this owner's acquired resources, retain the original refusal, keep FAILED_STARTUP armed, and never close the foreign provider. Setter returning None is not installation evidence. A mutation omitting this identity check must fail the foreign-installed-provider control. Test reset uses the same explicit installed-provider identity rather than assuming a no-op setter means successful installation.\n"
