One row per piece of evidence. Other documents in this pack refer to
evidence as `[EV-nnn]` instead of repeating links, so each item is described
and dated once.

The **Supports** column names the primary control sections for each item; it is
not an exhaustive reverse index. Claim-side citations are the authoritative
record of every place an item is relied upon.

Good evidence is specific and reproducible: a file at a commit, a workflow
run, a configuration export, a test with its result, or a query against an
audit database. A source file can establish design and implementation; an
executed test or query is stronger evidence that the behaviour was observed.
The **Type** column records that distinction. Dated command and hosted-service
results are snapshots and must be refreshed for an assessment; repository
artifacts remain bound to the listed commit.

Product evidence is populated here. Installation identifiers, configuration
exports, operational test results, screenshots and approvals belong in the
controlled deployment copy and remain open in the
[Deployment record](#deployment-record--installation-evidence) section.
