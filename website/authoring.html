Proposals and validation

A candidate remains separate from the active pipeline until the review and wiring steps are confirmed. Validation checks declared settings, connections and schema compatibility.

A passed check is evidence about the configuration. It does not establish that source material is accurate, an LLM answer is correct or the workflow is suitable for a decision.

Data and provider access

Operators configure the available plugins, model providers and permitted secret references. Authoring credentials and permission to execute are separate concerns.

Inspect the data destinations, error routes and external services before you run a pipeline.

Compose explicit processing steps.

Sources and sinks
Read inputs and write outputs through declared plugins. A text source and text sink support text workflows alongside structured file formats.
Transforms and gates
Map fields, process content or call configured models. Gates route rows using configured expressions.
Branching and joining
The graph supports structural queues, fork, and coalesce nodes. A structural queue brings routes to a common downstream node; it is not a human review queue. A fork creates branches; coalesce joins results according to its policy, including require_all .
